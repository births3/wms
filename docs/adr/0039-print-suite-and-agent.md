## 背景

ADR-0036 已完成 H9 第一阶段决策：WMS 管理字段库、模板版本、浏览器预览和浏览器打印。
实际出库还需要把同一批作业的随货同行单、药检单、发票和未来单据按客户要求归集，
依次生成 PDF，并路由到不同打印机或同一打印机的不同纸盒。

订单组号不能直接作为最终归集边界：同一客户可能在不同时间下单，同一送货地址也可能
需要合并多个订单。打印设备又属于执行资源，不能固化在打印模板或打印组套里。项目因此
需要在模板能力之上增加“业务归集、打印组套、PDF 渲染、任务编排、设备映射和
Print Agent”第二阶段。

## 候选方案

### A. 业务页面直接选择打印机并逐份打印

优点：实现路径短。

缺点：业务规则、模板、打印顺序和设备绑定耦合；无法可靠处理多订单归集、多 Agent、
断网续传、部分重打和历史追溯。

### B. 服务端编排打印组套，Print Agent 只负责本地执行

优点：

- 归集、模板、顺序、就绪策略和审计由 WMS 统一治理。
- 打印组套只引用逻辑输出槽，设备差异由 Agent 本地映射吸收。
- 能覆盖多 Agent、打印机故障、断网续打和按分类重打。

缺点：

- 需要新增服务端 PDF 渲染、任务队列、Agent 协议和本地客户端。
- 打印机、纸盒、Windows 驱动和真实产物必须取得 S4 硬件证据。

### C. 每台打印机运行独立服务并自行归集

优点：设备自治。

缺点：业务规则下沉到仓库终端，版本和审计分散；多个终端容易重复归集或重复打印。

## 决策

采用方案 B。ADR-0036 的第一阶段保持不变；本 ADR 定义 H9 第二阶段，不表示对应软件已经
实现或通过硬件验收。

### 1. 领域边界

```text
M4 出库订单及客户/地址/线路
  -> H9 归集与打印组套服务
  -> H9 Render Worker（服务端生成分类 PDF，写入 H-FILE）
  -> H9 打印任务与 Agent 分配
  -> Print Agent（Windows 本地执行）
  -> 打印机 / 纸盒
```

- M4 提供出库订单和冻结后的线路、客户、送货地址。
- H9 决定归集、打印内容、模板、顺序、就绪、任务和执行证据。
- H-FILE 保存或引用 PDF；H9 不自建第二套文件存储。
- Print Agent 不解释客户规则、不渲染业务模板，只执行已冻结的清单和 PDF。

### 2. 随货同行单归集

- 归集结果使用“随货同行单号”，不把 ERP 订单组号直接当最终打印归集号。
- 订单进入 WMS 时冻结线路；同一地址在同一时点只能归属一条线路。
- 到截单时间或授权人工截单时，冻结订单集合并生成随货同行单号。
- 截单时间使用结构化周计划和例外日期，解析优先级为：
  `客户 > 线路 > 货主+仓库`。
- 归集维度由受控配置选择订单标准字段并排列优先级；不允许自由 SQL、脚本或表达式。
- 不同送货地址禁止归入同一随货同行单；地址匹配使用 M1 稳定地址主数据 ID，不以地址文本作键。

### 3. 打印组套

- “打印组套”是面向客户要求的、可发布版本化的打印方案；已发布版本不可改写。
- 匹配优先级为：`送货地址 > 客户 > 线路 > 货主+仓库默认`。
- 同一作用对象和有效期只能存在一条有效规则；同级有效期重叠时禁止发布。
- 组套包含有序打印项。每一项独立指定单据分类、模板版本、份数、逻辑输出槽、是否必需、
  就绪策略和失败策略；同一分类的多份可以使用不同模板。
- 初始分类为随货同行单、药检单、发票；分类可受控新增。
- 发票是否必需、是否必须等待全部发票，以及药检单完整性策略按组套配置。发票完整指
  所有源订单均被有效发票覆盖；药检单完整指所有必需商品与批号均被有效报告覆盖。
- 必需单据未就绪时，组套可配置为仅挂起当前实例、允许后续已就绪实例继续，或暂停对应
  Agent 队列等待人工；该策略冻结到实例，且不得绕过必需性检查。
- 发票和药检单的“地址”指 H-FILE 文件 ID 或已摄取的稳定文件引用，不是客户地址；实际
  下载地址必须按需生成短期访问地址，不得把临时 URL 保存为业务事实。
- 组套版本冻结后，后续配置变更只影响新实例。

### 4. PDF 与打印顺序

- H9 Render Worker 在服务端渲染，按单据分类生成分类 PDF；打印前可选择全部分类或部分分类。
- 完整组套 PDF 仅按需临时合并，不作为唯一归档对象。
- 随货同行单 PDF 按受控保留策略归档；发票、药检单优先引用其权威文件，只保留短期缓存，
  不重复建立长期副本。
- 打印项必须严格按组套顺序提交，即使目标为不同打印机也不并行越序。
- “打印成功”的最低机器判据是本地打印后台任务完成且无设备错误；物理缺纸、卡纸或实际
  产物无法仅凭浏览器或服务端状态证明，需真实设备验收和人工异常处置。

### 5. 打印任务

- 队列按业务优先级后接 FIFO；授权加急可提高业务优先级。
- 组套实例一次只由一个 Agent 执行，一个 Agent 同时只执行一个组套实例。
- 支持整组套、单分类、单打印项重打；页码范围重打需要独立权限。
- 失败策略可配置为暂停或继续，但必需单据不得无授权自动跳过。
- 自动释放或人工释放可配置；作废、取消、重打、改派、跳过和人工确认都保留原 PDF 哈希、
  尝试记录和 H2 审计。
- “暂停接单”与“任务改派”分离：暂停在当前打印项结束后不再开始下一项，也不自动移动
  已分配队列；改派只作用于未开始实例。
- 紧急停止只能尽力取消本地打印后台任务；已提交但结果不明时进入人工确认，不自动重打。

### 6. 打印机、纸盒与逻辑输出槽

- 打印机归属物理打印站点，可被本站显式映射的多个货主+仓库共用，禁止跨站点使用。
- 一台打印机可以维护多个纸盒；纸张类型属于模板/打印项要求，纸盒声明其可承载纸张。
- 打印机和纸盒在独立维护页手工登记，并支持指定纸盒的测试打印和审计。
- 打印组套只引用逻辑输出槽，例如 `DELIVERY_NOTE`、`DRUG_REPORT`、`INVOICE`；
  每个 Agent 把逻辑槽映射到它可访问的主打印机/纸盒，以及可选的本站兼容备用设备。
- 运行中的组套实例使用启动时的映射快照；映射变更只影响新实例。
- 网络打印机可以登记到多个 Agent，但同一时点只能由一个 Agent 持有设备租约；USB 打印机
  只能由实际连接它的 Agent 使用。
- 设备租约释放支持“安全自动释放”和“仅人工释放”两种模式，默认仅人工释放。人工释放
  需要专用权限、原因、二次确认和 H2 审计。
- 租约模式在通用参数维护全局默认，在打印机维护页允许单机覆盖；运行中的租约使用快照。

### 7. Agent 分配与降级

- Print Agent 归属一个物理打印站点，可连接本站多台打印机；Agent 不归属打印组套。
- 分配规则优先级为：`送货地址 > 客户 > 线路 > 仓库默认`。同级同对象有效期重叠时禁止发布。
- 分配规则支持立即或未来生效；规则变更只影响尚未创建的组套实例，不追溯重算既有实例。
- 每条分配规则明确主 Agent 和可选备用 Agent；两者必须属于同一物理打印站点且输出槽兼容。
- Agent 在截单并创建组套实例时解析，不在订单入库时冻结；业务线路仍在订单入库时冻结。
- 主 Agent 开始前故障可转备用；已确认成功的打印项可从下一项续打；当前项结果不明时禁止
  自动重打或自动改派。
- 恢复后的主 Agent 只领取新实例；已分配给备用 Agent 的实例不自动回迁。
- 降级顺序为：Agent 内备用打印机/纸盒 → 备用 Agent → 授权人工改派本站兼容 Agent
  → 具备应急打印专用权限的用户下载 PDF。
- 人工改派保留原业务优先级和原排队时间；运行中、结果不明或等待对账的实例不可普通改派。

### 8. Agent 身份、状态与协议

- 每个 Agent 使用独立 H1 API Key，绑定 `agent_id + print_site_id` 和最小 Print Agent 权限；
  凭据轮换、吊销和过期复用 H1 生命周期，鉴权使用 H9 专用机器身份上下文，禁止用户令牌、
  共享 Key 或普通货主身份。
- Agent 只能领取服务端按 `agent_id` 分配的任务。服务端校验任务的
  `owner_id + warehouse_id` 属于 Agent 所在站点的显式映射；Agent 请求不得传入或选择
  `owner_id`，H2 审计使用任务货主并记录 Agent 与站点身份。
- 注册流程为管理端创建 Agent 并生成一次性注册码，本地录入后换取/激活独立凭据。
- 一次性注册码仅允许完成一次凭据激活，不是通用 API Key；激活后的创建、轮换、吊销、作用域
  和过期策略统一复用 H1 API Key 生命周期。
- 管理页展示 Agent 当前任务、排队实例、版本、心跳、输出映射、凭据状态和审计入口；
  本地 Agent 界面只管理本机，不替代 Web 管理端。
- Agent 主动发起 HTTP 长轮询，服务端不反向连接 Agent。
- 当前部署限定受控仓库局域网，可使用普通 HTTP，但必须同时校验独立 API Key 和精确源 IP
  白名单，禁止信任客户端传入的 `X-Forwarded-For`。该例外不得扩展到跨网段、公网或不可信
  网络；Agent 必须使用静态 IP 或 DHCP 保留地址，范围扩大时必须启用 HTTPS。
- 上述普通 HTTP 是对 ADR-0031 传输 HTTPS 的窄范围例外，只适用于 Print Agent 在受控仓库
  局域网内领取任务、下载其获授权的 PDF 和访问 `/agent-releases`；Web、H-FILE 通用
  上传/下载及其他模块仍执行 ADR-0031 的 HTTPS 契约。
- 配置状态为 `testing / active / disabled`；运行状态为
  `online / suspected / offline / paused`，两者不得相互覆盖。
- 默认心跳 10 秒、30 秒进入疑似离线、60 秒判离线、恢复稳定观察 60 秒；阈值可受控覆盖。
- 启用前测试 API Key、源 IP、物理打印站点及货主仓映射、协议、长轮询、心跳和逻辑输出槽
  完整性，并复用打印机维护页的设备测试结果，不使用真实业务单据测试。
- 站点、API Key、IP 白名单、协议或输出槽映射变化后回到 `testing`；名称和备注变化不触发。

### 9. 断网、对账与本地空间

- Agent 启动组套前必须完整下载清单、全部 PDF 和哈希。
- 执行中断网时只允许完成当前组套，不领取队列中的下一实例。
- 服务端标记“等待 Agent 对账”，不得在此期间自动故障转移当前实例。
- Agent 使用持久化本地日志；重启后扫描缓存并先恢复/对账，再领取新任务。
- 相同尝试标识、服务端仍等待且没有后续重打时可以自动对账；若已有人工动作或后续尝试，
  转人工处理冲突。
- PDF 写入专用 Agent 数据目录，仅作为缓存；服务端确认或人工确认后删除，持久日志不得保存
  业务正文。
- 专用数据目录必须位于应用安装目录之外，并使用 Windows ACL 限制为 Agent 运行账户和本机
  管理员访问；不得使用网络共享目录。
- 清理只删除已对账、已确认、已取消或允许清理的旧缓存；运行中、结果不明、等待对账和人工
  处理文件不得自动删除。空间仍不足时停止接单并告警。
- Web 管理页和本地界面都显示路径、容量、可用空间、缓存、未决文件、可回收空间、最后清理
  和失败原因；Agent 离线时 Web 同时显示最后上报时间。默认剩余空间 20% 告警、10% 停止
  接单；预下载还需满足组套大小加安全余量。
- 未决缓存存在时禁止改变数据目录；关闭未决项并通过权限与空间测试后才可变更，变更后回到
  `testing`。

### 10. Print Agent 客户端与更新

- 首期只支持 Windows，使用 Tauri 2 + React/Rust；采用登录自启动的托盘程序，不安装
  Windows Service，退出程序即 Agent 离线。
- React 只负责本地 UI；Rust 负责长轮询、凭据、Windows 打印、缓存、日志和更新编排。
- 管理页提供客户端下载地址、当前版本、推荐版本、最低版本、发布说明和更新状态。
- 客户端只在启动时检查更新；存在运行中、结果不明或等待对账任务时跳过更新，先恢复并对账。
- 当前版本不低于最低版本时可拒绝推荐更新；低于最低版本时禁止接单。
- 使用 Velopack 提供真实增量更新和完整包回退。增量或 SHA-256 校验失败时只再尝试一次完整
  包；仍失败则保留当前版本。无感仅指不丢任务；更新允许重启客户端。
- 更新只替换客户端程序目录，不得覆盖或清理独立的数据目录、凭据、缓存和持久日志。
- 更新源复用 WMS 固定 `/agent-releases` 地址，提供版本清单、当前 `pilot`、当前 `stable`、
  相邻增量、完整包和 SHA-256。下载复用 Agent 机器 API Key 与精确源 IP 白名单。
- 发布脚本/CI 先写临时文件，校验大小和 SHA-256 后原子改名，最后发布元数据。包按版本和
  SHA-256 不可变保存，WMS 运行进程只有读取权限；管理端不能上传可执行文件。
- Agent 启动时默认检查 `stable`。stable 更新可直接选择更新或暂不更新；选择 `pilot` 必须
  在线登录具备 Agent 管理权限的 H1 用户，不缓存离线凭据。选择只对本次启动有效，下次仍
  默认 stable。
- pilot 提升 stable 由具备 Agent 管理权限的用户手工执行，只改变数据库中的通道指向，必须
  复用完全相同的包和 SHA-256；不设置自动验证门禁，也不重新构建或复制包。H2 记录操作者、
  版本和 SHA-256。
- 禁止版本降级；错误版本使用旧代码重新发布更高版本。pilot 高于 stable 时，切回 stable
  不会降级；要继续取得 pilot 修复，必须在下次启动重新选择 pilot。
- 最低版本与 stable 独立维护；只有具备 Agent 管理权限的用户可以提高。操作前展示将停止
  接单的 Agent，要求二次确认和 H2 审计。低于最低版本的 Agent 先完成恢复/对账，再停止
  领取新任务直至更新成功。
- 在线目录只保留当前 pilot、当前 stable 和相邻增量，旧 Agent 缺少增量时下载完整包；历史
  构建由 CI artifact 归档。不建设 Agent 更新并发调度器。
- 本地日志记录完整更新过程；H2 只记录通道选择、接受更新、应用成功/失败、stable 提升和
  最低版本变更，并包含通道、原版本、目标版本、SHA-256 和结果。stable 接受动作没有用户
  登录时以 Agent 机器身份审计。
- 项目主人明确接受正式环境使用普通 HTTP + SHA-256 且不验证更新包发布者。SHA-256 只能
  检查内容完整性，不能证明来源；更新服务器或网络被控制时，攻击者可以同时替换包和哈希，
  这是已接受的供应链残余风险，不得标记为“发布者验真通过”。
- 更新通道跨网段、公网或其他不可信网络，或者发生更新包替换安全事件时，必须重新评估
  HTTPS 或代码签名；当前受控局域网内不增加签名系统。
- 首个正式版本前按 ADR-0038 直接更新和重装测试 Agent；正式发布后的破坏性 Agent 协议
  变更按 ADR-0016 两阶段实施：先发布可升级 Agent，再提高最低版本并切换服务端契约。

### 11. 管理端菜单和参数层级

“套打中心”保持三层菜单，通过名称前缀表达分组：

- `作业·随货同行单归集`
- `作业·打印任务`
- `方案·打印组套`
- `方案·Agent 分配规则`
- `设备·Print Agent 管理`
- `设备·打印机维护`
- `配置·参数配置`

参数配置只有三层覆盖：`客户 > 货主+仓库 > 全局`。地址、线路等业务匹配规则分别在打印
组套、截单或 Agent 分配页面维护，不塞入通用参数页。

物理打印站点及其货主仓映射复用“设备·Print Agent 管理”维护，不新增第八个菜单。

### 12. 多货主物理打印站点与 Agent 身份

已选择方案 B：新增 H9“物理打印站点”作为打印执行资源边界。一个站点显式映射多个受控的
`owner_id + warehouse_id`；Agent、打印机和设备租约绑定站点。该模型不替代 M1 仓库，也不
修改 M1 仓库的单货主隔离边界。

Agent 使用站点级最小权限机器身份，只能领取服务端已分配给自身且货主仓位于本站映射内的
任务。任务仍按自身 `owner_id` 隔离和审计，Agent 无权提交或切换货主。凭据秘密生命周期复用
H1 API Key，但 H9 通过专用机器身份上下文鉴权，不把站点身份伪装成普通 owner-scoped
`AuthContext`，也不授予通用跨货主业务权限。

## 后果

- 正面：
  - 业务归集、模板顺序和物理设备解耦。
  - 不同仓库可用同一打印组套，通过 Agent 输出槽适配本地设备。
  - 断网、故障转移、重打和人工应急都有可追溯边界。
- 负面：
  - 新增 Windows 客户端、PDF Render Worker、设备租约和本地缓存运维成本。
  - 严格串行保证顺序，但会牺牲同一组套内的并行吞吐。
- 风险：
  - 普通 HTTP 不提供机密性，API Key、业务 PDF 和 Agent 更新包只能在受控局域网例外中使用。
  - 打印后台成功不等于纸张物理成功，必须保留人工异常确认和真实硬件证据。
  - 正式环境更新没有发布者验真；SHA-256 与 IP 白名单不能抵御更新服务器或局域网被控制。
  - 物理打印站点与机器身份尚未实现，冻结设备/Agent 契约前仍需完成安全评审。

## 实施约束

1. 先完成用户故事、原型、OpenAPI 草案和安全评审，再按 outside-in TDD 实现。
2. 不在打印模板中保存打印机、纸盒、Agent 或客户归集规则。
3. 不把浏览器截图、mock 打印机或 PDF 文件存在视为真实打印 S4 证据。
4. Print Agent API Key、PDF 正文和一次性注册码不得写入日志或 H2 diff。
5. 所有配置发布、暂停、改派、重打、人工释放、应急打印和对账冲突都必须有权限和 H2 审计。
6. 首个正式版本前按 ADR-0038 直接维护当前契约，不建设兼容层。
7. 任何跨物理打印站点 Agent、跨站点打印机或结果不明自动重打方案都需要新 ADR，不得配置
   绕过。
8. `/agent-releases` 普通 HTTP 例外只适用于受控局域网内已通过机器 API Key 和精确源 IP
   校验的 Agent，不得扩展为匿名下载或 H-FILE 通用文件通道。
