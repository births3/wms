# ADR-0042：药检单独立客户平台与客户分发副本

## 背景

M-DI 原故事以外部药检平台扫码查询为主，不能覆盖已经确认的实际业务：

1. 药检单从 WMS 入库环节上传并审核，客户查询不能成为第二个写入口。
2. 一个 ASN 只有一个商品，但可以有多个批号，每个批号分别关联药检单。
3. 下游客户需要多账号、客户地址范围、订单范围、历史版本权限和批量下载。
4. 客户查询不能占用 WMS API 或数据库性能。
5. 货主需要在不修改权威原件的前提下，生成带 PNG 图章和可选图像增强的客户副本。

这同时涉及跨上下文集成、安全、文件派生、客户身份和部署边界，必须用 ADR 固定。

## 候选方案

### A. 独立客户平台、独立查询库、事件投影

WMS 保持唯一写入事实源，通过 H2 outbox/事件异步同步到独立客户平台。客户查询、认证、
批量导出和下载授权全部在客户平台完成。

优点：客户流量与 WMS 请求隔离；权限边界清楚；客户平台故障不阻塞仓内作业。

缺点：存在最终一致性和投影运维成本。

### B. 客户页面直接调用 WMS API

优点：实现路径短，不需要查询投影。

缺点：客户并发、批量下载和账号攻击面进入 WMS 核心请求链路，违背性能隔离目标。

### C. 客户平台读取 WMS 只读副本

优点：查询延迟低。

缺点：客户认证、地址范围和业务表结构与 WMS 数据库强耦合；数据库 schema 变化直接影响
客户平台，不能形成稳定防腐边界。

## 决策

采用方案 A。

### 1. 部署与数据所有权

```text
WMS 入库上传/复用/审核
  -> WMS PostgreSQL（唯一写入事实）
  -> H2 outbox / event
  -> 客户平台幂等消费者
  -> 客户平台 PostgreSQL 只读模型
  -> 客户 Web / 批量导出
```

- 客户平台是独立应用、独立服务和独立 PostgreSQL。
- 客户请求不访问 WMS API 或 WMS 数据库。
- 正常事件投影目标为 30 秒内可见；投影失败重试并进入 DLQ，不阻塞 WMS。
- 投影至少包含客户、客户地址、已发货/已签收订单、订单行、当前确认药检单、版本摘要和
  客户副本状态。

### 2. 客户身份与地址范围

- 客户平台使用独立用户名/密码和 token，不复用 WMS 用户或 WMS token。
- 安全实现复用 H1 的密码哈希、锁定、轮换和审计语义，不复用 WMS owner-scoped 中间件。
- 一个客户组织可以有多个账号。
- 客户管理员可以管理本客户账号并查看全部客户地址。
- 普通账号绑定一个或多个稳定客户地址 ID；没有地址范围时无数据访问权限。
- `can_view_report_history` 默认关闭，可以按账号开启。
- M4 出库订单必须持久化 `delivery_address_id` 和不可变地址快照；只将已发货/已签收订单
  投影到客户平台。

### 3. 文件读取与批量导出

- H-FILE 继续保存权威原件、客户分发副本和临时导出包。
- **首期下载通道（正式基线）**：
  1. 客户平台在本地查询库完成客户、地址、订单、商品和批号范围校验；
  2. 签发约 15 分钟有效的下载会话（token），响应 `url` 为客户平台路径
     `/api/v1/files/{token}`，**不是**对象存储预签名 GET URL；
  3. 浏览器再次请求该路径时，客户平台校验会话后 **流式读取** H-FILE 只读存储根并回传；
  4. 全程 **不经过 WMS API / WMS 数据库**。
- 测试实现使用本地或挂载的 `PORTAL_H_FILE_STORAGE_ROOT`；生产将同一语义映射到 H-FILE
  后端（可为对象存储挂载或兼容文件系统），但 **文件字节仍由客户平台下载接口交付**，
  除非后续单独决策升级为对象存储预签名直出。
- 客户平台主服务对附件只读。批量导出任务仅获得读取授权附件以及读写自身
  `wms-exports` 前缀的权限。
- 单次批量导出最多 200 份且不超过 2GB；相同报告版本去重，ZIP 附带包含缺失资料的清单。
- ZIP 保留 7 天；每次单份或 ZIP 下载仍先签发 15 分钟下载会话再流式回传。
- **可选演进**：在不改变鉴权与地址/历史范围模型的前提下，可将第 2～3 步替换为对象存储
  预签名直出，以卸载 portal 带宽；该演进不作为首期验收前置。

### 4. 权威原件与客户分发副本

```text
权威原件（不可变）
  -> 药检单版本（待确认/已确认/已替代）
  -> 图像处理结果（可重新生成）
  -> 固定图章版本
  -> 客户分发 PDF（可重新生成、不可覆盖旧副本）
```

- 权威原件永久不做覆盖处理。
- 图片上传人在审核前手工选择不处理、原色增强或黑白增强。
- JPG/PNG 不超过 5MB，解码后不超过 5000 万像素且单边不超过 12000 像素；PDF 上传沿用
  50MB 上限。
- 图片保留原始像素宽高和比例，放入 A4 页面且不裁剪；原色增强使用轻度去噪，黑白增强
  使用自适应二值化加轻度去噪，中间 JPG 质量为 85%。
- PDF 不做二值化和去噪。带数字签名的 PDF 允许生成盖章副本，客户平台页面提示签名可能
  失效；权威原件继续保留。
- 客户副本默认软上限 50MB。超过时由独立审核人填写原因批准；100MB 为绝对上限。

### 5. 图章与处理版本

- 一个货主同一时间只有一个生效图章。
- 货主管理员上传透明 PNG，在样例报告上拖动和等比例缩放；保存相对坐标和比例并应用
  到全部页面。
- 另一名质量负责人审核发布图章；配置人和审核人必须不同。
- 图像处理先执行，彩色图章最后叠加。
- 新图章和新处理规则均形成不可变版本。
- 发布新的处理规则时，操作人选择“仅用于之后确认”或“重新处理当前有效报告”。
- 重处理走后台任务，旧副本不删除；新副本成功后才切换当前客户副本。

### 6. 失败、安全与审计

- 副本生成失败不阻塞药检单确认、入库或发货；客户平台显示处理中/失败，不提供未盖章原件。
- WMS 审计上传、编辑、复用、审核、版本切换、图章发布、处理和事件投递。
- 客户平台审计登录、查询、查看、单份下载、批量导出和 ZIP 下载。
- 审计和日志不得记录密码、文件正文、存储凭据、完整下载 token 或可重放的临时 URL。
- 权限与范围校验必须在签发任何下载会话（或未来的预签名 URL）之前完成；批量任务不能
  绕过地址或历史版本范围。

## 与既有 ADR 的关系

1. 本 ADR 不取代 ADR-0031；文件仍由 H-FILE 统一保存。
2. 本 ADR 不改变 ADR-0041 的 H9 `external_file` 权威文件语义。客户分发副本是 M-DI
   专用派生物，不自动成为 H9 打印事实源。
3. 客户平台认证只复用 H1 安全语义，不共享 WMS 用户表、token 或权限中间件。

## 后果

### 正面

- 客户流量、批量导出和账号风险与 WMS 核心请求链路隔离。
- 原件、版本和客户副本分离，支持更正、重处理和完整审计。
- 地址范围与实际出库订单绑定，避免账号通过批号搜索看到非本订单资料。

### 负面

- 增加独立部署、事件投影、DLQ 和客户平台审计运维。
- 客户看到的数据存在正常不超过 30 秒的最终一致性窗口。
- PDF/图片处理需要受限后台任务和资源指标。

### 风险

- PNG 图章只是可视图章，不是带证书、可信时间戳和验签能力的法律电子签章；不得宣称具备
  正式电子签章效力。
- 二值化可能降低小字可读性；以并排预览、审核人切换原色增强和保留原件缓解。
- 重新处理当前有效报告可能产生大量任务；以 200 份/2GB 导出限制、后台队列和并发限制
  隔离，具体吞吐在生产实现前通过 L7 固化。

## 实施约束

1. 按 ADR-0043 直接在生产应用使用开发 Mock 走查，再定稿 OpenAPI 和生产数据表。
2. 生产实现使用 outside-in TDD；当前 ADR 和开发 Mock 不能作为软件完成证据。
3. PostgreSQL 约束至少覆盖当前确认版本唯一性、上传人与审核人不同、一个货主一个生效图章、
   事件幂等和导出任务范围。
4. L7 至少覆盖图像解码上限、100MB 硬上限、200份/2GB导出、事件30秒目标和客户查询容量。
5. 首个正式版本前按 ADR-0038 直接同步当前基线，不保留旧 M-DI 接口兼容层。
