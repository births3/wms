# ADR-0036：H9 打印模板引擎方案

- 状态：Accepted
- 决策日期：2026-07-05
- 决策人：项目主人
- 起草人：AI 助手
- 关联：H9 / H3 OpenAPI 契约 / H5 快递 / M2 入库 / M4 出库 / M6 报表 / M-PK 包装站 / [用户故事：H9 打印模板引擎](../domain/user-stories-h9-print-template.md)

## 背景

打印模板能力原先作为 M2 的 US-M2-009 记录，但实际被 ASN 单、验收记录单、随货同行单、库位标签、LPN 标签、商品标签、快递面单和台账打印等多个模块复用。若继续让 M2 承担模板设计、字段绑定、版本管理和打印记录，会造成跨模块重复实现。

已调研的 MES 项目采用 hiprint WebComponent 包装可视化设计器，具备拖拽设计、字段绑定、预览和浏览器打印基础能力。WMS 需要复用成熟设计器能力，但模板类型、字段库、货主覆盖、版本、审计、权限和业务接入必须由 WMS 自己治理。

## 候选方案

### A. 第一阶段使用 hiprint WebComponent，WMS 管理业务治理层

优点：
- 复用成熟模板设计器，减少从零实现拖拽设计器的成本。
- WMS 可以继续掌控字段库、版本、审计、货主覆盖和权限。
- 适合先跑通 PC Web 浏览器预览和浏览器打印。

缺点：
- hiprint JSON 与 WMS 字段库之间需要映射和版本治理。
- 依赖引入前必须完成许可证、维护活跃度、漏洞和浏览器兼容性检查。

### B. WMS 自研模板设计器和渲染器

优点：
- 模板 DSL、字段库、渲染行为完全受控。
- 后续可深度适配 GSP 单据格式。

缺点：
- 第一阶段成本高，且容易重复造设计器、拖拽、分页、缩放、条码等能力。
- 难以在当前业务缺口未收口时保证实现质量。

### C. 每个业务模块维护固定模板

优点：
- 各模块初始实现最短。
- 不需要横向模板中心。

缺点：
- 模板、字段、版本、审计和货主覆盖会分散。
- 后续新增单据和标签时重复实现，无法形成统一治理。

## 决策

采用方案 A：H9 作为独立横向能力，第一阶段使用 hiprint WebComponent 作为可视化设计器，WMS 负责外围业务治理层。

具体决策：

1. H9 从 M2 拆出，成为 `print-template` 横向能力。
2. 模板类型使用系统字典 `print_template_type` 维护，每个字典项绑定字段库编码。
3. 模板支持全局默认和货主覆盖；货主模板优先级高于全局模板。
4. 字段库草稿从 H3 OpenAPI schema 生成，字段元数据由数据库维护。
5. 字段库采用草稿 / 发布版本；模板版本只能绑定已发布字段库版本。
6. 已发布字段库版本、已发布模板版本、已产生打印记录的模板版本不可改写。
7. 第一阶段 PC Web 使用浏览器预览和浏览器打印；不默认引入静默打印客户端。
8. H5 快递面单、M6 法定报表、后端 PDF/Word 渲染和静默打印客户端只保留接入契约，不作为第一阶段深度范围。

## 后果

- 正面：
  - 打印模板从 M2 内嵌故事升级为横向能力，M2/M4/M1/M3/M-PK/H5/M6 可统一接入。
  - 复用 hiprint 设计器能力，避免先期投入过多 UI 设计器成本。
  - 字段库版本和模板版本可追溯，满足 GSP 场景下的审计要求。
- 负面：
  - 需要新增字段库元数据、模板版本、打印记录等后端模型。
  - hiprint 的模板 JSON 需要长期兼容策略，不能直接把第三方结构当作业务唯一事实源。
- 风险：
  - 若没有字段库版本治理，模板升级会影响历史打印。
  - 若直接让业务页面手写字段绑定，会重新出现跨模块字段漂移。
  - 若后续静默打印客户端提前进入范围，会扩大设备、驱动和部署复杂度。

## 实施约束

1. 先实现 H9 用户故事中定义的模板类型、字段库、字段元数据、模板版本、预览和浏览器打印，不直接展开静默打印客户端。
2. 任何业务模块新增打印场景，必须先登记或复用 `print_template_type` 字典项。
3. 任何模板版本保存时必须绑定字段库发布版本，禁止绑定字段库草稿。
4. 打印记录必须保存模板版本、业务单据标识、货主、操作人、打印状态和失败原因。
5. 业务接入必须按“显式模板校验 → 货主默认 → 全局默认”的顺序解析模板，禁止跨货主回退。
6. H9 的后端实现必须遵守 `handler -> service -> domain/repository` 分层；前端实现必须走 `page -> feature -> api-client` 和 `page -> @wms/ui business`。
7. 引入 hiprint 相关依赖前，必须按依赖治理检查许可证、维护活跃度、漏洞和浏览器兼容性。
8. M6 法定报表数据口径继续遵守 ADR-0023，H9 只提供模板能力。

## 实施记录

- 2026-07-07：PC H9 首个真实切片引入 `hiprint@0.4.0` 和 `jquery`，以动态导入方式接入设计器、预览和浏览器打印；模板主数据、模板版本、字段绑定和打印记录仍由 WMS 表和 OpenAPI 治理。
- 依赖治理记录：`hiprint@0.4.0` npm 声明 MIT，包来源为 CcSimple/vue-plugin-hiprint；构建时 Rollup 会提示 hiprint 包内部存在 `eval` 和较大动态 chunk。该风险必须在正式发布前复核，不得把 hiprint JSON 当作唯一业务事实源。
