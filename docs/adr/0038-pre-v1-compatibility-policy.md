# ADR-0038：首个正式版本前不保留版本兼容层

- 状态：Accepted
- 决策日期：2026-07-22
- 决策人：项目主人
- 关联：ADR-0006 / ADR-0016 / `AGENTS.md` / `docs/governance.md`

---

## 背景

项目尚未发布首个正式版本，没有需要继续服务的已发布数据库或 API 契约。此时维护旧字段、
旧接口、兼容迁移、双读双写和过渡适配会增加验证成本，却不能保护真实用户。

## 候选方案

1. 从开发期开始维护所有历史契约和迁移路径。
2. 首个正式版本前只维护当前基线，发布后再启用版本兼容治理。

## 决策

采用方案 2：

- 首个正式版本前，数据库、OpenAPI、api-client、前后端模型、测试和文档直接同步当前基线。
- 不保留未发布版本的旧字段、旧接口、兼容迁移、数据回填、双读双写、调用别名或过渡适配层。
- L9 版本兼容门禁在首个正式版本后启用；发布前只执行 L2 当前契约一致性检查。
- 首个正式版本发布后，破坏性变更、迁移、灰度和回滚按 ADR-0016 执行。
- 协议互操作、外部系统适配、业务降级、审计历史和规则版本历史不属于本 ADR 的版本兼容层。

本 ADR 仅替代 ADR-0006 中“开发期立即启用 L9”的时机，不改变其余 TDD 和测试分层决策。

## 后果

- 当前代码和迁移更少，开发期只验证一套事实源。
- 已应用旧 migration 的本地数据库需要重建，不能依赖迁移校验和继续升级。
- 首个正式版本发布前必须建立发布基线，届时启用 L9 和 ADR-0016 的兼容迁移流程。
