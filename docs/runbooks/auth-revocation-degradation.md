# H1 撤销存储故障运行手册

适用范围：Redis 撤销存储（`permissions_changed_at` 和 token blacklist）出现超时、连接
失败或抖动时的 WMS API 运行处置。策略由 [ADR-0046](../adr/0046-high-risk-write-revocation-fail-closed.md)
锁定。

## 1. 响应矩阵

| 请求 | Redis 正常且未撤销 | Redis 正常且已撤销 | Redis 不可用 | 恢复后的下一请求 |
|---|---|---|---|---|
| 读取 | 放行 | 401 `AUTH-004`/`AUTH-009` | 放行并记录 P1 | 重新检查，按正常列处理 |
| 普通写入 | 放行 | 401 `AUTH-004`/`AUTH-009` | 放行并记录 P1 | 重新检查，按正常列处理 |
| 高风险写入 | 放行 | 401 `AUTH-004`/`AUTH-009` | 503 `AUTH-010`，不启动业务事务 | 重新检查；未撤销才放行 |

高风险动作包括角色/用户/API Key/会话变更、双人策略和质量审批、库存盘点审批与
质检调整、M4 关键状态转换、H9 发布/准备/紧急打印，以及共享清单中的其他受控动作。

## 2. 发现与告警

1. 关注 API 日志中的 `auth revocation store unavailable`，字段 `alert=P1` 和
   `risk=HighRiskWrite` 用于区分影响范围。
2. 记录首次失败时间、最后失败时间、Redis 节点/连接错误、503 数量和受影响的高风险
   operation；不要只记录“Redis down”。
3. 普通读取/写入虽然会继续，但最长 access token TTL 的撤销窗口仍是安全事件，按 P1
   事件通知安全和业务负责人。

## 3. 处置步骤

1. 确认 API 进程仍在运行，并从非破坏性读取接口验证普通请求是否符合矩阵。
2. 检查 Redis 连接、故障转移和网络；禁止临时关闭撤销检查、修改 JWT secret 或把
   业务请求改走未鉴权入口。
3. 对高风险写入返回的 503 使用退避重试；非幂等写入必须先确认前一次请求是否已提交，
   再使用原幂等键重试。
4. Redis 恢复后，用一个未撤销 token 和一个已撤销 token 分别验证读取、高风险写入两类
   请求；确认高风险路径重新执行撤销检查。
5. 关闭事件前归档日志、时间线、Redis 故障原因、恢复验证和受影响操作清单。

## 4. 边界

- 当前策略不做 PostgreSQL 回查；数据库故障不会把 Redis 不可用转换为放行。
- Redis 恢复不会回放故障期间被普通写入接受的请求，也不会自动撤销已提交的业务事务；
  需要由安全/业务负责人按审计记录复核。
- 新增高风险接口必须先更新 `auth.rs` 清单、ADR-0046、H1 故事和矩阵测试。
