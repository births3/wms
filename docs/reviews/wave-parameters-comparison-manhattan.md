## 1. 上下文

本项目（医药冷链 GSP WMS）的出库波次能力当前由以下故事覆盖：

- **US-M4-001**：出库订单管理
- **US-M4-002**：波次规划（核心算法）
- **US-M4-009**：波次出库箱规则（v5 增加 6 种箱型 + 6 步尺寸推荐算法）
- **US-M4-010**：拣选路径策略
- **US-M4-011**：合并发货与拆单
- **US-M-TE-008**：PDA 任务执行通用规范（v5）
- **US-M-RP-002/003/004**：补货三层触发（日常/紧急/补拣）

Manhattan WMOS 是行业头部 WMS，其波次模板含约 99 个参数。本对比用于评估本项目波次能力的覆盖度。

## 4. 后续讨论清单（按优先级）

### 🔴 P0 — 强烈建议 Wave 4 出库模块详化时补齐

| # | 项 | 落点 | 理由 |
|---|---|------|------|
| P0.1 | 波次容量限制（最大订单数/明细行/重量/体积/件数）| M4-002 | 防止单波次过大失控 |
| P0.2 | 比较货品库存（拣货前再次校验库存）| M4-002 | GSP 严格性 |
| P0.3 | 失败订单 abort wave 策略 | M4-002 | 避免整波卡死 |
| P0.4 | 零拣补货源三级（存储 → 箱拣 → 零拣）| M-RP-002 | 完整补货链路 |
| P0.5 | WaveQueuePriority 对齐 M-TE 任务优先级 | M-TE-004 + M4-002 | 任务调度统一 |

### 🟡 P1 — 提效/可运营性

| # | 项 | 落点 | 理由 |
|---|---|------|------|
| P1.1 | 波次类型扩展（客户订单/补货/差异处理）| M4-002 | 不同业务流分类管理 |
| P1.2 | 波次模板（命名 + 工作日 + 轮班）| M4-002 | 运营层面 |
| P1.3 | 整箱/零拣处理类型提到波次级配置 | M4-002 + M4-003 | 让波次决定本次拣货模式 |
| P1.4 | 自定义说明字段 1-5 + 属性 1-5 | M4-002 | 扩展槽，避免后期改 schema |
| P1.5 | 拣货区分配（静态/动态）对齐 M-TE 任务组 | M-TE-002 + M4-002 | 任务组与区域绑定 |
| P1.6 | 合并发货拒绝规则（细化 M4-011）| M4-011 | 业务清晰 |
| P1.7 | 重新排序零拣库位（LIFO/FIFO 拣选顺序）| M4-010 | 与效期管理同源 |
| P1.8 | 日志摘要/详细级别 | H2 审计 | 便于排错 |

### 🟢 P2 — 看业务量再说（中大型仓库才需要）

| # | 项 |
|---|---|
| P2.1 | 散装波次（4 项）— 单仓 < 1000 单/天不必 |
| P2.2 | 区域拣选拆分维度（巷道/Bay/位置）— 大型仓 ≥ 5 库区才有意义 |
| P2.3 | 高级补货策略（合并/抑制/配平）|

### ⚪ 不做（医药 GSP 场景不允许）

| # | 项 | 理由 |
|---|---|------|
| 替代货品 | 医药严禁随意替代 |
| 散装拣货部分选项 | 与医药复核要求冲突 |

## 6. 不确定 / 待业务方确认

1. 工作日/轮班是否在 WMS 配置，还是由 ERP/排班系统给出（影响 P1.2）
2. 业务方对"散装波次"的实际需求强度（影响是否升 P2 → P1）
3. 区域拣选粒度（巷道/Bay/位置）取决于实际仓库布局，需仓库主管确认（影响 P2.2）
