## 5. 汇总：已落地模式 vs 真缺口

### 5.1 已落地模式（14 个，全部有独立模块/ADR 承载）

1. 规则引擎 → M-VR（词频 1026）
2. 审计引擎 → H2（词频 773）
3. 状态机引擎 → H6（词频 630）
4. 编码/追溯引擎 → M-TC + M-CG（词频 409）
5. 配置中心 → M1-008 + ADR-0013（词频 434）
6. 任务引擎 → M-TE（词频 345）
7. 通知/告警 → H4 + H-AL（词频 239）
8. 打印/模板引擎 → H9（词频 196）
9. ERP 防腐层 → H8（14 文件引用）
10. 导入导出引擎 → H7（6 文件引用）
11. 备份/归档 → H10 + sharding-matrix
12. 权限/多租户 → H1（14 文件引用）
13. 事件总线 → H2-005
14. 对账 → M-RC（8 文件引用）

### 5.2 真缺口（5 个，需要新增 ADR 或 infra 文档）

| # | 缺口 | 严重度 | 词频/文件数 | 建议时点 | 建议产出 |
|---|---|---|---|---|---|
| 1 | **弹性工程**（幂等/重试/限流/熔断/降级/死信） | 🔴 P0 | 173 次 / 散布全模块 | Wave 1 | ADR-0018 弹性工程 |
| 2 | **定时任务/调度框架** | 🟡 P1 | 12 个故事文件 | Wave 1 | coding-standards §调度约定 或 infra/scheduler.md |
| 3 | **文件存储/附件** | 🟡 P1 | 5 个故事文件 | Wave 2 前 | infra/file-storage.md |
| 4 | **并发控制策略** | 🟡 P1 | 3 个故事文件 | Wave 1 | coding-standards §并发控制 |
| 5 | **缓存策略** | 🟢 P2 | 29 次 | Wave 1 末 | infra/cache-strategy.md |

### 5.3 缺口优先级判断

- **弹性工程 P0**：173 次词频 + 散布全模块 + Wave 1 H1/H2 实施时就需要幂等/重试/限流 → 必须 Wave 1 启动前有方案
- **定时任务 P1**：12 个故事需要但 Wave 1 H 层不直接用（H10 备份用 cron 但已在 technical-specs 自描述）→ Wave 1 期间补即可
- **文件存储 P1**：5 个故事需要但 Wave 1 H 层不直接用 → Wave 2 前补
- **并发控制 P1**：3 个故事需要 + Wave 1 H1 token 刷新可能涉及 → Wave 1 期间补
- **缓存 P2**：ADR-0001 已选 Redis + Wave 1 末 H1 token 缓存才真正需要 → Wave 1 末补
