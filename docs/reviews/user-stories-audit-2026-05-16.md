**修复建议**：M1-008 配置分类表更新两行。

## 14. v6 修复（PDA 验收档案补录闭环）

> 时间：2026-05-16 14:30
> 触发：用户提出"验收 PDA 要加基础信息补录 要有记录"
> 设计原则：复用 M-QL 质量联系单 + H8 ERP 防腐层 + 阻塞性 ERP 闭环
> 关键决策：1B 复用 M-QL / 2 与质量联系单一致 / 3A 阻塞验收 / 4A 5 次重试

### 14.1 业务背景

PDA 验收时收货员可能发现商品基础档案与实物不符或档案缺失（如批准文号错误、包装层级缺失、储存条件枚举错误等）。需求：
- 现场补录新值
- 不在 WMS 修改主数据（商品主数据由 ERP 主管）
- 走完整 ERP 闭环：推送 → ERP 变更 → 同步回 WMS

### 14.2 设计架构（复用现有模式）

```
PDA 验收 → 触发"档案补录" → M-QL 联系单（新类型）→ 仓库主管审批
  ↓ 同意
WMS 写 H8 ERP 接口表（专用重试 5 次/5 分钟/24h 超时）
  ↓
ERP 拉取 → ERP 主数据变更（ERP 内部流程）
  ↓
ERP 通过 M1-001 商品档案 API 推送变更回 WMS
  ↓
M-QL 联系单状态变"已落地" → M2 ASN 解除"档案补录中"阻塞
  ↓
验收恢复，使用 ERP 同步后的最新档案值继续
```

### 14.3 文档修复（4 个故事 + 1 个基础设施）

| 文件 | 修改内容 |
|------|---------|
| **M-QL-001** | 联系单类型增加"档案补录" + 4h 超时（阻塞验收，需快速）|

## 32. v22 M3-006 库内移库扫码规则（2026-05-16 22:45）

> 触发：用户提"库内移库 由电子监管码的 强制 要扫电子监管码，参数进行控制"

### 32.1 业务规则梳理

| 移库模式 | 是否扫电子监管码 | 理由 |
|---------|---------------|------|
| 整托/整箱 LPN 全量迁移 | ❌ 不扫（LPN 容器码代替）| 一托盘几百个码扫不完，扫 LPN 即可 |
| 部分整件移库 | ✅ 必须逐件扫 | 物理上一件一件搬，扫码不增加额外工作量 |
| 零拣移库（拆零）| ✅ 必须逐件扫 | 同上 |
| M-TC 模块未启用项目 | ❌ 本规则不适用 | 项目层面未上追溯码体系 |

**关键洞察**：这不是参数控制，是**业务硬规则**——参数仅决定"M-TC 模块整体启用 / 关闭"。

### 32.2 修改 US-M3-006

从 7 项验收标准简版**重写**为完整故事：

- 增加：移库模式与扫码规则（mermaid 决策流程图 + 模式定义表）
- 增加：PDA 三件套（字段表 8 字段、扫码顺序 5 步、离线声明）
- 验收标准从 7 项扩到 12 项
- 新增"业务边界声明"段（6 条规则）

### 32.3 决策流程图（mermaid）

4 路决策：
1. M-TC 模块未启用 → 直接移库不扫码
2. M-TC 启用 + 整托 LPN → 扫 LPN 容器码代替
3. M-TC 启用 + 部分整件/零拣 → 必须逐件扫码
4. 系统按扫第 2 步内容（LPN 还是商品码）**自动判定**模式，**无需保管员手选**

### 32.4 联动 M-TC 跨故事约束

- **不上报"码上放心"**：移库不是国家平台接收的状态变更类型（与 v21 M-TC-007 上报内容仅含追溯码 + 状态变更类型 + 时间戳一致）

### 32.5 关键设计选择

| 设计点 | 选择 | 理由 |
|------|------|------|
