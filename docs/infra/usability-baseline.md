# 易用性基线（Usability Baseline）

> 定位：基础设施层文档（不是用户故事）
> 目的：把 GSP 5.63"操作便捷、维护方便、安全稳定"翻译为可测的 SLA + 验证手段
> 关联：ADR-0006 §2.1 L7 性能维度（含易用性 SLA）+ docs/compliance/gsp-ch5-warehouse-management.md 5.63

---

## 1. 背景

GSP 第 5 章 5.63 条要求计算机系统"操作便捷、维护方便、安全稳定"。这是模糊的法规语言，必须翻译为可测的工程指标，否则无法验证、无法审计、无法在 retro 时归责。

本文档定义的指标 = WMS 项目易用性的"地板"。所有相关功能必须达到，否则视为不满足 5.63。

---

## 2. 易用性 SLA 矩阵

### 2.1 PDA 端（操作便捷）

| 指标 | P95 阈值 | P99 阈值 | 测量方式 | 关联模块 |
|------|--------|--------|--------|--------|
| PDA 单步交互响应（从扫码 / 点击到 UI 反馈）| ≤ 1.5 s | ≤ 3.0 s | E2E 录像 + 服务端 trace 关联 | M2 / M4 / M-SA / M-PK |
| PDA 离线模式启用切换 | ≤ 0.5 s | ≤ 1.0 s | 本地操作埋点 | M2 / M4 / M-SA |
| PDA 离线数据同步（≤ 1000 条暂存）| ≤ 30 s | ≤ 60 s | 同步开始-结束时间戳 | 各 PDA 故事 |
| PDA 扫码识别准确率 | ≥ 99.0% | ≥ 99.5% | 真实扫码 1000 次 / 设备 / 商品类型 | M-TC / M2 / M4 |
| PDA 应用冷启动 | ≤ 4.0 s | ≤ 6.0 s | 启动埋点 | 全部 PDA 故事 |

## 3. 验证手段（L7 测试落地）

### 3.1 自动化测试

- **后端**：`criterion` 基准 + `cargo bench` 集成到 T4 verify；阈值违反时 CI 失败
- **前端**：Lighthouse CI（PC / PAD）+ Playwright trace（关键流程）+ Detox（PDA 启动 / 路由）
- **PDA**：真机回归至少 1 台 Android + 1 台 iOS（如有），关键路径每波次 retro 时跑一次

### 3.2 人工验证（NPS + 访谈）

- 每波次结束 retro 阶段：仓库主管 / 收货员 / 保管员各 ≥ 1 人填写易用性问卷（NPS ≥ 4 / 5）
- 关键页面（PDA 拣货 / 复核 / 双人扫码）每波次至少 1 次现场跟岗 30 分钟，记录卡点

### 3.3 监管检查现场支持

- 提供"检查员账号"演示模式：从首页到任一 GSP 法定台账 ≤ 3 次点击；含离线 PDF 导出能力（H9 模板引擎）

## 5. 不变量（红线）

1. **任何指标连续 2 个月未达标**：必须在 retro 中列为 Action Item，不允许搁置
2. **PDA 单步交互 P95 > 3 s** 或 **关键 API P95 > 1 s**：触发性能优化任务
3. **接口可用性 < 99%**：触发可用性专项 retro + 根因分析
4. **GSP 检查现场无法在 ≤ 5 分钟内导出指定时间窗的法定台账**：视为 5.63 不满足，整改后才可上线
5. **本文档阈值变更必须经 ADR 流程**：不允许个人下调而不留决策追溯

## 6. SLO / 性能预算（v3.1 引入，参 ADR-0011）

> 服务级目标（SLO）+ 错误预算（Error Budget）。每个核心 endpoint 必须达成。
> Wave 1 实施期开始建立 baseline，Wave 4 末转生产 SLO。

### 6.1 关键 endpoint SLO

| Endpoint 类别 | 频率 | p95 | p99 | 错误率 | 可用性 |
|---|---|---|---|---|---|
| **PDA 扫码（高频）** | > 1000 req/h | 200 ms | 500 ms | < 0.1% | 99.95% |
| **库存查询（中频）** | > 100 req/h | 300 ms | 800 ms | < 0.5% | 99.9% |
| **出库订单创建** | < 100 req/h | 500 ms | 1.5 s | < 0.5% | 99.9% |
| **报表生成（低频）** | < 10 req/h | 5 s | 15 s | < 1% | 99.5% |
| **监管上报（关键）** | < 100 req/h | 1 s | 3 s | < 0.01% | 99.99% |
| **审计追踪查询（GSP）** | < 50 req/h | 1 s | 3 s | < 0.1% | 99.9% |
| **PDA 离线同步** | 高频突发 | 500 ms | 2 s | < 0.5%（含 H1 §7 冲突）| 99.9% |

### 6.2 错误预算（Error Budget）

每月错误预算 = (1 − 可用性 SLO) × 30 天：

| SLO | 月度错误预算 | 触发"冻结发布"阈值 |
|---|---|---|
| 99.99% | 4.32 分钟 | 用尽 50% (2 分钟) |
| 99.95% | 21.6 分钟 | 用尽 50% (10.8 分钟) |
| 99.9%  | 43.2 分钟 | 用尽 50% (21.6 分钟) |
| 99.5%  | 3.6 小时 | 用尽 50% (1.8 小时) |

**冻结发布**：错误预算用尽 50% → 仅允许 hotfix；用尽 100% → 全部冻结，必须根因分析。

### 6.3 业务 SLI（Service Level Indicator）

每个核心模块至少 5 个 SLI（参 ADR-0011 §KPI 清单）：

| 模块 | 关键 SLI | 阈值 |
|---|---|---|
| M2 入库 | 收货流程 p95 耗时 | < 5 分钟 |
| M2 入库 | 双人验收触发率 | < 5%（特殊药品 100%）|
| M3 库存 | 库存查询 p95 | < 300 ms |
| M3 库存 | 状态变更 p99 | < 1 s |
| M3 库存 | 近效期商品识别 | 100% 匹配 expire_warning_days 配置 |
| M4 出库 | 拣选 p95 | < 30 秒 |
| M4 出库 | 复核错误率 | < 0.05% |
| M-TC 追溯码 | 监管上报 p99 | < 3 s |
| M-TC 追溯码 | 上报成功率 | > 99.5% |
| H1 鉴权 | token 校验 p99 | < 50 ms（含 Redis 缓存）|
| H4 通知 | 推送 p95 | < 5 s |

### 6.4 SLO 监控落地（Wave 1 末）

- Prometheus 抓取 metric → 计算 SLI（参 ADR-0011 metric 命名）
- Grafana SLO 仪表板（每 endpoint 一个 panel）
- 错误预算消耗速率告警（H-AL 集成）
- 月度 SLO 报告（自动生成 + 业务方 review）

### 6.5 容量规划

依据数据量评估（concept-audit 5 年累计 ≈ 164M 行 / 30GB）：

| 时点 | 数据量 | DB 配置 |
|---|---|---|
| Wave 4 末 | 1 亿行（迁移完成）| 8C / 32G / 1TB SSD |
| Wave 5 末 | 1.5 亿行 | 同上 |
| Year 2 | 1.8 亿行 | 同上（优化分区）|
| Year 5 | 3 亿行 | 16C / 64G / 2TB SSD |

> 详细分区策略参 docs/infra/sharding-decision-matrix.md

### 6.6 i18n / 国际化（显式推迟）

国际化不在当前易用性基线范围内。决策与启动条件参见 [ROADMAP.md](../../ROADMAP.md) 的"国际化（i18n）backlog（明示推迟到 v25+ / FDA 客户场景）"段。

简述：当前 100% 中国 GSP 场景，无 i18n ROI；ADR-0010 错误码已预留 `message_zh + message_en` 双语字段做最低限度兼容；前端/字段词典/日志保持纯中文。
