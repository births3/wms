# M2 PC Web 入库三页设计规划

> 记录时间：2026-06-27
> 适用范围：`apps/web-admin` 的 `M2 收货管理`、`M2 验收管理`、`M2 上架管理`
> 事实源：`docs/domain/user-stories-m2-inbound-asn.md`、`docs/domain/user-stories-m2-inbound-verify.md`、`docs/domain/clarifications.md` 问题 72-74。

## 1. 目标

PC Web 端支持 M2 收货、验收、上架三步，但不新增业务流程、状态、角色或接口语义。三个菜单必须是独立作业页，不再只是同一个“入库总览页”的筛选模式。

每个页面都要有真实前端截图证据，截图来源为 9002 端口运行的 `apps/web-admin`，并按页面和弹窗分类保存。

退货分类按 `docs/domain/clarifications.md#c8-销售退货与采购退货归类` 执行：销售退货 / 客户退货是货回仓，应归入入库业务；采购退货 / 退供应商归入出库业务。
销售退货不是独立入库流程或独立菜单，只是入库单据类型；PC Web 在 M2 收货、验收、上架页通过“单据类型”筛选和展示。

## 3. 通用页面结构

三页共享管理后台骨架，但页面内容按环节独立：

1. 左侧全局菜单固定保留，当前菜单高亮。
2. 页头只展示当前环节标题、说明和本环节动作；`新建 ASN` 只放在收货页。
3. 单据流程状态放在“订单详情”弹窗内，按当前单据状态高亮：已完成节点绿色、当前节点蓝色、未到节点灰色；页面不放全局流程条。
4. 订单详情弹窗按上下结构展示：订单信息 → 流程状态 / 节点选择 → 当前选中节点字段 → 入库明细；禁止左右两栏堆满全流程字段。
5. 订单信息放在流程状态上方，合并供应商、仓库、商品概要、预计到货和预报数量；销售退货入库额外显示原销售批号，采购入库不在收货阶段显示批号概要。
6. 订单详情弹窗一次只展示一个流程节点字段；从收货 / 验收 / 上架菜单打开时，默认选中对应节点，用户点击流程节点后切换字段内容。字段区使用两列紧凑卡片，不允许一行一个字段拉长页面。
7. 指标卡只统计本环节相关数量，不把三页都做成同一组总览。
8. 左侧主列表是本环节待办列表，默认筛选当前环节状态。
9. 当前环节动作放在列表行“操作”列，通过按钮打开弹窗；页面不常驻“本环节操作”卡片。
10. 写操作全部通过弹窗完成；弹窗标题等于动作，说明文本带当前 ASN。
11. 页面不放下方常驻入库明细表；入库明细、商品行和数量随“订单详情”弹窗查看，销售退货入库才展示批号。

## 4. 收货管理页面

面向收货员，处理 ASN 到货签收。

| 区域 | 目标内容 |
|---|---|
| 页头 | `M2 收货管理`；动作：刷新、打印、新建 ASN、返回工作台。 |
| 指标 | 待收货、收货异常、今日已收、本页合计。 |
| 列表 | ASN、单据类型、供应商/承运商、预计到货、到货温度、预报/实到/缺货/拒收、状态。 |
| 订单详情弹窗 | ASN 基本信息、流程状态、车辆/承运商、联系人、温度、数量闭合、随货单据核对。 |
| 列表操作 | 详情、收货；后续补整单拒收、上报异常。 |
| 收货弹窗 | 实到、缺货、拒收、商品温度属性、温控方式、车牌号、发运地点、承运商、联系人、电话、身份证、印章样式核对、备案件样式核对、异常备注。温控方式按商品温度属性只读推导；到货温度、启运时间、到货时间、冷链运输方式只在商品温度属性为冷藏 / 冷冻时显示并必填。 |

收货提交必须校验 `实到 + 缺货 + 拒收 = 预报数量`。PC Web 不支持离线提交，提交失败时保留表单草稿。

## 5. 验收管理页面

面向收货员（验收岗），处理效期、追溯码和质量结论；销售退货入库额外处理原销售批号。

| 区域 | 目标内容 |
|---|---|
| 页头 | `M2 验收管理`；动作：刷新、打印、返回工作台。 |
| 指标 | 验收中、待双人签字、档案补录中、不合格待处理。 |
| 列表 | ASN、单据类型、商品、销退批号数、已验/总数、近效期/过期提示、质量状态、状态。 |
| 订单详情弹窗 | 商品资料、流程状态、效期 / 销退批号、追溯码、抽验进度、质量核对项。 |
| 列表操作 | 详情、验收、双人签字；后续补档案补录。 |
| 验收弹窗 | 销退批号（销售退货入库时）、通过数量、拒收数量、生产日期、有效期、追溯码、外观、包装、说明书、标签、质量状态、备注。 |
| 双人签字弹窗 | 第一签字人、第二签字人、策略命中说明、签字备注。 |

验收页要明确“验收”和“双人签字”是同一页内两个动作，不拆成第四个菜单。档案补录需联网，离线下禁用。

## 6. 上架管理页面

面向保管员，处理验收合格后的库位确认和库存入账。

| 区域 | 目标内容 |
|---|---|
| 页头 | `M2 上架管理`；动作：刷新、打印、返回工作台。 |
| 指标 | 待上架、部分上架、库位异常、今日完成。 |
| 列表 | ASN、单据类型、商品 / 销退批号、待上架数量、推荐库位、实际库位、LPN、状态。 |
| 订单详情弹窗 | 流程状态、推荐库位 Top N、温区/色标/容量校验、容器信息、待上架数量。 |
| 列表操作 | 详情、上架；后续补重新推荐库位、上报库位异常。 |
| 上架弹窗 | LPN、商品编码、销退批号（销售退货入库时）、数量、推荐库位、实际库位、校验结果、备注。 |

上架确认必须保证库存增加、库位占用和上架记录在同一事务内完成；PC Web 不支持离线提交。

## 7. 组件与复用规划

按“先复用，缺口再标准化”执行：

| 能力 | 复用/新增方式 |
|---|---|
| 页面骨架 | 复用现有 `AppShell`、`PageHeader`、`Card`、`DataTable`、`StatusBadge`。 |
| 三页布局 | 保留一个共享 `M2InboundWorkspace` 或等价页面局部组件，三页只传环节配置和动作槽。 |
| 流程条 | 抽成页面局部 `M2InboundProgress`，根据单据状态计算完成/当前/未到节点。 |
| 筛选条 | 复用并收敛 `M2InboundFilterBar`，默认状态由页面环节决定。 |
| 操作列 | 复用 `Button` 和既有 `M2InboundDialogs`，行内按钮只负责选择单据并打开弹窗。 |
| 弹窗 | 现有 `M2InboundDialogs` 可继续拆为 `ReceivingDialog`、`InspectionDialog`、`SignDialog`、`PutawayDialog`，避免一个文件继续膨胀。 |
| 数据调用 | 继续走 `apps/web-admin/src/features/inbound/inbound-queries.ts`，不得裸 `fetch`。 |
| 后端能力 | 复用现有 M2 service、repository、审计和幂等逻辑；缺字段或接口语义需先确认，不在前端临时伪造。 |
