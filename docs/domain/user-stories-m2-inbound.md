## 入库状态机

```
┌──────────┐     ┌──────────┐     ┌──────────┐     ┌──────────┐     ┌──────────┐     ┌──────────┐     ┌──────────┐
│  待校验   │────→│  待收货   │────→│  收货中   │────→│  验收中   │────→│  上架中   │────→│  已完成   │────→│  已关闭   │
└──────────┘     └──────────┘     └──────────┘     └──────────┘     └──────────┘     └──────────┘     └──────────┘
     │                │                │                │
     │ 校验不通过       │ 作废(审批)      │ 整单拒收        │ 强制关闭(短少)
     ↓                ↓                ↓                ↓
┌──────────┐     ┌──────────┐     ┌──────────┐     ┌──────────┐
│  校验异常  │     │  已作废   │     │已关闭(拒收)│     │已关闭(短少)│
└──────────┘     └──────────┘     └──────────┘     └──────────┘
     │
     │ 人工修改后重新校验
     ↓
   (回到待校验)
```

### 状态说明

| 状态 | 含义 | 进入条件 | 可执行操作 |
|------|------|---------|-----------|
| 待校验 | ASN 已创建，等待规则校验 | API 推送 / 手工创建 | 校验规则自动执行 |
| 校验异常 | 校验不通过（供应商资质/经营范围等） | 规则校验失败 | 人工修改后重新校验 / 强制通过（创建质量联系单 → 企业微信审批 → 标记合规风险） |
| 待收货 | 校验通过，等待货到 | 校验通过（或无规则默认通过） | 作废（企业微信审批）、打印 ASN 单 |
| 收货中 | 货到了，正在录入到货信息 | PDA 开始收货 | 录入收货信息、整单拒收、追溯码扫码、绑定托盘/盲标签 |
| 验收中 | 收货信息提交完成，正在验收 | 收货信息提交 | 逐件验收、追溯码扫码、双人签字、强制关闭、绑定托盘/盲标签 |
| 上架中 | 验收通过+双人签字完成，正在上架 | 双人签字完成 | PDA 上架（可部分）；如配置全自动则瞬间完成 |
| 已完成 | 全部上架完成 | 最后一件上架 | 触发 ERP 反馈 → 自动归档 |
| 已作废 | 未收货前取消 | 待收货时申请 + 企业微信审批通过 | 终态 |
| 已关闭(拒收) | 整单拒收 | 收货环节拒收 | 终态 |
| 已关闭(短少) | 部分到货强制关闭 | 验收环节强制关闭 | 终态；缺货部分由 ERP 重新推新 ASN |
| 已关闭 | 正常归档 | 已完成 + ERP 反馈成功 | 终态 |

### 关键规则

- ASN 是**单品**（一个 ASN 只有一个商品，但可多批号多数量）
- **校验模块**（M-VR）在 ASN 创建后自动执行规则校验
- 收货环节已**闭环**：实到数量 + 缺货数量 + 拒收数量 = ASN 预报数量
- 不存在"同一 ASN 多次收货"——缺货部分由 ERP 推新 ASN
- 双人签字时机**可配置**（收货/验收/两者都要）
- 追溯码录入环节**可配置**（收货/验收）
- 上架模式**可配置**（全自动/半自动 PDA 确认）
**作为** 仓库主管（或外部系统通过 API）
**我要** 创建 ASN，登记预计到货的供应商、商品、批号、数量
**以便** 收货员提前知道今天要收什么货

### 验收标准

1. ASN 必填：供应商、商品（单品）、批号明细（批号+数量+生产日期+有效期，可多批号）、预计到货时间
2. ASN 单号由**编码生成模块**自动生成，格式：货主编码+ASN+P+日期+流水号，全局唯一
3. 创建时校验：供应商资质有效期（由 M-VR 校验规则模块执行；经营范围校验由 ERP 负责，WMS 不做）
4. ASN 状态初始为"待校验"（校验通过后变"待收货"）
5. **开放 API**：外部系统（ERP/采购）通过 API 推送 ASN（API Key 鉴权）
6. 支持手工创建（页面录入）
7. **ASN 打印**：打印 ASN 单据（含 ASN 单号条码，供 PDA 扫码定位）
8. **ASN 作废**：待收货状态可申请作废 → 推送企业微信审批 → 审批通过后状态变"已作废"
9. ASN 创建/修改/作废写入审计追踪

## US-M2-002：PDA 收货（到货签收）

**作为** 收货员
**我要** 在 PDA 上查找 ASN 并录入到货信息
**以便** 记录实际到货的完整信息，满足 GSP 收货记录要求

### PDA 查找 ASN 的方式

- 扫 ASN 单号条码 → 直接定位
- 扫追溯码 → 解析商品信息 → 查询该商品未收货的 ASN 列表 → 选择
- 手工输入 ASN 单号

### 收货录入字段

| 字段 | 必填 | 说明 |
|------|------|------|
| 到货温度 | 冷链必填 | 温度计读数 |
| 温控方式 | 冷链必填 | 冷藏车/保温箱/冰袋等 |
| 车牌号 | 是 | |
| 发运地点 | 是 | |
| 启运时间 | 是 | |
| 到货时间 | 是 | |
| 收货入库时间 | 是 | |
| 运输方式 | 是 | 冷藏车/普通车/快递等 |
| 承运商 | 是 | |
| 联系人 | 是 | 送货人 |
| 电话 | 是 | |
| 身份证 | 是 | |
| 印章样式核对 | 是 | 与备案件比对 |
| 备案件样式核对 | 是 | 随货同行单样式 |
| 预报数量 | 系统带出 | ASN 数量 |
| 送货数量 | 是 | 送货单上的数量 |
| 实际到货数量 | 是 | 实际清点数量 |
| 缺货数量 | 是 | 预报 - 实到（系统计算，可修正） |
| 拒收数量 | 拒收时 | |
| 拒收备注 | 拒收时 | |
| 批号 + 数量 | 是 | 多批号分别录入 |
| 第二收货员验证 | 可配置 | 系统参数决定是否需要 |

### 验收标准

1. 所有必填字段录入完成后可提交
2. **收货闭环**：实到数量 + 缺货数量 + 拒收数量 = 预报数量（系统校验，不等则不可提交）
3. **多到处理**：实到数量 > 预报数量时，多出部分拒收退回，或由 ERP 重新下 ASN 处理（WMS 不接受超量入库）
3. 温度超标：弹出警告，可选"拒收"或"继续（上传稳定性报告）"
4. 整单拒收：ASN 状态变为"已关闭(拒收)"
5. 第二收货员验证（如配置开启）：需另一用户 PDA 扫码/签字确认
6. 追溯码扫码（如配置在收货环节）：收货时扫追溯码绑定
7. 可绑定托盘/盲标签
8. 提交后 ASN 状态变为"验收中"
9. **离线支持**：断网暂存，恢复后同步
10. 收货信息写入审计追踪

## US-M2-003：PDA 验收

**作为** 收货员
**我要** 在 PDA 上对到货商品进行逐件验收，核对质量信息
**以便** 确认商品质量合格，满足 GSP 验收要求

### 验收核对内容

| 核对项 | 说明 |
|--------|------|
| 品名 | 与 ASN 一致 |
| 规格 | 与 ASN 一致 |
| 批号 | 扫追溯码自动获取 或 手工录入 |
| 有效期 | 扫追溯码自动获取 或 手工录入 |
| 生产日期 | |
| 数量 | 抽验数量 + 总数量 |
| 批准文号 | 与商品档案一致 |
| 外观 | 完好/破损 |
| 包装 | 完好/破损/潮湿 |
| 说明书 | 有/无/破损 |
| 标签 | 清晰/模糊/缺失 |

### 验收标准

1. **整单验收**：所有批号验完后统一提交验收结论
2. 追溯码扫码（如配置在验收环节）：扫追溯码自动获取批号/效期/数量
3. 追溯码无法扫取时 → 手工录入
4. 抽验数量录入（按 GSP 抽验比例）
5. 多批号分别录入质量状态
6. 质量状态判定：合格 / 不合格
7. **不合格处理**：
   - 部分不合格：不合格品上不合格库，合格品继续上架
   - 整单不合格：全部上不合格库
   - 不合格自动生成**质量联系单** → 推送企业微信审批 → 后续报损或采退
8. 近效期预警（距过期 < 配置月数）
9. 已过期自动标记不合格
10. 可绑定托盘/盲标签
11. 验收进度显示（已验/总数）
12. **离线支持**
13. 验收记录写入审计追踪

## US-M2-004：双人验收签字

**作为** 两个不同用户
**我要** 对验收结论进行双人签字确认
**以便** 满足 GSP 双人验收要求

### 验收标准

1. **签字时机**：整单验收完成后（所有批号验完）
2. 第一人签字 → 状态"待第二人签字"
3. 第二人签字 → 验收结论生效，ASN 状态流转到"上架中"
4. 两人必须是不同 user_id（系统校验）
5. 不限角色（权限可配置）
6. 签字记录：签字人、时间、结论、备注
7. 签字记录不可修改（append-only），写入审计追踪
8. 可关联电子药检单（上传附件）
9. **双人签字是否需要**：系统参数可配置（开启/关闭）

## US-M2-005：智能上架

**作为** 保管员
**我要** 将验收合格的商品上架到系统推荐的库位
**以便** 商品按温区、色标、货主规则存放到正确位置

### 验收标准

1. **上架模式可配置**（系统参数）：
   - **全自动**：系统分配库位 + 自动标记上架完成（无需 PDA 操作）
   - **半自动**：系统推荐库位，保管员 PDA 扫码确认
2. 库位推荐规则：温区匹配 → 色标匹配 → 货主匹配 → 同品同批就近 → **剩余容积足够**（商品体积 × 数量 ≤ 库位剩余容积）
3. 半自动模式：保管员可接受推荐或手动选择（系统校验合法性）
4. PDA 扫库位码确认上架 → 库存增加
5. 支持整托上架（扫LPN 码）
6. 支持部分上架（今天上 5 件，明天上剩余 5 件）
7. **全部上架完成后**：
   - ASN 状态变为"已完成"
   - 触发 ERP 反馈（异步，含商品/批号/数量/库位/时间）
   - 反馈失败可重试
8. 上架操作写入审计追踪 + 库存变动记录

## US-M2-006：收货异常处理

**作为** 仓库主管
**我要** 处理收货过程中的异常（拒收、短少、破损、温度超标）
**以便** 异常有闭环处置记录

### 验收标准

1. 异常类型：整单拒收、部分拒收、短少、破损、温度超标、资质异常
2. **整单拒收**：收货环节直接拒收 → ASN 状态"已关闭(拒收)"
3. **短少**：收货闭环已记录缺货数量；验收环节可"强制关闭" → ASN 状态"已关闭(短少)"；缺货部分由 ERP 推新 ASN
4. **温度超标继续收货**：正常流转 + 异常备注 + 上传稳定性报告附件
5. **验收不合格**：自动生成质量联系单 → 企业微信审批 → 报损/采退
6. 所有异常处置写入审计追踪
7. 异常统计可按供应商/商品/类型汇总
8. 异常触发企业微信通知（通知仓库主管）

## US-M2-007：收货单据打印

**作为** 收货员
**我要** 打印验收记录单
**以便** 纸质存档满足 GSP 台账要求

### 验收标准

1. 打印内容：ASN 编号、供应商、到货时间、商品明细（品名/规格/批号/效期/数量）、验收结论、双人签字、收货信息（温度/车牌/承运商等）
2. 冷链额外打印：温度/温控方式/运输时长
3. 使用打印模板引擎（US-M2-009）
4. 支持蓝牙打印机（PDA）和网络打印机（PC）
5. 打印记录写入审计追踪

## US-M2-008：收货进度看板

**作为** 仓库主管
**我要** 在 PC/PAD 端查看今日收货进度
**以便** 实时掌握收货状态，及时处理异常

### 验收标准

1. 看板按 ASN 状态分组统计（待收货/收货中/验收中/上架中/已完成/异常）
2. 支持按供应商、商品、时间筛选
3. 异常 ASN 高亮
4. 点击查看详情（收货信息/验收记录/签字/异常）
5. 自动刷新（可配置间隔）
6. 看板为只读查询，不产生写操作，无需独立审计追踪（数据来源的写操作已各自审计）

## US-M2-009：打印模板设计模块

**作为** 系统管理员
**我要** 可视化设计和管理各类打印模板
**以便** 不同仓库/货主可按需调整打印格式

### 验收标准

1. 模板类型：ASN 单、验收记录单、随货同行单、库位标签、托盘标签、货箱标签、商品标签、盲标签
2. **可视化设计器**：拖拽布局，支持文本、条码（一维/二维）、表格、图片、动态字段
3. 动态字段绑定：`{{asn.code}}`、`{{product.name}}`、`{{batch.expiry_date}}` 等
4. 条码/二维码：可绑定 ASN 单号、商品编码、追溯码、LPN 码、盲标签号
5. 模板版本管理（每次修改保存新版本，可回退）
6. 模板与货主关联（不同货主不同模板）
7. 预览（样例数据）
8. 导出 PDF
9. 打印尺寸配置：A4 / A5 / 热敏标签（自定义宽高）
10. 模板变更写入审计追踪

## 跨故事约束

1. **审计追踪**：所有操作写入审计表
2. **多货主**：ASN 绑定货主，数据按货主隔离
3. **GSP 强校验**：供应商资质过期 → 拒绝；商品过期 → 拒绝入库
4. **收货闭环**：实到 + 缺货 + 拒收 = 预报（系统强制校验）
5. **双人签字**：两个不同 user_id，时机可配置
6. **追溯码录入环节可配置**：收货 或 验收
7. **上架模式可配置**：全自动 或 半自动
8. **冷链**：冷链商品必须录入温度，超标必须有处置记录
9. **PDA 离线**：收货/验收/上架支持离线暂存
10. **开放 API**：ASN 创建支持外部系统推送
11. **ERP 反馈**：全部上架完成后异步反馈（失败可重试）
12. **企业微信审批**：作废/质量联系单通过企业微信审批流
13. **企业微信通知**：异常/预警通过企业微信通知相关人员
14. **幂等性**：所有写操作支持 Idempotency-Key
15. **打印模板**：所有打印使用 US-M2-009 模板引擎
