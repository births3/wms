## US-M3-004：在库养护

**作为** 养护员
**我要** 按养护计划对在库商品进行定期检查，记录养护结果
**以便** 满足 GSP 在库养护要求，按养护计划周期发现质量异常

### 验收标准

1. **养护计划自动生成规则**：

| 品种类别 | 养护频率 | 默认判定 | 可配置 |
|---------|---------|---------|--------|
| 重点养护品种 | 每月一次 | 生物制品 / 冷链药品（冷藏冷冻）/ 麻精药品 / 中药饮片 | 是 |
| 一般品种 | 每季度一次 | 普通化药 / 中成药（常温常规）| 是 |
| 特殊批次 | 入库后第 7 天追加一次 | 进口药品 / 长效近效期（剩余 ≤ 6 月） | 是 |
| 异常追踪 | 异常处置后 7 天内复查 | 上次养护异常但未销毁/未退货的批次 | 是 |

   - 计划生成时机：每月 1 日凌晨 + 异常处置后 + 配置变更后即时重算
   - 计划维度：商品 + 批号（同商品不同批号独立养护）
   - 输出：本月待养护清单（按库区聚集，便于路径规划）
2. 养护任务推送到养护员 PDA（通过 M-TE 任务引擎，任务类型 = "养护"）
3. **PDA 养护扫码顺序**：

```
1. 扫库位码  → 系统弹出该库位待养护商品清单（已按批号聚集）
2. 扫商品码或追溯码 → 校验商品是否在本次养护计划内
3. 录入养护结果（见字段表）→ 提交
   ↓ 异常时
4. 选择异常类型 → 必填异常照片（≥1 张，≤5 张） → 提交
   ↓ 系统自动生成 M-QL 质量联系单（养护异常类型）
```

4. **PDA 养护字段表**：

| 字段 | 必填 | 系统带出/录入 | 说明 |
|------|------|-------------|------|
| 养护任务 ID | 系统带出 | — | M-TE 任务引擎生成 |
| 库位编码 | 系统带出 | 扫码确认 | 扫码后自动填入 |
| 商品编码 | 系统带出 | 扫码确认 | |
| 批号 | 系统带出 | 扫码确认 | |
| 养护时间 | 系统带出 | — | PDA 提交时间（离线模式记 PDA 时间 + 同步时间）|
| 库区温度（℃）| 必填 | 录入 / 探头自动读取 | 冷链商品必填，从 M5 实时数据自动读 |
| 库区湿度（%）| 必填 | 录入 / 探头自动读取 | 同上 |
| 外观 | 必填 | 选择 | 完好 / 破损 / 变色 / 受潮 |
| 包装 | 必填 | 选择 | 完好 / 破损 / 漏液 / 标签模糊 |
| 虫害 | 必填 | 选择 | 无 / 有（数量描述）|
| 鼠害 | 必填 | 选择 | 无 / 有（迹象描述）|
| 霉变 | 必填 | 选择 | 无 / 有（部位/程度描述）|
| 养护结论 | 必填 | 选择 | 正常 / 异常 |
| 异常类型 | 条件必填 | 选择 | 结论=异常时必填：质量变化/包装破损/温湿度超标/虫鼠霉害/其他 |
| 异常照片 | 条件必填 | 拍照上传 | 结论=异常时 ≥1 张 ≤5 张 |
| 备注 | 可选 | 录入 | 自由文本 |
| 养护员 user_id | 系统带出 | — | 由登录态确定 |

5. 养护结论：正常 / 异常
6. **异常闭环处置**：养护异常 → 自动生成 M-QL 质量联系单（类型=养护异常）→ 仓库主管审批 → 处置（移库/降级/销毁），调用 M3 状态变更时携带 `approval_source = 养护异常, approval_id = 联系单 ID`（见 M3-003）
7. 养护记录不可修改（append-only），写入审计追踪
8. 养护完成率统计（已养护 / 应养护，按品类/库区/养护员维度）
9. 逾期未养护自动预警（默认计划日 +3 天未完成触发，可配置）
10. **离线支持**：PDA 养护记录支持离线暂存；离线期间该批次状态被他人改动（如已被报损）时按跨故事约束 7"暂存为'待主管处理'"事件，禁止覆盖已变状态

## US-M3-005：库存盘点

**作为** 保管员
**我要** 在 PDA 上执行盘点任务（循环盘/全盘/盲盘），录入实盘数量
**以便** 核实系统库存与实物一致，差异通过审批流程闭环处理

### 验收标准

1. 盘点类型：
   - **循环盘点**：按库区/商品类别轮流盘，不停业
   - **全盘**：全仓一次性盘点（通常年度）
   - **盲盘**：PDA 不显示系统数量，保管员录入实盘数后系统对比
2. 盘点任务创建：仓库主管指定范围（库区/商品/货主）→ 生成盘点单
3. PDA 执行：扫库位码 → 扫商品码 → 录入实盘数量
4. 盘点差异自动计算：盘盈 / 盘亏 / 无差异
5. **差异审批流程**：
   - 盘盈：需仓库主管审批 → 审批通过后库存增加
   - 盘亏：需仓库主管审批 → 审批通过后库存减少
   - 差异超过阈值需更高级别审批（**默认阈值**：单 SKU 差异 > 10% 或差异金额 > 1 万元；可在系统配置中心调整）
6. 盘点锁定：盘点进行中的库位/商品暂停出库分配
   - **已下发任务处置**（v3.1 新增，C6）：盘点锁仅阻止新订单的库存分配；盘点开始前已分配并下发的拣选任务**正常执行至完成**。盘点系统按"盘点开始时刻账面 − 已分配但未完成的预占数量"作为基准与实物比对。盘点报告显示：盘点开始时账面 / 盘点期间已发出 / 盘点结束时实物 / 差异。盘点期间所有变动写入审计追踪（含"盘点中"标识）
7. 盘点记录写入审计追踪
8. 盘点报告可打印

## US-M3-006：库内移库

**作为** 保管员
**我要** 在 PDA 上将商品从一个库位移动到另一个库位
**以便** 优化库位利用率或配合温区调整

### 移库模式与扫码规则（v22 业务硬规则）

> 移库时是否扫电子监管码由**移库模式**决定，**不是参数控制**（业务硬规则）。
> 参数仅决定"项目是否启用追溯码体系"（M-TC 模块整体启用 / 关闭）。

### 移库模式定义

| 模式 | 含义 | 扫码要求 |
|------|------|---------|
| **整托/整箱 LPN 全量迁移** | 容器（托盘/周转箱/出库箱）100% 内容物一起移到新库位，LPN 不变 | 扫源库位 + 扫 LPN 容器码 + 扫目标库位（**不扫电子监管码**）|
| **部分整件移库** | 容器内**部分件数**移到新库位，部分留在原 LPN 或新建 LPN | **必须逐件扫电子监管码** |
| **零拣移库**（拆零）| 拆零数量级（盒/支）移库，本身就是一件一件操作 | **必须逐件扫电子监管码** |
| **追溯码模块未启用** | 项目层面 M-TC 模块整体关闭，无追溯码概念 | 仅扫库位 + 商品/容器，**本规则不适用** |

### PDA 三件套

#### 字段表

| 字段 | 项目 | 必填 | 核对项 |
|------|------|------|--------|
| 源库位码 | 物理位置 | 是 | 扫库位码 |
| 目标库位码 | 物理位置 | 是 | 扫库位码 |
| 移库模式 | 业务标识 | 是 | 整托/整箱 LPN / 部分整件 / 零拣（系统按扫码内容自动判定，不需手选）|
| LPN 容器码 | 整托/整箱时 | 条件必填 | 模式 = 整托/整箱时必填 |
| 商品码 | 部分整件时 | 条件必填 | 模式 = 部分整件 / 零拣时必填 |
| **电子监管码列表** | **追溯码模块启用 + 模式 ≠ 整托/整箱时** | **条件必填** | **逐件扫码，数量 = 移库件数** |
| 件数 | 业务核对 | 是 | 系统自动按扫码计数 |
| 操作员签字 | 操作确认 | 是 | 工牌签字 |

#### 扫码顺序

1. 扫**源库位码** → 系统弹出库位上的容器/商品/批号清单
2. 选移库模式：
   - 扫 **LPN 容器码** → 系统判定"整托/整箱 LPN 全量迁移"模式 → 跳到第 4 步
   - 扫 **商品码** → 系统判定"部分整件 / 零拣"模式 → 进入第 3 步
3. **逐件扫电子监管码**（仅"部分整件/零拣"模式下）→ 系统校验：
   - 码归属于该商品 + 批号
   - 码当前位置 = 源库位（防止扫到不在该库位的码）
   - 码状态 = 已入库（不在隔离/不合格状态）
4. 扫**目标库位码** → 系统校验目标库位（温区/色标/容量）
5. 提交 → 系统执行：M3 库存数量调整 + M-TC 码库位置更新（仅模式 3）+ 写审计

#### 离线声明

PDA 移库支持离线：扫码、件数核对、签字均可离线完成；本地暂存到移库队列；恢复网络后自动同步。**联网后系统会重新校验码归属和目标库位状态**，校验失败的移库会标记为"待主管处理"由保管员主管处置。

### 验收标准

1. **移库模式自动判定**（系统根据扫码内容判定，不需手选）：
   - 第 2 步扫到 LPN 容器码 → "整托/整箱 LPN 全量迁移"
   - 第 2 步扫到商品码 → "部分整件 / 零拣"
2. **整托/整箱 LPN 全量迁移**（扫码免逐件）：
   - 扫源库位 + LPN 容器码 + 目标库位
   - 系统自动将该 LPN 内**所有**电子监管码的位置字段更新为新库位（M-TC 码库批量 UPDATE）
   - 不需要保管员逐件扫码
3. **部分整件 / 零拣移库**（必须逐件扫电子监管码）：
   - 扫商品码 → 进入逐件扫码模式
   - **逐件扫电子监管码**（每件一码）→ 系统逐码校验归属
   - 件数核对：系统计数 = 实扫码数；不一致拒绝提交
   - 码归属校验失败（码不在源库位 / 不在该批次 / 状态异常）→ 报警拒绝
4. **目标库位校验**（所有模式都做）：温区匹配、色标匹配、容量足够；不合法拒绝
5. **追溯码模块未启用场景**：本规则不适用；扫源库位 + 商品/容器 + 目标库位即可
6. **库存调整**（同一事务）：
   - 源库位库存 -N，目标库位 +N
   - 整托模式：源库位 -整托数量，目标库位 +整托数量；LPN 关联从源库位变为目标库位
   - 零拣/部分整件模式：源库位 -实扫码件数，目标库位 +实扫码件数
7. **M-TC 码库联动**（仅 M-TC 启用时）：
   - 整托模式：批量更新该 LPN 内所有码的位置字段为目标库位
   - 部分整件/零拣模式：仅更新被扫描的码的位置字段
   - 不上报"码上放心"（v21 决策：平台只接收码 + 状态变更，移库不算状态变更）
8. **库存流水写入**（M3 库存流水账，含追溯码列表 — 仅扫了码的部分）
9. **移库记录写入审计追踪**：actor = 操作员 user_id；记录源/目标库位、模式、件数、追溯码列表（如有）、签字时间
10. **PDA 离线模式**：操作可离线，但同步时重新校验码归属和目标库位状态；校验失败标"待主管处理"
11. **失败回滚**（同一事务）：任何环节失败（如目标库位被并发占满）→ 全部回滚；保管员重做
12. **不允许"调回去"**：移库错了需要新建移库单调回（保留完整历史，不允许覆盖原记录）

### 业务边界声明（v22）

> **移库与电子监管码的边界**：
>
> 1. **整托/整箱 LPN 移库免逐件扫码**：LPN 容器码已经"代表"内容物，逐件扫几百个码不现实
> 2. **部分整件 / 零拣移库强制扫码**：物理上一件一件搬，扫码不增加额外工作量
> 3. **本规则不依赖配置参数**：是业务硬规则；参数仅决定"M-TC 模块整体启用 / 关闭"
> 4. **追溯码模块未启用场景**：本规则不适用，等同 v22 之前的旧行为
> 5. **不上报码上放心**：移库不是国家平台关心的状态变更；与 v21 M-TC-007 上报内容一致
> 6. **数据一致性**：扫了码的部分 → M-TC 码库位置同步更新；未扫的部分 → 按"商品+批号"维度反查（粗粒度但仍可追溯）

## ~~US-M3-007：跨仓调拨~~（v23 移除：GSP 不合规）

> **v23 业务边界决策**：跨仓调拨由 WMS 直接执行不符合 GSP 合规要求。GSP 视角下两个独立法人许可证仓库之间的库存转移**等同于销售出库 + 采购入库**，必须走完整的销售/采购流程（资质校验 + 验收双人签字 + 抽样比例 + 随货同行单 + 追溯码核销 + 冷链温度记录等）。
>
> **替代方案**：由 ERP 主管销售订单 + 采购订单流程，WMS 通过 H8 ERP 防腐层接收两端的出库通知（→ 走 M4 出库标准流程）和入库通知（→ 走 M2 入库标准流程）。
>
> 同一法人多仓内部转移如需简化，应在 ERP 中作为"内部调拨单"处理，仍通过 ERP 推送到 WMS 走 M4 + M2 标准流程，**不在 WMS 直接做跨仓调拨**。
>
> 详见 [docs/compliance/gsp-ch6-procurement-acceptance.md](../compliance/gsp-ch6-procurement-acceptance.md) 第 6 章采购验收 + [docs/compliance/gsp-ch8-sales-delivery.md](../compliance/gsp-ch8-sales-delivery.md) 第 8 章销售出库。

## ~~US-M3-008：货主转换~~（v23 移除：GSP 不合规）

> **v23 业务边界决策**：货主转换（权属转移）由 WMS 直接执行不符合 GSP 合规要求。
>
> 1. **真实货权交易场景**：源货主与目标货主之间的所有权变更等同于销售/采购行为，需要走完整 GSP 流程（资质校验 + 验收 + 随货同行单 + 追溯码状态变更上报"码上放心" + 冷链记录）。WMS 不主管销售/采购合规；该流程必须由 ERP 主管销售订单 + 采购订单。
> 2. **3PL 计费归属变更场景**（物理货主不变，仅计费归属调整）：这是账务类调整，不应放在 M3 库存模块；如有需要应作为独立的"3PL 计费归属变更单"在 M9 计费模块处理（v23 后未落地，待业务确认实际是否有此需求）。
>
> **替代方案**：货权变更走 ERP 销售/采购流程；计费归属变更（如有需要）由 M9 计费独立设计，不复用本故事。
>
> 详见 [docs/compliance/gsp-ch8-sales-delivery.md](../compliance/gsp-ch8-sales-delivery.md) 第 8 章销售合规 + [docs/compliance/gsp-ch10-traceability.md](../compliance/gsp-ch10-traceability.md) 追溯码核销。

## US-M3-009：库存预警

**作为** 仓库主管
**我要** 系统自动监控库存异常并推送预警
**以便** 在阈值触发时主动处理近效期、超储、缺货等风险

### 验收标准

1. 预警类型：
   - **近效期预警**：距过期 < N 月（可配置）
   - **过期预警**：已到期未处置
   - **安全库存预警**：低于最低库存水位
   - **超储预警**：超过最高库存水位
   - **养护逾期预警**：超过养护周期未养护
   - **温湿度超标预警**：（关联 M5 冷链）
2. 预警推送方式：系统消息 + 可选短信/邮件（可配置）
3. 预警状态：待处理 → 已处理 / 已忽略
4. 预警处理记录写入审计追踪
5. 预警统计看板（按类型/商品/货主汇总）

## US-M3-010：ABC 分类管理

**作为** 仓库主管
**我要** 系统自动按出库频率对商品进行 ABC 分类，并支持手动调整
**以便** 上架策略和库位规划有数据依据（A 类放黄金库位）

### 验收标准

1. **自动分类**（定期执行，频率可配置，默认每月）：
   - 统计近 N 天（可配置）每个 SKU 的出库频次/出库量
   - 按帕累托法则分类：A 类（前 20% 高频）、B 类（中间 30%）、C 类（后 50%）
   - 分类阈值可配置（不一定是 20/30/50）
2. **手动调整**：仓库主管可手动将某商品调整为指定类别（优先级高于自动）
3. **分类结果**：写入商品属性，供上架策略（US-M2-010）和库位规划使用
4. **分类变化通知**：商品类别变化时通知仓库主管（如 B→A）
5. **分类报表**：展示各类别商品数量、占比、出库贡献
6. 分类变更写入审计追踪

## US-M3-011：库位历史追踪

**作为** 仓库主管 / 养护员
**我要** 查询任一库位过去一段时间内经历过的所有商品/批号变动
**以便** 追溯库位污染风险（如冷链商品错放在常温区后该库位的清洁状态）、识别频繁周转库位（用于库位规划优化）、配合 GSP 检查"该库位曾存放过哪些商品"

### 验收标准

1. **触发入口**：
   - 从 M3-001 库位维度专项视图点击"历史追踪"
   - 直接输入库位编码（或扫库位码）查询
   - 从养护单/盘点单关联跳转

2. **库位历史字段表**：

| 字段 | 来源 | 说明 |
|------|------|------|
| 流水号 | M-CG | 与 M6-001 库存流水账共用 |
| 操作时间 | 业务事件 | 精确到秒 |
| 库位编码 | 关联 | 当前查询的库位 |
| 操作类型 | M6-001 操作类型枚举 | 22 类（入库/出库/状态/锁定/移动）|
| 商品编码 + 名称 | M1-001 | |
| 批号 / 效期 | 业务流水 | |
| 数量变动 | Integer | 正/负 |
| 库位剩余容积变化 | 计算 | 反映库位利用率变化 |
| 操作人 | M1-006 | user_id + 姓名 |
| 关联单据 | 业务流水 | ASN / 出库订单 / 移库单等 |
| 关联容器 LPN | M1-004a | 整托/整箱操作时记录 |

3. **查询维度**：
   - 时间范围（默认近 30 天，可选 7/30/90 天/全部历史）
   - 操作类型多选过滤
   - 商品/批号过滤（看该库位是否曾存过特定批次）

4. **可视化**：
   - **时间轴视图**：按时间倒序排列所有变动事件
   - **商品分布饼图**：该库位历史上存过哪些商品的时长占比
   - **利用率折线图**：该库位剩余容积随时间变化（识别长期高占用 vs 频繁周转）

5. **风险识别**（核心价值）：
   - **温区错放追溯**：该库位是否曾存放过非匹配温区的商品（如冷链放常温区）→ 高亮显示 + 触发清洁记录提醒
   - **不合格品历史**：该库位是否曾存放过不合格品 → 提示需复核清洁状态
   - **批次混放历史**：该库位是否曾同时存放多个不同效期批次（GSP 关注点）

6. **导出与打印**：
   - 支持导出 Excel（GSP 检查时提供）
   - 支持打印库位历史报告（含时间轴 + 风险标记）

7. **数据来源**：M6-001 库存流水账（按库位字段筛选）+ M3 各操作（移库/盘点）记录

8. **货主隔离**：货主只能查询涉及自己货物的库位历史

9. 查询本身只读，不产生写操作

## 跨故事约束（适用于所有 M3 用户故事）

1. **审计追踪**：所有库存变动（增/减/移/隔离/类型变更）必须写入审计表
2. **多货主**：库存按货主隔离，查询/操作自动过滤
3. **库存变更必须经领域服务**：禁止直接 SQL 修改库存（红线）
4. **事务一致性**：移库的"减+增"必须在同一事务内
5. **幂等性**：所有写操作支持 Idempotency-Key
6. **出库批号由 ERP 指定**：WMS 不做 FIFO/FEFO 分配决策，只校验指定批号有库存并执行拣选
7. **PDA 离线**：移库/盘点支持离线暂存；离线期间发生数据冲突（如该库位被他人占用、库存被外部系统占用）时，**暂存为"待主管处理"事件**，由仓库主管在 PC 端手动决策，禁止静默覆盖
8. **开放 API**：库存查询支持外部系统调用
9. **系统触发的隔离免二次审批**（v3.1 新增，K14）：以下三种触发源在源模块内已有人工决策环节，进入 M3 状态隔离时不再要求仓库主管二次审批，但 `approval_source` 字段必须填具体来源 ID：
   - **对账差异**：`approval_source = M-RC` + 对账 ID（M-RC 主管已在差异列表勾选）
   - **质量联系单**：`approval_source = M-QL` + 联系单 ID（M-QL 已经过 H4 企微审批）
   - **温度超标处置**：`approval_source = M5-超标事件 ID + M-VR 处置规则 ID`
   保管员手动加锁则需走 M-QL 联系单审批（人工发起的状态变更必须有显式审批源）
10. 测试要求：写操作必须含 L4（错误路径）+ L5（数据一致）+ L8（权限）+ L11（幂等）；读操作必须含 L4 + L8
