## 出库状态机

```
┌──────────┐     ┌──────────┐     ┌──────────┐     ┌──────────┐     ┌──────────┐     ┌──────────┐     ┌──────────┐
│  待校验   │────→│  已确认   │────→│  已入波次  │────→│  库存锁定   │────→│  已复核   │────→│  已发货   │────→│  已签收   │
└──────────┘     └──────────┘     └──────────┘     └──────────┘     └──────────┘     └──────────┘     └──────────┘
     │                │                │
     │ 校验不通过       │ 作废(审批)      │ 强制作废(PDA回退上架)
     ↓                ↓                ↓
┌──────────┐     ┌──────────┐     ┌──────────┐
│  校验异常  │     │  已作废   │     │已作废(回退)│
└──────────┘     └──────────┘     └──────────┘
     │
     │ 人工修改后重新校验
     ↓
   (回到待校验)
```

### 状态说明

| 状态 | 含义 | 进入条件 | 可执行操作 |
|------|------|---------|-----------|
| 待校验 | 订单已创建，等待规则校验 | ERP 推送 / 手工创建 | 校验规则自动执行 |
| 校验异常 | 校验不通过（库存不足/资质不符等） | 规则校验失败 | 人工修改后重新校验 / 反馈 ERP |
| 已确认 | 校验通过，等待进入波次 | 校验通过 | 作废（企微审批）、手动/自动进入波次 |
| 已入波次 | 波次算法已分配库位，等待拣选 | 波次下发 | 强制作废（保管员 PDA 回退上架）、开始拣选 |
| 库存锁定 | 保管员 PDA 正在拣选 | 开始拣选 | 拣选完成（含短拣标识） |
| 已复核 | 复核完成，等待打印发货 | 复核确认 | 打印快递单 / 随货同行单 |
| 已发货 | 已交接给快递/司机 | 快递接口反馈 + 交接确认 | 等待签收 |
| 已签收 | 客户已签收 | 快递轨迹回写 / 手动确认 | 可退货 |
| 已作废 | 未进波次时取消 | 已确认时申请 + 企微审批 | 终态 |
| 已作废(回退) | 进了波次后强制取消 | 已入波次时强制取消 | 终态（保管员 PDA 回退上架） |
| 校验异常 | 校验不通过 | 规则校验失败 | 人工修改 → 重新校验 |

### 关键规则

1. **不回退**：拣选开始后不退回任何状态，有问题"先出后退"（事后走退货流程）
2. **整单出库**：不管拣到多少都整单走完流程（短拣标识差异 + 企业微信通知）
3. **复核无不通过**：复核只做确认，有问题事后退回处理
4. **作废窗口**：已确认可正常作废；已入波次（未开始拣选）可强制作废（PDA 回退上架）
5. **库存锁定不可作废**：开始拣选后只能走完
6. **没有部分发货**：一个订单必须整单发货
7. **订单 = 主单 + 明细单**：一个订单只能属于一个波次

## US-M4-001：出库订单管理

**作为** 仓库主管（或外部系统通过 API）
**我要** 创建和管理出库订单（销售出库/调拨出库/退货出库）
**以便** 驱动后续拣选、复核、发货流程

### 验收标准

1. 订单类型：销售出库、调拨出库、退货出库
2. 订单结构：**主单 + 明细单**（主单含客户/交货日期，明细含商品+批号+数量）
3. **双单号**：ERP 单号（ERP 推送时带入）+ WMS 单号（由**编码生成模块**自动生成，格式：货主编码+ASN+R+日期+流水号）
4. 订单必填：客户/门店、商品明细（商品+**批号**+数量，批号由 ERP 指定）、要求交货日期
5. 订单初始状态为"待校验"
6. **校验模块**（独立可配置规则引擎）自动校验：
   - 指定批号在 WMS 有足够合格库存
   - 门店经营范围校验
   - 其他可配置规则（客户资质、信用额度等）
6. 校验通过 → 状态变"已确认"
7. 校验不通过 → 状态变"校验异常"，人工界面可修改后重新校验
8. **订单作废**：已确认（未进波次）可申请作废 → 企微审批
9. **开放 API**：支持 ERP 推送出库订单（商品+批号+数量）
10. 订单创建/修改/作废写入审计追踪

## US-M4-002：波次规划

**作为** 仓库主管
**我要** 将多个出库订单合并为一个波次，由波次算法决定从哪些库位拣选并优化路径
**以便** 提高拣选效率（合并同库区/同路径的拣选动作，减少行走距离）

### 验收标准

1. 波次创建方式：
   - 手动选择订单组成波次
   - 自动波次：按规则（同客户/同库区/同配送路线/同时间窗）自动合并
2. **波次算法（WMS 核心价值）**：
   - 输入：订单明细（商品+批号+数量，批号由 ERP 指定）
   - 决策：从哪些库位拣（同商品同批号可能分布在多个库位）
   - 优化：拣选路径最短（按库位物理位置排序）
   - 约束：只从"合格"状态库位拣
3. 波次状态：待下发 → 库存锁定 → 已完成
4. 波次下发后生成拣选任务（含具体库位+数量，按路径排序）
5. 一个订单只能属于一个波次
6. 波次可取消（未开始拣选时）
7. 波次完成后自动流转到复核环节
8. 波次创建/取消写入审计追踪

## US-M4-003：PDA 拣选作业

**作为** 保管员
**我要** 在 PDA 上按拣选任务指引，到指定库位扫码拣货
**以便** 准确高效地完成拣选，避免拣错

### 验收标准

1. PDA 显示拣选任务列表（按波次/优先级排序）
2. 任务详情：目标库位（排-列-层）→ 商品 → 批号 → 数量
3. **最优路径引导**：按库位物理位置排序，减少行走距离
4. 拣选操作：扫库位码 → 扫商品码/电子监管码 → 确认数量
5. **批次强校验**：扫码后系统校验批号是否与分配一致，不一致则报警拒绝
6. 支持整托拣选（扫托盘码 = 拣整托）
7. 支持整箱拣选（扫货箱码 = 拣整箱）
8. **短拣处理**：实际可拣 < 分配数量时：
   - 强制出库（能拣多少出多少，整单继续走完流程）
   - 标识差异数量和原因
   - 差异库存加锁（隔离）
   - 企业微信通知仓库主管
   - **人工跟踪**：可添加后续跟踪记录（处理进展、最终结论）
9. 拣选完成后整单流转到复核（不管是否短拣）
10. **离线支持**：断网时暂存拣选数据
11. 拣选操作写入审计追踪

## US-M4-004：出库复核

**作为** 保管员（复核岗）
**我要** 对拣选完成的商品进行逐件复核，确认品种和数量正确
**以便** 防止拣错/拣少，满足 GSP 出库复核要求

### 验收标准

1. **双人复核**：拣选人和复核人必须是不同用户（系统校验 user_id 不同）
2. 复核方式：PDA 扫码逐件核对 或 PC 端扫码枪核对
3. 扫码校验：商品码/电子监管码 → 系统比对订单明细
4. 数量校验：复核数量与拣选数量核对（含短拣标识的差异）
5. **复核无"不通过"**：复核只做确认，有问题事后走退回流程处理
6. 复核完成 → 订单状态变为"已复核"
7. 复核记录写入审计追踪（复核人、时间）

## US-M4-005：随货同行单打印

**作为** 保管员（复核岗）
**我要** 在复核通过后打印随货同行单
**以便** 随货附带合规单据，满足 GSP 要求

### 验收标准

1. 随货同行单内容：销售方信息、购货方信息、商品明细（品名/规格/批号/效期/数量/单位）、发货日期、质量状态
2. **多货主抬头**：3PL 模式下，随货同行单抬头为货主信息（非仓库方）
3. 使用打印模板引擎（US-M2-009）
4. 支持一单多页（商品明细超一页时自动分页）
5. 打印后订单状态可流转到"已发货"
6. 打印记录写入审计追踪

## US-M4-006：发货与交接

**作为** 保管员
**我要** 将复核通过的包裹交接给司机/快递，记录交接信息
**以便** 明确责任交接节点，后续可追溯

### 验收标准

1. 交接记录：司机/快递员姓名、车牌号、交接时间、包裹数量
2. 冷链商品额外记录：装车温度、保温箱/冰袋配置
3. 交接后订单状态变为"已发货"
4. 支持批量交接（同一司机多个订单一次交接）
5. 交接单可打印（含交接双方签字栏）
6. 交接记录写入审计追踪

## US-M4-007：出库进度看板

**作为** 仓库主管
**我要** 在 PC/PAD 端查看出库作业进度（待分配/库存锁定/待复核/已发货）
**以便** 实时掌握出库状态，及时处理瓶颈和异常

3. 异常高亮：超时未拣选、短拣差异、校验异常

7. 看板为只读查询，不产生写操作，无需独立审计追踪（数据来源的写操作已各自审计）

## US-M4-008：出库退货处理

**作为** 业务人员 / 仓库主管
**我要** 通过完整的退货流程（申请→审批→提货→收货验收→上架）处理客户退货
**以便** 退货有完整记录和审批控制，退回商品按质量状态正确归位

### 退货状态机

```
┌──────────┐     ┌──────────┐     ┌──────────┐     ┌──────────┐     ┌──────────┐     ┌──────────┐
│  待审批   │────→│  已审批   │────→│  提货中   │────→│  已到货   │────→│  验收中   │────→│  已完成   │
└──────────┘     └──────────┘     └──────────┘     └──────────┘     └──────────┘     └──────────┘
     │                                                                    │
     │ 审批拒绝                                                            │ 整单拒收
     ↓                                                                    ↓
┌──────────┐                                                         ┌──────────┐
│  已拒绝   │                                                         │已关闭(拒收)│
└──────────┘                                                         └──────────┘
```

### 验收标准

1. **退货申请**（业务人员发起）：
   - 必填：原出库订单号、客户、退货商品明细（商品+批号+数量+退货原因）
   - 退货原因：质量问题/发错货/客户拒收/近效期/其他
   - 申请后状态为"待审批"
2. **审批**（仓库主管/质量负责人）：
   - 审核退货原因是否合理
   - 审批通过 → "已审批"；拒绝 → "已拒绝"（流程结束）
   - 审批通过企业微信审批流
3. **提货**（司机/快递）：
   - 审批通过后安排提货（或客户自行送回）
   - 提货中可记录：提货时间、提货人、运输方式
   - 冷链商品需记录运输温度
4. **收货验收**（收货员）：
   - 到货后 PDA 扫码确认到货
   - 验收内容：外观/包装/效期/追溯码核验/温度（冷链）
   - 验收结论决定库存状态：
     - 合格 → 合格品区（回到可用库存）
     - 不合格 → 不合格品区（走报损流程）
     - 需复验 → 隔离区（走质量联系单）
5. **上架**：验收合格的商品通过任务引擎生成"退货上架"任务
6. **整单拒收**：验收发现与申请不符（数量/品种/状态严重不符）→ 拒收退回客户
7. 退货全流程写入审计追踪
8. 退货统计可按客户/商品/原因/时间汇总

## US-M4-009：波次出库箱规则

**作为** 仓库主管
**我要** 配置波次生成出库箱的规则（按订单/按客户/按温区/按体积拆箱）
**以便** 系统在波次下发时自动规划出库箱数量和分配

### 验收标准

1. **出库箱规则**（可配置）：
   - 按订单：一个订单一个出库箱（默认）
   - 按客户合箱：同客户多个订单合入一个出库箱
   - 按温区拆箱：冷链和常温必须分箱
   - 按体积拆箱：单箱超过最大体积/重量时自动拆为多箱
   - 按品类拆箱：特殊品类（如精麻药）必须独立装箱
2. 波次下发时自动计算出库箱数量 + 分配商品到箱
3. 出库箱关联容器（LPN），生成 LPN 码
4. 规则可按货主/客户类型绑定不同方案
5. 规则变更写入审计追踪

## US-M4-010：拣选路径策略

**作为** 仓库主管
**我要** 配置拣选路径的行走顺序策略
**以便** 保管员按最优路径拣选，减少行走距离

### 验收标准

1. **路径策略**（可配置，按仓库/库区绑定）：
   - 库位编号顺序（按编号升序/降序）
   - S 型遍历（蛇形走法，奇数通道正向、偶数通道反向）
   - 最短路径（系统计算最短行走距离）
   - 分区汇合（按库区分段拣选，最后汇合到包装站）
2. **路径顺序可配置**：管理员可在界面选择策略类型
3. 波次下发后，拣选任务按路径策略排序后下发给保管员
4. PDA 显示拣选顺序（按路径排好的库位列表）
5. 支持"跳过"（当前库位无货时跳到下一个）
6. 路径策略变更写入审计追踪

## US-M4-011：合并发货与拆单

**作为** 仓库主管 / 系统（自动）
**我要** 将多个小订单合并发货，或将大订单拆分为多个包裹
**以便** 降低运输成本（合并）/ 满足包裹限重限体积（拆单）

### 验收标准

1. **合并发货**：
   - 合并条件（可配置）：同客户 + 同地址 + 同温区 + 同时间窗
   - 合并后生成一个发货批次，共享一个快递单号
   - 合并不改变原订单（原订单各自独立可查）
   - 合并规则可按货主/客户类型配置
2. **拆单**：
   - 拆单条件（可配置）：超过最大重量/最大体积/特殊品类必须独立
   - 拆单后每个子包裹独立快递单号
   - 子包裹关联原订单（可追溯）
3. **波次阶段执行**：合并/拆单在波次生成时自动计算
4. **手动干预**：仓库主管可手动合并/拆分
5. 合并/拆单记录写入审计追踪

## 跨故事约束（适用于所有 M4 用户故事）

1. **审计追踪**：所有出库操作（校验/拣选/复核/发货/退货/作废）写入审计表
2. **多货主**：订单绑定货主，数据按货主隔离；随货同行单用货主抬头
3. **出库批号由 ERP 指定**：WMS 只校验库存并决定从哪个库位拣（波次算法）
4. **库存锁定与扣减**：波次分配时锁定数量（状态不变，锁定部分不可再分配）；发货确认时正式扣减
5. **ERP 反馈**：发货完成后异步反馈 ERP"已出库"（商品/批号/数量/时间），失败可重试
6. **双人复核**：拣选人 ≠ 复核人（系统校验）
5. **不回退**：拣选开始后不退回任何状态，有问题"先出后退"（事后走退货流程）
6. **整单出库**：不管拣到多少都整单走完流程（短拣标识差异 + 企业微信通知）
7. **没有部分发货**：一个订单必须整单发货
8. **复核无不通过**：复核只做确认，有问题事后退回处理
9. **门店经营范围校验**：受限药品不可配送到无资质门店（校验规则模块）
10. **强制作废回退**：已入波次未拣选时可强制作废，保管员 PDA 回退上架
11. **PDA 离线**：拣选支持离线暂存
12. **幂等性**：所有写操作支持 Idempotency-Key
13. **开放 API**：订单创建、订单状态查询支持外部系统调用
14. **打印模板**：随货同行单、快递单、交接单使用 US-M2-009 打印模板引擎
15. **企业微信通知**：短拣差异、校验异常、强制作废通知仓库主管
