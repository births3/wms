## US-M4-003：PDA 拣选作业

**作为** 保管员
**我要** 在 PDA 上按拣选任务指引，到指定库位扫码拣货
**以便** 准确高效地完成拣选，避免拣错

### 拣选任务状态机

> 区别于 M4 顶部的"出库订单状态机"。订单是业务实体，拣选任务是任务引擎下发到具体保管员的执行单元。一个订单含多个拣选任务（每个库位一个），状态机如下。

=== "📊 流程图"

    ```mermaid
    stateDiagram-v2
        [*] --> 待分配 : 波次下发
        待分配 --> 已分配 : 任务引擎分配
        已分配 --> 已下发 : PDA 接收
        已分配 --> 待分配 : 主管重分配
        已下发 --> 拣选中 : 保管员开始扫码
        已下发 --> 待分配 : 主管召回
        拣选中 --> 已完成 : 拣选完成
        拣选中 --> 已完成_含短拣 : 短拣异常
        已完成 --> [*]
        已完成_含短拣 --> 生成补拣 : 触发 M-RP-004
        生成补拣 --> [*]
    ```

### 验收标准

1. PDA 显示拣选任务列表（按波次/优先级排序）
2. 任务详情：目标库位（排-列-层）→ 商品 → 批号 → 数量
3. **最优路径引导**：按库位物理位置排序，减少行走距离
4. **拣选模式区分**（按 M-TE 任务的 pick_mode 字段）：
   - **整件拣选（PIECE_FULL）**：拣完整件（按包装层级最大单位，如 1 件 = 10 盒），来源为存储位
   - **零件拣选（PIECE_LOOSE）**：拆零拣选（按盒/支等小单位），来源为零拣位（M-RP 补货）
5. **PDA 拣选扫码顺序**：

```
1. 扫源库位码 → 校验任务起点（不匹配报警拒绝）
   ↓
2a. 整件拣选：扫 容器 LPN（整托/整箱码）→ 系统自动展开数量 → 确认
2b. 零件拣选：循环扫 商品码/电子监管码 → 按件计数 → 达到数量后确认
   ↓
3. 录入实际数量（默认 = 计划数量；差异需选异常代码）
   ↓ 若拆零（零件）拣选完成需移交目标
4. 拣选车/暂存位扫码 → 提交
```

6. **PDA 拣选字段表**：

| 字段 | 必填 | 系统带出/录入 | 说明 |
|------|------|-------------|------|
| 拣选任务 ID | 系统带出 | — | M-TE 生成 |
| 波次号 | 系统带出 | — | M4 波次 ID |
| 拣选模式 | 系统带出 | — | 整件 / 零件（pick_mode）|
| 源库位 | 系统带出 | 扫码确认 | |
| 商品编码 | 系统带出 | 扫码确认 | |
| 批号 | 系统带出 | 扫码确认 | **强校验**：扫码批号必须与任务一致 |
| 计划数量 | 系统带出 | — | 整件按件、零件按盒/支 |
| 实际数量 | 必填 | 录入 | 默认 = 计划，差异需选异常代码 |
| 异常代码 | 条件必填 | 选择 | 短拣 / 破损 / 不足 / 混批 / 库存被锁 / 其他 |
| 异常备注 | 可选 | 录入 | |
| 容器 LPN（整件）| 条件必填 | 扫码 | 整件拣选时必扫 |
| 拣选车码（零件）| 条件必填 | 扫码 | 零件拣选完成后扫拣选车码暂存 |
| 拣选人 user_id | 系统带出 | — | 强校验：拣选人 ≠ 复核人（M4-004）|
| 开始时间 | 系统带出 | — | |
| 完成时间 | 系统带出 | — | |

7. **批次强校验**：扫码后系统校验批号是否与分配一致，不一致则报警拒绝
8. 支持整托拣选（扫托盘 LPN = 拣整托，自动展开数量）
9. 支持整箱拣选（扫货箱 LPN = 拣整箱）
10. **双人策略动态查询**（v25 升级）：拣选前调 M-VR 双人策略接口（US-VR-006）按 process=出库 + node=拣货 查询；返回 dual_scan / dual_scan_with_approval 时需另一保管员扫码或主管审批通过方可提交单条拣选；普通药品默认 single，按现有"拣选人 ≠ 复核人"约束保障
11. **短拣处理**：实际可拣 < 分配数量时：
    - 拣选/复核流程可继续，订单标记为短拣待补齐
    - 发货前必须补拣补齐，不允许少量发货
    - 标识差异数量和异常代码
    - 差异库存加锁（隔离）
    - 生成补拣任务（M-RP-004）
    - 企业微信通知仓库主管
    - **人工跟踪**：可添加后续跟踪记录（处理进展、最终结论）
12. 拣选完成后整单流转到复核（不管是否短拣）
13. **离线支持**：断网时暂存拣选数据；离线期间该批次被他人改动（如被报损/隔离）时按跨故事约束 13"暂存为'待主管处理'"事件
14. 拣选操作写入审计追踪
15. **拣选入箱双模式**（`pick_container_mode` 模板字段，wave-model §3.4）：
    - `direct_box` 直装：拣选直接入出库箱，明细挂 order_line_id；**箱级等待**（箱内任一缺口 → 整箱待补货）
    - `bound_tote` 绑定周转箱（默认）：拣选入周转箱（收集多任务）→ 绑定出库箱 → 发货前装箱；**任务级等待**（缺口行任务标记等待，齐货任务照常拣）
16. **出库箱 = outbound_box 容器**（wave-model §3.1）：波次计算产物，复用 `lpn_containers` 的 `outbound_box` 类型容器，box_no 与 lpn_code 同一取号（扫箱号 = 扫 LPN）；拣选任务挂 `box_id`（outbound_pick_tasks.box_id），PDA 扫箱号聚合显示箱内任务列表（按 route_sequence 排序）
17. **周转箱绑定**（wave-model §3.2）：出库箱绑定 **1..N** 个周转箱（tote 容器，可循环复用）；一个周转箱同一时刻只绑定一个出库箱；**一条箱明细只能绑定一个周转箱**（container_lines 行不跨周转箱，订单行可拆成多个箱明细行）；波次计算时按出库箱预分配周转箱（容器可用池），不足时可改绑
18. **缺口处理三策略**（wave-model §6）：
    - `wait_and_split`（默认）：缺口订单行标记"等待补货"、出库箱/任务标记待补货，波次继续下发；补货 done 后异步重算单纳入
    - `hold_wave`：波次挂起等待补货（urgent 场景，等待窗口模板可配，默认 30 分钟，超时转 wait_and_split）
    - `fail_order`：整订单失败回滚（现状语义，可配置为某货主默认）
    - **urgent 补货联动**：波次算单缺口即时触发 `priority='urgent'` 补货任务，任务 done 后订单行重新算单

## US-M4-004：出库复核

**作为** 保管员（复核岗）
**我要** 对拣选完成的商品进行逐件复核，确认品种和数量正确
**以便** 防止拣错/拣少，满足 GSP 出库复核要求

### 复核模式

复核分三种执行场景，按订单/波次属性自动选择：

| 模式 | 执行位置 | 适用场景 | 核对粒度 |
|------|---------|---------|---------|
| **包装站复核** | 包装站 PC + 扫码枪 | 多 SKU 合箱、需称重、电子秤工位场景 | 整箱明细比对 |
| **PDA 整件复核** | PDA（库内/移动） | 整件直发（整托/整箱出库，不拆包装）| 容器粒度（扫 LPN）|
| **PDA 零件复核** | PDA（库内/移动） | 零件拣选（拆零盒/支）| 逐件扫追溯码 |

### 验收标准

> 含通用验收标准 + 三种模式（包装站复核 / PDA 整件复核 / PDA 零件复核）各自的扫码顺序和字段表。

1. **双人复核**：拣选人和复核人必须是不同用户（系统校验 user_id 不同）
2. **复核无"不通过"**：复核只做确认，有问题事后走退回流程处理
3. 复核完成 → 订单状态变为"已复核"
4. 复核记录写入审计追踪（复核人、时间、模式、扫码记录、双人策略命中规则 ID）
5. **离线支持**：PDA 模式支持离线暂存；包装站模式不支持离线（PC 长在线）；离线期间订单状态被改时按跨故事约束 13"暂存为'待主管处理'"
6. **双人策略动态查询**（v25 升级）：复核前调 M-VR 双人策略接口（US-VR-006）按 process=出库 + node=复核 查询，三档行为：
   - `single`：单人复核即可（普通药品矩阵默认 dual_scan，可被覆盖至 single）
   - `dual_scan`：第一复核员扫码完成 + 第二复核员（user_id 不同）扫码确认；强校验复核员 ≠ 拣选员
   - `dual_scan_with_approval`：双人扫码 + 仓库主管企业微信审批通过后状态流转
7. **复核双模式**（`review_mode` 模板字段，wave-model §5.1）：
   - `box` 按出库箱聚合：扫箱号 → 聚合绑定周转箱全部明细核对 → 全部核对完成箱置 `reviewed`
   - `tote` 按周转箱逐箱：逐箱核对 → 全部绑定周转箱核对完成箱置 `reviewed`
   - 复核发现问题箱置 `exception` 单独处理，不阻塞其他周转箱继续核对
8. **集货**（wave-model §5.2）：`location_type='staging'` 集货位（复用 zone/容量/货主能力），位号编排 `STG-{wave_no}-{route}-{seq}`（同车次箱聚相邻位，装车按位序）；复核通过 → 扫箱入集货位（箱 `location_id` 更新为集货位）；支持同波次内换位（记录流水），跨波次禁止；扫码强度 `staging_scan_mode` 参数（默认 batch：按集货位整批流转）
9. **装箱 + 装车**（发货前，装车台合并执行，wave-model §5.3）：按绑定关系把周转箱货装入出库箱 → 装箱确认：container_lines 明细转移至出库箱 + 数量校验（转出=转入）+ 周转箱清空回 `idle`（可循环复用）；装箱确认成功 → 出库箱 `shipped` → 直接装车；失败 → `exception` 人工处理
10. **发运**（wave-model §5.4）：装车核对 `loading_scan_mode`（默认 mandatory 逐箱核对）；发运时按随货同行单核对装箱清单装车（装箱清单 = 出库箱 + 箱明细）；随货同行单集合维度由波次模板参数决定（order 默认 / wave）

### 模式 1：包装站复核（PC + 扫码枪）

## US-M4-005：随货同行单打印

**作为** 保管员（复核岗）
**我要** 在复核通过后打印随货同行单
**以便** 随货附带合规单据，满足 GSP 要求

### 验收标准

1. 随货同行单内容：销售方信息、购货方信息、商品明细（品名/规格/批号/效期/数量/单位）、发货日期、质量状态
2. **多货主抬头**：3PL 模式下，随货同行单抬头为货主信息（非仓库方）
3. 使用 H9 打印模板引擎
4. 支持一单多页（商品明细超一页时自动分页）
5. 打印后订单状态可流转到"已发货"
6. 打印记录写入审计追踪

## US-M4-006：发货与交接

**作为** 保管员
**我要** 将复核通过的包裹交接给自有司机或第三方快递员，按配送方类型记录差异化的交接信息
**以便** 明确责任交接节点，后续可追溯，并区分两种配送方的不同合规要求

### 配送方场景区分

交接流程根据 M10-004 给出的配送方类型分两路径：

| 维度 | 自有车队 | 第三方快递 |
|------|---------|----------|
| **司机** | 公司员工，含 user_id（M1-006）| 第三方人员，仅记姓名+电话 |
| **车辆** | 公司自有，含车辆档案 | 第三方车辆，仅记车牌 |
| **签收** | 司机扫码签字（PDA 或纸质 + 拍照）| 快递员手写签字 |
| **运单号** | 自营送货单号（M-CG 生成）| 快递商运单号（来自 H5-004 下单或 TMS 推送）|
| **后续追踪** | M10-002 在途温控 + 司机 PDA 上报 | H5-005 快递轨迹查询 |

### 验收标准

1. **交接记录通用字段**：交接时间、包裹数量、交接人 user_id（保管员）

2. **自有车队场景字段**：

| 字段 | 必填 | 说明 |
|------|------|------|
| 配送方类型 | 系统带出 | "自有车队"（来自 M10-004 调度结果）|
| 车辆编号 | 必填 | 关联 TMS 推送的车辆档案（M10-001 接收）|
| 车牌号 | 系统带出 | 由车辆编号自动带出 |
| 司机 user_id | 必填 | 关联 M1-006，扫司机工牌或选择 |
| 司机姓名 | 系统带出 | 由 user_id 自动带出 |
| 装车温度（冷链）| 冷链必填 | 保管员现场读取 |
| 保温箱/冰袋配置 | 冷链必填 | 复用 M-PK-004 配置 |
| 司机签字 | 必填 | PDA 签字面板 OR 纸质签字 + 拍照 |

3. **第三方快递场景字段**：

| 字段 | 必填 | 说明 |
|------|------|------|
| 配送方类型 | 系统带出 | "第三方快递"（来自 M10-004 / H5-002）|
| 快递商代码 | 系统带出 | 来自 H5-001 |
| 运单号 | 系统带出 | 来自 H5-004 下单或 TMS 推送 |
| 快递员姓名 | 必填 | 手动录入 |
| 快递员电话 | 必填 | 手动录入 |
| 车牌号 | 必填 | 手动录入 |

## 跨故事约束（适用于所有 M4 用户故事）

1. **审计追踪**：所有出库操作（校验/拣选/复核/发货/退货/作废）写入审计表
2. **多货主**：订单绑定货主，数据按货主隔离；随货同行单用货主抬头
3. **出库批号由 ERP 指定**：WMS 只校验库存并决定从哪个库位拣（波次算法）
4. **库存锁定与扣减**：波次分配时锁定数量（状态不变，锁定部分不可再分配）；发货确认时正式扣减
5. **ERP 反馈**：发货完成后异步反馈 ERP"已出库"（商品/批号/数量/时间），失败可重试
6. **双人复核（动态化）** (v25)：拣选人 ≠ 复核人为最低保障，但是否需要双人扫码 / 双人+主管审批由 M-VR 双人策略矩阵（US-VR-006）按 process=出库 + node=拣货/复核/装箱/发货交接 + process=退货 + node=退货验收/退货上架 动态决定（v25 流程-节点二维），矩阵 UI 在 M1-008 §11；普通药品矩阵默认仅 node=复核 双人扫码，特殊药品按 M1-010 字典预置默认值；显式调用见 M4-003 §10、M4-004 §6、M4-006 §9、M4-008 §4-§5、M-PK-002 §4
7. **不回退**：拣选开始后不退回任何状态，有问题"先出后退"（事后走退货流程）
8. **整单出库**：短拣订单可继续拣选/复核流程，但发货前必须补拣补齐；发货数量必须等于订单计划数量
9. **没有部分发货**：一个订单必须整单发货
10. **复核无不通过**：复核只做确认，有问题事后退回处理
11. **业务边界**：经营范围/客户资质/信用额度等合规校验由 ERP 负责，WMS 不重复
12. **强制作废回退**：已入波次未拣选时可强制作废，保管员 PDA 回退上架
13. **PDA 离线**：拣选支持离线暂存；离线期间冲突由跨故事约束统一处理（暂存待主管处理）
14. **幂等性**：所有写操作支持 Idempotency-Key
15. **开放 API**：订单创建、订单状态查询支持外部系统调用
16. **打印模板**：随货同行单、快递单、交接单使用 H9 打印模板引擎
17. **企业微信通知**：短拣差异、校验异常、强制作废通知仓库主管

### PDA 弹性

> 适用故事：US-M4-003（PDA 拣选）、US-M4-004（PDA 复核）、US-M4-006（PDA 交接扫码）

#### 离线策略

| 场景 | 行为 |
|------|------|
| PDA 离线时拣选 | 拣选任务本地缓存; 拣选确认暂存本地; 网络恢复后批量上传 |
| PDA 离线时复核 | 复核数据暂存本地; 网络恢复后同步（冲突：订单已被他人复核 → 提示） |
| 离线暂存上限 | 拣选最多 50 个任务; 复核最多 20 个订单 |

#### 扫码交互

| 场景 | 行为 |
|------|------|
| 拣选扫库位码 | 确认到达正确库位 → 显示待拣商品 |
| 拣选扫商品码 | 确认拣选正确商品 → 输入数量 |
| 复核扫商品码 | 逐件扫码核对 → 数量自动累加 → 与拣选数量比对 |
| 交接扫司机工牌 | 确认司机身份 → 进入交接签字流程 |

#### 异常恢复

| 场景 | 行为 |
|------|------|
| 拣选过程中 APP 崩溃 | 重启后恢复到当前拣选任务; 已扫码数据保留 |
| 复核中途断网 | 当前复核数据暂存; 网络恢复后继续 |
| 交接签字中断 | 本地暂存签字数据; 网络恢复后上传; 服务端幂等去重 |
