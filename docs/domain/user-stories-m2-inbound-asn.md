### 状态说明

| 状态 | 含义 | 进入条件 | 可执行操作 |
|------|------|---------|-----------|
| 待校验 | ASN 已创建，等待规则校验 | API 推送 / 手工创建 | 校验规则自动执行 |
| 校验异常 | 校验不通过（供应商资质等） | 规则校验失败 | 人工修改后重新校验 / 强制通过（创建质量联系单 → 企业微信审批 → 标记合规风险） |
| 待收货 | 校验通过，等待货到（代码 `released`） | 校验通过（或无规则默认通过） | 收货提交、整单拒收、作废（企业微信审批）、打印 ASN 单。打开收货弹窗或页面草稿不是状态迁移 |
| 验收中 | 收货信息提交完成，正在验收 | 待收货一次提交收货信息 | 逐件验收、追溯码扫码、双人签字、强制关闭、绑定托盘/盲标签、**触发档案补录** |
| **档案补录中** | **验收过程中触发档案补录，等待 ERP 同步主数据**（M-QL"档案补录"类型联系单）| **PDA/PC Web 验收时收货员触发档案补录** | **等待审批 + ERP 同步**；同步落地后自动恢复"验收中"；联系单被拒则保持"档案补录中"等人工修正或退回 |
| 上架中 | 验收通过+双人签字完成，正在上架 | 双人签字完成 | PDA/PC Web 上架（可部分）；如配置全自动则瞬间完成 |
| 已完成 | 全部上架完成 | 最后一件上架 | 触发 ERP 反馈 → 自动归档 |
| 已作废 | 未收货前取消 | 待收货时申请 + 企业微信审批通过 | 终态 |
| 已关闭(拒收) | 整单拒收 | 收货环节拒收 | 终态 |
| 已关闭(短少) | 部分到货强制关闭 | 验收环节强制关闭 | 终态；缺货部分由 ERP 重新推新 ASN |
| 已关闭 | 正常归档 | 已完成 + ERP 反馈成功 | 终态 |

### 关键规则

- ASN 是**单品**（一个 ASN 只有一个商品；采购入库 ASN 不预置批号，销售退货入库带原销售批号）
- **校验模块**（M-VR）在 ASN 创建后自动执行规则校验
- 收货环节已**闭环**：实到数量 + 缺货数量 + 拒收数量 = ASN 预报数量
- 不存在"同一 ASN 多次收货"——一 ASN 一条收货记录（正常收货与整单拒收互斥）；缺货部分由 ERP 推新 ASN
- 待收货（`released`）一次提交进入验收中（`inspecting`），**不持久化「收货中」**
- 收货与整单拒收均**不写库存**；库存写入发生在上架
- 实到数量 > 预报数量禁止入库，不得用备注放行
- 双人签字时机**可配置**（收货/验收/两者都要）；收货节点未查到 US-VR-006 时 fail-closed
- 追溯码录入环节**可配置**（收货/验收，**默认验收**）；默认下收货不强制扫码、不写码库
- 上架模式**可配置**（全自动/半自动；PDA 扫码确认或 PC Web USB 扫码枪/手工确认）
- PC Web 可执行收货、验收、上架，复用 PDA 的业务规则、权限、审计、幂等和双人策略；PC Web 不支持离线暂存
- **档案补录**：验收过程中发现商品基础档案与实物不符或缺失时可触发；ASN 进入"档案补录中"状态阻塞验收，走 M-QL 审批 + ERP 接口表 + ERP 主数据变更 + 反馈回写完整闭环（详见 M-QL-004）；**默认配置关闭**，需仓库主管开通

## US-M2-001：创建 ASN（采购入库通知）

**作为** 仓库主管（或外部系统通过 API）
**我要** 创建 ASN，登记预计到货的供应商、商品和数量
**以便** 收货员提前知道今天要收什么货

### 验收标准

1. ASN 必填：供应商、商品（单品）、预计数量、预计到货时间；采购入库不要求批号，销售退货入库必须带原销售出库批号
2. ASN 单号由**编码生成模块**自动生成，格式：货主编码+P+日期+流水号，全局唯一
3. 创建时校验：供应商资质有效期（由 M-VR 校验规则模块执行；经营范围校验由 ERP 负责，WMS 不做）
4. ASN 状态初始为"待校验"（校验通过后变"待收货"）
5. **开放 API**：外部系统（ERP/采购）通过 API 推送 ASN（API Key 鉴权）
6. 支持手工创建（页面录入）
7. **ASN 打印**：打印 ASN 单据（含 ASN 单号条码，供 PDA 扫码定位）
8. **ASN 作废**：待收货状态可申请作废 → 推送企业微信审批 → 审批通过后状态变"已作废"
9. ASN 创建/修改/作废写入审计追踪

## US-M2-002：PDA/PC Web 收货（到货签收）

**作为** 收货员
**我要** 在 PDA 或 PC Web 上查找 ASN 并录入到货信息
**以便** 记录实际到货的完整信息，满足 GSP 收货记录要求

### 查找 ASN 的方式

- 扫 ASN 单号条码 → 直接定位
- 扫追溯码 → 解析商品信息 → 查询该商品未收货的 ASN 列表 → 选择
- 手工输入 ASN 单号

### PC Web 输入方式

- 支持 USB 扫码枪键盘输入 ASN、商品条码、用于定位 ASN 的追溯码；销售退货入库可输入原销售批号
- 支持手工输入；不要求浏览器摄像头扫码
- 不支持离线暂存；断网或提交失败时保持页面草稿，恢复网络后重新提交

| 车牌号 | 是 | |

| 第二收货员验证 | 可配置 | 系统参数决定是否需要 |

### 验收标准

1. 所有必填字段录入完成后可提交
2. **收货闭环**：实到数量 + 缺货数量 + 拒收数量 = 预报数量（系统校验，不等则不可提交）
3. **多到处理**：实到数量 > 预报数量 → 拒绝提交（`OverReceiptNotAllowed`），不得用备注放行；多出部分不入库，缺货由 ERP 重新下 ASN
4. 温度超标：到货温度（收货员手填或从送货温度计读数，**WMS 不实时采集**）超出商品储存条件允许范围（见 M1 附录 A）→ 弹出警告，可选"拒收"或"继续"；继续必须强制上传 H-FILE 稳定性报告附件（澄清 #107）。附件能力未完成前本故事保持延期
5. **整单拒收**（收货节点动作，澄清 #113）：独立 `reject`，写一条 receipt（实到=0、拒收=预报），状态变为"已关闭(拒收)"（`closed_rejected`），不写库存；与正常收货互斥。异常分类 / M-QL / H4 / 统计归 US-M2-006，不作为本故事完成门槛
6. 多批号部分拒收：销售退货入库拒收必须落到批号级明细，批号级拒收数量合计 = ASN 拒收数量；未拒收批号继续进入验收。采购入库只记录商品级拒收数量和原因。
7. **双人策略动态查询**（v25 升级）：收货环节进入前调用 M-VR 双人策略接口（US-VR-006）查询 process=入库 + node=收货 的策略。查不到策略或 US-VR-006 未完成时 **fail-closed**，禁止按 `single` 放行（澄清 #108）。按返回的三档执行：
   - `single`：当前用户独立提交即可
   - `dual_scan`：另一用户扫码确认后提交（user_id 不同 + 角色满足收货员要求）
   - `dual_scan_with_approval`：双人扫码 + 仓库主管企业微信审批通过后提交
8. ~~第二收货员验证（如配置开启）~~ 已由 §7 双人策略统一管理（保留字段表"第二收货员验证"用于 dual_scan 时第二人 user_id 记录）
9. **追溯码**（澄清 #110）：本故事消费 US-TC-005，默认验收。默认配置下收货不强制扫码、不写码库。扫追溯码查找 ASN 只用于定位。配置=收货时的绑码归 US-TC-003 / US-TC-005，不是本故事完成条件
10. **托盘/盲标签**（澄清 #111）：不是本故事完成条件。盲标签是容器类型；容器主数据归 US-M1-004a，库存身份绑定在上架（US-M2-005）
11. 提交后 ASN 状态变为"验收中"（`inspecting`）；待收货一次提交，不经过持久化「收货中」
12. **离线**（澄清 #73 / #109）：PC Web 不支持离线提交，断网保留页面草稿。PDA 离线不是本故事完成条件；若后续 PDA 实现离线，冲突按 H1 统一策略暂存为"待主管处理"，禁止静默覆盖
13. 收货信息写入审计追踪（含双人策略命中规则 ID 与两个 user_id）

## 跨故事约束

1. **审计追踪**：所有操作写入审计表
2. **多货主**：ASN 绑定货主，数据按货主隔离
3. **GSP 强校验**：供应商资质过期 → 拒绝；商品过期 → 拒绝入库
4. **收货闭环**：实到 + 缺货 + 拒收 = 预报（系统强制校验）
5. **双人签字策略动态化** (v25)：双人签字 / 双人扫码 / 双人+主管审批 由 M-VR 双人策略矩阵（US-VR-006）按 process=入库 + node=收货/验收/上架 动态决定（v25 流程-节点二维），覆盖入库流程的 3 个节点；矩阵 UI 在 M1-008 §11；普通药品默认配置仅 node=验收 双人扫码，特殊药品按 M1-010 字典预置默认值；PDA 与 PC Web 共用同一策略
6. **追溯码录入环节可配置**：收货 或 验收（**默认验收**）
7. **上架模式可配置**：全自动 或 半自动（**默认半自动**）
8. **冷链**：冷链商品必须录入温度，超标必须有处置记录
9. **离线边界**：PDA 验收/上架支持离线暂存；离线期间发生数据冲突（如库位被占、ASN 状态被改）时，**暂存为"待主管处理"事件**，由仓库主管在 PC 端手动决策，禁止静默覆盖；PC Web 不支持离线暂存。US-M2-002 不把 PDA 离线当完成条件（澄清 #109）
10. **开放 API**：ASN 创建支持外部系统推送
11. **ERP 反馈**：全部上架完成后异步反馈（失败可重试）
12. **企业微信审批**：作废/质量联系单通过企业微信审批流
13. **企业微信通知**：异常/预警通过企业微信通知相关人员
14. **幂等性**：所有写操作支持 Idempotency-Key
15. **打印模板**：所有打印使用 H9 打印模板引擎

#### US-M2-002 PDA/PC Web 收货（到货签收）

| 维度 | 场景 |
|------|------|
| L4 错误路径 | ASN 不存在 → M2_ASN_NOT_FOUND; 非待收货状态收货 → InvalidStatus; 实到数量 > 预报数量 → OverReceiptNotAllowed（禁止备注放行）; 收货节点未查到 US-VR-006 策略 → fail-closed; 冷链超温继续但无 H-FILE 附件 → 拒绝 |
| L5 数据一致 | 实际到货数量 + 缺货数量 + 拒收数量 = 预报数量; 收货后状态原子变为验收中; 收货与整单拒收均不写 inventory_batches; 一 ASN 至多一条 receipt |
| L8 权限 | 仅收货员可操作; 保管员/货主 → 403; PDA 与 PC Web 权限一致 |
| L11 幂等 | 同一 ASN 重复收货或重复整单拒收 → 返回首次 receipt，不写第二条 |

### PDA 弹性

> 适用故事：US-M2-002（PDA/PC Web 收货签收）
>
> PDA 离线不是本故事完成条件（澄清 #109）。下列离线策略供后续 PDA 实现引用 H1，不作为 002 迁出延期门槛。

#### 离线策略

| 场景 | 行为 |
|------|------|
| PC Web 断网 | 不支持离线提交；保留页面草稿，恢复网络后重新提交 |
| PDA 离线时需要收货 | 非本故事完成条件。若后续实现：本地缓存 ASN 列表 + 扫码收货暂存本地 |
| 本地暂存数据量 | 最多暂存 50 个 ASN 的收货记录; 超过提示"请恢复网络同步" |
| 网络恢复冲突 | 按 H1 统一策略暂存为"待主管处理"，禁止静默覆盖 |

#### 扫码交互

| 场景 | 行为 |
|------|------|
| 扫描 ASN 条码 | 解析 ASN 单号 → 显示 ASN 明细 → 进入收货录入 |
| 扫描商品条码 | 匹配 ASN 明细行 → 自动填充商品信息 + 计数 |
| 扫描追溯码 | 解析 GS1 → 采购入库不提取批号；销售退货入库校验原销售批号 |
| 扫码无匹配 | 提示"该商品不在本次 ASN 中" |

#### PC Web 输入

| 场景 | 行为 |
|------|------|
| PC Web 收货 | 支持 USB 扫码枪键盘输入 + 手工输入 |
| PC Web 断网 | 不支持离线提交；保留页面草稿，恢复网络后重新提交 |
| PC Web 双人策略 | 与 PDA 共用 M-VR 返回的 single / dual_scan / dual_scan_with_approval |

#### 异常恢复

| 场景 | 行为 |
|------|------|
| 收货过程中 APP 崩溃 | 重启后恢复到收货页面（本地暂存未提交数据） |
| 电量耗尽 | 本地 SQLite 持久化; 充电重启后自动续传 |
| 部分上传成功 | 已上传行标记完成; 未上传行继续重试 |
