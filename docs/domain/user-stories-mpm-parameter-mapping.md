# 用户故事：M-PM 参数对照模块

> 模块：M-PM parameter-mapping
> 性质：横向业务模块（处理 ERP / 上游系统推送的不规则字段，规整化为 WMS 标准枚举）
> 波次：Wave 2（在 M1 主数据 CRUD 之前必须就位，否则商品档案接收会失败）
> 依赖：H1 权限/多租户、H2 审计、H8 ERP 防腐层、M-QL 质量联系单

---

## 背景

ERP / 采购平台 / 上游系统推送给 WMS 的字段经常**不规则**，例如：

| 字段 | ERP 推送的实际形态举例 | WMS 期望的标准枚举 |
|------|---------------------|----------------|
| 储存条件 | "2-8℃避光保存" / "阴凉处保存" / "室温" / "冷藏" | 冷藏 / 冷冻 / 阴凉 / 常温 |
| 剂型 | "片" / "片剂" / "普通片" / "薄膜衣片" | 片剂 |
| 单位 | "盒" / "小盒" / "BOX" / "box" | 盒 |
| 包装规格 | "10片*3板" / "30 片/盒" / "30s" | 30（数量）|
| 客户类型 | "医院" / "三甲" / "医疗机构" / "二甲医院" | 医疗机构 |

WMS 内部强制使用结构化枚举，但**不能拒收**所有不规则数据；必须有可维护的对照机制把"源系统不规则文本"映射到"WMS 标准枚举"。

本模块即为这类规整化能力的**统一基础设施**，所有上游字段映射均收口于此。

## US-MPM-001：参数对照字典定义

**作为** 系统管理员
**我要** 定义系统中需要做映射规整化的字段（字典）
**以便** 所有上游不规则字段统一收口到一处管理

### 验收标准

1. 字典必填字段：
   - 字典编码 dict_code（唯一，如 `storage_condition` / `dosage_form` / `unit` / `customer_type`）
   - 字典名称（中文）
   - 目标枚举值列表（即 WMS 标准枚举集合，与对应业务模块的字段保持一致）
   - 来源系统标识（ERP / 采购平台 / 手工录入 / 任意，可多选）
2. 字典属性：
   - 是否大小写敏感（默认否）
   - 是否启用空白字符标准化（去首尾空格 + 中英文括号空格归一，默认是）
   - 默认值策略：无 / 兜底枚举 / 标记待映射（默认"标记待映射"）
   - 启用状态（启用/停用）
3. 字典支持新增 / 编辑 / 停用，不物理删除（停用后历史规则保留）
4. 字典编码唯一性校验
5. 系统预置 5 个字典（开箱即用）：
   - `storage_condition`：储存条件（目标枚举：冷藏 / 冷冻 / 阴凉 / 常温，与 M1-001 附录 A 一致）
   - `dosage_form`：剂型
   - `unit_pack`：包装单位
   - `customer_type`：客户类型
   - `special_drug_category`：特殊药品分类（与 M1-010 字典联动）
6. 字典与目标枚举的字段绑定关系记录在元数据，**目标枚举变更时自动检测受影响规则**并提示管理员复核
7. 字典创建 / 修改 / 停用写入审计追踪
8. 字典操作支持 Idempotency-Key（重复提交返回相同结果）

## US-MPM-002：映射规则配置

**作为** 系统管理员
**我要** 为每个字典维护"源文本 → 目标枚举"的映射规则
**以便** 系统能自动把上游不规则字段转换为 WMS 标准值

### 验收标准

1. 规则必填字段：
   - 关联字典 dict_code
   - 匹配类型：精确匹配 / 通配符（含 `*`）/ 正则表达式 / 包含子串
   - 源文本模式（按匹配类型解释）
   - 目标枚举值（必须是该字典已定义的枚举之一）
   - 优先级（整数，数值小者优先；同优先级按创建时间倒序）
   - 置信度（整数 0-100，人工录入默认 100，系统建议默认 ≤80）
   - 生效时间段（可选，默认永久生效）
   - 启用状态
2. **预览匹配**：录入规则后可输入一段源文本测试是否命中
3. **冲突检测**：保存规则前系统自动检测是否与现有规则冲突（同源文本映射到不同枚举），冲突时提示管理员调整优先级
4. **批量导入**：支持 CSV / Excel 批量导入规则；导入前预览 + 冲突报告
5. **规则启用 / 停用**：停用后不参与匹配，但保留历史
6. 规则可编辑（编辑视为新版本，旧版本归档保留，便于追溯）
7. 规则不物理删除，仅停用
8. 规则创建 / 修改 / 停用 / 启用 / 批量导入写入审计追踪
9. 规则操作支持 Idempotency-Key

## US-MPM-003：待映射队列与质量联系单触发

**作为** 仓库主管
**我要** 处理上游推送来的、规则没命中的源文本
**以便** 缺漏的映射能被人工补全，相关业务对象不会被静默错配

### 验收标准

1. **未命中入队**：M-PM 映射执行（US-MPM-004）发现源文本无命中规则时，自动写入"待映射队列"
2. 队列字段：
   - 字典编码
   - 源系统标识 + 源记录 ID（如商品 ERP 编码）
   - 源文本原值
   - 首次出现时间 / 最近出现时间 / 出现累计次数
   - 处置状态：待处理 / 已映射 / 已忽略
   - 处置人 user_id（处置后填）
3. **同源文本去重合并**：同一字典 + 同一源文本只生成一条队列记录，重复出现时累计 count + 更新最近出现时间
4. **质量联系单触发**（决策 5 落地）：
   - 当字典策略 = "标记待映射"（默认）时，**每条新加入队列的源文本同时生成一个 M-QL 质量联系单**
   - 联系单类型 = "参数对照待映射"（M-QL-002 类型清单需新增此类型）
   - 联系单审批源 = "M-PM 待映射队列"
   - 通过企业微信推送给仓库主管（H4-001）
   - 联系单审批通过 = 仓库主管完成映射；审批拒绝 = 标记忽略
5. **业务阻塞策略**（按字典定义的"默认值策略"行为）：
   - 默认值策略 = "兜底枚举"：先用兜底值放行，待映射队列异步处理
   - 默认值策略 = "标记待映射"：相关业务对象进入待审核状态，**业务模块按本字段绑定的对象类型决定阻塞或放行**（详见跨故事约束 §6）
6. **批量处置**：仓库主管可在队列界面批量处理多条同字典的源文本（一次创建多条规则）
7. **处置入口直通规则配置**：从队列点"映射"按钮 → 自动带入字典 + 源文本预填到 US-MPM-002 规则配置界面
8. 队列查询支持过滤（字典 / 源系统 / 处置状态 / 时间范围 / 出现次数）
9. 队列处置写入审计追踪 + 同步关闭对应 M-QL 联系单
10. 处置操作支持 Idempotency-Key

## US-MPM-004：映射执行 API

**作为** 系统（H8 ERP 防腐层 / M1 / 其他业务模块）
**我要** 调用 M-PM 提供的映射服务把源文本规整为标准枚举
**以便** 业务模块只与 WMS 标准枚举打交道

### 验收标准

1. **接口契约**（内部 RPC + OpenAPI 暴露）：
   ```
   POST /m-pm/map
   Body: {
     dict_code: string,           // 字典编码，必填
     source_value: string,        // 源文本，必填
     source_system: string,       // 来源系统标识，可选
     source_record_id: string,    // 源记录 ID，可选（用于追溯）
     idempotency_key: string,     // 可选
   }
   Response: {
     status: "matched" | "unmatched" | "ambiguous",
     target_value: string | null,  // 命中时返回标准枚举值
     rule_id: string | null,       // 命中规则 ID（用于追溯）
     confidence: int,              // 0-100
     fallback_used: bool,          // 是否用了兜底值
     queued: bool,                 // 是否已入待映射队列
   }
   ```
2. **执行顺序**：
   1. 标准化源文本（按字典属性做大小写 / 空白处理）
   2. 按规则优先级顺序逐条匹配（精确 → 包含 → 通配符 → 正则）
   3. 第一条命中即返回
   4. 全部未命中：按字典默认值策略处理（兜底 / 入队列）
3. **性能要求**：单次映射 P95 < 50ms（字典规则数 ≤ 1000 条时）
4. **缓存**：命中结果按"dict_code + 源文本"缓存 5 分钟（可配置），规则变更时缓存失效
5. **批量接口**：`POST /m-pm/map-batch`，一次最多 500 条，超过分批处理
6. **错误处理**：字典不存在 → 4xx；规则执行异常 → 5xx 并写错误日志，**不阻塞调用方**（调用方按 unmatched 处理）
7. **追溯字段**：调用结果连同 rule_id 写入调用方业务对象（如 M1-001 商品档案保存"映射溯源元数据"）
8. 映射执行写入审计追踪（记录调用方、源值、命中规则、目标值、是否兜底）
9. 接口支持 Idempotency-Key

## US-MPM-005：反向追溯与映射溯源

**作为** GSP 审计员 / 仓库主管
**我要** 反查任一标准枚举值历史上接收过哪些源文本，以及任一规则命中过哪些业务对象
**以便** 满足 GSP 数据可追溯要求，规则调整时能评估影响范围

### 验收标准

1. **按目标枚举反查**：输入 `dict_code + 标准枚举值` → 显示历史命中的源文本清单（去重 + 出现次数 + 命中规则 ID）
2. **按规则反查**：输入 `rule_id` → 显示该规则命中过的业务对象清单（按调用方分组：M1-001 商品 / M1-003 客户 / 其他）
3. **按业务对象反查**：输入业务对象 ID（如商品编码） → 显示该对象所有字段的映射溯源（哪个字段、源值、命中规则、命中时间）
4. **规则变更影响评估**：在 US-MPM-002 规则编辑界面提供"查看影响范围"按钮 → 显示该规则当前命中过的业务对象数量与样本
5. **导出**：反查结果支持 Excel / CSV 导出
6. **保留期限**：映射溯源记录保留 ≥ 5 年（与审计追踪一致），过期数据归档冷存储
7. 反查界面只读，不产生写操作；查询请求不写审计（数据量大）
8. 导出操作写入审计追踪（操作人、时间、查询条件）

## US-MPM-006：交易类型字典管理（PIX 三码）

**作为** 仓库主管 / 系统管理员
**我要** 集中管理本系统的交易类型字典（reason_code / action_code / tran_code）
**以便** 业务模块的"原因码 / 动作码 / 交易码"统一可控可查可审计

### 背景

v3.1 字段词典识别 PIX 体系三码（来自 legacy `TRAN_*` 系列）：

- **reason_code 原因码**：库存调整 / 状态变更 / 退货等的原因（盘盈 / 盘亏 / 破损 / 近效期等）
- **action_code 动作码**：业务动作类型（收货 / 发货 / 移库 / 调整 / 销毁等）
- **tran_code 交易代码**：业务交易类型（采购入库 / 销售出库 / 退货 / 调拨 / 报损等）

各业务模块需要这套字典记录"为什么变 / 做了什么 / 在哪个交易"的统一标识。原本散落在 M-SA / M3-003 / M-RC / 各模块状态机中，本故事将其集中。

### 验收标准

1. **三码字典结构**（统一表，按 `code_type` 区分）：
   - 字典 ID / code_type（reason / action / tran）
   - 编码（如 `RSN-DAMAGE` / `ACT-RECV` / `TRAN-PURCHASE-IN`）
   - 中文名称
   - 父类编码（可选，支持层级）
   - 默认级别（info / warning / critical，用于 H-AL 联动）
   - 关联业务模块（M2 / M3 / M4 / M-SA / M-RC 等）
   - 启用 / 停用标志
   - 多语言名称（中文为主）
2. **三码独立性**：reason / action / tran 三类码可独立查询不混淆
3. **GSP 强制三码预置**（系统初始化时不可删除）：
   - reason：盘盈 / 盘亏 / 破损 / 近效期 / 不合格销毁 / 召回销毁
   - action：收货 / 发货 / 移库 / 调整 / 销毁 / 隔离 / 召回
   - tran：采购入库 / 销售出库 / 退货入库 / 退货出库 / 报损 / 调拨 / 销毁
4. **业务模块订阅**：M3-003 / M-SA / M-RC / M-QL 等通过本字典查询合法码值；本字典变更触发 H2-005 事件总线 → 业务模块刷新缓存
5. **变更审计**：增删改写入 H2 审计；停用必须填理由（避免误关键码）
6. **校验**：业务流水中的 code 字段值在字典中必须存在且启用，不存在则进入"待映射"队列（参见 MPM-003）
7. **统计**：按时段统计各 code 使用次数 + Top N（业务体检用）
8. **导入导出**：支持 Excel 批量导入字典 + 导出当前字典（迁移用）
9. **多货主隔离**：基础码全局共享；货主可加自有扩展码（前缀 + 货主 ID）
10. **报表关联**：M6 报表按 code 聚合查询的字典源
11. **关联 M-VR**：规则引擎可使用本字典的 code 作为校验值
12. **关联 H-AL**：告警可按 reason_code 路由到不同接收人组
13. **GSP 不可删除标识**：is_gsp_required = true 的码不可删除，停用需 GSP 审计员审批

### 异常路径

- 删除已有流水使用的 code → 拒绝并提示流水数量
- 业务流水带未知 code → 进"待映射"队列（MPM-003 复用）
- GSP 强制码尝试停用 → 拒绝（is_gsp_required=true）

## 跨故事约束

1. **审计追踪**：字典 / 规则 / 队列 / 映射执行 / 导出全部写入审计表
2. **多货主**：字典默认全局共享；规则可按货主级覆盖（同字典不同货主可有不同规则集，优先级：货主 > 全局）
3. **目标枚举一致性**：M-PM 字典的目标枚举必须与对应业务模块字段定义一致，**枚举变更需同步更新**（governance 脚本可校验）
4. **业务模块调用约定**：所有从外部系统接收的非结构化字段，必须通过 M-PM 映射后再写入业务表；禁止业务模块直接消费源文本
5. **H8 ERP 防腐层集成**：H8 在反序列化 ERP 推送数据时调用 M-PM 完成所有不规则字段规整化
6. **业务对象阻塞策略**：字典默认值策略 = "标记待映射" 时，依赖该字段的业务对象按下表处理：

| 业务对象 | 字段 | 未匹配时行为 |
|---------|-----|------------|
| M1-001 商品档案 | storage_condition | 商品状态 = "待映射"，不可用于新 ASN |
| M1-001 商品档案 | special_drug_category | 商品状态 = "待映射"，不可用于新 ASN |
| M1-001 商品档案 | dosage_form | 仅警告，不阻塞 |
| M1-003 客户档案 | customer_type | 仅警告，不阻塞 |

7. **缓存一致性**：规则启用 / 停用 / 编辑后立即失效相关缓存
8. **企业微信通知**：待映射队列新增 → 推送仓库主管（H4-001 通知模板）
9. **GSP 合规**：映射溯源是 GSP 数据完整性要求的一部分，溯源记录 append-only，不可修改
10. **幂等性**：所有写操作支持 Idempotency-Key，重复提交返回相同结果
11. **附录 A 引用**：储存条件字典的目标枚举严格遵循 user-stories-m1-master-data-product.md "附录 A：储存条件温度区间表"
12. 测试要求：写操作必须含 L4（错误路径）+ L5（数据一致）+ L8（权限）+ L11（幂等）；读操作必须含 L4 + L8

## 与其他模块的关系

| 模块 | 关系 |
|------|------|
| M1-001 商品档案 | 储存条件 / 剂型 / 包装单位接收时调 M-PM 规整化 |
| M1-003 客户档案 | 客户类型接收时调 M-PM |
| M1-010 特殊药品分类字典 | 提供 `special_drug_category` 字典的目标枚举来源 |
| H8 ERP 防腐层 | 调用 M-PM 完成 ERP 推送数据规整化 |
| M-VR 校验规则 | 规则的字段值来自 M-PM 规整后的标准枚举（不消费源文本）|
| M-QL 质量联系单 | 待映射队列触发"参数对照待映射"类型联系单 |
| M-CG 编码生成 | 不依赖（M-CG 处理单据号生成，与映射无关）|

### 测试维度覆盖

#### US-MPM-001 参数对照字典管理

| 维度 | 场景 |
|------|------|
| L4 错误路径 | 字典名重复 → PM_DICT_DUPLICATE; 映射规则语法错误 → PM_RULE_SYNTAX_ERROR; 删除有活跃映射的字典 → PM_DICT_IN_USE |
| L5 数据一致 | 字典变更后新映射使用新规则; 已完成的映射不受影响 |
| L8 权限 | 系统管理员可管理; 仓库主管只读 |
| L11 幂等 | 创建/修改支持 Idempotency-Key |
