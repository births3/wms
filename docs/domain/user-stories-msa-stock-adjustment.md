# 用户故事：M-SA 报损报溢模块

> 模块：M-SA stock-adjustment
> 性质：独立业务模块（库存调整，来源于 ERP）
> 波次：Wave 3（依赖 M3 库存）
> 依赖：M1 基础档案、M3 库存、H1 权限、H2 审计、H4 企业微信

---

## 背景

报损 = 库存减少（相当于出库）；报溢 = 库存增加（相当于入库）。
单据由 ERP 推送，WMS 执行实物操作并反馈 ERP。

---

## US-SA-001：报损单管理

**作为** 仓库主管（或 ERP 通过 API 推送）
**我要** 接收和执行报损单（库存减少）
**以便** 不合格品/过期品/盘亏确认后从库存中扣减

### 验收标准

1. 报损单来源：**ERP 推送**（API）或手工创建
2. 报损单必填：商品、批号、数量、报损原因（过期/破损/质量不合格/盘亏确认/销毁/**召回销毁**/其他）；**销毁原因码（v25）**：当报损原因 = 销毁 或 召回销毁 时，关联流程 process=销毁，否则 process=报损；**召回销毁特殊**（v25 审计修复）：报损原因 = 召回销毁时，必填 recall_id（关联 M-QL-002 §5 召回联系单 ID），M3 库存批次的 recall_flag 标记自动解除（销毁完成）
3. 报损单号由**编码生成模块**生成
4. 报损单状态：待执行 → 执行中 → 已完成
5. **执行操作**：保管员 PDA 扫码确认报损商品 → 从库位取出 → 库存扣减
6. **双人策略动态查询**（v25 新增）：执行前调 M-VR 双人策略接口（US-VR-006）查询：
   - 报损原因 ≠ 销毁：process=**报损** + node=**报损执行**
   - 报损原因 = 销毁：process=**销毁** + node=**销毁执行**（销毁流程复用本节点，仅传 process 参数差异）
   - 三档行为：`single` / `dual_scan`（两不同 user_id 扫码）/ `dual_scan_with_approval`（双人扫码 + 仓库主管企业微信审批）
   - 麻精毒放 / 放射性按 M1-010 字典默认值 → dual_scan_with_approval
7. **审批源传递**：调用 M3 库存扣减接口时必须携带 `approval_source = 质量联系单（如有审批）/ 报损报溢单（无审批），approval_id = 联系单 ID 或 报损/报溢单 ID`（见 M3-003 审批源枚举 7 类）
8. 报损 = 出库（库存减少），扣减后库存不可恢复（除非报溢）
9. 执行完成后**反馈 ERP**（异步，失败可重试）
10. 报损单需**质量联系单审批**（可配置：是否需要审批；销毁原因强制需审批）
11. 所有操作写入审计追踪（含双人策略命中规则 ID + 第一/第二操作人 user_id + 审批人 user_id）
12. 支持 API 查询报损单状态

## US-SA-002：报溢单管理

**作为** 仓库主管（或 ERP 通过 API 推送）
**我要** 接收和执行报溢单（库存增加）
**以便** 盘盈确认/退货入库/其他原因导致的库存增加有据可查

### 验收标准

1. 报溢单来源：**ERP 推送**（API）或手工创建
2. 报溢单必填：商品、批号、数量、报溢原因（盘盈确认/退货入库/系统差异修正/其他）
3. 报溢单号由**编码生成模块**生成
4. 报溢单状态：待执行 → 执行中 → 已完成
5. **执行操作**：保管员 PDA 扫码确认商品 → 上架到指定库位 → 库存增加
6. **双人策略动态查询**（v25 新增）：执行前调 M-VR 双人策略接口（US-VR-006）查询 process=**报溢** + node=**报溢执行**；三档行为同 US-SA-001 §6；麻精毒放 / 放射性按 M1-010 字典默认值
7. 报溢 = 入库（库存增加），上架规则同 M2 智能上架（温区/色标匹配）
8. 执行完成后**反馈 ERP**（异步，失败可重试）
9. 报溢单需**质量联系单审批**（可配置：是否需要审批）
10. 所有操作写入审计追踪（含双人策略命中规则 ID + 第一/第二操作人 user_id）
11. 支持 API 查询报溢单状态

## US-SA-003：报损报溢查询与统计

**作为** 仓库主管
**我要** 查询报损报溢历史记录和统计报表
**以便** 分析损耗趋势，优化库存管理

### 验收标准

1. 查询维度：类型（报损/报溢）、时间范围、商品、批号、原因、货主
2. 统计报表：
   - 按原因分布（哪种原因最多）
   - 按商品分布（哪个商品损耗最大）
   - 按时间趋势（月度报损/报溢数量和金额）
   - 按货主汇总
3. 支持导出 Excel
4. 审计追踪可追溯每笔报损报溢的完整操作链路

---

## 跨故事约束

1. **审计追踪**：所有操作写入审计表（含双人策略命中规则 ID + 第一/第二操作人 + 审批人）
2. **多货主**：报损报溢按货主隔离
3. **ERP 驱动**：单据主要来源于 ERP 推送，WMS 执行并反馈
4. **库存变动经领域服务**：报损扣减/报溢增加必须经 M3 库存服务（禁止直接 SQL）
5. **编码生成**：单号由 M-CG 编码生成模块统一生成
6. **质量联系单**：可配置是否需要审批（如报损金额超阈值需审批；销毁原因强制需审批）
7. **幂等性**：ERP 重复推送同一报损/报溢单不重复执行
8. **PDA 支持**：执行操作在 PDA 上完成（扫码确认）
9. **双人策略动态化** (v25)：报损执行 / 报溢执行 / 销毁执行（销毁流程复用报损执行节点）三个节点统一调用 M-VR 双人策略接口（US-VR-006），按特殊药品分类返回 single / dual_scan / dual_scan_with_approval；普通药品单人即可，麻精毒放 / 放射性按 M1-010 字典默认值
10. **销毁流程归属** (v25)：销毁不是独立模块，是一个独立流程（process=销毁），其执行节点（node=销毁执行）复用 M-SA-001 报损执行的物理操作 + 销毁原因码标识；M-VR 规则按 process 区分双人策略（销毁默认更严格）

#### US-SA-001 报损单创建与审批

| 维度 | 场景 |
|------|------|
