# 用户故事：M-SA 报损报溢模块

> 模块：M-SA stock-adjustment
> 性质：独立业务模块（库存调整，来源于 ERP）
> 波次：Wave 3（依赖 M3 库存）
> 依赖：M1 基础档案、M3 库存、H1 权限、H2 审计、H4 企业微信

---

## 背景

报损 = 库存减少（相当于出库）；报溢 = 库存增加（相当于入库）。
单据由 ERP 推送，WMS 执行实物操作并反馈 ERP。

---

## US-SA-001：报损单管理

**作为** 仓库主管（或 ERP 通过 API 推送）
**我要** 接收和执行报损单（库存减少）
**以便** 不合格品/过期品/盘亏确认后从库存中扣减

### 验收标准

1. 报损单来源：**ERP 推送**（API）或手工创建
2. 报损单必填：商品、批号、数量、报损原因（过期/破损/质量不合格/盘亏确认/其他）
3. 报损单号由**编码生成模块**生成
4. 报损单状态：待执行 → 执行中 → 已完成
5. **执行操作**：保管员 PDA 扫码确认报损商品 → 从库位取出 → 库存扣减
6. 报损 = 出库（库存减少），扣减后库存不可恢复（除非报溢）
7. 执行完成后**反馈 ERP**（异步，失败可重试）
8. 报损单需**质量联系单审批**（可配置：是否需要审批）
9. 所有操作写入审计追踪
10. 支持 API 查询报损单状态

---

## US-SA-002：报溢单管理

**作为** 仓库主管（或 ERP 通过 API 推送）
**我要** 接收和执行报溢单（库存增加）
**以便** 盘盈确认/退货入库/其他原因导致的库存增加有据可查

### 验收标准

1. 报溢单来源：**ERP 推送**（API）或手工创建
2. 报溢单必填：商品、批号、数量、报溢原因（盘盈确认/退货入库/系统差异修正/其他）
3. 报溢单号由**编码生成模块**生成
4. 报溢单状态：待执行 → 执行中 → 已完成
5. **执行操作**：保管员 PDA 扫码确认商品 → 上架到指定库位 → 库存增加
6. 报溢 = 入库（库存增加），上架规则同 M2 智能上架（温区/色标匹配）
7. 执行完成后**反馈 ERP**（异步，失败可重试）
8. 报溢单需**质量联系单审批**（可配置：是否需要审批）
9. 所有操作写入审计追踪
10. 支持 API 查询报溢单状态

---

## US-SA-003：报损报溢查询与统计

**作为** 仓库主管
**我要** 查询报损报溢历史记录和统计报表
**以便** 分析损耗趋势，优化库存管理

### 验收标准

1. 查询维度：类型（报损/报溢）、时间范围、商品、批号、原因、货主
2. 统计报表：
   - 按原因分布（哪种原因最多）
   - 按商品分布（哪个商品损耗最大）
   - 按时间趋势（月度报损/报溢数量和金额）
   - 按货主汇总
3. 支持导出 Excel
4. 审计追踪可追溯每笔报损报溢的完整操作链路

---

## 跨故事约束

1. **审计追踪**：所有操作写入审计表
2. **多货主**：报损报溢按货主隔离
3. **ERP 驱动**：单据主要来源于 ERP 推送，WMS 执行并反馈
4. **库存变动经领域服务**：报损扣减/报溢增加必须经 M3 库存服务（禁止直接 SQL）
5. **编码生成**：单号由 M-CG 编码生成模块统一生成
6. **质量联系单**：可配置是否需要审批（如报损金额超阈值需审批）
7. **幂等性**：ERP 重复推送同一报损/报溢单不重复执行
8. **PDA 支持**：执行操作在 PDA 上完成（扫码确认）
