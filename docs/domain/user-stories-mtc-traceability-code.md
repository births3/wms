# 用户故事：M-TC 追溯码模块

> 模块：M-TC traceability-code
> 性质：独立业务模块，被 M2 入库（收货/验收）和 M4 出库（复核）依赖
> 波次：Wave 2（与 M1 基础档案同期）
> 依赖：M1 商品档案、H1 权限、H2 审计
> 关联 ADR：ADR-0008 §ADR-0008 §5 GS1 nomenclature 数据驱动（trace_code_nomenclature + trace_code_rule，前后端共享 pattern matcher）

---

## US-TC-001：追溯码分类管理

**作为** 系统管理员
**我要** 配置追溯码的分类体系（码上放心码、GS1 码、其他码）
**以便** 系统能识别不同类型的追溯码并按规则解析

### 验收标准

1. 追溯码分类：码上放心码、GS1 码、其他（可扩展）
2. 每种分类配置：名称、编码规则（正则/长度）、解析规则、对接平台
3. 支持新增自定义分类
4. 分类变更写入审计追踪

---

## US-TC-002：码库管理（大中小码）

**作为** 系统（自动）/ 仓库主管
**我要** 从追溯码平台拉取入库订单的码（大码），解析为大/中/小码并存入码库
**以便** 出库复核/包装站/PDA 扫码时能核验数量、批号、效期

### 验收标准

1. **主动拉取**：系统调用追溯码平台 API，按入库订单拉取关联的追溯码
2. 拉取的码可能是大码（件码），系统按商品包装转换比解析为：
   - 大码（件码）
   - 中码（盒码）
   - 小码（支码）
3. 码库表字段：追溯码值、码类型（大/中/小）、分类（码上放心/GS1/其他）、关联商品、批号、效期、状态（未用/已入库/已出库/已核销）
4. 码库支持手工导入（Excel / API）
5. 码库支持按商品/批号/状态查询
6. 码库数据变更写入审计追踪

---

## US-TC-003：追溯码与商品绑定

**作为** 收货员 / 保管员
**我要** 在 PDA 上扫追溯码，将码与商品建立绑定关系
**以便** 后续出库扫码时能自动识别商品身份

### 验收标准

1. **PDA 追溯码绑定扫码顺序**：

```
1. 进入方式选择：（a）从收货/验收模块进入（默认关联当前 ASN）；（b）独立进入（手动选商品）
2. 扫追溯码 → 系统从"码上放心"接口或本地码库查询码信息
3. 显示码内容（商品/批号/效期）+ 是否已绑定标记
4. 选择目标商品 → 确认绑定 → 提交
   ↓ 多维度绑定可选
5. 可同时绑定到：托盘 LPN / 盲标签 / ASN 订单
```

2. **PDA 追溯码绑定字段表**：

| 字段 | 必填 | 系统带出/录入 | 说明 |
|------|------|-------------|------|
| 追溯码值 | 必填 | 扫码 | 大码/中码/小码均可 |
| 码类型 | 系统带出 | — | 大码（件）/ 中码（盒）/ 小码（支）|
| 码分类 | 系统带出 | — | 码上放心 / GS1 / 其他 |
| 关联 ASN | 系统带出 | 选择 | 从 ASN 入口默认带出 |
| 商品编码 | 必填 | 选择 | |
| 批号 | 必填 | 录入或扫码自动 | |
| 效期 | 必填 | 录入或扫码自动 | |
| 多维度绑定 | 可选 | 扫码 | 容器 LPN / 盲标签 |
| 是否已绑定 | 系统带出 | — | 是/否（防重复） |
| 操作人 user_id | 系统带出 | — | |
| 绑定时间 | 系统带出 | — | |

3. 已有绑定可解除（需权限）
4. 绑定错误时可修正（维护有历史记录，每次变更记录旧值/新值/操作人/时间）
5. 绑定关系存储：追溯码 → 商品 + 批号 + 效期
6. 追溯码可绑定到：托盘 / 盲标签 / ASN 订单（多维度绑定）
7. **追溯码单独一张表**（不嵌入商品表或库存表）
8. **离线支持**：PDA 离线时可暂存绑定操作；离线期间码已被他人绑定其他商品时按 M-TC 跨约束"暂存待主管处理"
9. 所有绑定/解绑/修正操作写入审计追踪

## US-TC-004：PDA 追溯码对应关系维护

**作为** 收货员 / 保管员
**我要** 在 PDA 上维护追溯码与商品的对应关系（新增/修正/解绑）
**以便** 码信息有误或缺失时能现场修正

### 验收标准

1. **PDA 追溯码维护扫码顺序**：

```
1. 扫追溯码 → 显示当前绑定信息（商品/批号/效期）
   ↓
2a. 如果未绑定 → 引导绑定流程（选择商品 → 确认）
2b. 如果绑定错误 → 修正流程（先扫旧绑定 → 解绑确认 → 扫/选新商品 → 重新绑定）
2c. 如果需解绑 → 选择"解绑" → 输入原因 → 提交
3. 所有动作均生成历史记录
```

2. **PDA 追溯码维护字段表**：

| 字段 | 必填 | 系统带出/录入 | 说明 |
|------|------|-------------|------|
| 追溯码值 | 必填 | 扫码 | |
| 操作类型 | 必填 | 选择 | 新增绑定 / 修正绑定 / 解绑 |
| 旧绑定信息 | 系统带出 | — | 商品/批号/效期（如已存在）|
| 新商品编码 | 条件必填 | 选择 | 新增/修正时必填 |
| 新批号 | 条件必填 | 录入 | |
| 新效期 | 条件必填 | 录入 | |
| 操作原因 | 必填 | 录入 | 解绑/修正必填，自由文本 |
| 操作人 user_id | 系统带出 | — | |
| 操作时间 | 系统带出 | — | |

3. 维护权限可配置（默认收货员和保管员可操作）
4. **离线支持**：PDA 离线时可暂存维护操作；离线期间码已被他人变更绑定时按"暂存待主管处理"
5. 所有维护操作有历史记录（谁/什么时间/改了什么），写入审计追踪

## US-TC-005：追溯码录入环节配置

**作为** 系统管理员
**我要** 配置追溯码的录入环节（放在收货环节 或 验收环节）
**以便** 不同仓库可按实际流程选择最合适的录入时机

### 验收标准

1. 系统参数：追溯码录入环节 = 收货 / 验收（二选一，**默认验收**）
2. 配置为"收货"：收货员在收货环节扫码录入
3. 配置为"验收"：收货员在验收环节扫码录入
4. 切换配置不影响历史数据
5. 配置变更写入审计追踪

## US-TC-006：出库追溯码核验

**作为** 保管员（复核岗）
**我要** 在出库复核/包装站扫追溯码，系统自动核验数量、批号、效期
**以便** 确保出库商品与订单一致，满足追溯要求

### 验收标准

1. 复核时扫追溯码 → 系统从码库查询：商品/批号/效期/数量
2. 自动比对订单明细：品种对不对、批号对不对、数量够不够
3. 不匹配时报警（扫错品/扫错批）
4. 扫码完成后追溯码状态变为"已出库"
5. 出库后码状态不可回退（除非退货入库）
6. 支持大码扫码（自动展开为中/小码数量）
7. **召回反查支持** (v25 新增)：M-QL "召回"类型联系单创建时，调用本模块的反查能力，按召回范围（商品/批号清单）反查所有已出库追溯码 → 输出受影响客户清单（recall_status 字段联动 M-QL-002 §5 affected_customers）；反查接口与 M6-001 §反向追溯能力对齐
8. 追溯码状态变更写入审计追踪（含召回反查触发时记录 recall_id 关联）

## US-TC-007："码上放心"平台上报

**作为** 系统（自动）
**我要** 在追溯码状态变更时（入库/出库/退货）将核销信息上报到"码上放心"国家追溯协同服务平台
**以便** 满足国家药品追溯监管要求，且追溯码核销与 WMS 业务实时一致

> 业务边界声明：码上放心上报由 WMS 直接对接（不绕 ERP），因为追溯码扫码事件由 WMS 唯一产生，绕道 ERP 会增加时延和复杂度（决策见 docs/domain/clarifications.md "追溯码边界"）。

### 验收标准

1. **触发时机**（追溯码状态变更事件触发，异步推送）：

| 状态变更 | 事件 | 上报内容 |
|---------|------|---------|
| 未用 → 已入库 | M2-003 PDA 验收扫码 / M-TC-003 绑定 | 追溯码 + 状态 + 时间戳 |
| 已入库 → 已出库 | M4-004 出库复核扫码 / M-PK-005 装箱核验 | 追溯码 + 状态 + 时间戳 |
| 已出库 → 已退回 | M4-008 退货入库 | 追溯码 + 状态 + 时间戳 |
| 已入库 → 已核销 | M-SA-001 报损执行 | 追溯码 + 状态 + 时间戳 |

> **接口约定**（v21 修正）：上报字段由**"码上放心"国家追溯协同服务平台**决定，WMS 仅按平台接口规范推送。
> v21 业务确认：平台接收"追溯码 + 状态变更类型 + 时间戳"三元组，**不需要 WMS 重传批号 / 客户 / 门店 / 流向等业务字段**（追溯码本身在国家平台已含完整商品+批号映射，WMS 重传反而可能引发不一致）。
> ⚠️ **待接口确认**：平台具体接口字段名 / 鉴权方式 / 错误码 / 频率限制等，需在 Wave 4 W4.D 启动前向"码上放心"接口方确认正式技术文档。

2. **上报方式**：调用"码上放心"REST API（批量异步，每 N 分钟聚合一次推送，N 默认 5 分钟可配置）
3. **上报失败处理**：
   - 自动重试（5 次/5 分钟间隔）
   - 重试失败 → 进入待补报队列
   - 失败超过 24 小时 → 企业微信通知仓库主管 + 监管负责人
4. **手动补报**：支持历史数据补传（按时间段筛选未上报或失败记录批量补传）
5. **上报状态可查**：每条追溯码事件可查询上报状态（未上报/上报中/已上报/失败）
6. **降级**：平台不可用时，事件先持久化到本地待补报队列，不阻塞 WMS 业务
7. **幂等性**：同一事件重复触发不重复上报（用事件 ID 去重）
8. 上报记录写入审计追踪（含上报时间、平台返回码、平台流水号）

## 跨故事约束

1. **追溯码表独立**：不嵌入商品表/库存表，通过关联关系连接
2. **历史记录不可删除**：所有绑定/解绑/修正操作 append-only
3. **多货主隔离**：码库数据按货主隔离
4. **平台对接**：当前支持"码上放心"主动拉取（M-TC-002 入库码）+ 主动上报（M-TC-007 出入库事件）；未来可扩展其他追溯平台
5. **幂等性**：码库导入/绑定/状态变更/平台上报支持 Idempotency-Key，重复操作不重复执行
6. **业务边界**："码上放心"由 WMS 直接对接（追溯码扫码事件由 WMS 唯一产生，不绕 ERP）；其他药监监管接口由 ERP 负责，WMS 不重复
7. **库内移库联动**（v22 新增）：
   - **整托/整箱 LPN 移库**：扫 LPN 容器码代替逐件扫码，M-TC 码库批量更新该 LPN 内所有码的位置字段
   - **部分整件 / 零拣移库**：必须逐件扫电子监管码，M-TC 码库逐码更新位置字段
   - **不上报"码上放心"**：移库不是国家平台接收的状态变更类型（v21 M-TC-007 上报内容仅含追溯码 + 状态变更类型 + 时间戳）
   - 详见 [US-M3-006 库内移库](user-stories-m3-inventory-operation.md#us-m3-006)
