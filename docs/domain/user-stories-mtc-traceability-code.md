# 用户故事：M-TC 追溯码模块

> 模块：M-TC traceability-code
> 性质：独立业务模块，被 M2 入库（收货/验收）和 M4 出库（复核）依赖
> 波次：Wave 2（与 M1 基础档案同期）
> 依赖：M1 商品档案、H1 权限、H2 审计

---

## US-TC-001：追溯码分类管理

**作为** 系统管理员
**我要** 配置追溯码的分类体系（码上放心码、GS1 码、其他码）
**以便** 系统能识别不同类型的追溯码并按规则解析

### 验收标准

1. 追溯码分类：码上放心码、GS1 码、其他（可扩展）
2. 每种分类配置：名称、编码规则（正则/长度）、解析规则、对接平台
3. 支持新增自定义分类
4. 分类变更写入审计追踪

---

## US-TC-002：码库管理（大中小码）

**作为** 系统（自动）/ 仓库主管
**我要** 从追溯码平台拉取入库订单的码（大码），解析为大/中/小码并存入码库
**以便** 出库复核/包装站/PDA 扫码时能核验数量、批号、效期

### 验收标准

1. **主动拉取**：系统调用追溯码平台 API，按入库订单拉取关联的追溯码
2. 拉取的码可能是大码（件码），系统按商品包装转换比解析为：
   - 大码（件码）
   - 中码（盒码）
   - 小码（支码）
3. 码库表字段：追溯码值、码类型（大/中/小）、分类（码上放心/GS1/其他）、关联商品、批号、效期、状态（未用/已入库/已出库/已核销）
4. 码库支持手工导入（Excel / API）
5. 码库支持按商品/批号/状态查询
6. 码库数据变更写入审计追踪

---

## US-TC-003：追溯码与商品绑定

**作为** 收货员 / 保管员
**我要** 在 PDA 上扫追溯码，将码与商品建立绑定关系
**以便** 后续出库扫码时能自动识别商品身份

### 验收标准

1. **从收货/验收模块进入**：默认关联当前 ASN 的商品（ASN 是单品）
2. **独立进入**：通过"码上放心"接口获取码信息 → 筛选商品字典 → 选择绑定
3. 绑定列表显示"是否已绑定过"标记
4. 已有绑定可解除（需权限）
5. 绑定错误时可修正（维护有历史记录，每次变更记录旧值/新值/操作人/时间）
6. 绑定关系存储：追溯码 → 商品 + 批号 + 效期
7. 追溯码可绑定到：托盘 / 盲标签 / ASN 订单（多维度绑定）
8. **追溯码单独一张表**（不嵌入商品表或库存表）
9. 所有绑定/解绑/修正操作写入审计追踪

---

## US-TC-004：PDA 追溯码对应关系维护

**作为** 收货员 / 保管员
**我要** 在 PDA 上维护追溯码与商品的对应关系（新增/修正/解绑）
**以便** 码信息有误或缺失时能现场修正

### 验收标准

1. PDA 扫追溯码 → 显示当前绑定信息（商品/批号/效期）
2. 如果未绑定 → 引导绑定流程（选择商品 → 确认）
3. 如果绑定错误 → 修正流程（解绑旧的 → 绑定新的）
4. 所有维护操作有历史记录（谁/什么时间/改了什么），写入审计追踪
5. 维护权限可配置（默认收货员和保管员可操作）

---

## US-TC-005：追溯码录入环节配置

**作为** 系统管理员
**我要** 配置追溯码的录入环节（放在收货环节 或 验收环节）
**以便** 不同仓库可按实际流程选择最合适的录入时机

### 验收标准

1. 系统参数：追溯码录入环节 = 收货 / 验收（二选一）
2. 配置为"收货"：收货员在收货环节扫码录入
3. 配置为"验收"：收货员在验收环节扫码录入
4. 切换配置不影响历史数据
5. 配置变更写入审计追踪

---

## US-TC-006：出库追溯码核验

**作为** 保管员（复核岗）
**我要** 在出库复核/包装站扫追溯码，系统自动核验数量、批号、效期
**以便** 确保出库商品与订单一致，满足追溯要求

### 验收标准

1. 复核时扫追溯码 → 系统从码库查询：商品/批号/效期/数量
2. 自动比对订单明细：品种对不对、批号对不对、数量够不够
3. 不匹配时报警（扫错品/扫错批）
4. 扫码完成后追溯码状态变为"已出库"
5. 出库后码状态不可回退（除非退货入库）
6. 支持大码扫码（自动展开为中/小码数量）
7. 追溯码状态变更写入审计追踪

---

## 跨故事约束

1. **追溯码表独立**：不嵌入商品表/库存表，通过关联关系连接
2. **历史记录不可删除**：所有绑定/解绑/修正操作 append-only
3. **多货主隔离**：码库数据按货主隔离
4. **平台对接**：当前仅支持主动拉取（调 API），未来可扩展为平台推送
