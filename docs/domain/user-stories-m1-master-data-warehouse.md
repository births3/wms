## US-M1-004：仓库与库位管理

**作为** 系统管理员
**我要** 配置仓库（物理仓/逻辑仓/虚拟仓）和库位（排-列-层）
**以便** 系统能按温区、色标、货主分配库位

### 验收标准

1. 仓库层级：物理仓 → 库区 → 库位
2. 库区属性：温区（冷藏/冷冻/阴凉/常温）、色标（合格绿/隔离黄/不合格红）
3. **库位编码规则**：区域编码（3 位）+ 排（2 位）+ 列（2 位）+ 层（2 位），如 `A01-01-02-03` = A01 区第 01 排第 02 列第 03 层
4. 库位属性：编码（唯一）、排、列、层、**最大容积（cm³）**、当前已用容积、剩余容积（自动计算）、**最大 SKU 数**（可配置：设为 1 = 单 SKU 库位，设为 N = 多 SKU 库位）、**库位类型**（存储位/箱拣位/零拣位）、所属库区
5. 支持多货主场景：库位可绑定货主或共享
6. **库位类型说明**：
   - 存储位：大批量整件存放（通常最大 SKU 数 = 1）
   - 箱拣位：按箱拣选的库位（可多 SKU）
   - 零拣位：拆零拣选的库位（可多 SKU，补货来源为存储位）
7. 库位状态：可用/占用/锁定/停用
8. **批量创建库位**：指定区域编码 + 排范围 + 列范围 + 层范围，系统自动生成所有组合（如区域 A01，排 01-10，列 01-05，层 01-03 → 生成 150 个库位）；批量创建时可统一设置库位类型、最大容积、最大 SKU 数
9. 仓库/库位变更写入审计追踪
10. **系统字典边界**：库区和库位仍是主数据实体，由 M1 库区管理 / 库位管理维护；系统字典只维护库区 / 库位属性枚举，包括 `temperature_zone`（库区温区）、`quality_color`（库区色标）、`zone_type`（库区类型）和 `location_type`（库位类型）。

## US-M1-004a：容器（LPN）管理

**作为** 保管员 / 系统管理员
**我要** 统一管理所有物理容器（托盘/周转箱/出库箱/保温箱/盲标签），每个容器一个唯一 ID（LPN）全程跟踪
**以便** 任何操作（上架/移库/拣选/出库/回收）都可以"扫一个码操作整个容器"

### 验收标准

1. **容器统一为 LPN 概念**：每个物理容器一个唯一编号（LPN 码），全程跟踪位置和内容物
2. 容器类型（可扩展）：
   - 托盘（可循环，标准/非标）
   - 周转箱（可循环，仓内流转不出库）
   - 出库箱（一次性，随货发出）
   - 保温箱（可循环，冷链配送用）
   - 盲标签（一次性，顺序递增编号，轻量标识）
3. 容器属性：LPN 码（唯一）、类型、容量（体积 cm³）、状态、当前库位、所属货主
4. 容器状态：空闲 → 在用 → 在途 → 回收中（可循环类型）/ 已出库（一次性类型）
5. **内容物管理**：容器关联商品+批号+数量（一个容器可装多种商品）
6. **嵌套关系**：托盘可包含多个周转箱/出库箱；周转箱可包含商品
7. **PDA 操作**：扫 LPN 码 = 操作整个容器（含所有内容物）
   - 整托上架/移库/出库
   - 整箱拣选/出库
8. 整容器操作时，容器内所有商品的库位同步变更
9. **LPN 码生成**：由编码生成模块统一生成（盲标签为顺序递增）
10. 容器标签支持打印（含 LPN 码条码/二维码 + 内容物摘要）
11. **回收追踪**（可循环类型）：出库后跟踪回收状态
12. 容器全生命周期写入审计追踪（创建/装箱/拆箱/移动/出库/回收）

## US-M1-004b：容器质量锁管理

**作为** 保管员 / 质量管理员
**我要** 对容器施加三类质量锁（隔离/不合格）并维护原因、双人见证、挂接质量联系单
**以便** 待查/不合格容器被强制阻断拣选与出库，保障 GSP 质量管控闭环

### 验收标准

1. **三类质量锁**：`qualified`（默认无锁）/ `quarantine`（隔离）/ `rejected`（不合格）
2. **锁原因复用 M1 系统字典**：隔离原因字典 `container_quarantine_reason`、不合格原因字典 `container_rejected_reason`，管理端【系统字典】维护，锁事件关联 `system_dictionary_items.item_code`
3. **仅人工加锁**：管理端容器页 / PDA 扫码操作加锁、换原因、解锁；无 `m1.quality-lock.manage` 权限拒绝操作
4. **双人见证**：加锁与解锁必须填写见证人 `witness_id`，且见证人与操作人必须为不同用户，缺见证人或见证人重复事务拒绝
5. **挂接 M-QL 质量联系单**：`rejected` 必填、`quarantine` 选填关联 `quality_liaison_orders`；**解锁前置条件：关联单已办结（`closed`）**
6. **作业阻断**：
   - `quarantine`：禁止拣选与出库，仅允许移库/上架至隔离库区（`zone.quality_color = quarantine_yellow`）
   - `rejected`：绝对禁止正常流转，仅允许移入不合格品库区（`unqualified_red`）
7. **批次状态联动**：加锁/换原因/解锁时容器下所有 `inventory_batches.status` 同步 `quarantined`/`unqualified`/`qualified` 并写入库存流水
8. **审计留痕**：加锁/换原因/解锁事件写入 `container_quality_lock_events`（纯 INSERT 审计表），全生命周期可追溯
9. **当前锁状态**：容器主档 `lpn_containers.current_lock_category` 实时反映当前锁，列表可筛选
10. **加锁前置状态**：仅 `in_use` 且挂载库存行的容器可加锁；`idle`/`in_transit`/`recycling`/`shipped` 禁止
11. **解锁回写防覆盖**：解锁只回写仍处于本锁联动状态的批次行；锁期间被质检/召回等其他流程变更过的行不回写，解锁完成后提示人工复核

## US-M1-005：客商开票信息

**作为** 仓库主管 / 财务专员
**我要** 维护客户和供应商的完整开票信息（抬头、统一社会信用代码、税号、银行信息、税率）
**以便** 出库打印随货同行单、3PL 计费账单和码上放心上报时使用合规的财税信息

### 验收标准

1. **基础开票信息字段**（必填）：
   - 发票抬头（VARCHAR(128)，非空）
   - 纳税人识别号 / 统一社会信用代码 USCC（VARCHAR(18)，正则 `^[0-9A-HJ-NPQRTUWXY]{2}\d{6}[0-9A-HJ-NPQRTUWXY]{10}$`）
   - 开户行（VARCHAR(128)）
   - 银行账号（VARCHAR(64)，加密存储 encryption=encrypted）
   - 注册地址（VARCHAR(256)）
   - 注册电话（VARCHAR(32)）
2. **税务字段**（条件必填，按业务类型）：
   - 默认增值税率（NUMERIC(5,4)，如 0.13 / 0.09 / 0.06 / 0.03 / 0.0；按 GB 商品分类自动建议默认值，可覆盖）
   - 发票类型（枚举：增值税专用发票 / 增值税普通发票 / 电子专用发票 / 电子普通发票）
   - 是否含税（boolean）：true → 单价含税；false → 单价不含税
3. **多套开票信息**：一个客商可绑定多套开票信息（如普票 + 专票）；每套有唯一标识 + 启用/停用标志 + 默认套标识（结算时取默认套）
4. **USCC 关联到 v3.1 P0 字段**：
   - 客户开票信息 → 出库时 `delivery_org_name` + `delivery_org_uscc` + `receiver_org_name` + `receiver_org_uscc` 自动取值
   - 供应商开票信息 → 入库时 `shipper_org_name` + `shipper_org_uscc` 自动取值
   - 这些字段在码上放心上报（M-TC US-TC-007）和随货同行单打印（M4-005）中作为合规字段使用
5. **校验规则**：
   - USCC 18 位字符强校验（正则）；新增/修改时校验通过才能保存
   - 同客商多套开票信息中默认套**有且仅有 1 个**（保存时强校验）
   - 银行账号脱敏显示（如 `6228 **** **** 1234`），完整账号仅财务专员角色可见
6. **金额字段计算口径**：
   - 含税金额 = 不含税金额 × (1 + 税率)
   - 含税单价 = 不含税单价 × (1 + 税率)
   - 应收金额、实收金额、核销金额（M9 计费 / 财务对账）按该客商默认开票信息的"是否含税"决定计算方式
7. **变更控制**：
   - 开票信息修改触发 M-QL 联系单（类型=客商开票变更）→ 仓库主管 + 财务专员双签后生效
   - 修改前后值写入 H2 审计追踪（`approval_source=M-QL` + 联系单 ID）
   - 字段加密属性的变更（如银行账号）需额外的运维管理员审批
8. **开票信息有效期**：
   - 可选有效期字段（生效时间 / 失效时间）；过期前 30 天自动 H4 通知客商联系人续签
   - 过期开票信息不可用于新出库订单 / 新入库 ASN，但历史单据保留快照
9. **跨模块联动**：
   - M9 计费账单生成时取本表当前默认开票信息生成快照
   - M4-005 随货同行单打印时取**单据创建时的快照**（不取当前值，避免单据回溯打印时显示新数据）
   - M-TC US-TC-007 码上放心上报时取本表的 USCC + 名称字段
10. **数据保留**：开票信息归档策略 = 关联业务最后一笔交易日期 + 5 年（H2-006 §7）；不与客户档案一起删除（即客户停用后开票信息仍可查）

### 异常路径

- **USCC 校验失败**：提示具体错误（位数错 / 校验位错），不允许保存
- **历史单据涉及已停用的开票信息**：单据可查（含原快照），但不允许新建关联此开票信息的单据
- **税率与商品分类不匹配**：保存时给出 warning 提示（如医药品默认 13% 但用户选了 6%），仍允许保存（业务可能有特殊安排），写入审计
- **多套开票信息均停用**：客商不可参与新交易，提示"无可用开票信息"

## US-M1-006：用户与权限管理

**作为** 系统管理员
**我要** 创建用户账号、分配角色、配置角色的菜单和操作权限
**以便** 不同岗位的人只能看到和操作自己职责范围内的功能

### 验收标准

1. 用户必填：用户名（唯一）、姓名、手机号、所属角色（可多角色）
2. 角色是权限模板：每个角色有默认的菜单权限集
3. 管理员可对角色增减任意菜单/操作权限
4. 权限粒度：菜单可见性 + 按钮级操作权限（如"创建收货单"、"审批出库"）
5. 支持多货主隔离：用户可绑定货主，只能看到所属货主的数据
6. 用户停用后立即失效（token 失效）
7. 密码策略：最小长度、复杂度、过期周期（可配置）
8. 用户/角色/权限变更写入审计追踪

## US-M1-007：多货主架构

**作为** 系统管理员
**我要** 创建货主账户并配置数据隔离规则
**以便** 3PL 模式下各货主数据严格隔离，互不可见

### 验收标准

1. 货主必填：名称、编码（唯一）、联系方式、合同信息
2. 数据隔离：库存、单据、报表按货主过滤（非本货主数据不可见）
3. 库位可配置为"货主专属"或"共享"
4. 用户绑定货主后，所有查询自动加货主过滤条件
5. 系统管理员可跨货主查看（超级权限）
6. ~~货主间货主转换需审批流程（权属转移）~~（v23 移除：货主转换 GSP 不合规，必须由 ERP 销售/采购驱动 WMS 走标准 M2/M4 流程，详见 user-stories-m3-inventory-query.md US-M3-008 strikethrough 说明）
7. 货主变更写入审计追踪

## US-M1-008：系统配置中心

**作为** 系统管理员
**我要** 在统一的配置中心管理所有业务参数，支持分类浏览、搜索、配置向导、变更审计
**以便** 不同仓库可按实际业务调整系统行为，无需改代码

### 验收标准

1. **配置分类**（按业务域分组展示）：

| 分类 | 配置项数 | 示例 |

| 库存管理 | 6 | 近效期预警天数、盘点差异阈值、ABC 阈值、ABC 重算频率、库位最大 SKU 数、效期隔离 |
| 包装站 | 2 | 称重偏差阈值、保温箱蓄冷剂规则 |

| 对账 | 2 | 对账频率、差异锁定阈值 |
| 计费 | 2 | 仓储费计算方式、账单生成日 |
| 通知 | 2 | 事件通知映射、审批超时时间 |
| 监管 | 2 | 上报频率、重试次数 |
| 多仓/连锁 | 4 | 默认仓库、跨仓可见性、门店补货统计天数、越库条件 |
| 容器/物流 | 2 | 容器超期未回收预警天数、回收追踪开关 |
| **双人作业矩阵** (v25) | 1 | 双人作业矩阵：流程 × 节点 × 特殊药品分类 → 单人 / 双人扫码 / 双人+主管审批 |
| **月台预约** (v3.1) | 5 | dock_management_enabled（默认 false 关闭）/ dock_appointment_window_minutes（30）/ dock_overlap_allowed（false）/ dock_advance_hours（48）/ cold_chain_priority（true，冷链优先抢占月台）|
| **告警引擎** (v3.1) | 4 | alert_escalation_levels（3 级 / 1 级简化）/ alert_silence_default_minutes（5）/ alert_off_hours_window（22:00-06:00）/ alert_dlq_threshold_count（1000）|
| **数据归档** (v3.1) | 5 | inline_retention_months（12）/ archive_job_cron（每月 1 日）/ recovery_window_hours（24）/ retention_普通业务（5 年）/ retention_特殊药品台账（30 年）|

2. **所有配置项必须有默认值**（开箱即用，无需配置即可运行）
3. **配置向导**：首次部署时引导用户确认关键配置（分步骤，可跳过用默认值）
4. **分级展示**：常用配置直接显示，高级配置折叠（点击展开）
5. **搜索**：支持按关键词搜索配置项
6. **配置作用域**：全局配置 / 仓库级配置 / 货主级配置（优先级：货主 > 仓库 > 全局）
7. **配置预览**：修改策略类配置前可模拟预览影响（如改上架策略后模拟推荐结果）
8. **GSP 参数保护**：GSP 合规相关参数变更需仓库主管审批
9. **配置导入导出**：支持 JSON 导入导出（用于跨仓复制配置）
10. 所有配置变更写入审计追踪（旧值/新值/操作人/时间/原因）
11. **双人作业矩阵 UI**（v25 重设计）：以"流程 Tab + 每个流程下的'分类（行）× 节点（列）'矩阵"形式提供可视化编辑界面，三档枚举（单人 / 双人扫码 / 双人+主管审批）：
    - **流程 Tab**（顶层切换，6 个预置流程，可扩展）：采购入库 / 销售出库 / 报损 / 报溢 / 销毁 / 退货
    - **每流程下的列**（节点）来源于 M-VR US-VR-006 流程-节点定义表：
      - 入库 Tab：收货 / 验收 / 上架（3 列）
      - 出库 Tab：拣货 / 复核 / 装箱 / 发货交接（4 列）
      - 报损 Tab：报损执行（1 列）
      - 报溢 Tab：报溢执行（1 列）
      - 销毁 Tab：销毁执行（1 列）
      - 退货 Tab：退货验收 / 退货上架（2 列）
    - **每流程下的行**（分类）来源于 M1-010 字典启用的所有分类（含"普通药品"），与 M-VR US-VR-006 §2 一致
    - **默认值**：行行从 M1-010 字典 `requires_dual_person_matrix` 取默认值（普通药品默认入库.验收 + 出库.复核 双人扫码；麻精毒放/放射性默认全部节点 dual_scan_with_approval）
    - **保存即同步**：矩阵任一格变更立刻同步生成 / 更新 M-VR 双人策略规则（适用场景="双人策略"，详见 US-VR-006 §8）
    - **流程层级覆盖**：支持按货主 / 仓库级覆盖（优先级：货主 > 仓库 > 全局）
    - **GSP 参数保护**：矩阵任一格变更须仓库主管审批（与现有跨故事约束一致）
    - **导出 JSON 跨仓复制**：可整套流程矩阵导出/导入；导入预览阶段标识与现有差异
    - **可扩展**：M1-010 新增分类 → 矩阵自动增行；新增流程或节点（设计层 ADR 决策）→ M-VR US-VR-006 流程-节点定义表更新 → 矩阵自动增 Tab / 增列

## US-M1-009：多仓管理

**作为** 系统管理员
**我要** 配置多个仓库，用户登录后选择/切换当前操作仓库
**以便** 一套系统管理多个物理仓库，数据按仓库隔离

### 验收标准

1. **仓库定义**：编号、名称、地址、类型（常温仓/冷库/阴凉库）、状态（启用/停用）
2. **仓库切换**：用户登录后选择当前仓库，所有操作在当前仓库上下文内
3. **数据隔离**：库存/库位/任务/订单按仓库隔离
4. **跨仓可见**：仓库主管可查看所有仓库的汇总数据（权限控制）
5. ~~**库间调拨**：M3 US-M3-007 已覆盖（调拨 = 源仓出库 + 目标仓入库）~~（v23 移除：跨仓调拨 GSP 不合规，由 ERP 销售/采购驱动 WMS 走标准 M2/M4 流程，详见 user-stories-m3-inventory-query.md US-M3-007 strikethrough 说明）
6. **用户权限**：用户可绑定多个仓库（有权操作哪些仓库）
7. 仓库配置变更写入审计追踪

## US-M1-010：特殊药品分类字典管理

**作为** 系统管理员
**我要** 维护"特殊管理药品分类"字典，每个分类可定义合规属性（双人作业要求 / 专用台账 / 经营资质要求）
**以便** 商品档案的 special_drug_category 字段有可扩展的字典来源，且每类的合规策略可在系统中差异化配置

### 验收标准

1. **预置分类**（系统初始化时载入，可停用不可物理删除）：

| 编码 | 名称 | 法规依据 | 合规属性默认值（v25 矩阵）|
|------|------|---------|--------------|
| `none` | 普通药品 | — | 入库.验收 / 出库.复核 = dual_scan；其他节点 single；不需专用台账 |
| `narcotic` | 麻醉药品 | 《麻醉药品和精神药品管理条例》| 全流程全节点 dual_scan_with_approval；专用台账；专柜专库 |
| `psychotropic_1` | 第一类精神药品 | 同上 | 全流程全节点 dual_scan_with_approval；专用台账；专柜专库 |
| `psychotropic_2` | 第二类精神药品 | 同上 | 全流程全节点 dual_scan；专用台账 |
| `toxic_medical` | 医疗用毒性药品 | 《医疗用毒性药品管理办法》| 入库.验收 + 出库.复核 + 报损.报损执行 + 销毁.销毁执行 = dual_scan_with_approval；其他节点 dual_scan；专用台账 |
| `radioactive` | 放射性药品 | 《放射性药品管理办法》| 全流程全节点 dual_scan_with_approval；专用台账；专柜专库 |
| `vaccine` | 疫苗 | 《疫苗管理法》| 入库.收货 + 入库.验收 + 出库.复核 + 报损.报损执行 = dual_scan；冷链强制；专用台账 |
| `blood_product` | 血液制品 | 《血液制品管理条例》| 全流程关键节点 dual_scan；专用台账 |

2. **可扩展自定义分类**：系统管理员可新增分类（编码 / 名称 / 法规依据 / 默认合规属性）
3. **分类字段**：
   - 编码 special_drug_category（唯一，与 M-PM 字典 `special_drug_category` 的目标枚举严格一致）
   - 中文名称
   - 法规依据（自由文本，引用法规条款）
   - 合规属性默认值：
     - `requires_dual_person_matrix`（v25 重命名，原 `requires_dual_person_steps` / `requires_approval_steps` 合并）：双人作业矩阵默认值，结构 `[{process, node, policy}]`，policy 取值 single / dual_scan / dual_scan_with_approval；process / node 取值见 M-VR US-VR-006 流程-节点定义表
     - `requires_dedicated_ledger`：是否需要专用台账（布尔，关联 M6-004）
     - `requires_dedicated_storage`：是否需要专柜专库（布尔，关联 M1-004 库区类型）
     - `requires_qualification`：经营资质码清单（如"麻精药品经营许可证"，由 ERP 校验，WMS 仅展示）
4. **分类停用**：分类停用后，已使用该分类的商品保持原值；无法分配给新商品
5. **合规属性可被矩阵覆盖**：本字典定义的是"默认值"；M1-008 双人作业矩阵可对每个仓库 / 货主级覆盖（v25 决策：矩阵 UI + M-VR 落库，二维 process×node）
6. **字典变更双人审批**：分类字段或合规属性默认值变更须仓库主管 + 质量负责人双人签字，企业微信审批通过后生效（避免误改导致合规风险）
7. **联动 M-PM**：M-PM 字典 `special_drug_category` 的目标枚举来源于本字典，本字典启用 / 停用 / 编辑后同步刷新 M-PM 字典
8. **联动 M-VR**：本字典任一分类的 `requires_dual_person_matrix` 默认值变更后，**自动重生成**对应的 M-VR 双人策略规则模板（仓库主管在 M1-008 矩阵 UI 二次确认后生效）
9. **GSP 法规依据可回查**：每个分类的法规依据字段在合规追溯矩阵 docs/compliance/gsp-special-drugs.md 引用
10. 分类查询 / 创建 / 修改 / 停用 / 启用写入审计追踪
11. 分类操作支持 Idempotency-Key

## US-M1-011：系统字典中心

**作为** 系统管理员 / 货主
**我要** 在系统字典中心维护 WMS 标准字典分类、字典项和字典项参数
**以便** 入库、出库、库内、主数据和外部映射都使用同一套受控标准值

### 验收标准

1. **字典分类由系统预置 / 开发发布**：运营页面不能新增字典分类，只能维护已有分类下的字典项；新增分类必须同步用户故事、RTM、OpenAPI、后端校验、前端入口和治理脚本。
2. **字典分类字段**：`dict_code`、中文名称、启用状态、受控级别（普通 / 受控 / GSP 关键）、`param_schema JSONB`、`scope_mode`、`override_policy`、排序号、备注。
3. **字典项字段**：`item_code`、中文名称、启用状态、`owner_id`、`params JSONB`、`effective_from`、`effective_to`、来源（global / owner）、停用原因；`owner_id = NULL` 表示全局项。
4. **作用域模式**：
   - `global_only`：只能全局维护，所有货主共用。
   - `owner_extensible`：全局预置，货主可新增自有字典项。
   - `owner_override`：全局默认，货主可覆盖名称、启停和 `override_policy` 允许的参数。
5. **优先级**：查询业务有效字典项时，货主配置优先于全局配置；后端返回合并后的有效结果，并可返回来源 `global` / `owner`。
6. **参数 schema 校验**：字典项保存时按 `param_schema JSONB` 校验 `params JSONB`，失败时拒绝保存并返回字段级错误；业务运行时读到无效参数必须 fail closed。
7. **覆盖规则**：货主配置只能覆盖字典分类 `override_policy` 声明允许覆盖的字段；`direction`、`workflow_template`、`batch_policy` 等流程关键参数默认不可覆盖，除非故事和治理脚本显式放开。
8. **版本与生效时间**：字典项支持 `effective_from` / `effective_to`；历史业务单据按业务发生时间解释当时生效的字典版本。
9. **变更审批**：普通字典直接生效；受控 / GSP 关键字典通过 M-QL 质量联系单审批后按生效时间启用，审批源记录字典分类、字典项和变更版本。
10. **影响预览**：受控字典提交审批前必须展示受影响业务模块、字典项、货主和历史引用数量；普通字典不强制影响预览。
11. **权限**：系统管理员维护全局字典；货主维护本货主覆盖项；受控字典由仓库主管 + 质量负责人审批后生效。
12. **审计与删除**：字典分类、字典项、导入导出、审批、启用、停用全部写入 H2 审计；字典项不物理删除，已被业务单据引用的停用项继续可查。
13. **导入导出**：系统字典支持 Excel 作为业务用户正式格式，CSV 作为脚本、治理和批量初始化格式；导入前必须预览差异和校验错误。
14. **缓存刷新**：字典变更生效后通过 H2-005 事件总线广播，业务模块刷新缓存；业务模块不得长期使用过期字典快照。
15. **M-PM 边界**：系统字典定义 WMS 标准值；M-PM 参数对照只把 ERP / 上游系统不规则源文本映射到系统字典项编码，不维护标准值本身。
16. **首批单据类型字典**：`dict_code = document_type`，`scope_mode = owner_override`，首批预置 `purchase_inbound`（采购入库）、`sales_return`（销售退货入库）、`purchase_return_outbound`（采购退货出库）、`sales_outbound`（销售出库）。
17. **单据类型参数**：`document_type` 字典项必须绑定 `direction`、`workflow_template`、`batch_policy`；三者只能选择系统预置模板或策略，运营不能通过新增字典项创建新流程。
18. **单据类型接入规则**：M2 入库和 M4 出库创建业务单据时必须校验 `document_type` 存在、启用、在生效期内、作用域匹配、参数有效；不满足时拒绝创建。
19. **首批库区 / 库位属性字典**：系统预置 `temperature_zone`（库区温区：`normal` / `cool` / `cold` / `frozen`）、`quality_color`（库区色标：`qualified_green` / `quarantine_yellow` / `unqualified_red`）、`zone_type`（库区类型：`storage` / `receiving` / `return` / `unqualified` / `shipping`）和 `location_type`（库位类型：`storage` / `case_pick` / `piece_pick`）。
20. **库区实体边界**：`zone_type` 是库区类型字典，不代替库区实体表；库区编码、名称、仓库归属、容量和库位集合仍在 M1 库区管理中维护。

## 跨故事约束（适用于所有 M1 用户故事）

1. **审计追踪**：所有创建/修改/删除/停用操作必须写入审计表（旧值、新值、操作人、时间）
2. **多货主**：所有数据查询默认按当前用户所属货主过滤（除系统管理员）
3. **软删除**：不物理删除数据，只标记停用/禁用
4. **双人作业可配置**：双人要求由"双人作业矩阵"（M1-008 配置类目"双人作业矩阵"）按"特殊药品分类 × 流程 × 节点"定义；普通药品默认仅入库.验收和出库.复核两个节点双人，特殊药品按 M1-010 字典预置默认值。所有双人节点强校验两个 user_id 不同，且角色满足该节点的岗位要求。详见 M-VR US-VR-006
5. **权限可配置**：上述"作为 XX 角色"仅表示默认权限归属，实际由管理员配置决定
6. **系统字典与参数对照边界**：M1-011 是 WMS 标准字典事实源；M-PM 只做外部源文本到标准字典项编码的映射，不新增、覆盖或删除标准字典项。

7. **幂等性**：所有写操作（创建/修改/删除/停用）支持 Idempotency-Key，重复提交返回相同结果

## 附录 A：储存条件温度区间表

> 业务背景：药品包装上的储存条件文字写法不规范（如"常温保存""阴凉处保存""2-8℃避光保存"）。
> 商品档案录入时必须强制映射到下表 4 个标准枚举之一，由 M-VR 校验规则模块基于温度区间判定温度超标。

| 枚举值 | 温度区间 | 湿度区间 | 适用商品类型（举例） |
|--------|---------|---------|--------------------|
| 冷冻 | ≤ -18℃ | 不限 | 部分生物制品、疫苗 |
| 冷藏 | 2℃ ~ 8℃ | 35% ~ 75% | 生物制品、疫苗、胰岛素 |
| 阴凉 | ≤ 20℃ | 35% ~ 75% | 部分中药材、易受热分解药品 |
| 常温 | 10℃ ~ 30℃ | 35% ~ 75% | 大多数普通药品 |

### 使用约定

1. **录入约束**：商品档案的"储存条件"字段是结构化枚举，不接受自由文本（M1-001 验收标准 5）
2. **温度判定**：温度数据由外部冷链系统采集后通过 M5-002 推送到 WMS；M-VR 规则可比对**温度超标事件**与商品所在库区/运输工具的允许温度区间用于业务关联（v7 边界：WMS 不直接采集温度，原 M5-001 已移除）
3. **库区匹配**：M1-004 库区"温区"属性使用同一枚举集，上架时温区不匹配拒绝（M2-005）
4. **冷链定义**：储存条件为"冷藏"或"冷冻"的商品在本系统统一称为"冷链商品"，涉及冷链业务规则
5. **可扩展**：未来如需新增枚举（如"阴凉冷藏"），由系统管理员在配置中心维护，本表同步更新
6. **ERP 推送的不规则文本规整化**：ERP / 上游系统推送的储存条件常为不规则自由文本（如"2-8℃避光保存""阴凉处保存""室温"），由 **M-PM 参数对照模块**（user-stories-mpm-parameter-mapping.md）通过字典 `storage_condition` 自动规整化到本表 4 个标准枚举；未命中规则的源文本进入 M-PM 待映射队列并触发 M-QL"参数对照待映射"类型联系单（PM-003）

### 例外处理

- 商品包装写"室温保存" → M-PM 规则映射为"常温"
- 商品包装写"低温保存" → 需供应商澄清具体区间，规则不预置默认映射；进入 M-PM 待映射队列，由仓库主管处置后映射为"冷藏"或"冷冻"
- 包装无明确储存条件 / M-PM 全部规则未命中 → 商品状态进入"待映射"（M-PM 跨约束 §6），不可用于新 ASN 直至仓库主管完成映射
