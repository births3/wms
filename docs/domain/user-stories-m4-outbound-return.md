## ~~US-M4-008：销售退货入库处理（历史编号，归口 M2）~~

> 归口说明：按 C8，销售退货 / 客户退货是货回仓，生产菜单和 PC Web 入口归 M2 入库；M4 出库页面不承载本故事。保留 US-M4-008 编号用于历史追溯，后续实现不得按 M4 出库流程落地。

**作为** 保管员 / 仓库主管
**我要** 通过完整的退货流程（申请→审批→提货→收货验收→上架）处理客户退货
**以便** 退货有完整记录和审批控制，退回商品按质量状态正确归位

### 验收标准

1. **退货申请**（保管员发起）：
   - 必填：原出库订单号、客户、退货商品明细（商品+批号+数量+退货原因）
   - 退货原因：质量问题/发错货/客户拒收/近效期/其他
   - 申请后状态为"待审批"
2. **审批**（仓库主管/质量负责人）：
   - 审核退货原因是否符合配置的退货原因清单
   - 审批通过 → "已审批"；拒绝 → "已拒绝"（流程结束）
   - 审批通过企业微信审批流
3. **提货**（司机/快递）：
   - 审批通过后安排提货（或客户自行送回）
   - 提货中可记录：提货时间、提货人、运输方式
   - 冷链商品需记录运输温度
4. **收货验收**（收货员）：
   - 到货后 PDA 扫码确认到货
   - **退货批号策略**（v3.1 新增，C7）：
     - 退货批号由 ERP 在退货申请/退货 ASN 中指定（ERP 取原销售出库订单的批号，原单退货）
     - WMS 收货验收时**校验 ERP 指定批号是否存在于 WMS 已有批号表**（即该批号曾经入库过）
     - 校验通过 → 使用该批号上架，保留原效期、原生产日期、原生产厂家
     - **校验失败（批号不存在）→ 异常处理**：标记为"退货批号异常"，进入隔离区 + 自动创建质量联系单（M-QL 类型=退货批号异常）→ 仓库主管 + 质量负责人审批决定处置（人工核实后修正批号 / 按新批号入库 / 拒收退回）
   - 验收内容：外观/包装/效期/追溯码核验/温度（冷链）
   - 验收结论决定库存状态：
     - 合格 → 合格品区（回到可用库存）
     - 不合格 → 不合格品区（走报损流程）
     - 需复验 → 隔离区（走质量联系单）
   - **双人策略动态查询**（v25 新增）：验收前调 M-VR 双人策略接口（US-VR-006）按 process=入库 + node=验收 查询；返回 dual_scan / dual_scan_with_approval 时需双人扫码或主管审批通过方可提交；普通药品默认 single；麻精毒放/放射性按 M1-010 字典默认值 dual_scan_with_approval
5. **上架**：验收合格的商品通过任务引擎生成"退货上架"任务
   - **双人策略动态查询**（v25 新增）：上架前调 M-VR 双人策略接口（US-VR-006）按 process=入库 + node=上架 查询；三档行为同上；麻精毒放/放射性按 M1-010 字典默认值
6. **整单拒收**：验收发现与申请不符（数量/品种/状态严重不符）→ 拒收退回客户
7. 退货全流程写入审计追踪（含双人策略命中规则 ID + 第一/第二操作人 user_id）
8. 退货统计可按客户/商品/原因/时间汇总

## US-M4-009：波次出库箱规则

**作为** 仓库主管
**我要** 配置波次生成出库箱的规则（按订单/按客户/按温区/按体积拆箱 + 尺寸推荐）
**以便** 系统在波次下发时自动规划出库箱数量、分配商品到箱、推荐箱型尺寸

### 验收标准

1. **出库箱规则**（可配置）：
   - 按订单：一个订单一个出库箱（默认）
   - 按客户合箱：同客户多个订单合入一个出库箱
   - 按温区拆箱：冷链和常温必须分箱
   - 按体积拆箱：单箱超过最大体积/重量时自动拆为多箱
   - 按品类拆箱：特殊品类（如精麻药）必须独立装箱
2. **箱型主数据**（可配置，每个仓库独立维护）：

| 箱型代码 | 名称 | 内尺寸（长×宽×高 mm）| 内容积上限（cm³）| 重量上限（kg）| 适用 |
|---------|------|-------------------|---------------|-----------|------|
| BOX-S | 小箱 | 200×150×100 | 3,000 | 5 | 零件少量 |
| BOX-M | 中箱 | 350×250×200 | 17,500 | 15 | 一般订单 |
| BOX-L | 大箱 | 500×350×300 | 52,500 | 25 | 多品订单 |
| BOX-XL | 特大箱 | 600×400×400 | 96,000 | 30 | 大件商品 |
| BOX-INSULATED-M | 中保温箱 | 300×200×200 | 12,000 | 12 | 冷链 2-8℃ |
| BOX-INSULATED-L | 大保温箱 | 450×300×300 | 40,500 | 20 | 冷链 2-8℃ |

   - 箱型可启用/停用；可新增自定义箱型（管理员维护）
   - 重量包含**包装材料净重**（保温箱含蓄冷剂占用）

3. **尺寸推荐算法**（波次生成时执行）：

```
输入：本订单/合箱组的商品列表（含每件商品 长×宽×高 + 重量，从 M1-001 取）

步骤 1: 计算总体积 = Σ(商品体积 × 数量) × 1.2（1.2 为装填损耗系数，可配置）
步骤 2: 计算总重量 = Σ(商品重量 × 数量) + 包材重量
步骤 3: 判断温区：含冷链商品 → 仅在保温箱箱型中选；否则在普通箱型中选
步骤 4: 在符合温区的启用箱型中，按内容积升序排序
步骤 5: 选择最小的能容纳（内容积 ≥ 总体积 AND 重量上限 ≥ 总重量）的箱型
步骤 6: 若无单个箱型可容纳 → 触发拆箱：
        按"按体积拆箱"规则拆为 N 个子包裹，每个子包裹独立推荐箱型
```

4. **算法可配置参数**：
   - 装填损耗系数（默认 1.2，反映商品形状非完美贴合）
   - 包材重量（默认 200g/箱，可按箱型独立配置）
   - 拆箱时是否优先"装满大箱"还是"分散到多个中箱"（默认装满大箱）

5. 波次下发时自动执行算法 → 输出每订单/子包裹的：
   - 推荐箱型代码
   - 预估总体积 / 总重量
   - 推荐数量（拆箱时 > 1）
6. 出库箱关联容器（LPN），装箱时生成 LPN 码（M-PK-002）
7. **保管员可调整**：装箱时（M-PK-002）若推荐箱型不可用（缺货/形状特殊），可手动选择其他箱型，差异需选调整原因，写入审计
8. 规则可按货主/客户类型绑定不同方案
9. 规则/箱型变更写入审计追踪

## US-M4-010：拣选路径策略

**作为** 仓库主管
**我要** 配置拣选路径的行走顺序策略
**以便** 保管员按最优路径拣选，减少行走距离

### 验收标准

1. **路径策略**（可配置，按仓库/库区绑定）：
   - 库位编号顺序（按编号升序/降序）
   - S 型遍历（蛇形走法，奇数通道正向、偶数通道反向）
   - 最短路径（系统计算最短行走距离）
   - 分区汇合（按库区分段拣选，最后汇合到包装站）
2. **路径顺序可配置**：管理员可在界面选择策略类型
3. 波次下发后，拣选任务按路径策略排序后下发给保管员
4. PDA 显示拣选顺序（按路径排好的库位列表）
5. 支持"跳过"（当前库位无货时跳到下一个）
6. 路径策略变更写入审计追踪

## US-M4-011：合并发货与拆单

**作为** 仓库主管 / 系统（自动）
**我要** 将多个小订单合并发货，或将大订单拆分为多个包裹
**以便** 降低运输成本（合并）/ 满足包裹限重限体积（拆单）

### 验收标准

1. **合并发货**：
   - 合并条件（可配置）：同客户 + 同地址 + 同温区 + 同时间窗
   - 合并后生成一个发货批次，共享一个快递单号
   - 合并不改变原订单（原订单各自独立可查）
   - 合并规则可按货主/客户类型配置
2. **拆单**：
   - 拆单条件（可配置）：超过最大重量/最大体积/特殊品类必须独立
   - 拆单后每个子包裹独立快递单号
   - 子包裹关联原订单（可追溯）
3. **波次阶段执行**：合并/拆单在波次生成时自动计算
4. **手动干预**：仓库主管可手动合并/拆分
5. 合并/拆单记录写入审计追踪

## US-M4-012：采购退货出库

**作为** 仓库主管 / 保管员
**我要** 处理退供应商的采购退货出库申请、审批、拣货、复核和出库交接
**以便** 采购退货按出库链路扣减库存，并与销售退货入库链路分开管理

### 验收标准

1. **采购退货申请**：
   - 必填：采购退货单号、原采购入库单、供应商、退货原因、商品明细（商品 + 数量）
   - 原采购入库按 C8 批号口径不要求批号；采购退货出库不把批号作为申请、拣货或复核字段
   - 销售退货 / 客户退货不在本故事处理，按 C8 归入入库业务
   - 申请后状态为"待审批"
2. **审批**：
   - 仓库主管审批通过 → 状态变为"待拣货"
   - 审批拒绝 → 状态变为"已拒绝"，流程结束
3. **拣货**：
   - 按商品和数量生成采购退货拣货任务
   - 只允许从可出库库存拣货，实拣差异必须记录差异原因
4. **复核**：
   - 复核商品和数量与采购退货申请一致
   - 复核通过 → 状态变为"待交接"
5. **出库交接**：
   - 记录承运方、车牌号、交接人和交接时间
   - 交接确认后扣减库存，状态变为"已发货"
   - 审批源：采购退货审批（`approval_source=purchase_return_approval`）
6. 采购退货申请、审批、拣货、复核、出库交接和库存扣减写入审计追踪

## 跨故事约束（适用于所有 M4 用户故事）

1. **审计追踪**：所有出库操作（校验/拣选/复核/发货/退货/作废）写入审计表
2. **多货主**：订单绑定货主，数据按货主隔离；随货同行单用货主抬头
3. **出库批号由 ERP 指定**：WMS 只校验库存并决定从哪个库位拣（波次算法）
4. **库存锁定与扣减**：波次分配时锁定数量（状态不变，锁定部分不可再分配）；发货确认时正式扣减
5. **ERP 反馈**：发货完成后异步反馈 ERP"已出库"（商品/批号/数量/时间），失败可重试
6. **双人复核（动态化）** (v25)：拣选人 ≠ 复核人为最低保障，但是否需要双人扫码 / 双人+主管审批由 M-VR 双人策略矩阵（US-VR-006）按 process=出库 + node=拣货/复核/装箱/发货交接 动态决定（v25 流程-节点二维），矩阵 UI 在 M1-008 §11；普通药品矩阵默认仅 node=复核 双人扫码，特殊药品按 M1-010 字典预置默认值；采购退货出库复用出库节点，销售退货入库的验收 / 上架按 C8 归 M2 入库承接；显式调用见 M4-003 §10、M4-004 §6、M4-006 §9、M-PK-002 §4
7. **不回退**：拣选开始后不退回任何状态，有问题"先出后退"（事后走退货流程）
8. **整单出库**：不管拣到多少都整单走完流程（短拣标识差异 + 企业微信通知）
9. **没有部分发货**：一个订单必须整单发货
10. **复核无不通过**：复核只做确认，有问题事后退回处理
11. **业务边界**：经营范围/客户资质/信用额度等合规校验由 ERP 负责，WMS 不重复
12. **强制作废回退**：已入波次未拣选时可强制作废，保管员 PDA 回退上架
13. **PDA 离线**：拣选支持离线暂存；离线期间冲突由跨故事约束统一处理（暂存待主管处理）
14. **幂等性**：所有写操作支持 Idempotency-Key
15. **开放 API**：订单创建、订单状态查询支持外部系统调用
16. **打印模板**：随货同行单、快递单、交接单使用 H9 打印模板引擎
17. **企业微信通知**：短拣差异、校验异常、强制作废通知仓库主管

|------|------|

| L5 数据一致 | 箱规则与实际装箱结果一致; 规则变更后新波次立即使用 |
| L8 权限 | 仓库主管可配置; 保管员只读 |
| L11 幂等 | 配置变更支持 Idempotency-Key |

#### US-M4-010 拣选路径策略

| 维度 | 场景 |
|------|------|
| L4 错误路径 | 策略参数不合法 → M4_INVALID_STRATEGY; 库位坐标缺失 → M4_LOCATION_NO_COORDS（降级为默认顺序） |
| L5 数据一致 | 路径策略与实际拣选顺序一致; 策略变更后新任务立即使用 |
| L8 权限 | 仓库主管可配置; 保管员只读 |
| L11 幂等 | 配置变更支持 Idempotency-Key |

#### US-M4-011 合并发货与拆单

| 维度 | 场景 |
|------|------|
| L4 错误路径 | 合并订单客户不同 → M4_MERGE_CUSTOMER_MISMATCH; 拆单后子单数量合计 ≠ 原单 → M4_SPLIT_QTY_MISMATCH; 已发货订单不可拆 → M4_ALREADY_SHIPPED |
| L5 数据一致 | 合并后库存预占合并; 拆单后子单预占之和 = 原单预占; 合并/拆单与审计原子 |
| L8 权限 | 仓库主管可合并/拆单; 保管员 → 403 |
| L11 幂等 | 合并/拆单支持 Idempotency-Key |

### PDA 弹性

> 适用故事：US-M4-008（销售退货入库验收扫码，归口 M2）、US-M4-010（PDA 拣选路径导航）

#### 离线策略

| 场景 | 行为 |
|------|------|
| PDA 离线时退货验收 | 退货验收数据暂存本地; 网络恢复后同步 |
| PDA 离线时拣选导航 | 使用本地缓存的库位坐标; 路径计算在本地完成 |

#### 扫码交互

| 场景 | 行为 |
|------|------|
| 退货扫商品码 | 匹配退货单明细 → 确认商品 + 数量 + 外观检查 |
| 退货扫追溯码 | 验证批号与原出库一致 |
| 退货扫库位码 | 确认退货上架位置 |

#### 异常恢复

| 场景 | 行为 |
|------|------|
| 退货验收中断 | 重启后恢复; 已扫码数据保留 |
| 拣选导航中断 | 重启后从当前位置继续导航 |
