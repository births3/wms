## 补货逻辑确认（2026-05-16）

### 阈值设置

- **动态计算**：每天自动计算，公式 = 日均出库量 × (补货响应时间/工作时长) × 安全系数
- **人工设置**：可手动覆盖，优先级高于动态计算
- **快速设置界面**：批量计算建议值 → 预览 → 确认应用
- **参数可配置**：统计天数、安全系数、响应时间

### 补货数量

- 补固定件数（整件/整箱，按商品包装层级）
- 补完后库存 > 阈值
- 上限 = 零拣位剩余容量

### 补货与拣选关系：方案 4 混合模式

| 层级 | 触发条件 | 优先级 | 说明 |
|------|---------|--------|------|
| 日常补货 | 零拣位库存 < 阈值 | 中 | 每天定时检查，持续补 |
| 波次补货 | 波次需求 > 零拣位库存 | 高 | 波次下发时检查，紧急补 |
| 拣选补拣 | 拣选时实际不足 | 最高 | 短拣后触发补拣任务 |

> v7 边界更新：温度采集数据由外部冷链系统持有，不在 WMS 数据量内。WMS 仅缓存温度超标事件（量级远小，并入审计追踪估算）。

### 结论

- **数据量级别**：中型（3 年 ~151M 行，~28GB；扣除温度采集后下调）
- **PostgreSQL 单机足够**，不需要分库分表
- **需要分区的表**：见 [docs/infra/sharding-decision-matrix.md](../infra/sharding-decision-matrix.md) 三档分级粒度策略（高频日志按月 / GSP 长期表按季度 / 低频中等表按年）
- **并发**：20 人，连接池 50-100，不需要读写分离
- **存储**：单机 SSD 256GB 足够
- **归档**：3 年以上数据移到归档分区（只读，不删除）

> **v25 修正**（2026-05-17）：基于业务方现有 Oracle WMS 真实数据（4.84 亿行 / 721 张表）发现本初版预估**严重低估 ~10x**：
> - 追溯码：预估 9M / 实际 86M（C_GSP_NBR_TRKG）
> - 缺漏关键大表：作业绩效追踪 86M / 装箱明细 82M / 系统消息日志合计 64M / PIX 接口日志 24M
> - 业务方已实施按 WHSE+时间分区（PURGE_IDX 系列）
>
> **修正结论**：3 张表分区不够，需 5 张超大表 + 5 张中等表分区；详见 [docs/infra/sharding-decision-matrix.md](../infra/sharding-decision-matrix.md) 与 `docs/legacy-analysis/legacy-comparison-matrix.md`。

## #47 审计发现业务决策（2026-05-17 v3.1）

> 背景：用户故事审计发现 C1/C6/C7 三项业务取舍需用户决策

### C1 PDA 离线冲突统一策略

**决策**：方案 A — 集中到 H1 跨约束，默认 24h 可配置
- 普通离线：暂存 → 恢复后自动同步
- 冲突离线（服务端已变）：不覆盖 → "待主管处理" → 主管企微选择处置
- 超时 24h 强制联网

### C6 盘点期间已下发的拣选任务

**决策**：方案 A — 已下发任务继续执行完成
- 盘点锁仅阻止新分配
- 盘点基准 = 盘点开始时账面 − 已分配预占
- 盘点报告显示"盘点期间已发出"列

### C7 退货上架后批号/效期保留

**决策**：用户自定义方案
- **退货批号来自 ERP**：ERP 取原销售出库订单的批号（原单退货）
- **WMS 校验已有批号表**：退货验收时校验 ERP 指定批号是否存在于 WMS 已有批号表（该批号曾经入库过）
- **校验通过**：使用该批号上架，保留原效期/生产日期/生产厂家
- **校验失败（批号不存在）= 异常**：进隔离区 + M-QL 质量联系单（类型=退货批号异常）→ 主管决定处置
- **不新增 `is_returned` 字段**：因为批号是 ERP 给的且校验已有，不存在"退货独立批次"概念，退货回来就是原批次

### C8 销售退货与采购退货归类

**决策**：销售退货归入入库业务，采购退货归入出库业务。
- **销售退货 / 客户退货**：货物从客户或门店回仓，后续节点是收货、验收、上架，应归入入库业务。
- **采购退货 / 退供应商**：货物从仓库发出退回供应商，后续节点是申请、审批、拣货、复核、出库交接，应归入出库业务。
- **批号口径**：采购入库不把批号作为 ASN / 收货前置字段；销售退货入库必须带原销售出库批号。
- **PC Web 菜单口径**：M4 出库页面只承载采购退货出库；销售退货不设独立流程入口，在 M2 收货、验收、上架页按入库单据类型筛选和处理。

| MDI-P12 | 图像处理 | 图片上传后、审核前由上传人手工选择不处理、原色增强或黑白增强；原色增强轻度去噪，黑白增强使用自适应二值化+轻度去噪，审核人并排查看并可切回原色增强。 |
| MDI-P13 | 文件限制 | JPG/PNG 原件不超过5MB、解码后不超过5000万像素且单边不超过12000像素；PDF原件沿用50MB。中间JPG质量85%。客户PDF软上限50MB，独立审核人填写原因可批准，绝对上限100MB。 |
| MDI-P14 | 处理规则更新 | 发布新处理规则时弹窗选择仅用于未来或重新处理当前有效报告；后台重处理保留旧副本，新副本成功后切换，不处理已被替代版本。 |
| MDI-P15 | 失败边界 | 副本生成、盖章、客户平台或事件同步失败不阻塞入库、报告确认或发货；客户不得降级下载未盖章原件。 |
| MDI-P16 | 版本可见性 | 客户账号默认只看当前有效版本；开启历史权限后可以查看原版本、更正版和更正记录，批量下载默认仍只含当前版本。 |
| MDI-P17 | H-FILE 权限 | 客户平台主服务只读授权附件；导出任务仅可读取授权附件并读写自己的 `wms-exports` 前缀。 |
| MDI-P18 | 审计 | 上传、修改、复用、审核、更正、图章发布、处理、重生成、查看、下载和批量导出均留审计；不记录密码、正文、凭据或完整临时 URL。 |
| MDI-P19 | 端范围纠正 | DI-002 使用 WMS PC 生产前端审核页面；旧矩阵的 PDA 扫码查询范围作废，治理脚本不再把 US-DI-002 强制列为 PDA 操作故事。 |
| MDI-P20 | 入库资料清单 | 新增独立菜单“入库作业 / 入库资料录入”。每个 ASN 一行并显示上游采购订单号；按实际收货时间查询，默认最近90天。未实际收货的 ASN 清空日期后可见，药检单显示“待收货/待批号”且不计缺失。 |
| MDI-P21 | 缺失快捷筛选 | 公共 QueryPanel 提供通用胶囊快捷标签；本页使用“药检单不齐”和“上游随货同行单不齐”，点击立即查询，两个同时选中按任一资料不齐（OR）匹配。 |
| MDI-P22 | 上游随货同行单关联 | 此处仅指供应商随采购入库货物提供的上游随货同行单，与 H9 出库同行单分离。一份单据可以关联多个 ASN；从当前 ASN 进入时默认勾选当前 ASN，并只搜索同供应商候选，收货日期默认当天且允许人工调整范围。 |
| MDI-P23 | 上游同行单上传与版本 | 统一“录入资料”弹窗分药检单、上游随货同行单两个页签。上游同行单支持一个 PDF 或多张 JPG，每个文件不超过5MB；上传成功即视为已录入，不做图像处理、确认或审核。重新上传必须填写修改原因并生成新版本，旧文件、修改人、时间和原因永久保留。 |
