# 用户故事：M-RP 补货模块

> 模块：M-RP replenishment
> 性质：独立业务模块（存储位→拣选位自动补货）
> 波次：Wave 3（依赖 M-TE 任务引擎 + M3 库存）
> 依赖：M-TE 任务引擎、M3 库存、M1 基础档案（商品包装层级）、H4 企业微信

---

## 背景

零拣位库存不足时需要从存储位搬运商品过来。补货通过任务引擎生成任务，保管员 PDA 执行。三层触发：日常阈值补 + 波次紧急补 + 拣选补拣。

---

## US-RP-001：补货阈值管理

**作为** 仓库主管
**我要** 管理每个商品在零拣位的补货阈值（动态计算 + 人工覆盖）
**以便** 系统知道什么时候该触发补货

### 验收标准

1. **动态计算**（每天自动执行）：
   - 公式：建议阈值 = 日均出库量 × (补货响应时间 / 工作时长) × 安全系数
   - 参数可配置：统计天数（默认 30）、安全系数（默认 1.5）、响应时间（默认 30 分钟）、工作时长（默认 8 小时）
2. **人工设置**：可手动为某商品设置固定阈值，**优先级高于动态计算**
3. **快速设置界面**：
   - 批量选择商品范围（全部/某类别/某库区）→ 一键计算建议值
   - 预览：商品、当前阈值、建议阈值、日均出库量、差异
   - 确认后批量应用
   - 单个商品可手动调整
4. **定期重算**：每天凌晨自动重算（未被人工覆盖的商品）
5. 阈值变更写入审计追踪

---

## US-RP-002：日常补货（阈值触发）

**作为** 系统（定时检查）
**我要** 定时检查零拣位库存，低于阈值时自动生成补货任务
**以便** 零拣位始终有足够库存供拣选

### 验收标准

1. 检查频率可配置（默认每 15 分钟）
2. 触发条件：零拣位当前库存 < 阈值
3. **补货数量**：补固定件数（整件/整箱，按商品包装层级）
   - 补货量 = 整件数量的倍数
   - 上限 = 零拣位剩余容量
   - 补完后库存 > 阈值
4. **补货源**：从存储位取（同商品同批号，优先同库区）
5. 存储位库存不足时：标记"补货源不足" + 企业微信通知仓库主管
6. 生成补货任务 → 进入任务引擎（优先级：中）
7. 补货任务写入审计追踪

---

## US-RP-003：波次补货（紧急触发）

**作为** 系统（波次下发时自动检查）
**我要** 在波次下发前检查零拣位库存是否满足波次需求，不足时紧急补货
**以便** 拣选时零拣位有足够库存

### 验收标准

1. 触发时机：波次下发时自动检查
2. 检查逻辑：波次需求量 > 零拣位当前库存（含已锁定量）
3. 不足时：生成紧急补货任务 → 进入任务引擎（优先级：高）
4. **补货完成后才释放对应的拣选任务**（通过任务引擎的释放控制）
5. 补货超时未完成 → 企业微信通知仓库主管
6. 波次补货写入审计追踪

---

## US-RP-004：拣选补拣（兜底触发）

**作为** 系统（拣选短拣时自动触发）
**我要** 在拣选发现实际不足时触发补拣流程
**以便** 短拣的差异能尽快补齐

### 验收标准

1. 触发条件：拣选任务执行时实际可拣 < 需求量（短拣）
2. 短拣后：
   - 当前拣选任务继续（拣能拣的，标记短拣）
   - 自动生成补货任务（优先级：最高）
   - 补货完成后自动生成"补拣任务"（优先级：最高）
3. 补拣任务：从补货后的零拣位拣取差异数量 → 合并到原订单
4. 补拣完成后原订单恢复完整
5. 全程写入审计追踪 + 企业微信通知

---

## 跨故事约束

1. **审计追踪**：所有补货操作写入审计表
2. **任务引擎**：所有补货通过 M-TE 任务引擎生成和调度
3. **库存变动**：补货 = 存储位库存减少 + 零拣位库存增加（同一事务）
4. **包装层级**：补货数量按商品包装层级取整（整件/整箱）
5. **企业微信通知**：补货源不足、补货超时通知仓库主管
6. **多货主**：补货按货主隔离（A 货主的存储位只补 A 货主的零拣位）
