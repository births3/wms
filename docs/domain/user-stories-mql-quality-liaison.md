# 用户故事：M-QL 质量联系单模块

> 模块：M-QL quality-liaison
> 性质：独立业务模块（校验异常/验收不合格/强制通过等场景触发）
> 波次：Wave 2（M-VR 校验规则模块依赖）
> 依赖：H1 权限、H2 审计、H4 企业微信

---

## 背景

当业务流程中出现质量/合规相关的异常（校验不通过需强制、验收不合格、养护异常等），需要生成质量联系单走审批流程。不同类型的质量联系单走不同的企业微信审批模板，审批结果回写系统后才能继续操作。

---

## US-QL-001：质量联系单类型与审批模板配置

**作为** 系统管理员
**我要** 配置质量联系单的类型，并为每种类型绑定企业微信审批模板
**以便** 不同场景的质量问题走不同的审批流程

### 验收标准

1. 质量联系单类型（可扩展）：
   - 校验强制通过（入库/出库校验异常需强制放行）
   - 验收不合格（入库验收发现质量问题）
   - 养护异常（在库养护发现质量问题）
   - 库存状态调整（合格→隔离/不合格）
   - 近效期处置（近效期商品处置决策）
   - **档案补录（PDA 验收时发现商品主数据缺失/错误，需推送 ERP 由 ERP 发起主数据变更）**
   - **批号调整（v21 新增：库存批号录入错误的主数据级修正，由 M-BA 模块驱动；详见 user-stories-mba-batch-adjustment.md）**
   - **召回（v25 新增：药品召回流程，含一/二/三级召回；联动 M3 库存批次 recall_flag + M-TC 反查 + H4 通知客户）**
   - 其他（自定义类型）
2. 每种类型绑定一个企业微信审批模板（模板 ID）
3. 每种类型可配置：审批人规则（指定角色/指定人/按货主）、超时时长（**默认值见下表**）

| 联系单类型 | 超时时长默认值 |
|----------|-------------|
| 校验强制通过 | 4 小时 |
| 验收不合格 | 4 小时 |
| 养护异常 | 24 小时 |
| 库存状态调整 | 4 小时 |
| 近效期处置 | 7 天 |
| 档案补录 | 4 小时（阻塞验收，需在 4 小时内处理）|
| **批号调整** | **24 小时（双人审批，需仓库主管 + 质量负责人均同意）** |
| **召回** (v25) | **一级 24 小时 / 二级 48 小时 / 三级 72 小时（按召回级别字段自动带出）**|
| 其他（自定义） | 24 小时 |
4. 类型可启用/停用
5. 配置变更写入审计追踪

## US-QL-002：创建质量联系单

**作为** 系统（自动）/ 仓库主管
**我要** 在异常场景触发时自动或手动创建质量联系单
**以便** 启动审批流程，记录质量问题的处置过程

### 验收标准

1. **自动创建**触发场景：
   - M-VR 校验异常选择"强制通过" → 自动创建"校验强制通过"类型联系单
   - M2 验收不合格 → 自动创建"验收不合格"类型联系单
   - M3 养护异常 → 自动创建"养护异常"类型联系单
   - M3 库存状态调整 → 自动创建"库存状态调整"类型联系单
   - **M2-003 PDA 验收发现档案缺失/错误 → 自动创建"档案补录"类型联系单**（含商品编码 + 缺失/错误字段 + 收货员录入的新值 + 拍照证据）
   - **召回流程触发** (v25)：药监召回通知接收 / 仓库主管手动发起召回 → 自动创建"召回"类型联系单（含召回级别 + 召回范围 + 召回时限）
2. **手动创建**：仓库主管可在界面手动创建任意类型的质量联系单
3. 联系单必填：类型、关联单据（ASN 号/订单号/批号）、问题描述、处置建议
4. **档案补录类型联系单的特殊必填字段**：
   - 商品编码（与 ASN 关联）
   - 待补录的字段名（批准文号 / 包装层级 / 储存条件 / 物理属性 / 其他）
   - 当前档案值（如有）
   - 收货员录入的新值
   - 拍照证据（≥1 张实物包装照片，≤5 张）
   - 触发的 ASN 号 + 验收记录 ID（用于阻塞当前验收）
5. **召回类型联系单的特殊必填字段** (v25)：
   - 召回级别（枚举：一级 / 二级 / 三级，对应法规分级）
   - 召回时限（按级别自动带出：一级 24 小时 / 二级 48 小时 / 三级 72 小时；可仓库主管手动调整）
   - 召回范围：商品编码 + 批号清单（多批次）+ 涉及客户清单（M-TC 反查自动带出）
   - 召回原因（自由文本 + 法规依据引用）
   - 召回记录字段（v25 新增字段，与 M3 库存批次的 `recall_flag` 联动）：
     - `recall_id`：召回记录唯一 ID（M-CG 编码生成）
     - `recall_level`：召回级别
     - `affected_batches`：受影响批次清单
     - `affected_customers`：受影响客户清单
     - `recall_status`：发起 / 通知中 / 回收中 / 回收完成 / 销毁完成
     - `regulator_notification`：药监局通知方式（由 ERP 主管，WMS 仅展示）
   - GSP 法规依据：不-4 召回流程；clarifications #21 决策
6. 联系单状态：待审批 → 审批中 → 已通过 / 已拒绝；档案补录类型在已通过后增加子状态：**待 ERP 同步 → 已落地**（见 US-QL-004）；召回类型在已通过后进入"召回执行中"子状态（联动 M3 库存批次 recall_flag）
7. 创建后自动推送到企业微信审批流（按类型选择对应审批模板）
8. 创建记录写入审计追踪

## US-QL-003：质量联系单审批

**作为** 仓库主管（作为联系单审批人，通过企业微信操作）
**我要** 在企业微信上审批质量联系单（同意/拒绝 + 审批意见）
**以便** 质量问题有明确的处置决策

### 验收标准

1. 审批人在企业微信收到审批通知（含问题摘要、关联单据、处置建议）
2. 审批动作：同意 / 拒绝 + 必填审批意见
3. 审批结果自动回写 WMS：
   - **同意** → 联系单状态变"已通过" → 触发后续动作（见 US-QL-004 联动业务流程）
   - **拒绝** → 联系单状态变"已拒绝" → 原操作不执行（如：不允许强制通过，订单保持校验异常；档案补录被拒则当前 ASN 验收无法继续，需人工修正 ASN 数据后重启）
4. **档案补录类型审批通过的额外动作**：审批通过后系统将补录数据写入 ERP 接口表（H8 ERP 防腐层），等待 ERP 拉取并发起主数据变更；联系单状态进入"待 ERP 同步"子状态
5. 审批超时提醒（按类型配置的超时时长）
6. 审批记录存储在 WMS（审批人、时间、结论、意见）
7. 审批记录写入审计追踪

## US-QL-004：质量联系单与业务流程联动

**作为** 系统（自动）
**我要** 在质量联系单审批通过后自动执行对应的业务动作
**以便** 审批结果直接驱动业务流转，无需人工二次操作

### 验收标准

1. **校验强制通过**审批通过 → 订单状态从"校验异常"变为"已确认"/"待收货" + 标记"合规风险"
2. **验收不合格**审批通过 → 确认处置方式（报损 / 采退 / 降级 / **销毁**）→ 执行对应操作；**销毁动作 (v25)** 走独立流程：M-QL 触发 M-SA-001 报损单且 reason=销毁，PDA 执行节点调 M-VR `process=销毁 + node=销毁执行` 取双人策略（详见 user-stories-msa-stock-adjustment.md US-SA-001 §6 销毁分支）
3. **养护异常**审批通过 → 确认处置方式（移库到不合格区/报损/继续观察）
4. **库存状态调整**审批通过 → 执行状态变更（加减锁）+ 反馈 ERP
5. **档案补录**审批通过 → 走完整 ERP 闭环：

```
Step 1：WMS 将补录数据写入 ERP 接口表（H8 ERP 防腐层提供的"档案补录推送"通道）
        - 字段：商品编码、字段名、新值、拍照证据 URL、ASN 号、验收记录 ID、联系单 ID、时间戳
Step 2：联系单状态变为"待 ERP 同步"，原 ASN 状态保持"档案补录中"（阻塞验收，见 M2 状态机）
Step 3：ERP 拉取接口表 → ERP 端发起商品主数据变更流程（ERP 内部审批/合规等）
Step 4：ERP 完成主数据变更 → 通过 M1-001 商品档案 API 推送新值回 WMS
Step 5：WMS 收到推送，调用回调通知 M-QL：联系单状态变为"已落地"
Step 6：M-QL 通知 M2-003 验收：ASN 解除阻塞，恢复"验收中"状态，使用 ERP 同步后的最新档案值继续验收
```

   - 整个链路异步、有超时（默认 24 小时未落地告警 + 企业微信通知主管）
   - **重试机制**：ERP 接口表写入失败重试 5 次（每次间隔 5 分钟），全部失败后联系单状态变"同步失败"，挂起等人工干预
6. **审批源传递**：所有联动调用 M3 库存状态变更接口时必须携带 `approval_source = 质量联系单, approval_id = 联系单 ID`（见 M3-003 审批源枚举），保证审计追踪可反向追溯
7. 审批拒绝 → 原操作不执行，订单/库存保持当前状态：
   - 档案补录被拒 → 当前 ASN 仍处"档案补录中"阻塞状态；需仓库主管手动从 ERP 修正商品档案后再重启验收，或由收货员退回 ASN
8. 联动执行写入审计追踪

## US-QL-005：质量联系单查询与统计

**作为** 仓库主管
**我要** 查询质量联系单历史记录和统计报表
**以便** 分析质量问题趋势，改进供应商管理和仓库操作

### 验收标准

1. 查询维度：类型、状态、时间范围、关联商品/供应商/货主
2. 统计报表：
   - 按类型分布（哪种质量问题最多）
   - 按供应商分布（哪个供应商问题最多）
   - 按时间趋势（月度质量联系单数量变化）
   - **合规风险统计**：强制通过的笔数、原因分布
   - **档案补录统计**：补录笔数（按字段名/商品/供应商/货主分布）+ ERP 同步成功率 + 平均同步时长（用于评估 ERP 主数据质量与同步效率）
3. 支持导出 Excel
4. 联系单详情可查看完整审批链路

## 跨故事约束

1. **审计追踪**：所有创建/审批/联动操作写入审计表
2. **多货主**：质量联系单按货主隔离
3. **企业微信审批**：所有审批通过企业微信完成，结果回写 WMS
4. **不阻塞但必须走流程**：强制通过不是"跳过"，而是"走质量联系单审批后放行"
5. **合规风险标记**：强制通过审批的订单永久标记"合规风险"
6. **可追溯**：每张质量联系单关联到具体单据（ASN/订单/批号），可正反向追溯
7. **幂等性**：联系单创建/审批/联动操作支持 Idempotency-Key，重复触发不重复执行
8. **审批集中入口（v3.1 新增，K15）**：本系统所有"仓库主管审批"动作（散落于 M1/M2/M3/M4/M5/M6/MBA/M-PK/M-PM/M-RC/M-SA/M-VR/H-Store/H1/M10 等 16 个模块）一律通过 M-QL 质量联系单走流程：（a）发起方调用 US-QL-002 创建对应类型的联系单；（b）通过 US-QL-003 在企业微信完成审批；（c）审批结果通过 US-QL-004 回写并触发后续业务动作；（d）所有审批源声明（approval_source）必须指向 M-QL 联系单 ID 或本模块的 v25 兜底审批源。各模块故事提到"主管审批"时默认走此链路，无需另行说明
9. 测试要求：写操作必须含 L4（错误路径）+ L5（数据一致）+ L8（权限）+ L11（幂等）；读操作必须含 L4 + L8

### 测试维度覆盖

#### US-QL-001 质量联系单创建

| 维度 | 场景 |
|------|------|
| L4 错误路径 | 联系单类型不在枚举内 → QL_INVALID_TYPE; 关联批次不存在 → M3_BATCH_NOT_FOUND; 必填字段缺失 → QL_FIELD_REQUIRED; 重复创建同一批次同一类型 → QL_DUPLICATE |
| L5 数据一致 | 联系单创建与批次隔离状态联动（验收不合格 → 自动隔离）; 联系单号全局唯一 |
| L8 权限 | 仓库主管/收货员可创建; 货主只读; 跨货主 → 403 |
| L11 幂等 | 创建支持 Idempotency-Key |

#### US-QL-002 质量联系单审批流

| 维度 | 场景 |
|------|------|
| L4 错误路径 | 审批人无权限 → QL_APPROVER_UNAUTHORIZED; 审批超时 → 升级通知; 审批意见为空 → 校验拒绝; 联系单已关闭 → QL_ALREADY_CLOSED |
| L5 数据一致 | 审批结果与联系单状态原子更新; 审批通过后关联批次状态联动（放行/销毁） |
| L8 权限 | 仓库主管审批; 质量负责人终审; 保管员 → 403 |
| L11 幂等 | 同一联系单重复审批 → 返回当前状态 |

#### US-QL-003 质量联系单处理

| 维度 | 场景 |
|------|------|
| L4 错误路径 | 处理方案不在合法枚举 → QL_INVALID_DISPOSITION; 处理数量 > 联系单数量 → QL_QTY_EXCEEDED; 处理后库存不足 → M3_INSUFFICIENT_QTY |
| L5 数据一致 | 处理完成后库存变动原子（销毁减库存/放行恢复可用）; 处理记录与审计一致 |
| L8 权限 | 仓库主管可处理; 销毁需双人审批 |
| L11 幂等 | 处理操作支持 Idempotency-Key |

#### US-QL-004 质量联系单查询与统计

| 维度 | 场景 |
|------|------|
| L4 错误路径 | 查询时间范围过大 → 分页; 无匹配 → 空列表 |
| L5 数据一致 | 统计数字与明细可对账 |
| L8 权限 | 仓库主管查本仓; 货主查本货主; GSP 审计员查全部 |
| L11 幂等 | 查询天然幂等 |

#### US-QL-005 召回联系单

| 维度 | 场景 |
|------|------|
| L4 错误路径 | 召回批次无出库记录 → QL_NO_SHIPMENT_FOUND; 受影响客户清单为空 → 提示确认; 召回通知发送失败 → 重试 + 告警 |
| L5 数据一致 | 召回范围与实际出库记录一致; 召回状态与回收进度联动 |
| L8 权限 | 仓库主管/质量负责人可发起; 需双人审批 |
| L11 幂等 | 同一批次重复发起召回 → 返回已有召回单 |
