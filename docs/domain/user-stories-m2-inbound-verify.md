## US-M2-003：PDA/PC Web 验收

**作为** 收货员
**我要** 在 PDA 或 PC Web 上对到货商品进行逐件验收，核对质量信息
**以便** 确认商品质量合格，满足 GSP 验收要求

### 验收核对内容

| 核对项 | 说明 |
|--------|------|
| 品名 | 与 ASN 一致 |
| 规格 | 与 ASN 一致 |
| 销售退货批号 | 销售退货入库由原销售出库带出；采购入库不要求批号 |
| 有效期 | 扫追溯码自动获取 或 手工录入 |
| 生产日期 | |
| 数量 | 抽验数量 + 总数量 |
| 批准文号 | 与商品档案一致 |
| 外观 | 完好/破损 |
| 包装 | 完好/破损/潮湿 |
| 说明书 | 有/无/破损 |
| 标签 | 清晰/模糊/缺失 |

### 验收标准

1. **整单验收**：所有商品行验完后统一提交验收结论
2. 追溯码扫码（如配置在验收环节）：PDA 扫码或 PC Web USB 扫码枪输入追溯码；销售退货入库校验原销售批号，采购入库不要求批号
3. 追溯码无法扫取时 → 手工录入
4. 抽验数量录入（按 GSP 抽验比例）
5. 销售退货入库多批号分别录入质量状态；采购入库按商品行录入质量状态
6. 质量状态判定：合格 / 不合格
7. **不合格处理**：
   - 部分不合格：不合格品上不合格库，合格品继续上架
   - 整单不合格：全部上不合格库
   - 不合格自动生成**质量联系单** → 推送企业微信审批 → 后续报损或采退
8. 近效期预警（距过期 < 配置月数）
9. 已过期自动标记不合格
10. **档案补录入口**：验收过程中收货员发现商品基础档案与实物不符或档案缺失时，可在 PDA 或 PC Web 上触发"档案补录"流程：

#### 档案补录顺序（在 M2-003 验收界面内的子流程）

```
1. 验收过程中点击"档案补录"按钮（需配置开通：默认关闭，仓库主管可在系统配置中心开通）
2. 选择待补录的字段（批准文号 / 包装层级 / 储存条件 / 物理属性 / 其他）
3. 显示当前档案值（如有）+ 录入新值
4. 拍照（≥1 张实物包装照片，≤5 张，必填）
5. 录入补录原因 → 提交
6. 系统自动生成"档案补录"类型质量联系单（M-QL-002）
7. 推送企业微信审批（M-QL-003）
8. **当前 ASN 状态自动变为"档案补录中"，验收暂停**
9. 等待审批 + ERP 同步完成后（M-QL-004 的 6 步闭环），ASN 状态恢复"验收中"，使用最新档案值继续验收
```

#### 档案补录字段表（PDA/PC Web 录入）

| 字段 | 必填 | 系统带出/录入 | 说明 |
|------|------|-------------|------|
| 关联 ASN 号 | 系统带出 | — | 当前验收 ASN |
| 商品编码 | 系统带出 | — | 与 ASN 关联 |
| 待补录字段 | 必填 | 选择 | 批准文号 / 包装层级 / 储存条件 / 物理属性 / 其他 |
| 当前档案值 | 系统带出 | — | 如有，否则显示"档案缺失" |
| 收货员录入新值 | 必填 | 录入 | 文本/数字/枚举（按字段类型）|
| 实物拍照 | 必填 | 拍照 | ≥1 张 ≤5 张，存对象存储 |
| 补录原因 | 必填 | 录入 | 自由文本（说明实物为何与档案不符）|
| 收货员 user_id | 系统带出 | — | |
| 触发时间 | 系统带出 | — | |

11. 可绑定托盘/盲标签
12. 验收进度显示（已验/总数）
13. **离线支持**：仅 PDA 验收记录支持离线暂存；离线期间 ASN 状态被改时按跨故事约束 9"暂存为'待主管处理'"事件；PC Web 不支持离线提交；**档案补录功能需联网（必须推送 ERP 接口表，离线下禁用入口）**
14. 验收记录写入审计追踪

## US-M2-004：双人验收签字

**作为** 收货员（验收岗）
**我要** 由两名不同用户对验收结论进行双人签字确认（按 M-VR 双人策略矩阵动态决定是否需要）
**以便** 满足 GSP 双人验收要求

### 验收标准

1. **签字时机**：整单验收完成后（所有商品行验完）
2. **双人策略动态查询**（v25 升级）：本环节双人要求由 M-VR 双人策略接口（US-VR-006）按 process=入库 + node=验收 决定，三档行为：
   - `single`：单人签字即可（普通药品历史默认为 dual_scan，但可被矩阵覆盖）
   - `dual_scan`：第一人签字 → 状态"待第二人签字" → 第二人签字 → 验收结论生效
   - `dual_scan_with_approval`：双人签字 + 仓库主管企业微信审批通过后流转到"上架中"
3. **签字人资格强校验**：双人均必须是"收货员（验收岗）"角色（即拥有验收权限的用户），且 user_id 不同；非验收岗用户即使有审批权也不可签字
4. 签字记录：签字人、时间、结论、备注
5. 签字记录不可修改（append-only），写入审计追踪（含双人策略命中规则 ID）
6. 按货主 + 商品 + 批号关联 M-DI 药检单：已有已确认版本时复用；没有时进入人工上传，上传人与审核人必须分离
7. ~~**双人签字是否需要**：系统参数可配置（开启/关闭，默认开启）~~ 已迁移到 M1-008 双人作业矩阵 + M-VR US-VR-006 统一管理（v24）

## US-M2-005：PDA/PC Web 智能上架

**作为** 保管员
**我要** 在 PDA 或 PC Web 上将验收合格的商品上架到系统推荐的库位
**以便** 商品按温区、色标、货主规则存放到正确位置

### 验收标准

1. **上架模式可配置**（系统参数，**默认半自动**）：
   - **全自动**：系统分配库位 + 自动标记上架完成（无需 PDA 操作）
   - **半自动**：系统推荐库位，保管员 PDA 扫码确认，或在 PC Web 使用 USB 扫码枪/手工输入确认
2. 库位推荐规则：温区匹配（**温度区间见 M1 附录 A**） → 色标匹配 → 货主匹配 → 同品就近（销售退货入库同批就近） → **剩余容积足够**（商品体积 × 数量 ≤ 库位剩余容积）
3. 半自动模式：保管员可接受推荐或手动选择（系统校验合法性）
4. **上架确认顺序**（半自动模式）：

```
1. 扫/录入待上架容器 LPN 或商品码 → 系统弹出推荐库位 Top N
2. 保管员选择推荐库位（或手动扫描其他合法库位）
3. 走到库位 → 扫/录入目标库位码 → 系统校验温区/色标/容量合法性
4. 不合法报警拒绝；合法则提交 → 库存增加
```

5. **上架字段表（PDA/PC Web）**：

| 字段 | 必填 | 系统带出/录入 | 说明 |
|------|------|-------------|------|
| 上架任务 ID | 系统带出 | — | M-TE 生成 |
| 容器 LPN（整托/箱）| 条件必填 | 扫码 | 整托/整箱上架时必扫 |
| 商品编码 | 系统带出 | 扫码确认 | |
| 销售退货批号 | 销售退货入库时系统带出 | 扫码确认 | 采购入库不要求 |
| 数量 | 必填 | 录入 | 默认 = 待上架数量 |
| 推荐库位 | 系统带出 | — | Top N 推荐 |
| 实际库位 | 必填 | 扫码/录入 | 推荐 ≠ 实际时记录差异 |
| 校验结果 | 系统带出 | — | 通过 / 不合法（报警拒绝）|
| 上架人 user_id | 系统带出 | — | |
| 上架时间 | 系统带出 | — | |

6. 支持整托上架（扫 LPN 码）
7. 支持部分上架（今天上 5 件，明天上剩余 5 件）
8. **双人策略动态查询**（v25 升级）：上架前调 M-VR 双人策略接口（US-VR-006）按 process=入库 + node=上架 查询；返回 dual_scan / dual_scan_with_approval 时需第二保管员扫码/登录确认或主管审批通过方可提交（普通药品默认 single）
9. **全部上架完成后**：
   - ASN 状态变为"已完成"
   - 触发 ERP 反馈（异步，含商品/数量/库位/时间；销售退货入库含原销售批号）
   - 反馈失败可重试
10. **离线支持**：仅 PDA 上架支持离线暂存；离线期间该库位被他人占用时按跨故事约束 9"暂存为'待主管处理'"事件；PC Web 不支持离线提交
11. 上架操作写入审计追踪 + 库存变动记录（含双人策略命中规则 ID 与参与的 user_id）
12. **质量锁校验**（6 维校验第③步）：容器质量锁为 `quarantine`/`rejected` 的容器严禁上架合格区（目标库区 `zone.quality_color` 不匹配即报警拒绝）；散货上架读取批次 `status`，非 `qualified` 强阻断报错

## US-M2-006：收货异常处理

**作为** 仓库主管
**我要** 处理收货过程中的异常（拒收、短少、破损、温度超标）
**以便** 异常有闭环处置记录

### 验收标准

1. 异常类型：整单拒收、部分拒收、短少、破损、温度超标、资质异常
2. **整单拒收**：收货节点动作（独立 `reject`、一条 receipt、`closed_rejected`、不写库存）见 US-M2-002 / 澄清 #113。本故事覆盖异常分类、M-QL、H4 通知与统计，不重复实现收货主链
3. **部分拒收**：销售退货入库多批号时必须逐批记录批号、拒收数量、拒收原因；批号级拒收数量合计回写 ASN 拒收数量，未拒收批号继续流转。采购入库记录商品级拒收数量和原因
4. **短少**：收货闭环已记录缺货数量；验收环节可"强制关闭" → ASN 状态"已关闭(短少)"；缺货部分由 ERP 推新 ASN
5. **温度超标继续收货**：正常流转 + 异常备注 + 上传稳定性报告附件
6. **验收不合格**：自动生成质量联系单 → 企业微信审批 → 报损/采退
7. 所有异常处置写入审计追踪
8. 异常统计可按供应商/商品/类型汇总；销售退货入库可按批号汇总
9. 异常触发企业微信通知（通知仓库主管）

**作为** 仓库主管
**我要** 在 PC/PAD 端查看今日收货进度

6. 看板为只读查询，不产生写操作，无需独立审计追踪（数据来源的写操作已各自审计）

## US-M2-010：上架策略配置

**作为** 仓库主管
**我要** 配置上架策略规则（多条规则按优先级排序），系统根据策略推荐最优库位
**以便** 不同商品/场景使用不同的上架逻辑，且规则可灵活调整

### 验收标准

1. **策略规则引擎**（可配置界面，规则按优先级排序执行）：
   - 温区匹配（冷链商品只能放冷库）
   - 品类分区（中药/西药/器械分区存放）
   - 同品聚集（同 SKU 优先放到已有该商品的库位）
   - ABC 分类（A 类商品放黄金库位/靠近出库口）
   - 空库位优先（优先放空库位，减少混放）
   - 货主隔离（不同货主不混放）
   - 容积匹配（商品体积 × 数量 ≤ 库位剩余容积）
   - 效期隔离（不同效期不混放；销售退货入库不同批号不混放，可配置是否允许）
2. **规则优先级可拖拽排序**（界面操作）；**默认优先级**：温区匹配 > 货主隔离 > 容积匹配 > 同品聚集 > ABC 分类 > 品类分区 > 效期隔离 > 空库位优先（可拖拽调整）
3. **规则可启用/停用**（不删除，支持一键切换策略方案）；**默认全部启用**
4. **多策略方案**：可配置多套策略方案，按商品类别/货主/仓库绑定不同方案；**默认使用"通用方案"**（含上述全部规则）
5. **推荐结果**：系统按规则过滤+排序后返回 Top N 推荐库位（N 可配置，**默认 N=3**）
6. **无合适库位时**：提示"无可用库位" + 企业微信通知仓库主管
7. 策略变更写入审计追踪

## 跨故事约束

1. **审计追踪**：所有操作写入审计表
2. **多货主**：ASN 绑定货主，数据按货主隔离
3. **GSP 强校验**：供应商资质过期 → 拒绝；商品过期 → 拒绝入库
4. **收货闭环**：实到 + 缺货 + 拒收 = 预报（系统强制校验）
5. **双人签字策略动态化** (v25)：双人签字 / 双人扫码 / 双人+主管审批 由 M-VR 双人策略矩阵（US-VR-006）按 process=入库 + node=收货/验收/上架 动态决定（v25 流程-节点二维），覆盖入库流程的 3 个节点；矩阵 UI 在 M1-008 §11；普通药品默认配置仅 node=验收 双人扫码，特殊药品按 M1-010 字典预置默认值；PDA 与 PC Web 共用同一策略
6. **追溯码录入环节可配置**：收货 或 验收（**默认验收**）
7. **上架模式可配置**：全自动 或 半自动（**默认半自动**）
8. **冷链**：冷链商品必须录入温度，超标必须有处置记录
9. **离线边界**：PDA 验收/上架支持离线暂存；离线期间发生数据冲突（如库位被占、ASN 状态被改）时，**暂存为"待主管处理"事件**，由仓库主管在 PC 端手动决策，禁止静默覆盖；PC Web 不支持离线暂存。US-M2-002 不把 PDA 离线当完成条件（澄清 #109）
10. **开放 API**：ASN 创建支持外部系统推送
11. **ERP 反馈**：全部上架完成后异步反馈（失败可重试）
12. **企业微信审批**：作废/质量联系单通过企业微信审批流
13. **企业微信通知**：异常/预警通过企业微信通知相关人员
14. **幂等性**：所有写操作支持 Idempotency-Key
15. **打印模板**：所有打印使用 H9 打印模板引擎

### 测试维度覆盖

#### US-M2-003 PDA/PC Web 验收

| 维度 | 场景 |
|------|------|
| L4 错误路径 | 销售退货批号格式不合法 → M2_BATCH_FORMAT_INVALID; 效期 < 当前日期 → M2_BATCH_EXPIRED; 商品储存条件与库区温区不匹配 → M2_TEMP_ZONE_MISMATCH; 追溯码已存在（重复入库）→ M2_TRACE_CODE_DUPLICATE |
| L5 数据一致 | 验收数量 ≤ 签收数量; 验收结论（合格/不合格/待检）与库存状态联动; 入库明细写入库存表原子 |
| L8 权限 | 仅收货员（验收岗）可操作; 保管员 → 403; 跨货主 → 403; PDA 与 PC Web 权限一致 |
| L11 幂等 | 同一 ASN 明细行重复验收 → 返回首次结果；销售退货入库叠加批号校验 |

#### US-M2-004 双人验收签字

| 维度 | 场景 |
|------|------|
| L4 错误路径 | 两个签字人相同 → M2_SAME_VERIFIER; 第二人无验收岗权限 → M2_VERIFIER_UNAUTHORIZED; 签字超时（默认 30 分钟）→ M2_SIGN_TIMEOUT |
| L5 数据一致 | 双人签字完成后验收状态原子更新; 签字记录与审计一致 |
| L8 权限 | 两个签字人必须都有验收岗角色; 且 user_id 不同 |
| L11 幂等 | 同一验收单重复双签 → 返回首次结果（已签完） |

#### US-M2-005 PDA/PC Web 智能上架

| 维度 | 场景 |
|------|------|
| L4 错误路径 | 推荐库位已满 → 推荐次优库位; 所有库位满 → M2_NO_AVAILABLE_LOCATION; 温区不匹配 → 拒绝上架 + 提示正确温区; 容器绑定失败 → M2_LPN_BINDNG_FAILED |
| L5 数据一致 | 上架后库位占用 + 库存增加原子; 上架数量 = 验收合格数量; FIFO 顺序正确 |
| L8 权限 | 仅保管员可操作; 收货员 → 403; PDA 与 PC Web 权限一致 |
| L11 幂等 | 同一上架任务 + 同一库位重复上架 → 返回首次结果 |

#### US-M2-006 收货异常处理

| 维度 | 场景 |
|------|------|
| L4 错误路径 | 异常类型不在枚举内 → M2_INVALID_EXCEPTION_TYPE; 关联 ASN 不存在 → M2_ASN_NOT_FOUND; 处理方案未填 → 校验拒绝 |
| L5 数据一致 | 异常记录与 ASN 状态联动; 拒收数量回写 ASN; 销售退货批号级拒收数量合计 = ASN 拒收数量; 异常处理完成后未拒收商品行可继续流转 |
| L8 权限 | 仓库主管可处理异常; 收货员可上报但不可处理 |
| L11 幂等 | 异常上报支持 Idempotency-Key; 处理操作幂等 |

#### US-M2-007 收货单据打印

| 维度 | 场景 |
|------|------|
| L4 错误路径 | 打印机离线 → 进入待补打队列; 模板不存在 → M2_TEMPLATE_NOT_FOUND; 数据不完整 → 提示缺失字段 |
| L5 数据一致 | 打印内容与 ASN 实际数据一致; 补打不重复生成单号 |
| L8 权限 | 收货员可打印; 货主 → 403 |
| L11 幂等 | 重复打印同一单据 → 使用已有数据（不重新生成） |

#### US-M2-008 收货进度看板

### 端能力差异

> 适用故事：US-M2-003（验收）、US-M2-005（上架）、US-M2-007（打印）

#### 离线策略

| 场景 | 行为 |
|------|------|
| PDA 离线时验收 | 允许离线验收：扫码录入效期/数量暂存本地；销售退货入库额外暂存批号；网络恢复后批量上传 |
| PDA 离线时上架 | 允许离线上架：扫库位码 + 商品码暂存本地; 网络恢复后同步（冲突：库位已满 → 提示重新选择） |
| 离线暂存上限 | 验收最多 200 行; 上架最多 100 条; 超过提示"请恢复网络" |

#### 扫码交互

| 场景 | 行为 |
|------|------|
| 验收扫商品条码 | 匹配 ASN 明细 → 自动填充商品信息 → 输入效期/数量；销售退货入库校验批号 |
| 验收扫追溯码 | GS1 解析 → 自动提取效期 + 序列号；销售退货入库额外提取并校验批号 |
| 上架扫库位码 | 解析库位 → 校验温区匹配 → 确认上架 |
| 上架扫容器码 | 解析容器 → 绑定商品 → 放入库位 |
| 扫码失败 | 提示手动输入; 连续 3 次失败 → 建议检查条码清晰度 |

#### PC Web 输入策略

| 场景 | 行为 |
|------|------|
| PC Web 验收 | 支持 USB 扫码枪键盘输入 + 手工输入；不要求浏览器摄像头扫码 |
| PC Web 上架 | 支持 USB 扫码枪键盘输入 + 手工输入库位 / 容器 / 商品码 |
| PC Web 断网 | 不支持离线提交；保留页面草稿，恢复网络后重新提交 |
| PC Web 双人策略 | 与 PDA 共用 M-VR 返回的 single / dual_scan / dual_scan_with_approval |

#### 异常恢复

| 场景 | 行为 |
|------|------|
| 验收过程中 APP 崩溃 | 重启后恢复到验收页面; 已扫码数据保留 |
| 上架过程中断网 | 当前上架记录暂存; 网络恢复后同步; 库位冲突 → 提示重选 |
| 双人验收第二人扫码时断网 | 第一人签字已暂存; 第二人网络恢复后继续签字; 超时 → 重新发起 |
