# 用户故事：M-TE 任务引擎

> 模块：M-TE task-engine
> 性质：横向业务模块（所有仓库物理操作的统一调度中心）
> 波次：Wave 2-3（基础框架 Wave 2，业务任务类型随各模块 Wave 3+ 逐步接入）
> 依赖：H1 权限、H2 审计、H4 企业微信

---

## 背景

仓库所有物理操作（拣选/上架/补货/移库/盘点/装车/退货上架）统一抽象为"任务"，由任务引擎集中管理。保管员 PDA 只有一个统一待办列表，引擎决定优先级、分配、合并。

---

## US-TE-001：任务类型配置

**作为** 系统管理员
**我要** 配置任务类型（拣选/上架/补货/移库/盘点/装车/退货上架等）
**以便** 不同操作有不同的优先级规则和分配策略

### 验收标准

1. 任务类型：拣选、上架、补货、移库、盘点、装车、退货上架（可扩展）
2. 每种类型可配置：默认优先级、预计耗时、是否可合并、是否可插单
3. 类型可启用/停用
4. 类型变更写入审计追踪

---

## US-TE-002：任务组与人员资格

**作为** 系统管理员
**我要** 配置任务组（按区域/类型分组）并设置人员资格
**以便** 任务只分配给有资格的人，避免跨区域无效行走

### 验收标准

1. 任务组定义：名称、适用库区、适用任务类型
2. 示例：A 区拣选组、B 区补货组、冷库专属组、全区盘点组
3. 人员绑定任务组（一人可属多组）
4. 任务只分配给所属任务组内的人员
5. 人员资格变更写入审计追踪

---

## US-TE-003：任务创建（各模块触发）

**作为** 系统（各业务模块自动触发）
**我要** 在业务事件发生时自动创建对应类型的任务
**以便** 所有操作统一进入任务队列等待调度

### 验收标准

1. 任务创建触发源：

| 触发事件 | 任务类型 | 来源模块 |
|---------|---------|---------|
| 波次下发 | 拣选 | M4 出库 |
| 验收通过 | 上架 | M2 入库 |
| 零拣位低于阈值 | 补货（日常） | M-RP 补货 |
| 波次需求 > 零拣位库存 | 补货（紧急） | M-RP 补货 |
| 短拣后补货完成 | 补拣 | M-RP 补货 |
| 主管发起移库 | 移库 | M3 库存 |
| 盘点单下发 | 盘点 | M3 库存 |
| 复核完成 | 装车 | M4 出库 |
| 销退入库 | 退货上架 | M4 出库 |

2. 任务必填：类型、来源单据号、商品、数量、源库位、目标库位（如有）
3. 创建后状态为"待分配"
4. 任务创建写入审计追踪

---

## US-TE-004：任务优先级规则

**作为** 系统管理员
**我要** 配置任务优先级的计算规则
**以便** 紧急任务排在前面，保管员总是先做最重要的事

### 验收标准

1. 优先级计算因素（可配置权重）：
   - 任务类型默认优先级（拣选 > 补货 > 上架 > 盘点）
   - 订单时效（加急订单 +N 分）
   - 等待时长（等越久优先级越高）
   - 温区（冷链任务优先，避免温度超标）
   - 手动加急（主管可手动提升某任务优先级）
2. 优先级为数值（越大越优先），系统按数值排序
3. 优先级规则变更写入审计追踪

---

## US-TE-005：任务分配

**作为** 系统（自动）/ 仓库主管（手动）
**我要** 将任务分配给具体的保管员
**以便** 每个人知道自己该做什么

### 验收标准

1. **自动分配**规则（可配置）：
   - 按任务组资格过滤（只分配给有资格的人）
   - 就近原则（保管员当前位置离任务源库位最近的优先）
   - 均衡原则（任务量少的人优先接新任务）
   - 技能匹配（如冷库操作需要冷库资格）
2. **手动指派**：仓库主管可在界面手动将任务指派给具体人
3. 分配后任务状态变为"已分配"，推送到保管员 PDA
4. 分配记录写入审计追踪

---

## US-TE-006：任务释放控制

**作为** 系统管理员
**我要** 配置任务的释放规则（什么时候下发给保管员）
**以便** 控制任务下发节奏，避免一次性下发太多导致混乱

### 验收标准

1. 释放策略（可配置）：
   - 立即释放（创建即分配）
   - 定时释放（每 N 分钟释放一批）
   - 条件释放（前置任务完成后才释放，如补货完成后释放拣选）
   - 容量释放（每人同时最多 N 个任务）
2. 未释放的任务状态为"待释放"
3. 释放规则变更写入审计追踪

---

## US-TE-007：任务合并

**作为** 系统（自动）
**我要** 将多个相近的任务合并为一次执行
**以便** 减少保管员行走距离，提高效率

### 验收标准

1. 合并条件（可配置）：
   - 同一库位的多个拣选任务 → 合并为一次到该库位
   - 同一路径上的多个任务 → 合并为一次行走
   - 同一商品的多个补货任务 → 合并为一次搬运
2. 合并后生成"组合任务"，包含多个子任务
3. 保管员 PDA 看到的是组合后的任务（按路径排序）
4. 可配置是否启用合并（某些任务类型不合并）
5. 任务合并记录写入审计追踪

---

## US-TE-008：任务执行（PDA）

**作为** 保管员
**我要** 在 PDA 上查看统一待办列表，按顺序执行任务
**以便** 不用切换多个模块，一个列表搞定所有操作

### 验收标准

1. PDA 统一待办列表：按优先级排序显示所有已分配给我的任务
2. 任务卡片显示：类型图标、优先级、源库位→目标库位、商品、数量、预计耗时
3. 点击任务 → 进入执行界面（扫码确认）
4. 执行完成 → 任务状态变"已完成" → 自动弹出下一个任务
5. **插单**：执行过程中收到更高优先级任务 → 提示"有紧急任务，是否切换"
6. **离线支持**：断网时可继续执行已下发的任务，恢复后同步
7. 任务执行写入审计追踪

---

## US-TE-009：任务跟踪看板

**作为** 仓库主管
**我要** 在 PC/PAD 上实时查看所有任务的执行状态
**以便** 掌握作业进度，及时处理异常

### 验收标准

1. 看板维度：按状态（待分配/已分配/执行中/已完成）、按类型、按人员、按库区
2. 实时更新（可配置刷新间隔）
3. 异常高亮：超时未完成、长时间未接单
4. 可手动干预：重新分配、取消任务、调整优先级
5. 超时任务自动推送企业微信通知

---

## US-TE-010：任务绩效统计

**作为** 仓库主管
**我要** 查看每个保管员的任务完成绩效
**以便** 评估效率、发现瓶颈、优化人员配置

### 验收标准

1. 绩效指标：
   - 完成任务数（按类型/按天/按周）
   - 平均完成时长（按类型）
   - 行走距离（如有定位数据）
   - 准确率（无短拣/无错拣的比例）
2. 排行榜：按完成数/效率排名
3. 趋势图：近 30 天绩效变化
4. 支持导出 Excel
5. 绩效数据写入审计追踪

---

## US-TE-011：设备接口抽象（RFID/AGV/输送线预留）

**作为** 系统管理员
**我要** 配置自动化设备（RFID 读写器/AGV/输送线）的接口参数
**以便** 未来接入自动化设备时，任务引擎可将任务下发给设备执行

### 验收标准

1. **设备抽象层**：定义统一的设备接口（任务下发/状态回报/异常上报）
2. **设备类型**（预留，当前不实现具体驱动）：
   - RFID 读写器（自动识别容器 LPN）
   - AGV（自动搬运任务）
   - 输送线（自动传送到指定工位）
   - 电子标签（亮灯拣选）
3. **设备注册**：编号、类型、通信协议（HTTP/MQTT/WebSocket）、状态
4. **任务路由**：任务引擎分配任务时，可选择"人工执行"或"设备执行"
5. **设备状态监控**：在线/离线/故障
6. **降级策略**：设备故障时自动切换为人工任务
7. 设备配置变更写入审计追踪

> 注：Wave 2-3 只实现接口抽象和配置界面，具体设备驱动按需开发。

## 跨故事约束

1. **审计追踪**：任务全生命周期（创建/分配/释放/执行/完成/取消）写入审计表
2. **多货主**：任务关联货主，数据按货主隔离
3. **PDA 统一入口**：保管员只通过任务引擎接收工作，不直接操作各业务模块
4. **企业微信通知**：超时/异常任务通知仓库主管
5. **幂等性**：同一触发事件不重复创建任务
6. **可扩展**：新增任务类型不改引擎代码，只需配置
