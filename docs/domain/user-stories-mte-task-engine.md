# 用户故事：M-TE 任务引擎

> 模块：M-TE task-engine
> 性质：横向业务模块（所有仓库物理操作的统一调度中心）
> 波次：Wave 2-3（基础框架 Wave 2，业务任务类型随各模块 Wave 3+ 逐步接入）
> 依赖：H1 权限、H2 审计、H4 企业微信

---

## 背景

仓库所有物理操作（拣选/上架/补货/移库/盘点/装车/退货上架）统一抽象为"任务"，由任务引擎集中管理。保管员 PDA 只有一个统一待办列表，引擎决定优先级、分配、合并。

---

## 任务状态机

> 所有业务模块（M2 上架/M3 盘点/M4 拣选/M-RP 补货/M-PK 装箱/M-SA 报损/M4 退货上架）的任务统一使用此状态机。M4 拣选任务（M4 文件中专门的"拣选任务状态机"）是本状态机的扩展（加短拣分支），其他任务类型沿用本基础状态机。

## US-TE-001：任务类型配置

**作为** 系统管理员
**我要** 配置任务类型（拣选/上架/补货/移库/盘点/装车/退货上架等）
**以便** 不同操作有不同的优先级规则和分配策略

### 验收标准

1. 任务类型：拣选、上架、补货、移库、盘点、装车、退货上架（可扩展）
2. 每种类型可配置：默认优先级、预计耗时、是否可合并、是否可插单
3. 类型可启用/停用
4. 类型变更写入审计追踪

## US-TE-002：任务组与人员资格

**作为** 系统管理员
**我要** 配置任务组（按区域/类型分组）并设置人员资格
**以便** 任务只分配给有资格的人，避免跨区域无效行走

### 验收标准

1. 任务组定义：名称、适用库区、适用任务类型
2. 示例：A 区拣选组、B 区补货组、冷库专属组、全区盘点组
3. 人员绑定任务组（一人可属多组）
4. 任务只分配给所属任务组内的人员
5. 人员资格变更写入审计追踪

## US-TE-003：任务创建（各模块触发）

**作为** 系统（各业务模块自动触发）
**我要** 在业务事件发生时自动创建对应类型的任务
**以便** 所有操作统一进入任务队列等待调度

### 验收标准

1. 任务创建触发源：

| 触发事件 | 任务类型 | 来源模块 |
|---------|---------|---------|
| 波次下发 | 拣选 | M4 出库 |
| 验收通过 | 上架 | M2 入库 |
| 零拣位低于阈值 | 补货（日常） | M-RP 补货 |
| 波次需求 > 零拣位库存 | 补货（紧急） | M-RP 补货 |
| 短拣后补货完成 | 补拣 | M-RP 补货 |
| 主管发起移库 | 移库 | M3 库存 |
| 盘点单下发 | 盘点 | M3 库存 |
| 复核完成 | 装车 | M4 出库 |
| 销退入库 | 退货上架 | M4 出库 |

2. 任务必填：类型、来源单据号、商品、数量、源库位、目标库位（如有）
3. 创建后状态为"待分配"
4. 任务创建写入审计追踪

## US-TE-004：任务优先级规则

**作为** 系统管理员
**我要** 配置任务优先级的计算规则
**以便** 紧急任务排在前面，保管员总是先做最重要的事

### 验收标准

1. 优先级计算因素（可配置权重）：
   - 任务类型默认优先级（拣选 > 补货 > 上架 > 盘点）
   - 订单时效（加急订单 +N 分）
   - 等待时长（等越久优先级越高）
   - 温区（冷链任务优先，避免温度超标）
   - 手动加急（主管可手动提升某任务优先级）
2. 优先级为数值（越大越优先），系统按数值排序
3. 优先级规则变更写入审计追踪

实现澄清：每个货主只维护一组结构化附加权重，任务类型默认优先级仍在任务类型中配置；不开放自由表达式。数值越界或等待间隔非法统一返回 `M_TE_RULE_INVALID`，单货主唯一规则从数据结构上避免规则冲突，因此不需要额外的冲突确认分支；未命中加急、冷链或手动加急因素时使用任务类型默认优先级。

## US-TE-005：任务分配

**作为** 系统（自动）/ 仓库主管（手动）
**我要** 将任务分配给具体的保管员
**以便** 每个人知道自己该做什么

### 验收标准

1. **自动分配**规则（可配置）：
   - 按任务组资格过滤（只分配给有资格的人）
   - 就近原则（保管员当前位置离任务源库位最近的优先）
   - 均衡原则（任务量少的人优先接新任务）
   - 技能匹配（如冷库操作需要冷库资格）
2. **手动指派**：仓库主管可在界面手动将任务指派给具体人
3. 分配后任务状态变为"已分配"，推送到保管员 PDA
4. 分配记录写入审计追踪

## US-TE-006：任务释放控制

**作为** 系统管理员
**我要** 配置任务的释放规则（什么时候下发给保管员）
**以便** 控制任务下发节奏，避免一次性下发太多导致混乱

### 验收标准

1. 释放策略（可配置）：
   - 立即释放（创建即分配）
   - 定时释放（每 N 分钟释放一批）
   - 条件释放（前置任务完成后才释放，如补货完成后释放拣选）
   - 容量释放（每人同时最多 N 个任务）
2. 未释放的任务状态为"待释放"
3. 释放规则变更写入审计追踪

## US-TE-007：任务合并

**作为** 系统（自动）
**我要** 将多个相近的任务合并为一次执行
**以便** 减少保管员行走距离，提高效率

### 验收标准

1. 合并条件（可配置）：
   - 同一库位的多个拣选任务 → 合并为一次到该库位
   - 同一路径上的多个任务 → 合并为一次行走
   - 同一商品的多个补货任务 → 合并为一次搬运
2. 合并后生成"组合任务"，包含多个子任务
3. 保管员 PDA 看到的是组合后的任务（按路径排序）
4. 可配置是否启用合并（某些任务类型不合并）
5. 任务合并记录写入审计追踪

## US-TE-008：任务执行（PDA）

**作为** 保管员
**我要** 在 PDA 上查看统一待办列表，按顺序执行任务
**以便** 不用切换多个模块，一个列表搞定所有操作

### 验收标准

1. PDA 统一待办列表：按优先级排序显示所有已分配给我的任务
2. 任务卡片显示：类型图标、优先级、源库位→目标库位、商品、数量、预计耗时
3. 点击任务 → 进入执行界面（扫码确认）
4. 执行完成 → 任务状态变"已完成" → 自动弹出下一个任务
5. **插单**：执行过程中收到更高优先级任务 → 提示"有紧急任务，是否切换"
6. **离线支持**：断网时可继续执行已下发的任务（任务详情已缓存到 PDA），恢复网络后增量同步执行结果；离线期间数据冲突按跨故事约束 7"暂存为'待主管处理'"处理
7. 任务执行写入审计追踪

### PDA 任务执行通用规范（所有任务类型共用）

> 拣选/上架/补货/移库/盘点/装车/退货上架/补拣 等所有任务类型在 PDA 执行时遵循以下统一规范，避免各业务模块各自定义。

#### 字段表（PDA 任务执行界面共用字段）

| 字段 | 必填 | 系统带出/录入 | 说明 |
|------|------|-------------|------|
| 任务 ID | 系统带出 | — | 由 M-TE 生成，唯一 |
| 任务类型 | 系统带出 | — | 拣选/上架/补货/移库/盘点/装车/退货上架/补拣 |
| 源库位 | 系统带出 | — | 任务起点（如拣选源、移库源） |
| 目标库位 | 系统带出 | — | 任务终点（如上架目标、移库目标），盘点/查询类无此字段 |
| 商品编码 | 系统带出 | — | |
| 批号 | 系统带出 | — | 由 M3 锁定批次（拣选/移库时强校验） |
| 计划数量 | 系统带出 | — | 任务下发时确定 |
| 实际数量 | 必填 | 录入 | 默认等于计划数量，差异需选异常代码 |
| 异常代码 | 条件必填 | 录入 | 短拣/破损/不足/混批/其他（实际 ≠ 计划时必填） |
| 异常备注 | 可选 | 录入 | 异常说明文本 |
| 容器 LPN | 条件必填 | 扫描录入 | 整托/整箱操作时必扫 |
| 操作人 user_id | 系统带出 | — | 由登录态确定 |
| 操作时间 | 系统带出 | — | 服务器时间，离线模式记 PDA 时间 + 同步时间 |

#### 扫码顺序（标准三步式）

```
1. 扫源库位码  → 校验任务起点库位匹配，否则报警拒绝
2. 扫商品码/容器码 → 校验商品/批号与任务一致；不一致报警拒绝
3. 录入实际数量（或确认默认值）→ 提交
   ↓ 若任务有目标库位（上架/移库/补货）
4. 扫目标库位码 → 校验合法性（温区/色标/容量），通过后提交
```

特殊任务类型扫码差异：
- **盘点**：扫库位 → 扫商品 → 录入实盘数量（无目标库位）
- **装车**：扫出库箱 LPN → 扫车牌 → 确认（实物动作记录）
- **退货上架**：扫退货容器 → 扫商品 → 选择上架库位（按 M2 上架策略推荐）

#### 离线声明

PDA 在以下场景支持离线：

| 场景 | 离线行为 |
|------|---------|
| 任务详情查看 | 执行前已下发的任务详情缓存在 PDA 本地（SQLite），离线可读 |
| 扫码执行 | 离线下扫码、录入数量、提交结果都暂存本地 |
| 校验规则 | 离线时跳过服务端校验（如批号一致性），恢复网络后服务端兜底校验，校验失败的任务自动转"待主管处理"队列 |
| 容器/库位映射 | 关键字典（库位、容器、商品）随登录预下载到 PDA 本地缓存，每日一次增量更新 |
| 数据同步 | 网络恢复后批量上行（按时间顺序），上行失败自动重试（最多 5 次），仍失败转"待主管处理" |
| 冲突处理 | 离线期间该资源（库位/批次）被他人占用 → 暂存为"待主管处理"事件，禁止静默覆盖（参 M-TE 跨故事约束 7）|

## US-TE-010：任务绩效统计

**作为** 仓库主管
**我要** 按岗位/人员/轮班/时段多维度查看任务绩效，支持横向对比和趋势分析
**以便** 评估效率、发现瓶颈、优化人员配置和排班

### 验收标准

1. **绩效指标**：
   - 完成任务数（按类型/按天/按周/按月）
   - 平均完成时长（按任务类型 + 按岗位）
   - 平均等待时长（任务下发到领取间隔，反映调度效率）
   - 行走距离（如有定位数据，PDA 提供）
   - 准确率（无短拣/无错拣/无差异的比例）
   - **首次完成率**（一次完成 vs 需要返工的比例）

2. **多维度统计**：
   - **按岗位维度**（核心新增）：
     - 收货员（M2 收货/验收任务）
     - 养护员（M3 养护任务）
     - 保管员-上架（M2 上架）
     - 保管员-拣选（M4 拣选）
     - 保管员-复核（M4 复核 / M-PK 复核）
     - 保管员-包装（M-PK 装箱）
     - 保管员-补货（M-RP 补货）
     - 保管员-移库（M3 移库）
     - 保管员-盘点（M3 盘点）
     - 保管员-装车（M4 装车）
   - **按人员维度**：每个 user_id 的任务完成情况
   - **按轮班维度**（早班 8:00-16:00 / 中班 16:00-24:00 / 晚班 24:00-8:00，可配置）
   - **按时段维度**：每小时任务完成数（识别峰值/低谷时段）
   - **按任务类型维度**（v5 已有）

3. **横向对比**（核心新增）：
   - **同岗位不同人员对比**：同一岗位下所有人员的指标排行 + 平均值 + 中位数 + 标准差
   - **不同轮班对比**：早/中/晚班的同岗位效率对比（识别轮班优化机会）
   - **同人员不同时段对比**：某人在不同月份/周的趋势（识别个人效率变化）

4. **错误追溯**（核心新增）：
   - 短拣/错拣 → 关联到具体拣选员（M4-003 拣选记录）
   - 错复核 → 关联到复核员（M4-004 后续退货时反查）
   - 养护漏检 → 关联到养护员（M3-004 异常处置时反查）
   - 错误率公式：错误任务数 / 总任务数 × 100%

5. **排行榜**：
   - 按完成数 / 准确率 / 效率（任务/小时） 排名
   - 支持按岗位/时段/月份过滤
   - 默认 TOP 10 + 倒数 5（识别需要培训的员工）

6. **趋势图**：
   - 近 30 天 / 6 个月 / 12 个月绩效变化
   - 多人员同图对比（最多 5 人）
   - 多指标叠加（如完成数 + 准确率）

7. **绩效报告导出**：
   - Excel 全字段
   - PDF 图表（适合发给岗位主管 / HR）
   - 支持按邮件 / 企业微信定时推送（每周/每月）

8. **数据来源**：M-TE 任务执行记录 + 各业务模块的操作记录（M2/M3/M4/M-RP/M-PK 等）

9. **货主隔离**：3PL 模式下，仓库主管看全部 / 货主仅看自己货的相关绩效

10. 绩效数据本身写入审计追踪（不可篡改）

|------|------|

## US-TE-011：设备接口抽象（RFID/AGV/输送线预留）

**作为** 系统管理员
**我要** 配置自动化设备（RFID 读写器/AGV/输送线）的接口参数
**以便** 未来接入自动化设备时，任务引擎可将任务下发给设备执行

### 验收标准

1. **设备抽象层**：定义统一的设备接口（任务下发/状态回报/异常上报）
2. **设备类型**（预留，当前不实现具体驱动）：
   - RFID 读写器（自动识别容器 LPN）
   - AGV（自动搬运任务）
   - 输送线（自动传送到指定工位）
   - 电子标签（亮灯拣选）
3. **设备注册**：编号、类型、通信协议（HTTP/MQTT/WebSocket）、状态
4. **任务路由**：任务引擎分配任务时，可选择"人工执行"或"设备执行"
5. **设备状态监控**：在线/离线/故障
6. **降级策略**：设备故障时自动切换为人工任务
7. 设备配置变更写入审计追踪

> 注：Wave 2-3 只实现接口抽象和配置界面，具体设备驱动按需开发。

## 跨故事约束

1. **审计追踪**：任务全生命周期（创建/分配/释放/执行/完成/取消）写入审计表
2. **多货主**：任务关联货主，数据按货主隔离
3. **PDA 统一入口**：保管员只通过任务引擎接收工作，不直接操作各业务模块
4. **企业微信通知**：超时/异常任务通知仓库主管
5. **幂等性**：同一触发事件不重复创建任务
6. **可扩展**：新增任务类型不改引擎代码，只需配置
7. **PDA 离线**：任务执行支持离线暂存（US-TE-008）；离线期间任务状态/资源发生冲突时，**暂存为"待主管处理"事件**，由仓库主管在 PC 端手动决策，禁止静默覆盖

### PDA 弹性

> 适用故事：US-TE-005（PDA 领取任务）、US-TE-008（PDA 执行任务）

#### 离线策略

| 场景 | 行为 |
|------|------|
| PDA 离线时领取任务 | 显示最后同步的可领取任务列表; 领取暂存本地; 网络恢复后同步（冲突：已被他人领取 → 提示重选） |
| PDA 离线时执行任务 | 执行数据暂存本地; 网络恢复后批量上传 |
| 离线暂存上限 | 最多 20 个任务的执行数据 |

#### 扫码交互

| 场景 | 行为 |
|------|------|
| 扫描任务条码领取 | 解析任务 ID → 领取确认 |
| 执行中扫库位码 | 确认到达正确位置 |
| 执行中扫商品码 | 确认操作正确商品 |
| 执行完成扫确认码 | 标记任务完成 |

#### 异常恢复

| 场景 | 行为 |
|------|------|
| 执行过程中 APP 崩溃 | 重启后恢复到当前任务; 已录入数据保留 |
| 任务执行超时 | 本地提示"任务即将超时"; 超时后服务端自动释放; PDA 端提示"任务已被回收" |
| 网络恢复后任务状态冲突 | 以服务端为准; 如任务已被重分配 → 提示"任务已转给他人" |
