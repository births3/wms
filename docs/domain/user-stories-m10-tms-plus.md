# 用户故事：M10 运输协同（WMS-TMS 集成）

> 模块：M10 tms-plus
> 波次：Wave 5
> 依赖：M4 出库、M5 冷链、H5 快递、H-INT 外部集成契约
> **业务边界**：车辆排班/路径规划/在途监控**由外部 TMS（运输管理系统）负责**，WMS 仅做"出库订单推送 + 调度结果接收 + 温控数据接收 + 容器回收追踪"

---

## US-M10-001：接收 TMS 路径规划结果

**作为** 仓库主管
**我要** 接收外部 TMS 推送的当日配送路径规划结果，关联到出库订单
**以便** WMS 出库装车环节按 TMS 给定的车辆/门店顺序执行，仓库主管可在 WMS 内查询配送路线

> 业务边界：路径规划算法/车辆排班/动态调整**由外部 TMS 负责**（含路径优化引擎、地图 API、车辆容量约束等）；WMS 不做规划，只接收结果。

### 验收标准

1. **数据接入**：通过 M10 TMS 接入端口（遵循 H-INT 契约）接收路径规划结果
2. **接收数据结构**：
   - 配送日期
   - 车辆编号 + 车牌（关联 WMS 自有车辆档案，见 M10-004）
   - 司机 user_id（关联 M1-006）
   - 路线序列：门店列表 + 顺序 + 预计到达时间
   - 关联出库订单列表（与 WMS 出库订单关联）
3. **WMS 内展示**：仓库主管可查询当日车辆/路线
4. **手动调整**：仅在 TMS 不可用时降级支持人工录入路线（标记"手动调整"，需仓库主管审批）
5. **不可推送回 TMS**：WMS 接收后的人工调整仅在 WMS 内有效，不反向修改 TMS（避免双源）
6. 接收记录写入审计追踪

---

## US-M10-002：在途温控数据接入

**作为** 系统（接收外部冷链系统数据）
**我要** 接收外部冷链系统推送的运输途中温湿度数据，并关联到出库订单
**以便** 冷链运输全程可追溯，GSP 检查时通过 WMS 查询关联到具体订单

> 业务边界：温控采集/监控/超标判定**由外部冷链系统**负责（如车载 GPS+温度网关、第三方冷链监控平台）；WMS 仅接收数据用于业务关联和展示（参 M5-002）。

### 验收标准

1. **数据接入**：通过 M5 冷链接入端口（遵循 H-INT 契约）接收车载温度数据 + GPS 位置（外部系统主动推送）
2. **关联出库订单**：按车牌+时间窗将温度数据关联到对应的出库订单
3. **超标预警**：超标判定由外部冷链系统给出（携带 `is_exceeded = true` 标志），WMS 接收后通过 H4 推送企业微信通知 + 触发 M5-003 温度超标事件流程
4. **到达后自动生成温控记录**：可打印温控曲线二维码随货（二维码内容由外部冷链系统提供链接）
5. **数据保留**：WMS 缓存近 1 年用于查询；GSP 要求 ≥ 5 年由外部冷链系统持有
6. **车辆归属**：温控数据可关联到自有车辆（车牌匹配 M10-004 车辆档案）或第三方车辆（仅记录车牌）
7. 数据接入和关联操作写入审计追踪

---

## US-M10-003：容器回收追踪

**作为** 仓库主管
**我要** 追踪可循环容器（保温箱/周转箱）的出库和回收状态
**以便** 防止容器流失

### 验收标准

1. 可循环容器出库时记录：去了哪个客户/门店、出库时间、配送方（自有车队 / 第三方快递）
2. 回收状态：待回收 → 已回收 → 已清洗 → 可复用
3. 超期未回收预警（**默认 7 天未回收触发预警**，可配置）→ 企业微信通知
4. **自有车队场景**：司机送货后回程带回容器，扫码即可"已回收"（PDA 扫容器 LPN）
5. **第三方快递场景**：客户拒收/退货时随货返回，或专门派人取回（操作人手动标记"已回收"）
6. 回收率统计报表（按配送方分组）
7. 容器回收写入审计追踪

---

## US-M10-004：出库订单与 TMS 协作

**作为** 系统（自动）
**我要** 在出库订单"已复核"后将订单推送给外部 TMS，由 TMS 决定走自有车队还是第三方快递，并接收 TMS 调度结果
**以便** 自有车队 vs 第三方快递的路由由 TMS 统一管理，WMS 不重复决策

> 业务边界：**车辆资源/司机排班/路径规划/配送方选择由外部 TMS 决策**；WMS 推送订单 + 接收结果 + 跟随执行。

### 验收标准

1. **推送时机**：订单状态变"已复核"后，由系统自动推送给 TMS（异步）
2. **推送内容**：
   - 订单号 / 货主 / 客户/门店地址 / 商品体积+重量
   - 温区要求（冷链/常温）
   - 出库箱明细（含 LPN）
   - 计划发货日 / 时间窗
   - 优先级（加急/普通）
3. **TMS 调度结果接收**（通过 M10 TMS 接入端口并遵循 H-INT 契约）：
   - 配送方类型：**自有车队 / 第三方快递**
   - 自有车队场景：分配车辆编号 + 司机 user_id + 预计装车时间
   - 第三方快递场景：指定快递商代码（H5-001 配置的）+ TMS 给定的运单号（如 TMS 已经在快递商下单）
4. **路由分发**：
   - **自有车队** → WMS 进入装车流程（M4-006 发货交接，按司机 user_id 关联）
   - **第三方快递** → WMS 进入快递面单打印流程（H5-003 / M-PK-006），如 TMS 给了运单号则直接打面单，否则 WMS 自己调用快递商 API 下单
5. **降级**：TMS 不可用时，WMS 可手动选择配送方（仓库主管在 PC 端选）
6. **失败重试**：推送 TMS 失败 5 次后告警 + 转人工干预
7. **状态联动**：TMS 反馈"装车完成"后 WMS 订单状态变"已发货"
8. **车辆档案数据来源**：自有车辆档案由 TMS 主管，WMS 通过此故事的接收数据中带的车辆信息冗余存储（仅用于审计追踪和签收证据）
9. 推送/接收记录写入审计追踪

---

## 跨故事约束

1. **审计追踪**：所有 TMS 协作操作（推送/接收/路由分发）写入审计表
2. **冷链 GSP**：在途温控数据是合规证据，由外部冷链系统持有
3. **容器（LPN）**：回收追踪复用 M1 容器管理
4. **业务边界**：M10 是 WMS-TMS 集成模块，**WMS 不做车辆排班/路径规划/在途监控**；这些由外部 TMS / 冷链系统负责
5. **降级**：TMS 不可用不阻塞业务（保留人工录入路径 + 手动选择配送方）；冷链系统不可用不阻塞业务（仓库内业务正常）
6. **多货主**：路径/温控/回收数据按货主隔离
7. **幂等性**：TMS 重复推送同一调度结果不重复处理（用调度结果 ID 去重）

### 测试维度覆盖

#### US-M10-001 接收 TMS 路径规划结果

| 维度 | 场景 |
|------|------|
| L4 错误路径 | TMS 推送格式错误 → M10_DATA_FORMAT_INVALID; 关联订单不存在 → M10_ORDER_NOT_FOUND; TMS 接口超时 → 重试（ADR-0018 L2） |
| L5 数据一致 | 路径规划结果与出库订单关联一致; 多次推送以最新为准（版本号递增） |
| L8 权限 | 外部 TMS 通过 API Key 推送; 仓库主管可查看 |
| L11 幂等 | 同一订单 + 同一版本号重复推送 → 去重 |

#### US-M10-002 在途温控数据接入

| 维度 | 场景 |
|------|------|
| L4 错误路径 | 温控设备不存在 → M10_DEVICE_NOT_FOUND; 数据时间戳异常 → M10_INVALID_TIMESTAMP; 温度超标 → 触发 H-AL 告警 |
| L5 数据一致 | 在途温控数据与车辆/订单关联; 超标事件与 M5 冷链联动 |
| L8 权限 | 外部系统推送; 仓库主管/司机可查看; 货主查本货主 |
| L11 幂等 | 同一设备 + 同一时间戳 → 去重 |

#### US-M10-003 容器回收追踪

| 维度 | 场景 |
|------|------|
| L4 错误路径 | 容器编号不存在 → M10_CONTAINER_NOT_FOUND; 回收确认超时 → 告警; 容器已回收 → M10_ALREADY_RECOVERED |
| L5 数据一致 | 回收状态与容器台账一致; 回收数量与发出数量可对账 |
| L8 权限 | 司机可确认回收; 仓库主管可查看/催收 |
| L11 幂等 | 同一容器重复确认回收 → 返回首次结果 |

#### US-M10-004 出库订单与 TMS 协作

| 维度 | 场景 |
|------|------|
| L4 错误路径 | TMS 不可用 → 降级（人工安排配送）+ 告警; 订单取消后 TMS 已调度 → 通知 TMS 取消; 协作超时 → 重试 |
| L5 数据一致 | WMS 订单状态与 TMS 调度状态同步; 取消/变更双向一致 |
| L8 权限 | 系统自动协作; 仓库主管可手动干预 |
| L11 幂等 | 协作请求支持 Idempotency-Key; TMS 回调幂等处理 |

### PDA 弹性

> 适用故事：US-M10-003（PDA 端容器回收扫码确认）

#### 离线策略

| 场景 | 行为 |
|------|------|
| PDA 离线时确认容器回收 | 暂存回收记录; 网络恢复后同步 |

#### 扫码交互

| 场景 | 行为 |
|------|------|
| 扫描容器条码确认回收 | 解析容器编号 → 匹配发出记录 → 确认回收 |
| 扫码无匹配 | 提示"该容器不在待回收列表中" |

#### 异常恢复

| 场景 | 行为 |
|------|------|
| 回收确认同步失败 | 本地保留; 自动重试; 服务端幂等去重 |
