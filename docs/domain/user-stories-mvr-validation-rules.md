# 用户故事：M-VR 校验规则模块

> 模块：M-VR validation-rules
> 性质：横向业务模块（入库/出库订单通用的规则引擎）
> 波次：Wave 2（M2 入库 + M4 出库都依赖）
> 依赖：M1 基础档案、H1 权限、H2 审计

---

## 背景

入库（ASN）和出库订单在创建/确认时需要经过一系列业务校验（供应商资质、库存充足、客户经营范围、信用额度等）。这些校验规则**不应硬编码**，而是由业务人员在界面上配置维护，系统按规则自动执行并改变订单状态。

---

## US-VR-001：校验规则配置

**作为** 系统管理员
**我要** 在界面上配置校验规则（适用场景、条件、动作）
**以便** 业务规则变化时无需改代码，直接调整配置即可生效

### 验收标准

1. 规则适用场景：入库校验 / 出库校验（可多选）
2. 规则结构：**条件（IF）+ 动作（THEN）**
   - 条件：字段 + 运算符 + 值（支持 AND/OR 组合）
   - 动作：通过 / 拒绝 / 警告（不阻塞但标记）
3. 可用条件字段（按场景）：
   - **入库**：供应商资质有效期、供应商经营范围、商品储存条件、到货温度
   - **出库**：批号库存数量、客户/门店经营范围、客户信用额度、商品近效期天数
   - 字段列表可扩展（新增字段不改代码，配置即可）
4. 运算符：等于 / 不等于 / 大于 / 小于 / 包含 / 不包含 / 为空 / 不为空 / 已过期 / 未过期
5. 规则优先级：多条规则按优先级顺序执行，遇到"拒绝"即停止
6. 规则启用/停用（停用后不执行）
7. 规则生效时间段（可选：如促销期间临时放宽某规则）
8. 规则变更写入审计追踪

---

## US-VR-002：校验规则执行

**作为** 系统（自动）
**我要** 在订单创建/确认时自动按配置的规则逐条校验
**以便** 不合规的订单被拦截或标记，合规的订单自动流转

### 验收标准

1. 触发时机：
   - 入库：ASN 创建时自动校验
   - 出库：订单创建后自动校验（状态从"待校验"流转）
2. 执行逻辑：按优先级逐条执行规则
   - 全部通过 → 订单状态变为"已确认"
   - 遇到"拒绝" → 订单状态变为"校验异常"，记录失败原因
   - 遇到"警告" → 订单继续流转但标记警告信息
3. 校验结果记录：每条规则的执行结果（通过/拒绝/警告 + 具体原因）
4. 校验结果可在订单详情页查看
5. 校验执行写入审计追踪

---

## US-VR-003：校验异常人工处理

**作为** 仓库主管
**我要** 在界面上查看校验异常的订单，修改后重新校验或强制通过
**以便** 异常订单不会永远卡住，有人工干预的出口

### 验收标准

1. 校验异常列表：按订单类型（入库/出库）、异常原因、时间筛选
2. 查看详情：哪条规则失败、失败原因、相关数据
3. 处理方式：
   - **修改后重新校验**：修改订单数据（如换批号/换供应商）→ 重新触发校验
   - **强制通过**：跳过校验直接确认（需审批权限 + 填写强制原因）
   - **驳回**：关闭订单 / 反馈 ERP
4. 强制通过需企业微信审批（可配置是否需要审批）
5. 所有处理操作写入审计追踪

---

## US-VR-004：校验规则模板

**作为** 系统管理员
**我要** 使用预置的规则模板快速创建常用校验规则
**以便** 不用从零配置，降低配置门槛

### 验收标准

1. 系统预置模板（开箱即用）：
   - 供应商 GSP 证有效期校验
   - 供应商经营范围匹配校验
   - 出库批号库存充足校验
   - 门店经营范围校验
   - 近效期商品出库警告
2. 模板可一键启用（自动创建对应规则）
3. 启用后可修改（基于模板微调）
4. 支持自定义模板（将已有规则保存为模板）
5. 模板启用/修改写入审计追踪

---

## US-VR-005：校验规则测试

**作为** 系统管理员
**我要** 在规则上线前用模拟数据测试规则效果
**以便** 确认规则配置正确，不会误拦或漏拦

### 验收标准

1. 测试模式：输入模拟订单数据 → 执行规则 → 显示结果（通过/拒绝/警告）
2. 不影响真实数据（测试不写库、不改状态）
3. 显示每条规则的匹配过程（命中/未命中 + 原因）
4. 测试记录可保存（供后续对比）

---

## 跨故事约束

1. **审计追踪**：规则配置变更 + 规则执行结果 + 人工处理全部写入审计表
2. **多货主**：规则可按货主隔离（不同货主不同规则集）
3. **入库/出库通用**：同一套规则引擎，通过"适用场景"区分
4. **不阻塞主流程**：校验异常有人工出口（强制通过），不会让订单永远卡住
5. **可扩展**：新增校验字段不改代码，只需在规则配置中新增字段定义
6. **企业微信**：强制通过需审批时推送企业微信审批流
