# 用户故事：M-VR 规则引擎（统一）

> 模块：M-VR validation-rules
> 性质：横向业务模块（**统一的 IF-THEN 规则引擎，服务所有业务场景**）
> 波次：Wave 2（所有策略类模块都依赖）
> 依赖：M1 基础档案、H1 权限、H2 审计

---

## 背景

系统中所有"IF 条件 THEN 动作"的业务逻辑统一由 M-VR 规则引擎管理。不仅限于入库/出库校验，还包括上架策略、波次规则、补货规则等所有可配置的业务决策。

### 规则引擎服务的场景

| 场景 | 消费模块 | 规则类型 |
|------|---------|---------|
| 入库校验 | M2 | IF 供应商资质过期 THEN 拒绝 |
| 出库校验 | M4 | IF 库存不足 THEN 拒绝 |
| 上架策略 | M2 | IF 商品温区=冷链 THEN 推荐冷库库位 |
| 波次分组 | M4 | IF 同客户+同温区 THEN 合并波次 |
| 拣选路径 | M4 | IF 库区=A THEN S型遍历 |
| 出库箱规则 | M4 | IF 总重量>10kg THEN 拆箱 |
| 补货触发 | M-RP | IF 零拣位库存<阈值 THEN 生成补货任务 |
| 任务优先级 | M-TE | IF 任务类型=拣选 AND 订单加急 THEN 优先级+10 |
| 快递选择 | H5 | IF 重量<1kg AND 同城 THEN 选择闪送 |
| **双人策略** (v25) | M2 / M4 / M-SA / M-QL | IF 商品.special_drug_category=麻醉 AND process=入库 AND node=收货 THEN 双人+主管审批 |

## US-VR-001：校验规则配置

**作为** 系统管理员
**我要** 在界面上配置校验规则（适用场景、条件、动作）
**以便** 业务规则变化时无需改代码，直接调整配置即可生效

### 验收标准

1. 规则适用场景：入库校验 / 出库校验 / 上架策略 / 波次规则 / 补货规则 / 任务优先级 / 快递选择 / **双人策略** / 参数对照（可扩展）
2. 规则结构：**条件（IF）+ 动作（THEN）**
   - 条件：字段 + 运算符 + 值（支持 AND/OR 组合）
   - 动作：通过 / 拒绝 / 警告（不阻塞但标记） / **双人策略动作**（v24 新增：单人 / 双人扫码 / 双人+主管审批）
3. 可用条件字段（**从数据模型动态读取，零代码扩展**）：
   - **入库**：供应商资质有效期、商品储存条件（枚举见 M1 附录 A）、外部冷链系统推送的温度超标事件等
   - **出库**：批号库存数量、客户信用额度、商品近效期天数等（**经营范围/客户资质均由 ERP 校验，WMS 不重复**）
     - **批号校验语义澄清**：校验对象 = ERP 在订单中指定的批号；校验逻辑 = 该批号在 WMS 是否有 ≥ 订单数量的合格状态库存。WMS 不做 FIFO/FEFO 决策，分配批号是 ERP 的职责（参见 M3-002 §2 / M4-001 §跨故事约束 3）
     - **批号校验语义澄清**：校验对象 = ERP 在订单中指定的批号；校验逻辑 = 该批号在 WMS 是否有 ≥ 订单数量的合格状态库存。WMS 不做 FIFO/FEFO 决策，分配批号是 ERP 的职责（参见 M3-002 §2 / M4-001 §跨故事约束 3）
   - 系统自动从实体字段注册表读取可用字段，新增实体字段后自动可用于规则配置
4. 运算符：等于 / 不等于 / 大于 / 小于 / 包含 / 不包含 / 为空 / 不为空 / 已过期 / 未过期
5. 规则优先级：多条规则按优先级顺序执行，遇到"拒绝"即停止
6. 规则启用/停用（停用后不执行）
7. 规则生效时间段（可选：如促销期间临时放宽某规则）
8. 规则变更写入审计追踪

## US-VR-002：校验规则执行

**作为** 系统（自动）
**我要** 在订单创建/确认时自动按配置的规则逐条校验
**以便** 不合规的订单被拦截或标记，合规的订单自动流转

### 验收标准

1. 触发时机：
   - 入库：ASN 创建后自动校验（状态从"待校验"流转）
   - 出库：订单创建后自动校验（状态从"待校验"流转）
2. 执行逻辑：按优先级逐条执行规则
   - 全部通过 → 订单状态变为"已确认"（入库变为"待收货"）
   - 遇到"拒绝" → 订单状态变为"校验异常"，记录失败原因
   - 遇到"警告" → 订单继续流转但标记警告信息
   - **无规则时默认通过**（空规则集 = 不校验）
3. 校验结果记录：每条规则的执行结果（通过/拒绝/警告 + 具体原因）
4. 校验结果可在订单详情页查看
5. 校验执行写入审计追踪

## US-VR-003：校验异常人工处理

**作为** 仓库主管
**我要** 在界面上查看校验异常的订单，修改后重新校验或强制通过
**以便** 异常订单不会永远卡住，有人工干预的出口

### 验收标准

1. 校验异常列表：按订单类型（入库/出库）、异常原因、时间筛选
2. 查看详情：哪条规则失败、失败原因、相关数据
3. 处理方式：
   - **修改后重新校验**：修改订单数据（如换批号/换供应商）→ 重新触发校验
   - **强制通过**：创建"校验强制通过"类型的质量联系单（M-QL）→ 推送企业微信审批 → 审批通过后订单状态变为"已确认"
     - 强制通过的订单标记为**"合规风险"**
     - 合规风险订单在报表中单独统计（本月/本季度强制通过笔数、原因分布）
   - **驳回**：关闭订单 / 反馈 ERP
4. 强制通过需企业微信审批（可配置是否需要审批）
5. 所有处理操作写入审计追踪

## US-VR-004：校验规则模板

**作为** 系统管理员
**我要** 使用预置的规则模板一键启用常用校验规则
**以便** 不用从零配置，降低配置门槛

### 验收标准

1. 系统预置模板（开箱即用）：
   - 供应商 GSP 证有效期校验
   - 出库批号库存充足校验
   - 近效期商品出库警告
2. 模板可一键启用（自动创建对应规则）
3. 启用后可修改（基于模板微调）
4. 支持自定义模板（将已有规则保存为模板）
5. 模板启用/修改写入审计追踪

## US-VR-005：校验规则测试

**作为** 系统管理员
**我要** 在规则上线前用模拟数据测试规则效果
**以便** 确认规则配置正确，不会误拦或漏拦

### 验收标准

1. 测试模式：输入模拟订单数据 → 执行规则 → 显示结果（通过/拒绝/警告）
2. 不影响真实数据（测试不写库、不改状态）
3. 显示每条规则的匹配过程（命中/未命中 + 原因）
4. 测试记录可保存（供后续对比）

## US-VR-006：双人策略矩阵规则

**作为** 仓库主管
**我要** 用 M-VR 规则定义"特殊药品分类 × 流程 × 节点 → 双人策略"的矩阵
**以便** 任意业务模块在执行流程的每个节点前，可查询当前商品的双人策略；规则与 M1-008 矩阵 UI 双向同步

### 术语对齐（v25 重设计）

| 概念 | 含义 | 例子 |
|------|------|------|
| **流程**（process）| 端到端业务对象的生命周期 | 采购入库 / 销售出库 / 报损 / 报溢 / 销毁 / 退货 |
| **节点**（node）| 流程中的关键操作环节，是双人策略的最小粒度 | 收货、验收、上架（入库流程节点）；拣货、复核（出库流程节点）；报损执行（报损流程节点）|

### 流程-节点定义表（v25 预置）

| 流程 process | 节点 node | 实现模块 / 故事 |
|------|------|------|
| 入库 | 收货 | M2-002 |
| 入库 | 验收 | M2-003 + M2-004 |
| 入库 | 上架 | M2-005 |
| 出库 | 拣货 | M4-003 |
| 出库 | 复核 | M4-004 |
| 出库 | 装箱 | M-PK-002 |
| 出库 | 发货交接 | M4-006 |
| 报损 | 报损执行 | M-SA-001 §5 |
| 报溢 | 报溢执行 | M-SA-002 §5 |
| 销毁 | 销毁执行 | M-SA-001 §5 + 销毁原因码（销毁流程复用报损执行节点）|
| 退货 | 退货验收 | M4-008 §4 |
| 退货 | 退货上架 | M4-008 §5 |

> 流程与节点是**设计层管理**对象（变更频率极低），扩展须：(a) 经 ADR 决策 + (b) 修订本表 + (c) 同步 M1-008 §11 矩阵 UI 列定义 + (d) M1-010 字典各分类的 `requires_dual_person_matrix` 同步补默认值。**不是运营时由系统管理员在配置中心新增**。

### 验收标准

1. **规则适用场景**：双人策略（与现有"入库校验/出库校验"等并列）
2. **规则条件字段**：
   - 商品.special_drug_category（取值见 M1-010 字典）
   - 流程 process（取值见上方流程-节点定义表的 process 列，可扩展）
   - 节点 node（取值见上方流程-节点定义表的 node 列，必须属于指定 process）
   - 货主（可选，支持按货主级覆盖）
   - 仓库（可选，支持按仓库级覆盖）
3. **规则动作**（双人策略动作类型）：返回三档之一
   - `single`：单人即可
   - `dual_scan`：两个不同 user_id 扫码确认
   - `dual_scan_with_approval`：两个不同 user_id 扫码 + 仓库主管企业微信审批
4. **优先级匹配**：货主级 > 仓库级 > 全局级；同级按规则优先级
5. **未命中默认值**：规则集为空或未命中 → `single`（当前业务默认行为）
6. **查询接口**（提供给 M2 / M4 / M-SA / M-QL 调用）：
   ```
   GET /m-vr/dual-person-policy
     ?product_id=XXX
     &process=入库 | 出库 | 报损 | 报溢 | 销毁 | 退货
     &node=收货 | 验收 | 上架 | 拣货 | 复核 | 装箱 | 发货交接
          | 报损执行 | 报溢执行 | 销毁执行 | 退货验收 | 退货上架
     &owner_id=YYY
     &warehouse_id=ZZZ
   Response: { policy: "dual_scan_with_approval", source_rule_id: "...", process, node }
   ```
   - 调用方必须明示 process + node（不允许仅传 node，避免节点同名歧义）
   - 流程与节点不匹配（如 process=入库 + node=报损执行）→ 返回 4xx
7. **规则模板预置**：系统初始化时按 M1-010 字典各分类的 `requires_dual_person_matrix` 默认值生成预置规则（覆盖全部流程节点；可一键启用）
8. **矩阵 UI 同步**（与 M1-008 §11 双向）：
   - 用户在 M1-008 矩阵 UI 编辑某格（流程 Tab → 分类×节点矩阵）→ 后端自动 upsert 对应规则
   - 用户在 US-VR-001 直接编辑规则 → 矩阵 UI 自动反映（无需手动刷新）
   - 同步操作幂等（按 dict_code + process + node + 货主 + 仓库 唯一）
9. **冲突检测**：保存规则前检测是否与现有规则冲突（同条件返回不同策略），冲突时报警提示主管处理
10. **PDA 离线降级策略**：PDA 离线状态下取最近一次同步的规则缓存；缓存过期超 24 小时则禁用特殊药品操作（避免错配双人策略导致违规）；恢复联网后立即同步并校验离线期间产生的双人记录
11. 规则查询接口性能：P95 < 30ms（缓存命中），所有规则配置变更后立即失效缓存
12. **流程扩展**：新增流程或节点须经 ADR 决策（设计层变更，非运营时配置），同步更新 US-VR-006 §流程-节点定义表 + M1-008 §11 矩阵 UI 列定义 + M1-010 各分类 `requires_dual_person_matrix` 默认值；本规则的 process/node 字段在表更新后自动支持新值
13. 规则配置 / 启用 / 停用 / 同步操作写入审计追踪
14. 查询接口与同步操作支持 Idempotency-Key

## 跨故事约束

1. **审计追踪**：规则配置变更 + 规则执行结果 + 人工处理全部写入审计表
2. **多货主**：规则可按货主隔离（不同货主不同规则集）
3. **入库/出库/策略通用**：同一套规则引擎，通过"适用场景"区分校验类和策略类
4. **不阻塞主流程**：校验异常有人工出口（强制通过），不会让订单永远卡住
5. **可扩展**：新增校验字段不改代码，只需在规则配置中新增字段定义
6. **企业微信**：强制通过需审批时推送企业微信审批流
7. **冷链边界**：M-VR 不采集、不判定原始温度；规则只能使用 M5 冷链接入端口按 H-INT 契约接收的外部冷链事件（如 `temperature_exceeded_event`）和商品储存条件做业务关联
8. **幂等性**：规则配置/启用/校验执行支持 Idempotency-Key，相同输入产生相同输出
9. **"校验异常"状态名跨模块说明**（v3.1 新增，K13）：M2 入库 / M4 出库 / M8 零售连锁的状态机均含"校验异常"状态，语义一致（= 本模块规则引擎拦截单据 → 进入待人工处理），但作用域不同。审计追踪、报表、状态机图中应使用模块前缀区分（如"M2-校验异常"/"M4-校验异常"），数据库中通过 module_code + status 联合标识，避免跨模块查询时混淆

#### US-VR-001 校验规则配置

| 维度 | 场景 |
|------|------|
| L4 错误路径 | 规则表达式语法错误 → VR_RULE_SYNTAX_ERROR; 规则名重复 → VR_RULE_DUPLICATE; 删除正在使用的规则 → VR_RULE_IN_USE |

#### US-VR-002 校验规则执行

| 维度 | 场景 |
|------|------|
| L4 错误路径 | 规则执行超时 → VR_EXECUTION_TIMEOUT（降级放行 + 告警）; 规则引用的数据不存在 → VR_DATA_NOT_FOUND; 规则结果矛盾（多规则冲突）→ 取最严格 |

| L8 权限 | 系统自动执行; 校验结果对操作人可见 |
| L11 幂等 | 同一业务操作 + 同一规则集 → 相同校验结果（确定性） |

| 维度 | 场景 |
|------|------|

|------|------|
| L4 错误路径 | 测试数据格式错误 → VR_TEST_DATA_INVALID; 规则不存在 → VR_RULE_NOT_FOUND |
| L5 数据一致 | 测试结果与正式执行结果一致（同一输入同一输出）; 测试不影响生产数据 |
| L8 权限 | 仓库主管/系统管理员可测试 |
| L11 幂等 | 测试天然幂等（无副作用） |

#### US-VR-006 双人策略矩阵规则

| 维度 | 场景 |
|------|------|
| L4 错误路径 | 矩阵配置缺失（特殊药品分类无对应规则）→ VR_MATRIX_NOT_CONFIGURED; 两个签字人相同 → VR_SAME_PERSON; 签字人无对应岗位资格 → VR_UNQUALIFIED |
| L5 数据一致 | 矩阵配置与 M1-010 特殊药品分类联动; 矩阵变更后新操作立即使用 |
| L8 权限 | 仓库主管可配置矩阵; 矩阵生效需双人确认 |
| L11 幂等 | 矩阵配置变更支持 Idempotency-Key |
