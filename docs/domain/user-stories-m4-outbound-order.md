### 状态说明

| 状态 | 含义 | 进入条件 | 可执行操作 |
|------|------|---------|-----------|
| 待校验 | 订单已创建，等待规则校验 | ERP 推送 / 手工创建 | 校验规则自动执行 |
| 校验异常 | 校验不通过（库存不足/资质不符等） | 规则校验失败 | 人工修改后重新校验 / 反馈 ERP |
| 已确认 | 校验通过，等待进入波次 | 校验通过 | 作废（企微审批）、手动/自动进入波次 |
| 已入波次 | 波次算法已分配库位，等待拣选 | 波次下发 | 强制作废（保管员 PDA 回退上架）、开始拣选 |
| 库存锁定 | 保管员 PDA 正在拣选 | 开始拣选 | 拣选完成（含短拣标识） |
| 已复核 | 复核完成，等待打印发货 | 复核确认 | 打印快递单 / 随货同行单 |
| 已发货 | 已交接给快递/司机 | 快递接口反馈 + 交接确认 | 等待签收 |
| 已签收 | 客户已签收 | 快递轨迹回写 / 手动确认 | 可退货 |
| 已作废 | 未进波次时取消 | 已确认时申请 + 企微审批 | 终态 |
| 已作废(回退) | 进了波次后强制取消 | 已入波次时强制取消 | 终态（保管员 PDA 回退上架） |

### 关键规则

1. **不回退**：拣选开始后不退回任何状态，有问题"先出后退"（事后走退货流程）
2. **整单出库**：短拣订单可继续拣选/复核流程，但发货前必须补拣补齐；发货数量必须等于订单计划数量
3. **复核无不通过**：复核只做确认，有问题事后退回处理
4. **作废窗口**：已确认可正常作废；已入波次（未开始拣选）可强制作废（PDA 回退上架）
5. **库存锁定不可作废**：开始拣选后只能走完
6. **没有部分发货**：一个订单必须整单发货
7. **订单 = 主单 + 明细单**：一个订单只能属于一个波次
8. **交货地址可追溯**：订单必须保存稳定的 `delivery_address_id` 和创建时地址快照；后续地址档案修改不得改变历史订单解释

### 关键配置默认值（v13）

> 这些参数在 M1-008 配置中心可调整，以下是开箱即用的默认值。

| 配置项 | 默认值 | 可选值 | 影响 |
|------|------|------|------|
| **波次触发方式** | 定时触发（每 30 分钟）+ 手动触发 | 定时 / 手动 / 订单数阈值（≥ N 单触发）| 详见 M4-008 合单 |
| **库存扣减时机** | 发货确认时扣减（已发货状态）| 拣选完成时 / 复核完成时 / 发货时 | 影响库存可见性窗口；GSP 推荐"发货时"以匹配真实出库 |
| **复核方式** | 整单全扫码复核 | 全扫码 / 抽样复核 / 免复核（不推荐）| 详见 M4-004 三模式 |
| **拣选路径策略** | 库位编号顺序（升序）| 编号升降序 / S 型蛇形 / 启发式（贪婪）| 详见 M4-010 |

### 流程关键点

| 节点 | 关键约束 |
|------|---------|
| 整件 vs 零件路径分支 | 由 M4-003 拣选模式（pick_mode）决定，PDA 任务字段已携带 |
| 包装站复核 vs PDA 复核 | 见 M4-004 三模式（包装站 / PDA 整件 / PDA 零件）|
| 称重校验 | 仅包装站路径需要（PDA 整件直发不称重，因容器内容物已固定）|
| 追溯码核销 → 码上放心上报 | 实时触发（M-TC-007），走 H8 防腐层异步聚合推送 |
| 随货同行单 | 不论配送方都打（GSP 必备） |
| **配送方决策** | **由 TMS 主管（M10-004）**；TMS 不可用时降级到 H5-002 路由规则 |
| **PDA 端打面单**（v10 新增）| 整件直发场景免去到包装站；蓝牙打印机 + 网络打印机皆可；蓝牙超时降级到包装站补打 |
| 自有车队尾段 | 不打快递面单；走 M4-006 自有司机交接（user_id 工牌 + 数字签字）；轨迹由 M10-002 + TMS 司机上报 |
| 第三方快递尾段 | 打快递面单；走 M4-006 第三方交接（手写签字+拍照）；轨迹由 H5-005 查询 |
| ERP 反馈时机 | 订单"已发货"后异步反馈，不阻塞业务 |

### 异常分支

| 异常 | 处理 |
|------|------|
| 复核扫码不匹配 | 复核无不通过原则 → 接受 + 标记差异 + 后续退货流程处理 |
| 称重偏差超阈值 | 报警提示 → 人工确认强制通过（M-PK-003）→ 写审计 |
| 追溯码核销不匹配 | 报警拒绝 → 转人工处理（不进入下游打印）|
| TMS 不可用 | 降级到 H5-002 配送方路由规则；继续走流程 |
| 快递 API 不可用 | 降级：先打随货同行单、订单先转"已复核"等待人工补打面单（H5 跨约束）|
| PDA 蓝牙打印失败 | 提示切换打印机或前往包装站补打（运单号已生成不重复下单）|
| 交接失败（车没来 / 货没装齐）| 订单保持"已复核"，不流转"已发货" |

## US-M4-001：出库订单管理

**作为** 仓库主管（或外部系统通过 API）
**我要** 创建和管理出库订单（销售出库/调拨出库/退货出库）
**以便** 驱动后续拣选、复核、发货流程

### 验收标准

1. 订单类型：销售出库、调拨出库、退货出库
2. 订单结构：**主单 + 明细单**（主单含客户、稳定交货地址 ID、不可变地址快照和交货日期，明细含商品+批号+数量）
3. **双单号**：ERP 单号（ERP 推送时带入）+ WMS 单号（由**编码生成模块**自动生成，格式：货主编码+R+日期+流水号）
4. 订单必填：客户/门店、`delivery_address_id`、交货地址快照、商品明细（商品+**批号**+数量，批号由 ERP 指定）、要求交货日期
5. 订单初始状态为"待校验"
6. **校验模块**（独立可配置规则引擎）自动校验：
   - 指定批号在 WMS 有足够合格库存
   - 其他可配置规则（近效期警告等。**经营范围/客户资质/信用额度均由 ERP 校验，WMS 不重复**）
7. 校验通过 → 状态变"已确认"
8. 校验不通过 → 状态变"校验异常"，人工界面可修改后重新校验
9. **订单作废**：已确认（未进波次）可申请作废 → 企微审批
10. **开放 API**：支持 ERP 推送出库订单（稳定交货地址 ID + 地址快照 + 商品 + 批号 + 数量）
11. 订单创建/修改/作废写入审计追踪

## US-M4-002：波次规划

**作为** 仓库主管
**我要** 将多个出库订单合并为一个波次，由波次算法决定从哪些库位拣选并优化路径
**以便** 提高拣选效率（合并同库区/同路径的拣选动作，减少行走距离）

### 验收标准

1. 波次创建方式：
   - 手动选择订单组成波次
   - 自动波次：按规则（同客户/同库区/同配送路线/同时间窗）自动合并
2. **波次算法（WMS 核心价值）**：
   - 输入：订单明细（商品+批号+数量，批号由 ERP 指定）
   - 决策：从哪些库位拣（同商品同批号可能分布在多个库位）
   - 优化：拣选路径最短（按库位物理位置排序）
   - 约束：只从"合格"状态库位拣
3. 波次状态：待下发 → 库存锁定 → 已完成
4. 波次下发后生成拣选任务（含具体库位+数量，按路径排序）
5. 一个订单只能属于一个波次
6. 波次可取消（未开始拣选时）
7. 波次完成后自动流转到复核环节
8. 波次创建/取消写入审计追踪

### 合单参数表（核心：决定哪些订单合并为同一波次）

> 参考 Manhattan WMOS 波次模板（已记录在 docs/reviews/wave-parameters-comparison-manhattan.md）的 P0 项落地。
> 合单规则通过 M-VR 规则引擎"波次分组"适用场景配置。

#### 合并条件（IF 部分，多条件 AND/OR 组合）

| 条件类型 | 字段 | 默认值 | 说明 |
|---------|------|-------|------|
| 客户维度 | 同客户 | 启用 | 同客户多订单合并 |
| 客户维度 | 同地址 | 启用 | 同收货地址 |
| 时间窗 | 同发货日期 | 启用 | 计划发货日相同 |
| 时间窗 | 时间窗宽度（小时）| 24 | 默认 24 小时内的订单可合并 |
| 温区 | 同温区 | 强制 | 不同温区**禁止合并**（GSP 强制）|
| 货主 | 同货主 | 强制 | 不同货主**禁止合并**（多货主隔离）|
| 配送 | 同配送路线 | 可选 | 关联 M10-001 路径优化 |
| 品类 | 同品类组 | 可选 | 特殊品类（精麻药）单独成波 |

#### 容量上限（一旦满足任一上限，新订单不再加入当前波次，开新波次）

| 上限类型 | 字段 | 默认值 | 来源 |
|---------|------|-------|------|
| **最大订单数** | max_orders | 100 | 防止单波次过大失控 |
| **最大订单行数** | max_order_lines | 1000 | 总明细行 |
| **最大件数** | max_units | 10000 | 总件数 |
| **最大重量** | max_weight_kg | 1000 | 关联 M4-009 箱型重量 |
| **最大体积** | max_volume_cm3 | 5_000_000 | 关联 M4-009 箱型体积 |
| **最大拣货任务数** | max_pick_tasks | 500 | 子任务数（关联 M-TE 任务）|

#### 失败处理（核心：单订单异常对整波的影响）

| 场景 | 默认策略 | 可选 |
|------|---------|------|
| 单订单库存校验失败 | 该订单转校验异常，**波次继续** | 整波 abort（保守模式）|
| 单订单 PDA 短拣异常 | 该订单标短拣并生成补拣任务，**波次继续**；发货前必须补拣补齐 | — |
| 单订单交货地址错误 | 该订单转校验异常，**波次继续** | — |
| 拣选员长时间未领单（超 4h）| 自动重分配（M-TE-005）| 主管手动介入 |

#### 波次类型（v9 新增分类）

| 类型 | 触发 | 备注 |
|------|------|------|
| 客户订单波次 | M4-001 出库订单合并 | 默认 |
| 补货波次 | M-RP 补货任务批量化 | 待 Wave 4 补 |
| 退货上架波次 | M4-008 退货验收合格批量上架 | 待 Wave 4 补 |
| 差异处理波次 | M-RC 对账差异 / 短拣补拣 | M4 发货前置校验依赖 |

## 跨故事约束（适用于所有 M4 用户故事）

1. **审计追踪**：所有出库操作（校验/拣选/复核/发货/退货/作废）写入审计表
2. **多货主**：订单绑定货主，数据按货主隔离；随货同行单用货主抬头
3. **出库批号由 ERP 指定**：WMS 只校验库存并决定从哪个库位拣（波次算法）
4. **库存锁定与扣减**：波次分配时锁定数量（状态不变，锁定部分不可再分配）；发货确认时正式扣减
5. **ERP 反馈**：发货完成后异步反馈 ERP"已出库"（商品/批号/数量/时间），失败可重试
6. **双人复核（动态化）** (v25)：拣选人 ≠ 复核人为最低保障，但是否需要双人扫码 / 双人+主管审批由 M-VR 双人策略矩阵（US-VR-006）按 process=出库 + node=拣货/复核/装箱/发货交接 + process=退货 + node=退货验收/退货上架 动态决定（v25 流程-节点二维），矩阵 UI 在 M1-008 §11；普通药品矩阵默认仅 node=复核 双人扫码，特殊药品按 M1-010 字典预置默认值；显式调用见 M4-003 §10、M4-004 §6、M4-006 §9、M4-008 §4-§5、M-PK-002 §4
7. **不回退**：拣选开始后不退回任何状态，有问题"先出后退"（事后走退货流程）
8. **整单出库**：短拣订单可继续拣选/复核流程，但发货前必须补拣补齐；发货数量必须等于订单计划数量
9. **没有部分发货**：一个订单必须整单发货
10. **复核无不通过**：复核只做确认，有问题事后退回处理
11. **业务边界**：经营范围/客户资质/信用额度等合规校验由 ERP 负责，WMS 不重复
12. **强制作废回退**：已入波次未拣选时可强制作废，保管员 PDA 回退上架
13. **PDA 离线**：拣选支持离线暂存；离线期间冲突由跨故事约束统一处理（暂存待主管处理）
14. **幂等性**：所有写操作支持 Idempotency-Key
15. **开放 API**：订单创建、订单状态查询支持外部系统调用
16. **打印模板**：随货同行单、快递单、交接单使用 H9 打印模板引擎
17. **企业微信通知**：短拣差异、校验异常、强制作废通知仓库主管
