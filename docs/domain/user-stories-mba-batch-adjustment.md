# 用户故事：M-BA 批号调整模块（batch-adjustment）

> 模块：M-BA batch-adjustment
> 性质：库内业务模块（主数据级修正）
> 波次：Wave 3（依赖 M3 库存 + M-QL 联系单 + H8 ERP 防腐层）
> 依赖：M1 基础档案、M3 库存、M-QL 质量联系单、M-TC 追溯码、H1 权限、H2 审计、H4 企业微信、H8 ERP 防腐层

---

## 背景

业务场景：已入库的库存发现批号录入错误（如 ERP 推送的 ASN 批号与实物外箱批号不一致 / 收货员误录），需要对 WMS 内部数据做主数据级修正。

**关键边界**（v21 决策）：

1. **WMS 主动发起**（不接收 ERP 推送批号修改单）
2. **WMS 修正后通知 ERP**（H8 防腐层异步反馈，单向 WMS → ERP）
3. **GSP 关键字段** → 必须双人审批（仓库主管 + 质量负责人）
4. **复用 M-QL 联系单**（不新增审批源枚举，类型=批号调整）
5. **追溯码联动**：仅更新 WMS 内部码库（M-TC 追溯码表）的批号字段；**不需要**反向通知"码上放心"（v21 业务确认：平台只收码 + 状态，不收批号）

---

## 跨故事约束

1. **审计追踪**：所有批号调整操作写入 H2 审计；旧批号 + 新批号 + 操作人 + 审批人均记录
2. **多货主隔离**：批号调整按货主隔离，不允许跨货主操作
3. **GSP 合规**：批号是法定字段，所有变更可追溯 ≥ 5 年；记录格式满足 GSP 第 5 章计算机系统操作记录要求
4. **幂等性**：调整单支持 Idempotency-Key；同一调整单二次执行返回相同结果
5. **审批源**：调用 M3 库存批号变更接口时携带 `approval_source = 质量联系单, approval_id = M-QL 联系单 ID`（M3-003 现有 7 类枚举之一，不新增）
6. **状态机闭合**：批号调整单走 M-QL 联系单状态机（待审批/已审批/已完成/已拒绝）+ 本模块自有的执行状态机
7. **不允许批号"调回去"**：错改后再改回需要新建调整单（保留完整历史，不允许覆盖）
8. 测试要求：写操作必须含 L4（错误路径）+ L5（数据一致）+ L8（权限）+ L11（幂等）；读操作必须含 L4 + L8

## US-BA-001：创建批号调整单

**作为** 仓库主管 / 收货员（PDA） / 系统管理员
**我要** 在 PC 端或 PDA 端创建批号调整单（指定商品 + 库位 + 数量 + 旧批号 + 新批号 + 调整原因）
**以便** 启动批号调整流程，闭环 GSP 主数据级修正

### PDA 三件套

#### 字段表

| 字段 | 项目 | 必填 | 核对项 |
|------|------|------|--------|
| 商品编码 | 业务标识 | 是 | 扫商品码或库位带出 |
| 库位 | 物理位置 | 是 | 扫库位码 |
| 旧批号 | 当前批号 | 是 | 系统从 M3 库存带出 |
| 新批号 | 目标批号 | 是 | 录入或扫外箱批号条码 |
| 数量 | 调整数量 | 是 | 默认全量；可拆分调整 |
| 调整原因 | 枚举 | 是 | ERP 推错 / 收货员误录 / 外箱标签错 / 系统错乱 / 其他 |
| 实物批号照片 | 证据 | 是 | 拍外箱实物批号 ≥1 张 |
| 联系单关联 | 自动 | 是 | 系统创建/关联 M-QL 联系单（类型=批号调整）|

#### 扫码顺序

1. 扫库位码 → 系统弹出库位上的商品+批号清单
2. 选择要调整的商品 + 旧批号 → 显示当前数量
3. 扫商品外箱批号条码 OR 录入新批号
4. 拍照（实物外箱批号）+ 选调整原因 + 提交
5. 系统自动创建 M-QL 联系单 → 走双人审批流（US-BA-002）

#### 离线声明

PDA 创建批号调整单**支持离线**：扫码、拍照、录入均可在无网络下完成；本地暂存到调整单队列；恢复网络后自动同步。**审批阶段必须在线**（双人审批 + ERP 反馈需要联网）。

### 验收标准

1. **触发端**：PC（仓库主管 / 系统管理员）+ PDA（收货员发现批号错时即时发起）
2. **必填字段**：商品 + 库位 + 旧批号 + 新批号 + 数量 + 调整原因 + 实物照片
3. **校验**：
   - 旧批号必须存在于该库位的 M3 库存中
   - 新批号格式校验（按 M1-001 商品档案的批号规则）
   - 新批号若已存在该商品库存中 → 提示"将与现有批号合并"+ 主管确认
4. **联系单创建**：系统自动创建 M-QL 联系单（类型=批号调整）+ 关联本调整单 ID
5. **状态初始化**：调整单状态 = 待审批
6. **PDA 即时发起场景**：收货员在 PDA 验收/上架时发现批号错 → 直接 PDA 端发起调整单（即时性）
7. **审计**：actor = 创建人 user_id，记录所有字段 + 实物照片 hash
8. **多货主隔离**：调整单与库存货主一致

## US-BA-002：批号调整双人审批

**作为** 仓库主管 + 质量负责人
**我要** 通过企业微信审批批号调整单
**以便** 把控 GSP 关键字段变更，避免误改、滥改

### 验收标准

1. **审批人**：仓库主管 + 质量负责人（双人审批，**两人都同意才放行**）
2. **审批方式**：H4 企业微信审批（双卡片同时推送给两人）
3. **审批人查看的内容**：
   - 调整单详情（商品 / 旧批号 / 新批号 / 数量 / 调整原因）
   - 实物照片（拍批号外箱）
   - 影响评估：受影响的库存数量、是否已扫追溯码、是否已上报码上放心
   - 历史相关：该商品近期批号调整历史
4. **审批选项**：
   - 同意（必填批注）
   - 拒绝（必填理由）
   - 退回补充材料（要求重新拍照 / 补充原因说明）
5. **任一人拒绝 → 调整单关闭**（状态=已拒绝），通知发起人 + 重新发起
6. **任一人退回 → 调整单回到草稿**，发起人补充后重新提交
7. **两人都同意 → 调整单状态变"已审批"**，触发 PDA 执行（US-BA-003）
8. **审批超时**（默认 24 小时，可配置）→ 升级通知主管的主管（区域经理 / 公司质量负责人）
9. **审计**：每个审批动作均写审计（actor = 审批人 user_id，approval_source = 质量联系单，approval_id = M-QL 联系单 ID）
10. **GSP 合规**：审批意见、批注、时间戳、双人 user_id 均保留 ≥ 5 年

## US-BA-003：PDA 执行批号调整（实物核对 + 库存与追溯码联动）

**作为** 保管员（接收已审批的调整单）
**我要** 在 PDA 上扫码执行批号调整，物理上验证后系统更新库存批号 + 追溯码记录批号字段
**以便** 完成实物与系统数据的同步修正

### PDA 三件套

#### 字段表

| 字段 | 项目 | 必填 | 核对项 |
|------|------|------|--------|
| 调整单号 | 业务标识 | 是 | 扫单号或从待办列表选 |
| 库位码 | 物理验证 | 是 | 扫库位码核对位置 |
| 商品码 | 物理验证 | 是 | 扫商品码核对商品 |
| 旧批号 | 系统带出 | 是 | 与调整单一致 |
| 新批号扫码确认 | 物理验证 | 是 | 扫商品外箱批号条码（**实物必须与新批号一致**才放行）|
| 数量核对 | 物理盘点 | 是 | 实际可调整数量（如不足则报警）|
| 完成签字 | 操作确认 | 是 | 保管员工牌签字 |

#### 扫码顺序

1. 扫调整单号 → 系统拉取调整单详情
2. 扫库位码 → 校验库位匹配
3. 扫商品码 → 校验商品匹配
4. 扫商品外箱新批号条码 → **实物必须与调整单"新批号"一致**（不一致则报警拒绝）
5. PDA 显示数量 + 操作员确认 + 工牌签字
6. 提交 → 系统执行：M3 库存批号字段更新 + M-TC 内部码库批号字段同步 + ERP 反馈队列

#### 离线声明

执行操作**需要联网**（涉及主数据修改 + 双向数据同步，不允许离线暂存延迟）；离线时提示"无网络，无法执行批号调整"。

### 验收标准

1. **执行前置条件**：调整单状态 = 已审批
2. **三道实物核对**：库位码 + 商品码 + 新批号外箱条码扫码全部匹配
3. **任何不匹配 → 报警拒绝**：写"实物核对失败"审计 + 通知仓库主管 + 调整单回到"已审批"等再次执行
4. **库存批号更新**（M3 库存层）：
   - UPDATE 库存表：批号字段 旧 → 新
   - 携带 `approval_source = 质量联系单, approval_id = M-QL 联系单 ID`
   - 旧批号 + 新批号 + 数量写库存流水（M3 库存流水）
5. **追溯码内部库批号同步**（M-TC 追溯码表）：
   - 找出该库位 + 商品 + 旧批号关联的所有追溯码
   - 批量 UPDATE 追溯码表：批号字段 旧 → 新
   - **不上报码上放心**（v21 决策：平台只收码+状态，不传批号）
6. **数量核对**：
   - 如实际数量 < 调整单数量 → 提示"实物不足"+ 询问是否仅调整可见数量
   - 如实际数量 > 调整单数量 → 提示"超出调整范围，请检查或拆分调整"
7. **完成后状态**：调整单状态 = 已完成 + M-QL 联系单状态 = 已完成
8. **触发 ERP 反馈**：异步推送到 ERP（US-BA-004）
9. **审计**：执行人 user_id + 三道扫码记录 + 实际数量 + 完成时间，全部写审计
10. **离线限制**：本故事强制联网（区别于 US-BA-001 创建可离线）

## US-BA-004：ERP 反馈批号调整结果

**作为** 系统（自动）
**我要** 在批号调整执行完成后，通过 H8 ERP 防腐层异步推送到 ERP
**以便** ERP 主数据保持与 WMS 一致

### 验收标准

1. **触发时机**：US-BA-003 执行完成后立即入队
2. **推送通道**：H8 ERP 防腐层"批号调整反馈"通道（新增子通道）
3. **推送内容**：
   - 调整单号、商品、库位、旧批号、新批号、数量
   - 调整原因、双人审批人 user_id、执行人 user_id
   - 调整完成时间戳
   - **不包含追溯码列表**（追溯码归 M-TC，与 ERP 主数据无关）
4. **失败处理**：
   - 自动重试（5 次/5 分钟间隔）
   - 24 小时仍失败 → H4 通知仓库主管 + ERP 对接负责人
   - 进入待补传队列（人工干预）
5. **ERP 反馈回写**：
   - ERP 收到后处理 → 回写"已确认接收" / "已更新主数据" / "拒绝接收（原因）"
   - 回写内容写入审计 + 调整单关联状态
6. **降级**：ERP 不可用时本地持久化调整单 + 失败队列；不阻塞 WMS 业务
7. **幂等性**：同调整单 ID 重复推送不重复处理
8. **审计**：每次推送 / 重试 / 回写均写审计

## 业务边界声明

> M-BA 批号调整模块的边界（v21 决策）：
>
> 1. **WMS 主动发起**：不接收 ERP 推送的批号修改单（与 M-SA 报损单的 ERP 推送方向相反）
> 2. **WMS → ERP 单向反馈**：调整完成后通知 ERP；ERP 处理是 ERP 内部事务
> 3. **审批源复用 M-QL**：不新增"批号调整"审批源枚举，复用 `质量联系单`（M3-003 现有 7 类）
> 4. **追溯码联动仅 WMS 内部**：M-TC 内部码库批号字段同步；**不上报"码上放心"**（v21 业务确认：平台只收码+状态）
> 5. **GSP 法定字段保护**：批号是 GSP 监管核心字段，本模块强制双人审批 + 实物三道核对
> 6. **离线限制**：US-BA-001 创建可离线（PDA 即时发起），US-BA-002/003/004 必须联网（审批 + 主数据修改 + ERP 反馈）

### 测试维度覆盖

#### US-BA-001 批号调整申请

| 维度 | 场景 |
|------|------|
| L4 错误路径 | 原批号不存在 → BA_BATCH_NOT_FOUND; 新批号格式不合法 → BA_BATCH_FORMAT_INVALID; 调整原因未填 → BA_REASON_REQUIRED; 批次有未完成出库 → BA_BATCH_IN_USE |
| L5 数据一致 | 调整申请与原批次状态关联; 申请不立即生效（需审批） |
| L8 权限 | 仓库主管可申请; 保管员 → 403; 跨货主 → 403 |
| L11 幂等 | 创建支持 Idempotency-Key |

#### US-BA-002 批号调整审批与执行

| 维度 | 场景 |
|------|------|
| L4 错误路径 | 审批人无权限 → 403; 审批超时 → 通知升级; 执行时原批次已变更 → BA_BATCH_CHANGED（需重新确认） |
| L5 数据一致 | 审批通过后原批次库存减 + 新批次库存增原子; 追溯码关联同步更新; 审计记录完整 |
| L8 权限 | 质量负责人审批; 需双人确认; 执行需仓库主管 |
| L11 幂等 | 审批/执行支持 Idempotency-Key; 重复执行 → 返回已执行状态 |

#### US-BA-003 批号调整 PDA 操作

| 维度 | 场景 |
|------|------|
| L4 错误路径 | 扫码批次与申请不匹配 → BA_BATCH_MISMATCH; 调整数量 > 实际库存 → BA_QTY_EXCEEDED |
| L5 数据一致 | PDA 操作结果与 PC 端一致; 调整后库位库存准确 |
| L8 权限 | 仓库主管/保管员可操作（已审批的调整单） |
| L11 幂等 | 同一调整单重复确认 → 返回已执行状态 |

#### US-BA-004 批号调整查询与追溯

| 维度 | 场景 |
|------|------|
| L4 错误路径 | 查询时间范围过大 → 分页; 无匹配 → 空列表 |
| L5 数据一致 | 调整历史与审计追踪一致; 可从新批号反查原批号 |
| L8 权限 | 仓库主管查本仓; GSP 审计员查全部 |
| L11 幂等 | 查询天然幂等 |

### PDA 弹性

> 适用故事：US-BA-002/003（PDA 端批号调整扫码操作）

| 场景 | 行为 |

#### 扫码交互

| 场景 | 行为 |
