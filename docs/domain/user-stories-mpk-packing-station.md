# 用户故事：M-PK 包装站

> 模块：M-PK packing-station
> 性质：独立业务模块（出库复核后的装箱/称重/贴面单环节）
> 波次：Wave 4（依赖 M4 出库复核完成 + M-TE 任务引擎 + H5 快递）
> 依赖：M4 出库、M-TE 任务引擎、M-TC 追溯码、H5 快递、M1 商品（重量/体积）

---

## 背景

拣选复核完成后，商品进入包装站进行装箱、称重校验、追溯码核验、贴快递面单。支持多品合箱和保温箱配置。

---

## US-PK-001：包装站工位管理

**作为** 系统管理员
**我要** 配置包装站工位（工位编号、绑定设备、适用温区）
**以便** 系统按工位状态和负载分配任务，避免单工位积压

### 验收标准

1. 工位属性：编号、名称、绑定打印机、绑定电子秤、适用温区（常温/冷链）

3. 保管员登录工位（PDA/PC 扫工位码）→ 工位变忙碌
4. 工位配置变更写入审计追踪

## US-PK-002：装箱作业

**作为** 保管员（包装岗）
**我要** 在包装站或 PDA 上将拣选完成的商品装入出库箱
**以便** 商品安全包装后可以发货

### 装箱模式

装箱按订单/波次属性自动选择两种模式：

| 模式 | 执行位置 | 适用场景 |
|------|---------|---------|
| **包装站装箱** | 包装站 PC + 工位（电子秤、打印机）| 多 SKU 合箱、零件复核完成、需称重 |
| **PDA 装箱** | PDA（库内/移动）| 整件直发（整托整箱出库不拆包装、单订单单容器）|

### 验收标准

> 含通用验收标准 + 两种模式（包装站装箱 / PDA 装箱）各自的扫码顺序和字段表。

1. 包装任务来源：拣选复核（M4-004）完成后，M-TE 任务引擎生成"装箱"任务，按场景分配到包装站或 PDA
2. **出库箱尺寸推荐**：波次生成时（M4-009）已计算每订单的出库箱尺寸（小/中/大/特大），装箱时按推荐尺寸取空箱；保管员可手动调整（差异需备注）
3. 装箱完成后扫出库箱码封箱确认（生成出库箱 LPN，关联订单）
4. **双人策略动态查询**（v25 新增）：装箱前调 M-VR 双人策略接口（US-VR-006）按 process=出库 + node=装箱 查询；返回 dual_scan / dual_scan_with_approval 时需另一保管员扫码或主管审批通过方可封箱；普通药品默认 single；麻精毒放/放射性按 M1-010 字典默认值 dual_scan_with_approval（混箱风险高，强制双人）
5. 装箱记录写入审计追踪（含模式、推荐尺寸、实用尺寸、调整原因、双人策略命中规则 ID + 第一/第二操作人 user_id）
6. **离线支持**：PDA 装箱支持离线暂存；包装站模式不支持离线（PC 长在线 + 电子秤需联网）；离线期间订单状态被改时按跨故事约束 9"暂存为'待主管处理'"

### 模式 1：包装站装箱（PC + 工位）

#### 扫码顺序

```
1. 扫工位码 → 关联当前包装站（M-PK-001）
2. 扫订单号或波次号 → 拉取待装箱明细 + 系统推荐尺寸
3. 取对应尺寸空箱 → 扫空箱码（出库箱 LPN）
4. 循环扫 商品码/追溯码 → 装入箱中（系统逐项打勾）
5. 装满或扫完 → 转 M-PK-003 称重校验 → M-PK-006 打面单
```

#### 字段表

| 字段 | 必填 | 系统带出/录入 | 说明 |
|------|------|-------------|------|
| 装箱任务 ID | 系统带出 | — | M-TE 生成 |
| 工位码 | 系统带出 | 扫码 | M-PK-001 工位 |
| 订单号 / 波次号 | 系统带出 | 扫码确认 | |
| 推荐箱型 | 系统带出 | — | 从 M4-009 出库箱规则计算 |
| 实用箱型 | 必填 | 扫码确认 | 推荐 ≠ 实用时需选调整原因 |
| 调整原因 | 条件必填 | 选择 | 推荐尺寸不可用/商品形状特殊/客户要求/其他 |
| 出库箱 LPN | 必填 | 扫码 | 空箱码 |
| 装入商品列表 | 系统带出 | 扫码累计 | 商品编码 + 批号 + 数量 |
| 装箱人 user_id | 系统带出 | — | |
| 装箱完成时间 | 系统带出 | — | |

### 模式 2：PDA 装箱

#### 扫码顺序


| 订单号 | 系统带出 | 扫码确认 | |
| 推荐箱型 | 系统带出 | — | |
| 实用箱型 | 必填 | 扫码确认 | |
| 调整原因 | 条件必填 | 选择 | 同模式 1 |
| 出库箱 LPN | 必填 | 扫码 | |

## US-PK-003：称重校验

**作为** 保管员（包装岗）
**我要** 在封箱后对出库箱称重，系统自动校验实测重量与理论重量偏差是否在阈值内
**以便** 发现漏装/多装/错装

### 验收标准

1. 电子秤自动读取重量（对接电子秤设备）
2. 系统计算理论重量 = 箱内所有商品重量之和 + 包材重量
3. **校验规则**：实际重量与理论重量的偏差 < 可配置阈值（默认 ±5%）
4. 偏差超标 → 报警提示（可能漏装/多装）→ 需人工确认
5. 人工确认后可强制通过（记录原因）
6. 称重记录写入审计追踪

## US-PK-004：保温箱配置（冷链）

**作为** 系统（自动建议）/ 保管员
**我要** 根据商品温区和当前气温，建议保温箱型号和蓄冷剂（冰袋）配置
**以便** 冷链商品在运输途中保持温度合规

### 验收标准

1. 触发条件：出库箱内含冷链商品
2. 系统建议（**仅给建议；运输途中实际温度由外部冷链系统监控，不在 WMS 范围内**）：
   - 保温箱型号（根据体积，参 M4-009 箱型主数据）
   - 蓄冷剂数量（根据运输时长 × 当前气温 × 商品温区要求；当前气温由外部冷链系统提供或保管员手填）
3. 配置规则可维护（气温区间 → 蓄冷剂数量映射表）
4. 保管员确认或调整建议
5. 保温箱配置记录写入审计追踪（GSP 冷链发货前记录；运输途中温度由外部冷链系统持有，参 M5-002）

## US-PK-005：追溯码出库核验

**作为** 保管员（包装岗）
**我要** 在装箱时扫追溯码核验商品身份和数量
**以便** 确保出库商品与订单一致，满足追溯要求

### 验收标准

1. 装箱时扫追溯码 → 系统从码库查询：商品/批号/效期/数量
2. 自动比对订单明细：品种、批号、数量
3. 不匹配报警（扫错品/扫错批）
4. 扫码完成后追溯码状态变为"已出库"
5. 支持大码扫码（自动展开为中/小码数量）
6. 核验记录写入审计追踪

---

## US-PK-006：快递面单打印

**作为** 保管员（包装岗）
**我要** 在装箱完成后打印快递面单并贴到出库箱上
**以便** 包裹可以交接给快递

### 验收标准

1. 装箱 + 称重 + 追溯码核验全部完成后可打印
2. 系统按 H5 快递选择规则自动推荐快递商
3. 调用快递 API 获取运单号 → 打印面单
4. 面单贴到出库箱 → 扫面单条码确认关联
5. 一个出库箱一张面单
6. 打印记录写入审计追踪

## 跨故事约束

1. **审计追踪**：所有包装操作写入审计表
2. **任务引擎**：包装任务通过 M-TE 分配到工位
3. **追溯码**：装箱时必须扫码核验（复用 M-TC 模块）
4. **快递**：面单打印复用 H5 快递模块
5. **称重设备**：需对接电子秤硬件（串口/USB/网络）
6. **打印模板**：面单使用 US-M2-009 打印模板引擎
7. **冷链 GSP**：保温箱配置记录是 GSP 合规证据
8. **多货主**：包装按货主隔离（不同货主的商品不混箱）
9. **幂等性**：装箱/称重/快递面单/追溯码核验所有写操作支持 Idempotency-Key

### PDA 弹性

> 适用故事：US-PK-002（PDA 装箱扫码）、US-PK-005（PDA 追溯码核验）

#### 离线策略

| 场景 | 行为 |
|------|------|
| PDA 离线时装箱 | 装箱数据暂存本地; 网络恢复后同步; 冲突（订单已被他人装箱）→ 提示 |
| PDA 离线时核验追溯码 | 本地缓存码库执行离线核验; 标记"离线核验，待服务端确认" |

#### 扫码交互

| 场景 | 行为 |
|------|------|
| 装箱扫商品码 | 匹配订单明细 → 计数 → 放入当前箱 |
| 装箱扫箱号码 | 切换到该箱 → 显示已装商品 |
| 核验扫追溯码 | 匹配当前箱内商品 → 核验通过/失败 |
| 扫码无匹配 | 提示"该商品不在当前订单/箱中" |

#### 异常恢复

| 场景 | 行为 |
|------|------|
| 装箱过程中 APP 崩溃 | 重启后恢复; 已扫码数据保留 |
| 称重过程中蓝牙断开 | 提示重连; 重连后自动重新读取 |
| 打印中途断开 | 进入待补打队列; 重连后提示补打 |
