# 用户故事：H-Driver 司机端

> 模块：H-Driver driver-portal
> 依赖：H1 权限/多租户、H2 审计、M4 出库（M4-006 发货交接）、M10 TMS 集成（M10-002 在途温控）、H4 企业微信通知
> 关联 ADR：0001（技术栈）、0006（TDD）
> 业务边界：本模块为 v13 P2 决策 B 选项的 Wave 4 W4.E 落地。司机此前在 M1-006 角色清单标"被动"，v15 升级为主动 actor 的故事

---

## 角色清单

> 本文件唯一主角色为"司机"（M1-006 中已定义为被动角色，v15 W4.E 升级为主动故事 actor）。
>
> 司机分两类：
> - **自有车队司机**：有 user_id（系统员工或长期合作司机），扫工牌签字
> - **第三方快递司机**：仅记录姓名/手机号，手写签字+拍照（不在本模块范围，由 H5 快递处理）
>
> 本文件**仅服务自有车队司机**。

---

## 跨故事约束

1. **审计追踪**：司机所有签收/上报操作均写入 H2 审计追踪（actor = 司机 user_id）
2. **多货主隔离**：司机仅能看到自己被分配的订单（H1 权限边界）
3. **离线支持**：所有 PDA/移动端操作支持离线暂存，恢复网络后自动同步（≤ 5 分钟同步窗口）
4. **GSP 合规**：所有交接、签收、温控上报数据保留 ≥ 5 年
5. **幂等性**：所有写操作支持 Idempotency-Key，相同 key 二次提交返回相同结果
6. **业务边界**：司机不能修改订单内容（仅签收/上报）；调度由 TMS 主管，本模块仅承载司机的执行端
7. 测试要求：写操作必须含 L4（错误路径）+ L5（数据一致）+ L8（权限）+ L11（幂等）；读操作必须含 L4 + L8

## US-DR-001：司机端登录与今日任务列表

**作为** 自有车队司机
**我要** 在司机端 App（PDA 或手机）登录后查看今日分配给我的配送任务
**以便** 知道今天要送哪些订单、去哪些地点、运送什么货物

### PDA 三件套

#### 字段表

| 字段 | 项目 | 必填 | 核对项 |
|------|------|------|--------|
| 司机工牌号 | 登录账号 | 是 | 与 user_id 关联 |
| 任务列表 | 订单号 / 客户 / 收货地址 / 计划送达时间 / 是否冷链 | 是 | 系统按 TMS 调度结果带出 |
| 总任务数 | 任务统计 | 是 | 含未完成 / 已完成 / 异常 三态 |

#### 扫码顺序

1. 扫工牌（或输入工号 + 密码）→ 登录
2. 扫订单号或点击列表 → 进入订单详情
3. 详情页可继续扫追溯码 → 验证货物匹配（可选）

#### 离线声明

司机端登录态缓存 24 小时；任务列表本地缓存；离线时仍可查看任务详情和上报信息（暂存到本地队列），恢复网络后自动同步。

### 验收标准

1. **登录方式**：工牌扫码 / 工号 + 密码（H1 权限统一鉴权，含 token 机制）
2. **任务列表显示**：
   - 订单号、客户名称、收货地址、计划送达时间、是否冷链
   - 状态：未开始 / 在途 / 已签收 / 异常
   - 按计划送达时间升序
3. **任务来源**：M10-001 接收的 TMS 路径规划结果中含本司机的订单
4. **支持视图切换**：列表 / 地图（地图上显示所有任务地点 + 路径，使用第三方地图 API）
5. **多货主显示**：每个订单显示货主标识（多货主场景）
6. **当日任务实时刷新**：每 5 分钟拉一次新任务（TMS 可能调整）
7. **冷链订单标识**：保温箱配置 + 商品冷链属性高亮显示
8. **审计**：登录、任务查看写入审计

## US-DR-002：司机签收（自有车队交接确认）

**作为** 自有车队司机
**我要** 在订单从仓库交接给我时扫码确认签收
**以便** 完成 M4-006 发货交接的司机端动作，订单状态从"已复核"流转到"已发货"

### PDA 三件套

#### 字段表

| 字段 | 项目 | 必填 | 核对项 |
|------|------|------|--------|
| 订单号 | 业务标识 | 是 | 与 M4 订单一一对应 |
| 容器 LPN | 物理载具 | 是 | 一个订单可含多个容器（保温箱/普通箱）|
| 数字签字 | 司机确认 | 是 | 司机在屏幕上签名（电子签）|
| 工牌签字 | 身份验证 | 是 | 扫工牌触发，actor = 司机 user_id |
| 签收时间 | 系统自动 | 是 | 服务端时间戳 |
| 备注 | 异常说明 | 否 | 如"破损 1 件"等 |

#### 扫码顺序

1. 扫订单号 → 系统带出订单详情和容器列表
2. 逐个扫容器 LPN → 系统核对完整性（容器数量 = 订单容器数）
3. 拍照（可选）→ 签字（电子签 + 工牌扫码）
4. 提交 → 订单状态变"已发货"，触发 M10-002 在途监控启动

#### 离线声明

签收支持离线：扫码、签字、拍照均可在无网络下完成，本地暂存队列；恢复网络后批量同步到服务端。同步成功后才正式更新订单状态（在途监控延后启动）。

### 验收标准

1. **签收前置条件**：订单状态必须为"已复核"（M4 状态机）
2. **容器完整性校验**：扫码核对容器 LPN 数量与订单一致；少扫 → 提示"还有 N 个容器未扫"；多扫 → 提示"容器不在订单"
3. **签字方式**：
   - 电子签字（屏幕画押）
   - + 工牌扫码（actor = 司机 user_id，与电子签字双重身份验证）
4. **拍照（可选）**：交接现场拍照（如有破损）
5. **冷链订单额外字段**：保温箱编号 + 蓄冷剂数量记录（M-PK-004 发货前记录的，司机签收时核对）
6. **数据一致性**：
   - 签收后订单状态变"已发货"（M4 状态机 [已复核 → 已发货]）
   - 触发 M10-002 在途监控启动
   - 触发 ERP 反馈"已出库"
7. **失败重试**：网络错误时本地暂存，最多重试 3 次，失败则标"待人工处理"
8. **审计**：actor = 司机 user_id，记录签收时间、签字图片 hash、容器列表、备注、approval_source = `司机签收`
9. **GSP 合规**：所有签收记录保留 ≥ 5 年

## US-DR-003：在途异常上报

**作为** 自有车队司机
**我要** 在配送途中遇到异常时（车辆故障 / 路线绕行 / 客户不在 / 货物破损 / 冷链故障等）能在司机端 2 分钟内完成上报
**以便** 仓库主管在异常发生后 5 分钟内收到通知并处置，避免影响 GSP 合规

### PDA 三件套

#### 字段表

| 字段 | 项目 | 必填 | 核对项 |
|------|------|------|--------|
| 订单号 | 关联订单 | 是 | 必须是当前在途订单 |
| 异常类型 | 枚举 | 是 | 车辆故障 / 路线绕行 / 客户拒收 / 货物破损 / 冷链温度超标 / 其他 |
| 异常描述 | 文本 | 是 | 详细情况说明 |
| GPS 位置 | 自动捕获 | 是 | 上报时点的位置坐标 |
| 异常时间 | 系统自动 | 是 | 服务端时间戳 |
| 拍照 | 多张 | 是 | 异常现场至少 1 张照片 |

#### 扫码顺序

1. 选择当前订单（任务列表选择 OR 扫订单号）
2. 选异常类型（按钮列表）
3. 填描述 + 拍照（至少 1 张）
4. 提交 → 系统自动捕获 GPS

> 注：本故事不强制扫追溯码（异常上报场景不需要 ≥2 处扫码）

#### 离线声明

异常上报必须**联网提交**（异常需立即通知主管）；如离线则提示"无网络，请尽快移动到有信号区域"，本地暂存的上报会在恢复网络后立即推送（不延后）。

### 验收标准

1. **异常类型枚举（可配置）**：
   - 车辆故障
   - 路线绕行（含交通管制）
   - 客户拒收
   - 客户不在（约定改时间）
   - 货物破损
   - 冷链温度超标（与 M5-003 联动）
   - 其他（填描述）
2. **GPS 位置**：自动捕获（司机授权后）；GPS 不可用时记录"位置不详"
3. **拍照**：至少 1 张异常现场照片
4. **上报后联动**：
   - **冷链温度超标**：触发 M5-003 温度超标事件 + 调用 M3-003 库存隔离动作（携带 approval_source = `温度超标事件`）
   - **货物破损**：触发 H4 企业微信通知给仓库主管 + 创建 M-QL 质量联系单（类型=养护异常）
   - **车辆故障 / 路线绕行**：触发 H4 通知 + 推送 TMS 系统（M10 接收方）
   - **客户拒收 / 客户不在**：触发 H4 通知给销售/客户负责人
5. **响应 SLA**：上报后 H4 通知 ≤ 30 秒推送给仓库主管
6. **审计**：actor = 司机 user_id，记录异常类型、描述、位置、照片 hash、关联联系单 ID（如有）
7. **GSP 合规**：冷链异常上报数据 ≥ 5 年保留

## US-DR-004：司机端到店签收（客户签字）

**作为** 自有车队司机
**我要** 在到达客户/门店后，由客户签字确认收货
**以便** 闭合 M4 订单状态机（已发货 → 已签收）

### PDA 三件套

#### 字段表

| 字段 | 项目 | 必填 | 核对项 |
|------|------|------|--------|
| 订单号 | 关联 | 是 | — |
| 容器 LPN 列表 | 实物核对 | 是 | 司机现场扫客户接收的容器（应等于发货时容器）|
| 客户签字 | 电子签 / 拍照 | 是 | 客户在屏幕上签字 OR 客户名片/身份证拍照 |
| 客户姓名 | 文本输入 | 是 | 签字人姓名（自由文本）|
| 签收时间 | 系统自动 | 是 | 服务端时间戳 |
| GPS 位置 | 自动捕获 | 是 | 验证是否在客户地址附近（可配置容差）|
| 备注/异常 | 文本 | 否 | 部分签收/拒收说明 |

#### 扫码顺序

1. 扫订单号 → 进入签收页面
2. 逐个扫容器 LPN → 客户验视
3. 客户屏幕签字 + 输入姓名（或扫名片/身份证）
4. 提交 → 订单状态变"已签收"

#### 离线声明

签收支持离线（边远地区可能无信号）：电子签字、拍照、容器扫描全部本地暂存；恢复网络后批量同步。

### 验收标准

1. **签收前置条件**：订单状态必须为"已发货"
2. **GPS 校验**：签收点 GPS 与客户地址距离 ≤ 配置容差（默认 500 米）；超容差则提示"签收位置异常"+ 强制填备注
3. **容器完整性校验**：与签收时一致（少扫提示，多扫提示）
4. **签字方式**：
   - 电子签字（客户在屏幕画押）+ 客户姓名输入
   - OR 拍照客户名片/身份证 + 客户姓名输入
5. **部分签收**：客户拒收部分容器 → 标"部分签收"+ 必填备注 + 触发部分退货流程（M4 退货）
6. **整单拒收**：客户拒收全部 → 订单不变"已签收"，进入退货流程（M4 退货状态机）
7. **数据一致性**：成功签收后：
   - 订单状态变"已签收"（M4 状态机终态）
   - 触发 ERP 反馈"已签收"
   - 触发 H4 通知给仓库主管和销售（如配置）
8. **审计**：actor = 司机 user_id，记录签字图片 hash、客户姓名、GPS、容器列表、备注、approval_source = `客户签收`

## US-DR-005：司机端工作日志与绩效查询

**作为** 自有车队司机
**我要** 查看自己最近 7 / 30 天的配送数据（订单数、签收率、异常率、里程、工时）
**以便** 了解自己的工作量和绩效，配合 M-TE-010 任务引擎多维绩效

### 验收标准

1. **数据维度**：
   - 完成订单数 / 计划订单数（完成率）
   - 异常订单数（拒收 / 破损 / 冷链异常）
   - 总里程（GPS 累计）
   - 工时（登录到登出）
   - 平均每单配送时长
2. **时间窗口**：今日 / 本周 / 本月 / 自定义范围
3. **排名（可选）**：在自有车队中的排名（保护隐私默认不显示，可由主管开启）
4. **数据对接 M-TE-010**：本数据源对接任务引擎绩效模块，统一汇总到员工绩效报表
5. **审计**：仅查询，无写操作；审计可关闭以减小审计表压力（默认开启）
6. **多货主隔离**：司机数据按服务的货主聚合（如同时跑多货主，分别展示）

## 业务边界声明

> **司机模块的边界由 v13/v14/v15 决策共同界定**：
>
> 1. **司机不主导调度**：调度由 TMS 主管（M10-001 接收）；司机仅是执行端
> 2. **司机不修改订单**：订单内容（商品/数量）只读；司机仅签收/上报
> 3. **第三方快递司机不在本模块**：他们走 H5-005 快递 API 查询，不需要本系统账号
> 4. **温控由外部冷链系统采集**：司机端仅做"温度异常"二次确认上报（v7 边界）
> 5. **司机签字 ≠ 仓库交接签字**：M4-006 是仓库主管 → 司机的工牌签字（仓库视角）；本模块 DR-002 是司机视角的"我接到货了"（司机视角）。两个视角是同一物理事件的两端确认。
