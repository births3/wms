# 用户故事：H-Store 门店用户端

> 模块：H-Store store-portal
> 依赖：H1 权限/多租户、H2 审计、M4 出库、M-TC 追溯码、H5 快递、H4 企业微信通知、M-RP 补货
> 关联 ADR：0001（技术栈）、0006（TDD）
> 业务边界：本模块为 v13 P2 决策 B 选项的 Wave 4 W4.E 落地。门店用户此前在 M1-006 角色清单标"被动"，v15 升级为主动 actor 的故事

---

## 角色清单

> 本文件主角色为"门店用户"（连锁药店的店长/采购员）。
>
> 门店用户类型：
> - **连锁门店店长**：管理本店订货、收货、退货、库存查询
> - **门店采购员**：发起补货请求、查看商品目录
> - **门店质量负责人**：查看冷链订单的温控记录、追溯码核销

---

## 跨故事约束

1. **审计追踪**：门店用户的下单、签收、查询操作均写入 H2 审计追踪
2. **多货主隔离**：门店用户只能看到所属货主/品牌商的商品和订单（H1 权限边界）
3. **门店级数据隔离**：连锁体系下，门店用户只能看到所属门店的数据，区域经理可看多门店
4. **GSP 合规**：门店签收记录、追溯码记录保留 ≥ 5 年
5. **幂等性**：所有写操作支持 Idempotency-Key
6. **业务边界**：门店用户**不能修改商品主数据**（由 ERP 推送）；不能直接修改库存（仅触发请求）
7. **设备**：门店用户主要在 PC 端 / PAD 端访问（移动端可选）；不强制 PDA
8. 测试要求：写操作必须含 L4（错误路径）+ L5（数据一致）+ L8（权限）+ L11（幂等）；读操作必须含 L4 + L8

## US-ST-001：门店登录与首页

**作为** 门店店长
**我要** 在门店端 Web/PAD 登录后看到本店当前业务概览
**以便** 一眼了解订单状态、近期到货、库存预警

### 验收标准

1. **登录方式**：手机号 + 短信验证 / 用户名 + 密码（H1 权限）
2. **首页 Dashboard**：
   - 待签收订单数（红色高亮）
   - 在途订单数（蓝色）
   - 近 7 天已签收订单数
   - 库存预警（按 M-RP-001 阈值，低于阈值的商品数量）
   - 本月退货数 + 异常单数
3. **多门店切换**（如店长管理多店）：顶部下拉切换
4. **快捷入口**：下单 / 收货 / 退货 / 商品目录 / 订单历史
5. **公告区**：货主/总部推送的政策/促销公告
6. **审计**：登录、切换门店、首页查看写入审计

## US-ST-002：门店订货与补货请求

**作为** 门店采购员
**我要** 在门店端选择商品下单，或基于库存预警发起补货请求
**以便** 触发 ERP/仓库的备货流程，确保门店不缺货

### 验收标准

1. **订货方式**（两种）：
   - **手动下单**：商品目录搜索 → 选商品 + 数量 → 提交
   - **自动补货请求**：基于 M-RP-001 阈值，系统自动建议补货清单（M-RP-002 自动补货请求）
2. **商品目录**：
   - 货主推送的可订商品（M1-001 商品档案）
   - 含商品图片、规格、起订量、价格（按门店等级，由 ERP 维护）
   - 支持搜索、分类筛选、效期/批号偏好
3. **门店经营范围校验**：依 v7 边界，**经营范围校验由 ERP 负责**；本系统仅做"商品类别 vs 门店标签"的非阻断提示（如"该商品需要冷链证，请确认"）
4. **订单提交**：
   - 必填：商品 + 数量 + 期望到货时间
   - 提交后通过 H8 ERP 防腐层推送 ERP，ERP 走采购流程后回传 ASN 触发 M2 入库
   - 订单状态：待审批 / 已审批 / 备货中 / 已发货 / 已签收 / 已取消
5. **冷链订单标识**：含冷链商品的订单需勾选"接受冷链送达条件"（GSP 合规）
6. **支持订单复制**（用上次订单作为模板）
7. **审计**：actor = 门店用户 user_id，记录订单详情、提交时间、approval_source = `门店订单`

## US-ST-003：门店签收（电子签收）

**作为** 门店店长
**我要** 在订单到达门店后扫码确认签收
**以便** 闭合 M4 订单状态（已发货 → 已签收），并触发 ERP 入库

### PDA 三件套

#### 字段表

| 字段 | 项目 | 必填 | 核对项 |
|------|------|------|--------|
| 订单号 | 关联 | 是 | — |
| 容器 LPN 列表 | 实物核对 | 是 | 扫描所有容器 |
| 追溯码（抽检）| 货物核对 | 否 | 抽扫几个追溯码验证商品/批号匹配（可配置）|
| 签收人姓名 | 文本 | 是 | 默认填登录用户姓名 |
| 电子签字 | 屏幕签 | 是 | 屏幕画押 |
| 签收时间 | 系统自动 | 是 | 服务端时间戳 |
| GPS 位置 | 自动捕获 | 否 | 移动端有；PC 端不要求 |
| 异常说明 | 文本 | 否 | 部分签收/拒收 |

#### 扫码顺序

1. 扫订单号 OR 选择列表 → 进入签收页
2. 逐个扫容器 LPN → 系统核对完整性
3. 抽扫追溯码（可配置数量比例，默认 10%）→ 核对商品
4. 签字 + 提交

#### 离线声明

门店签收支持离线：所有签收数据本地缓存；恢复网络后同步。冷链订单签收必须在线（确保实时上报码上放心）。

### 验收标准

1. **签收前置条件**：订单状态必须为"已发货"
2. **容器完整性**：扫码核对容器 LPN 数量
3. **追溯码抽检**（可配置）：
   - 默认抽检比例 10%
   - 抽检发现追溯码与订单不匹配 → 拒绝签收 + 自动创建 M-QL 质量联系单
4. **冷链订单**：
   - 显示该订单从离仓到送达的温度曲线（来自 M5-002 接收的外部冷链系统数据）
   - 如有温度超标记录 → 提示门店"是否仍签收"（如签收，触发 M-QL 联系单）
   - 必须在线签收（确保 M-TC-007 上报"码上放心"实时）
5. **部分签收 / 拒收**：
   - 部分签收 → 触发 M4 退货流程
   - 整单拒收 → 订单不变"已签收"
6. **签收后联动**：
   - M4 状态机 [已发货 → 已签收]
   - 触发 ERP 入库反馈
   - 触发 M-TC-007 码上放心上报
   - 触发 H4 通知给货主/区域经理（可配置）
7. **审计**：actor = 门店用户 user_id，approval_source = `门店签收`

## US-ST-004：门店退货发起

**作为** 门店店长
**我要** 在发现质量问题/过期/客户退货等情况下发起退货请求
**以便** 启动 M4 退货流程（M4 退货状态机）

### 验收标准

1. **退货发起条件**：
   - 订单已签收（一定时间内可退）
   - 商品质量问题
   - 客户退回
   - 过期临近不可销售
2. **退货必填**：原订单号、商品、批号、数量、退货原因（枚举）、照片（质量问题必拍）
3. **退货原因枚举**（可配置）：
   - 质量不合格
   - 过期/近效期
   - 商品损坏
   - 客户退货
   - 数量误收
   - 其他（填描述）
4. **退货流程**：
   - 提交 → M4 退货状态机 [待审批]
   - 主管审批通过 → [已审批]
   - 仓库安排提货（如自有车队）OR 门店自寄回（第三方快递）→ [提货中]
   - 商品到仓 → [已到货 → 验收中 → 已完成]
5. **冷链商品退货**：必须勾选"是否保留冷链运输条件"，影响接收方处置
6. **审计**：actor = 门店用户 user_id，记录退货原因、关联订单、批号、approval_source = `门店退货`

## US-ST-005：门店订单查询与历史

**作为** 门店店长 / 门店质量负责人
**我要** 查询本店所有历史订单，支持多维筛选和导出
**以便** 对账、库存盘点、GSP 检查时提供台账

### 验收标准

1. **查询维度**：
   - 时间范围（开始日期 - 结束日期）
   - 订单状态（待审批 / 已发货 / 已签收 / 已退货 / 已取消）
   - 商品（含追溯码反查）
   - 批号
   - 是否冷链
2. **结果列表**：订单号、下单时间、商品摘要、总金额、状态、签收人、签收时间
3. **详情页**：
   - 订单完整信息（含商品明细 / 容器 / 追溯码 / 温度曲线（冷链））
   - 状态历史（来自 H2 审计追踪查询，本故事仅读取，不变更状态）
   - 关联文档（随货同行单 / 发票 / 质量联系单等）
4. **导出**：Excel / PDF（GSP 法定台账格式）
5. **GSP 法定台账**：含"购进记录"必备字段（商品、批号、效期、供应商、数量、日期、签收人）
6. **追溯码反查**：输入追溯码 → 反查到具体订单和签收记录（监管检查必备）
7. **数据保留**：本系统保留 ≥ 5 年（GSP）；超期归档到只读分区
8. **审计**：仅查询，记入审计追踪（含查询条件 + IP，敏感操作）；导出操作单独记审计

## US-ST-006：门店冷链订单温控查询（GSP 合规专项）

**作为** 门店质量负责人
**我要** 查询冷链商品订单的全程温度记录
**以便** 履行 GSP 冷链商品验收时的温控核查义务

### 验收标准

1. **触发场景**：
   - 冷链订单签收前的预审（US-ST-003 内联）
   - 收到冷链商品后的事后检查
   - 监管检查时的证据提供
2. **数据来源**：M5-002 接收的外部冷链系统温度数据 + M5-003 温度超标事件
3. **展示**：
   - **温度曲线图**：从离仓到签收的全程温度（折线图）
   - **温度区间标识**：商品要求的允许温度区间（绿色带）
   - **超标事件标记**：超出允许区间的时段（红色高亮）+ 持续时长 + 是否处置
4. **报告导出**：
   - PDF 温控记录（含曲线图 + 摘要 + 签字栏）→ GSP 检查附件
   - Excel 原始数据（来自外部冷链系统的逐条温度采集，仅在外部冷链系统开放原始数据时可用）
5. **业务边界**：
   - 温度数据由外部冷链系统采集，本系统仅展示和关联订单（v7 边界）
   - 超标判定由外部冷链系统执行，本系统接收事件
   - GSP 5 年原始数据由外部冷链系统持有，本系统仅缓存近期（默认 1 年）便于查询
6. **审计**：查询操作记录到审计；下载报告记录"导出审计"（含导出时间、用户、订单号）

### 测试维度覆盖

#### US-ST-001 门店登录与首页

| 维度 | 场景 |
|------|------|
| L4 错误路径 | 门店账号未激活 → H1_AUTH_ACCOUNT_INACTIVE; 门店经营范围未配置 → 提示"请联系总部配置"; 首页数据拉取超时 → 显示骨架屏 |
| L5 数据一致 | 首页待办数与实际待处理订单一致 |
| L8 权限 | 门店用户只能看本门店数据; 跨门店 → 403 |
| L11 幂等 | 登录/查询天然幂等 |

#### US-ST-002 门店订货与补货请求

| 维度 | 场景 |
|------|------|
| L4 错误路径 | 商品不在门店经营范围 → ST_PRODUCT_OUT_OF_SCOPE; 库存不足（仓库侧）→ 提示"库存不足，建议调整数量"; 订货金额超限 → ST_ORDER_AMOUNT_EXCEEDED |
| L5 数据一致 | 订货单创建与库存预占原子（或异步确认）; 订货单号全局唯一 |
| L8 权限 | 仅门店采购员可订货; 门店店长可审批; 其他角色 → 403 |
| L11 幂等 | 相同 Idempotency-Key → 返回首次订货单 |

#### US-ST-003 门店签收（电子签收）

| 维度 | 场景 |
|------|------|
| L4 错误路径 | 签收数量 > 发货数量 → ST_QTY_EXCEEDED; 冷链商品温度异常 → 强制拍照 + 记录异常; 电子签名采集失败 → 允许拍照替代 |
| L5 数据一致 | 签收记录与出库订单状态原子更新; 签收数量与库存变动一致 |
| L8 权限 | 仅门店店长可签收; 门店采购员可查看但不可签收 |
| L11 幂等 | 同一订单重复签收 → 返回首次结果 |

#### US-ST-004 门店退货发起

| 维度 | 场景 |
|------|------|
| L4 错误路径 | 退货商品不在原订单中 → ST_PRODUCT_NOT_IN_ORDER; 超过退货时限 → ST_RETURN_EXPIRED; 退货原因未填 → 校验拒绝 |
| L5 数据一致 | 退货单创建与原订单关联; 退货审批通过后库存变动原子 |
| L8 权限 | 门店店长可发起退货; 仓库主管审批 |
| L11 幂等 | 相同 Idempotency-Key → 返回首次退货单 |

#### US-ST-005 门店订单查询与历史

| 维度 | 场景 |
|------|------|
| L4 错误路径 | 查询时间范围过大 → 分页; 无匹配 → 空列表 |
| L5 数据一致 | 查询结果与实际订单状态一致 |
| L8 权限 | 门店店长/质量负责人查本门店; 跨门店 → 403 |
| L11 幂等 | 查询天然幂等 |

#### US-ST-006 门店冷链订单温控查询

| 维度 | 场景 |
|------|------|
| L4 错误路径 | 温控数据未接入 → 提示"该订单暂无温控数据"; 数据延迟 → 标记最后更新时间 |
| L5 数据一致 | 温控数据与 M5 冷链记录一致; 超标标记与实际阈值一致 |
| L8 权限 | 门店质量负责人可查; 普通门店用户 → 403 |
| L11 幂等 | 查询天然幂等 |

### PDA 弹性

> 适用故事：US-ST-003（门店签收可能在移动端操作）

#### 离线策略

| 场景 | 行为 |
|------|------|
| 门店网络不稳定时签收 | 签收数据暂存本地; 网络恢复后同步; 本地显示"待同步"状态 |
| 离线时查看订单 | 显示最后同步的订单列表（标记"离线数据"） |

#### 扫码交互

| 场景 | 行为 |
|------|------|
| 扫描送货单条码签收 | 解析订单号 → 显示送货明细 → 逐项确认数量 → 电子签名 |
| 扫描商品条码逐件验收 | 扫码 → 匹配订单明细行 → 自动计数 |
| 扫码无匹配 | 提示"该商品不在本次送货单中" |

#### 异常恢复

| 场景 | 行为 |
|------|------|
| 签收过程中 APP 崩溃 | 重启后恢复签收页面（本地暂存未提交数据） |
| 网络恢复后签收冲突 | 以服务端状态为准; 如已被他人签收 → 提示"订单已签收" |

## 业务边界声明

> **门店用户模块的边界由 v13/v14/v15 决策共同界定**：
>
> 1. **门店不修改主数据**：商品档案、价格、经营范围由 ERP 维护
> 2. **门店不直接修改库存**：仅通过订货 / 退货触发流程
> 3. **经营范围校验由 ERP 主管**：本系统仅做非阻断提示（v7 边界）
> 4. **门店温控数据来自外部冷链系统**：本系统不采集，仅展示（v7 边界）
> 5. **多门店切换 vs 多货主**：连锁体系下店长可管多店；多货主下门店用户只看自己服务的货主数据
> 6. **设备约束**：门店用户主要 PC/PAD；移动端轻量化（不强制 PDA 三件套）
