# 用户故事：H-DOCK 月台预约管理（dock-management）

> 模块：H-DOCK 横向能力 / Wave 4-5（业务方启用时实施）
> 性质：可启用 / 不启用的横向能力（默认关闭，多货主 3PL 与冷链优先仓启用）
> 依赖：H1（权限）/ H2（审计）/ H4（通知）/ H6（状态机）
> 关联 ADR：ADR-0001（技术栈）/ ADR-0007（v0.3 路线）

---

## 背景

医药仓多货主 3PL 场景下，多家货主车辆同时到仓会竞争月台资源。冷链车与常温车不能共用同一月台（防交叉污染 + 温区差异）。需要：

- 预约系统：到仓前预约月台 + 时间窗
- 资源管理：月台档案（编号 / 类型 / 占用状态）
- 实到对账：核对预约信息

本模块为**可启用横向能力**：单货主小仓默认关闭（先到先服务即可），多货主 3PL / 冷链优先仓启用。

---

## 启用机制

通过 **M1-008 配置中心**控制启用：

```yaml
dock_management_enabled: false      # 默认关闭
dock_appointment_window_minutes: 30  # 单次预约时间窗
dock_overlap_allowed: false         # 同月台是否允许重叠（冷链/常温车混合）
dock_advance_hours: 48              # 预约提前时间
```

**关闭时**：M2-002 PDA 收货 / M4-006 发货交接跳过预约校验，按当前流程执行。
**启用时**：相关业务节点必须先校验预约。

## US-DOCK-001：月台档案管理

**作为** 仓库主管
**我要** 维护本仓的月台资源（编号、类型、温区、状态）
**以便** 预约系统知道有哪些可用资源

### 验收标准

1. **月台字段**：
   - 月台编号（VARCHAR(32)，全仓唯一）
   - 月台类型：收货 / 发货 / 收发两用
   - 温区匹配：常温 / 冷藏 / 冷冻 / 冷链兼容（决定哪些车辆可用）
   - 月台状态：启用 / 停用 / 维护中
   - 月台位置（GIS 坐标可选 / 文字描述）
   - 关联仓库 ID（多仓场景）
2. **唯一约束**：月台编号 + 仓库 ID 联合唯一
3. **状态变更**：停用后该月台不再出现在预约可选列表
4. **维护期**：月台维护中可以预约其他月台，本月台显示"X 月 X 日恢复"
5. **批量导入**：支持 Excel 批量导入月台档案
6. **变更审计**：月台档案的增删改写入 H2 审计追踪
7. **多货主隔离**：月台档案按仓库归属，不按货主（月台是物理资源）
8. **角色权限**：仅仓库主管 + 系统管理员可维护

### 异常路径

- 删除已有预约关联的月台 → 不允许删除，提示"该月台有 N 笔未完成预约"
- 启用一个温区与既有预约冲突的月台 → 警告并要求确认

## US-DOCK-002：预约创建

**作为** ERP / 货主端 / 仓库主管
**我要** 在车辆到仓前创建月台预约（指定时间窗 + 关联单据）
**以便** 提前安排资源 + 减少现场排队

### 验收标准

1. **预约触发源**（多入口）：
   - ERP API 推送（采购入库单 / 销售出库单创建后自动）
   - 货主端门户手动创建（H-Store 接口）
   - 仓库主管 PC 端手动创建
   - PDA 现场创建（仅仓库主管角色）
2. **预约必填字段**：
   - 关联单据：ASN 号（入库）/ 出库单号（出库）/ 退货单号
   - 预约时间窗：开始时间 + 结束时间（默认 30 分钟，可配置）
   - 车辆信息：车牌号 / 车辆类型（常温 / 冷藏车）
   - 司机姓名 + 联系电话
   - 货主 ID（多货主隔离）
3. **月台分配策略**：
   - 自动分配：按 (车辆类型 ⇄ 月台温区) 匹配 + 时间窗空闲 + 货主优先级
   - 手动分配：仓库主管可指定月台
4. **预约状态机**：
   - 待确认 → 已确认 → 已到达 → 已完成 / 已超时未到 / 已取消
5. **预约编号**：调 M-CG 编码生成器，格式 `DOCK + 日期 + 流水号`
6. **预约时间窗**：默认提前 48 小时可预约（可配置 `dock_advance_hours`）
7. **关联**：一个 ASN/订单可有多次预约（重新调度场景），但同时只有一条 active 预约
8. **审计**：预约创建写入 H2 审计

### 异常路径

- 关联单据不存在 / 已完成 → 不允许预约
- 时间窗已过 → 不允许预约
- 车辆温区与所选月台不匹配 → 提示重新选择
- ERP 推送的预约缺字段 → 进入"待补全"状态，不直接驳回

## US-DOCK-003：预约时间窗冲突检测

**作为** 系统（自动）
**我要** 在预约创建/变更时校验同月台时间窗不重叠
**以便** 防止双预约导致现场冲突

### 验收标准

1. **冲突定义**：同一月台 + 时间窗有交集 → 冲突
2. **冲突处理**：
   - `dock_overlap_allowed = false`（默认）→ 拒绝创建，提示已被预约的单据 + 联系人
   - `dock_overlap_allowed = true`（仅特殊场景，如装卸效率高的双工位月台）→ 允许，但标记为"并行作业"
3. **预留时间**：每次预约后 + 5 分钟缓冲（清理 + 切换车辆，可配置）
4. **冷链优先**：`cold_chain_priority = true` 时冷链车辆预约可挤占常温车辆（提前 N 小时通知调整）
5. **建议替代**：冲突时系统提示同温区其他空闲月台 + 同月台下一空闲时间窗
6. **预约变更**：修改时间或月台时重新校验
7. **审计**：冲突拒绝事件记入 H2 审计（actor=system，含拒绝原因）

### 异常路径

- 系统时间偏移 → 用服务器时间为准 + 客户端本地时间作记录
- 业务高峰冲突频繁 → 看板告警 + 仓库主管手动协调

## US-DOCK-004：预约变更与取消

**作为** ERP / 货主 / 仓库主管
**我要** 修改或取消已创建的预约
**以便** 适应实际车辆调度变化

### 验收标准

1. **变更触发**：ERP 推送变更 / 货主端手动 / 仓库主管手动
2. **可变更字段**：时间窗 / 月台 / 车辆 / 司机
3. **不可变更字段**：关联单据（变更等同于重建预约）
4. **变更流程**：保留原预约记录 + 新建新版本（version 字段递增），不直接覆盖
5. **取消流程**：
   - 已确认状态可取消 → 释放月台资源
   - 已到达状态不可取消（需要走异常处理）
6. **超时未到**：超过预约结束时间 + 1 小时未实到 → 自动状态变为"已超时未到"+ 释放月台 + 通知货主
7. **延迟通知**：货主预报延迟时可主动调用接口延后预约时间（保留原月台）
8. **变更审计**：旧值/新值/操作人/原因写入 H2 审计

### 异常路径

- 修改导致冲突 → 拒绝并提示替代方案
- 已超时再取消 → 仅做记录，不影响月台释放
- 变更时月台已被新预约占用 → 拒绝并提示

## US-DOCK-005：实到对账

**作为** 收货员 / 发货员（PDA）
**我要** 在车辆到仓时扫码核对预约
**以便** 实到信息与预约一致 + 异常预警

### 验收标准

1. **扫码进入**：PDA 扫车牌号 / 输入预约编号
2. **核对项**：
   - 预约存在性（无预约车辆 → 异常处理）
   - 时间偏差（提前到 / 准时 / 迟到，分级提示）
   - 车辆类型匹配（车辆温区 vs 月台温区）
   - 司机身份（车牌 + 司机姓名）
3. **核对一致**：状态变为"已到达"，预约绑定到实际收货单 / 发货单
4. **核对不一致**：
   - 无预约 → 走"异常车辆登记"流程，主管确认是否破例接收
   - 时间偏差大（迟到 > 2 小时）→ 提示是否仍按预约处理
   - 车辆类型不匹配 → 拒绝接货并通知货主
5. **关联流转**：到达后 PDA 自动跳转到 M2-002 收货 / M4-006 发货故事
6. **GSP 8.116 启运/送达时间字段自动填充**：实到时间 = 启运时间（出库）/ 送达时间（入库）
7. **PDA 离线**：按 H1 §7 PDA 离线统一策略处理（暂存 + 冲突走"待主管处理"）
8. **审计**：实到对账事件写入 H2 审计

### PDA 字段表

| 字段名 | 必填/条件必填/可选/系统带出 | 来源 |
|---|---|---|
| 预约编号 | 必填 | 扫码 / 手输 |
| 车牌号 | 必填 | 扫码 / OCR |
| 司机姓名 | 系统带出（预约关联） | DB |
| 实到时间 | 系统带出 | 服务端时间 |
| 时间偏差 | 系统带出（计算） | 实到时间 - 预约开始时间 |
| 月台编号 | 系统带出（预约关联） | DB |
| 异常类型 | 条件必填（核对失败时）| 用户选择 |
| 主管确认 user_id | 条件必填（异常破例时）| 扫工牌 |

### 异常路径

- 车牌识别失败 → 手动输入预约编号
- 网络断开 → 离线模式，恢复后同步
- 主管不在现场 → 暂存为"待主管处理"事件，车辆等候

## US-DOCK-006：月台占用看板

**作为** 仓库主管 / 现场调度员
**我要** 实时看到所有月台的占用与排队情况
**以便** 现场调度 + 调整预约

### 验收标准

1. **看板内容**：
   - 月台时间线（甘特图，按月台 × 时间二维展示）
   - 当前占用状态（绿/黄/红：空 / 占用中 / 超时）
   - 未来 24 小时预约队列
   - 排队统计（等待中的车辆数、平均等候时长）
2. **多视角**：按仓库 / 按温区 / 按货主筛选
3. **实时更新**：状态变化 ≤ 5 秒刷新（基于 H-EVT 事件订阅，新版 H2-005）
4. **导出**：导出当日月台占用记录 Excel
5. **告警集成**：月台空置率 > 阈值或排队 > 阈值触发 H-AL 告警
6. **打印**：可打印当日预约时刻表（H9 打印模板）

### 异常路径

- 看板加载慢 → 缓存 + 增量更新
- 多仓数据混淆 → 切换仓库时清缓存

## US-DOCK-007：预约统计与报表

**作为** 仓库主管 / 货主财务
**我要** 按时段统计月台使用率与预约情况
**以便** 优化资源 + 计费依据

### 验收标准

1. **统计维度**：日 / 周 / 月 / 货主 / 月台 / 车辆类型
2. **统计指标**：
   - 月台使用率（占用时长 / 总时长）
   - 预约准时率（准时到 / 总预约）
   - 平均等候时长
   - 货主预约量排行
   - 异常车辆比例（无预约 / 临时调整）
3. **导出**：Excel + PDF
4. **审计接入**：报表查询写入 H2 审计（who / when / 维度）
5. **跨模块联动**：M9 计费可读取本模块的月台占用时长作计费依据（计费规则配置）

## 跨故事约束（适用于所有 H-DOCK 用户故事）

1. **启用开关**：本模块所有故事仅在 `dock_management_enabled = true` 时生效；未启用时调用接口返回"功能未启用"
2. **审计追踪**：所有预约创建/变更/取消/实到对账写入 H2 审计追踪
3. **多货主隔离**：预约按货主隔离查询；月台档案按仓库归属（不按货主）
4. **多仓**：本模块按仓库切片
5. **幂等性**：预约创建 / 变更 / 取消支持 Idempotency-Key
6. **企业微信通知**：预约确认 / 即将到达 / 超时未到 触发 H4 通知（已确认 → 货主联系人；超时未到 → 仓库主管 + 货主联系人）
7. **GSP 字段联动**：实到时间自动填充 8.116 启运时间 / 送达时间字段
8. **冷链优先**：`cold_chain_priority = true` 时冷链车辆 + 冷链月台分配优先级最高（GSP 9.121）
9. **测试要求**：写操作必须含 L4（错误路径）+ L5（数据一致）+ L8（权限）+ L11（幂等）；读操作必须含 L4 + L8

| 维度 | 场景 |

| L8 权限 | 仅仓库主管可管理月台; 其他角色 → 403 |

#### US-DOCK-002 预约创建

| 维度 | 场景 |
|------|------|
| L4 错误路径 | 时间窗冲突 → DOCK_TIME_CONFLICT; 月台不可用 → DOCK_UNAVAILABLE; 冷链车辆未匹配冷链月台 → DOCK_COLD_CHAIN_MISMATCH |

#### US-DOCK-003 预约时间窗冲突检测

| 维度 | 场景 |
|------|------|
| L4 错误路径 | 并发创建同一时间窗 → 仅一个成功，另一个返回 DOCK_TIME_CONFLICT; 系统时钟偏移 → 以服务端时间为准 |

| L8 权限 | 系统自动检测，不需用户权限 |
| L11 幂等 | 检测本身无副作用（幂等） |

#### US-DOCK-004 预约变更与取消

| 维度 | 场景 |
|------|------|
| L4 错误路径 | 变更已完成的预约 → DOCK_ALREADY_COMPLETED; 取消已取消的预约 → 200（幂等）; 变更后时间窗冲突 → DOCK_TIME_CONFLICT |

| L8 权限 | ERP/货主/仓库主管可变更自己的预约; 跨货主 → 403 |
| L11 幂等 | 取消操作幂等（已取消 → 200）; 变更支持 Idempotency-Key |

|------|------|

| L5 数据一致 | 实到时间写入预约记录 + GSP 8.116 字段原子更新; 实到与 ASN 收货关联 |

| L8 权限 | 仓库主管查本仓; 货主财务查本货主 |
| L11 幂等 | 查询/导出天然幂等 |

### PDA 弹性

> 适用故事：US-DOCK-002（PDA 端创建预约）、US-DOCK-005（PDA 端实到对账）

#### 离线策略

| 场景 | 行为 |
|------|------|
| PDA 离线时需要签到 | 暂存签到记录（车牌 + 时间 + 月台）到本地; 网络恢复后同步 |
| PDA 离线时查看预约 | 显示最后一次同步的预约列表（标记"离线数据"） |

#### 扫码交互

| 场景 | 行为 |
|------|------|
| 扫描车辆二维码签到 | 解析车牌号 → 匹配今日预约 → 确认到达 → 更新预约状态 |
| 扫码无匹配 | 提示"未找到该车辆的预约，请确认车牌或联系调度" |

#### 异常恢复

| 场景 | 行为 |
|------|------|
| 签到过程中 APP 崩溃 | 重启后检查本地暂存 → 有未同步签到则自动续传 |
| 网络恢复后签到冲突 | 服务端以实际到达时间为准; 本地时间作为辅助字段 |

## 业务边界声明

> H-DOCK 月台预约管理的边界：
>
> 1. **物理资源管理**：月台是仓库的物理资源，不属于任何货主，按仓库归属
> 2. **不主管业务**：本模块只做"预约调度"，不做"业务规则判断"（业务规则由 M-VR / M-QL 处理）
> 3. **可选启用**：本模块为"建议启用"而非"必须启用"——启用决策由业务方根据仓库规模 + 货主数量 + 是否冷链作出
> 4. **GSP 间接相关**：本模块支撑 GSP 6.83 / 8.116 / 9.121 等时间字段的合规性，但本模块本身不是 GSP 硬要求
> 5. **与 M10 TMS+ 的关系**：M10 管运输全程；H-DOCK 仅管仓门口的预约和实到对账；两者通过预约接口对接
