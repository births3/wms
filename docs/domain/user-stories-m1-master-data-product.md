## 角色清单

### 用户角色（有 user_id，参与权限/审计）

| 角色 | 说明 | 类型 |
|------|------|------|
| 系统管理员 | 用户/权限/系统配置 | 主动 |
| 仓库主管 | 审批、报表、异常处理 | 主动 |
| 收货员 | PDA 收货、验收 | 主动 |
| 养护员 | 在库养护 | 主动 |
| 保管员 | 上架/拣货/复核/盘点（含复核岗、包装岗、退货发起等子岗位） | 主动 |
| 货主 | 查看自己的数据（3PL） | 主动（只读为主） |
| 门店用户 | 下单、查看配送、签收（v13：作为外部触发源使用，故事中通常以"外部系统"或被动接收方出现，本系统主要为门店用户提供查询/签收接口）| 被动 |
| 司机 | 签收、在途温控（v13：作为外部触发源使用，主要在 M4-006 交接、M10-002 在途温控、H5-005 快递查询中作为信息接收/上报方出现，不主动发起 WMS 操作）| 被动 |

> **角色类型**：
> - **主动**：在用户故事中以"作为 XX"形式出现，直接发起业务操作
> - **被动**：拥有账号和权限但主要接收信息或被动签收，操作通常由其他主动角色协同完成

> 用户角色是权限模板（默认权限集），管理员可对任何角色配置任意菜单/权限。
> 子岗位（如"保管员（复核岗）"）通过角色括号附注表达，不另立独立角色。

### 非用户触发源（无 user_id，审计追踪记标识）

| 触发源 | 说明 | 审计记录方式 |
|--------|------|------------|
| 系统 | 由调度器/事件触发的自动操作（定时任务/状态机回调/补货检查/对账等） | 审计 actor = `system`，附触发上下文（任务 ID/事件 ID） |
| 外部系统 | 通过 API 调用的第三方系统（ERP、采购平台、电商平台、码上放心、药监局、企业微信等） | 审计 actor = API Key 标识 + 调用方名称 |

> 故事正文中"作为 系统（XXX 触发）"或"作为 外部系统（ERP）"使用这两个触发源；它们不是用户角色，不参与权限分配，但必须有审计追踪。

## US-M1-001：商品档案管理

**作为** 仓库主管
**我要** 查询商品档案，并在发现资料错误时发起受控变更请求
**以便** 不绕过 ERP 主数据权威的前提下，保证入库/出库/养护使用正确的储存要求和 GSP 规则

**作为** 外部系统（ERP）
**我要** 通过 H8 商品消息同步商品档案和变更结果
**以便** ERP 作为商品主数据唯一事实源，WMS 只保存经防腐层规整后的作业投影

### 验收标准

1. `active` / `disabled` 商品必填字段：编码（唯一，**由 ERP 给定，WMS 不生成**）、名称、规格、储存条件（**结构化枚举**：冷藏/冷冻/阴凉/常温，对应温度区间见本文末"附录 A：储存条件温度区间表"）、**特殊药品分类**（结构化枚举，字典见 US-M1-010）。ERP 未提供或 M-PM 未能映射的值不得以“常温/普通药品”等默认值代填
2. 可选字段：剂型、批准文号、UDI 唯一码、电子监管码关联、生产厂家
3. **包装层级**：件/盒/支（或自定义层级），每级之间转换比可配置（如 1 件=10 盒，1 盒=12 支），需设置默认值
4. **物理属性**：长、宽、高（mm）、体积（cm³，可自动计算）、重量（g）
5. **储存条件是结构化枚举字段，不接受自由文本**：ERP 发布器在写接口表前必须按 **M-PM 参数对照模块**（见 user-stories-mpm-parameter-mapping.md US-MPM-004）的受控字典 `storage_condition` 完成规整；未命中值留在 ERP 发布失败队列，不得写入接口表。若违规消息绕过前置校验，H8 以 422 不可重试错误拒绝且不得创建 M1 商品
6. 编码唯一性校验（重复时提示已存在）
7. 管理端商品页只读展示 ERP 投影；“创建、编辑、批量导入、停用/启用”不得直接修改商品主数据，只能发起可审计的 ERP 变更请求
8. ERP 通过 H8 回传停用/启用结果；停用商品不可用于新 ASN
9. **特殊药品标识强校验**：标识为麻精毒放等特殊管理药品的商品，库区温区匹配之外还须满足该类别的双人作业矩阵约束（M-VR）和专用台账登记（M6-004）
10. 商品变更写入审计追踪（含 special_drug_category 字段变更时双人审批，详见 US-M1-010 §6）
11. **开放 API 与防腐层边界**：商品创建/更新必须使用 H8 `product_master` / `product_change` REST 或接口表入口（API Key 鉴权），所有不规则字段（储存条件 / 剂型 / 包装单位 / 特殊药品分类）经 M-PM 规整化后入库；M1 商品 `GET` 保留查询能力，M1 `POST` / `PATCH` / `DELETE` / `batch-sync` 对 JWT 和 API Key 主体都拒绝，避免形成第二写入口
12. **批量同步**：ERP 批量数据由 H8 受控消息逐条进入共享防腐层。管理端 `.xlsx/.csv` 可以用于校验和生成 ERP 变更请求，不得调用 M1 原子 `batch-sync` 直接落商品；预览必须展示 M-PM 映射结果与未匹配项
13. **档案补录回写**：M2-003 PDA 验收触发"档案补录"质量联系单 → 审批通过后 WMS 写 ERP 接口表 → ERP 完成主数据变更后通过本接口（步骤 11 的 API）推送变更回 WMS；该机制保证商品档案的"单一真相源"始终是 ERP，WMS 不直接修改主数据（详见 M-QL-004 6 步闭环）
14. **映射溯源元数据**：每个经 M-PM 规整化的字段保留命中规则 ID + 源系统 + 源原值，供反向追溯（M-PM US-MPM-005）
15. **发布前置与二次防线**：ERP 商品发布单元的储存条件、特殊药品分类和全部包装单位必须在 INSERT 前映射齐全；WMS 仍重复校验，任一必需映射未命中时仅记录 H8 死信与 M-PM 待办，M1 商品、包装和映射溯源均零写入。历史 `pending_mapping` 数据只按受控清理流程处置，不再由 ERP 入站创建

### US-M1-001 字段契约

| 字段 | API 名称 | 必填 | 约束 |
|------|----------|------|------|
| 商品编码 | `product_code` | 是 | 货主内唯一，创建后不可修改 |
| 商品名称 | `product_name` | 是 | 非空 |
| 规格 | `spec` | 是 | 非空 |
| 储存条件 | `attrs.storage_condition` | 是 | `frozen/cold/cool/normal`；外部源值在发布前经 M-PM 映射，未命中不得发布 |
| 特殊药品分类 | `special_drug_category_code` | 是 | 已启用 M1-010 字典项；未命中不得发布 |
| 剂型 | `dosage_form` | 否 | 外部源值先经 M-PM |
| 批准文号 | `approval_no` | 否 | 文本 |
| UDI 唯一码 | `udi_code` | 否 | 货主内非空值唯一 |
| 电子监管码关联 | `electronic_regulatory_code` | 否 | 文本 |
| 生产厂家 | `manufacturer` | 否 | 文本 |
| 长/宽/高 | `physical_dimensions.{length_mm,width_mm,height_mm}` | 否 | 原子对象，单位 mm；三项同时提供且均大于 0，变更请求不得逐字段初始化或部分更新 |
| 体积 | `volume_cm3` | 否 | 单位 cm³；未传且长宽高齐全时按 `长×宽×高÷1000` 计算 |
| 重量 | `weight_g` | 否 | 单位 g；大于 0 |
| 包装层级 | `packaging_levels` | 是 | 至少一层；完整约束见下表 |

### 包装层级契约

| 字段 | 含义 | 约束 |
|------|------|------|
| `unit_code` | WMS 标准包装单位编码 | 商品内唯一；外部源值先经 M-PM `unit_pack` |
| `unit_name` | 中文显示名称 | 非空 |
| `ratio_to_base` | 相对基础单位的换算数量 | 正整数；基础单位固定为 1 |
| `is_base` | 基础单位 | 每个商品恰好一条 |
| `is_default` | 默认业务单位 | 每个商品恰好一条；允许与基础单位不同 |
| `sort_order` | 展示顺序 | 非负整数；商品内唯一 |

示例：`支=1（基础单位）`、`盒=12（默认单位）`、`件=120`。换算统一以基础单位为锚点，避免相邻层级链式换算产生累计误差。商品与全部包装层级必须在同一数据库事务内创建或整体替换；任一层非法时不得留下商品、包装、审计或幂等残留。

### 2026-07-23 实施决策

## US-M1-002：供应商资质档案

**作为** 仓库主管
**我要** 录入供应商信息并上传资质证照（营业执照、经营许可证、GSP 证）
**以便** 收货时系统自动校验供应商是否有权供货

**作为** 外部系统（ERP/采购平台）
**我要** 通过 API 接口同步供应商档案和资质信息
**以便** 供应商主数据由上游统一管理，WMS 自动接收

### 验收标准

1. 供应商必填：名称、统一社会信用代码、联系方式
2. 资质证照：营业执照、经营许可证、GSP 证（每项含有效期）
3. 经营范围字段（文本 + 结构化标签，用于收货时匹配商品类别）
4. 有效期到期前 30 天自动预警（可配置天数）
5. 资质过期的供应商，系统拒绝其收货单创建
6. 支持上传证照图片/PDF（存对象存储）
7. 印章样张、随货同行单样张可备案
8. 供应商变更写入审计追踪
9. **开放 API**：提供 RESTful 接口供外部系统创建/更新/查询供应商（需 API Key 鉴权）
10. **批量导入**：支持 API 批量推送 + 页面 Excel 导入

## US-M1-003：客户/门店档案

**作为** 仓库主管
**我要** 维护客户和门店信息（名称、多地址、资质、经营范围）
**以便** 出库时保留客户/门店主数据与资质档案，供 ERP 合规校验结果回写和 WMS 单据展示使用

**作为** 外部系统（ERP/电商平台）
**我要** 通过 API 接口同步客户档案
**以便** 客户主数据由上游统一管理，WMS 自动接收

### 验收标准

1. 客户必填：名称、联系方式
2. **多地址**：一个客户可有多个收货地址（每个地址含：省市区、详细地址、联系人、电话、是否默认）
3. 门店额外字段：经营范围、资质证照、所属连锁
4. 连锁门店支持批量导入
5. 门店经营范围作为档案字段维护（**WMS 不基于此校验，由 ERP 在出库前判定**）
6. 客户/门店变更写入审计追踪
7. **开放 API**：提供 RESTful 接口供外部系统创建/更新/查询客户（需 API Key 鉴权）
8. **批量导入**：支持 API 批量推送 + 页面 Excel 导入

## 跨故事约束（适用于所有 M1 用户故事）

1. **审计追踪**：所有创建/修改/删除/停用操作必须写入审计表（旧值、新值、操作人、时间）
2. **多货主**：所有数据查询默认按当前用户所属货主过滤（除系统管理员）
3. **软删除**：不物理删除数据，只标记停用/禁用
4. **双人作业可配置**：双人要求由"双人作业矩阵"（M1-008 配置类目"双人作业矩阵"）按"特殊药品分类 × 流程 × 节点"定义；普通药品默认仅入库.验收和出库.复核两个节点双人，特殊药品按 M1-010 字典预置默认值。所有双人节点强校验两个 user_id 不同，且角色满足该节点的岗位要求。详见 M-VR US-VR-006
5. **权限可配置**：上述"作为 XX 角色"仅表示默认权限归属，实际由管理员配置决定

---
6. **幂等性**：所有写操作（创建/修改/删除/停用）支持 Idempotency-Key，重复提交返回相同结果
7. 测试要求：写操作必须含 L4（错误路径）+ L5（数据一致）+ L8（权限）+ L11（幂等）；读操作必须含 L4 + L8

### 测试维度覆盖

#### US-M1-001 商品档案管理

| 维度 | 场景 |
|------|------|
| L4 错误路径 | M1 直写入口一律拒绝；重复商品编码 → M1_PRODUCT_DUPLICATE；必需受控值未映射 → 422、H8 死信、M1 零写入；物理尺寸部分提供 → 422 |
| L5 数据一致 | H8 商品写入、包装、映射溯源、审计和状态原子提交；ERP 未通过发布前映射校验不得写接口表；停用后不可用于新 ASN |
| L8 权限 | 仓库主管/系统管理员可读并发起变更请求但不可直写；H8 ERP 机器主体只经共享防腐层写入；货主只读；收货员越权写入 → 403 |
| L11 幂等 | 相同 H8 Idempotency-Key 重复同步或变更 → 返回首次结果，不重复商品、映射任务或审计 |

#### US-M1-003 客户/门店档案

| 维度 | 场景 |
|------|------|
| L4 错误路径 | 客户编码重复 → M1_CUSTOMER_DUPLICATE; 门店地址不完整 → M1_ADDRESS_INCOMPLETE |
| L5 数据一致 | 客户/门店变更与审计记录原子写入; 客户停用后不可新建出库订单 |
| L8 权限 | 仓库主管可管理; 门店用户只读本门店 |
| L11 幂等 | 创建/修改支持 Idempotency-Key |

## 附录 A：储存条件温度区间表

> 业务背景：药品包装上的储存条件文字写法不规范（如"常温保存""阴凉处保存""2-8℃避光保存"）。
> 商品档案录入时必须强制映射到下表 4 个标准枚举之一，由 M-VR 校验规则模块基于温度区间判定温度超标。

| 枚举值 | 温度区间 | 湿度区间 | 适用商品类型（举例） |
|--------|---------|---------|--------------------|
| 冷冻 | ≤ -18℃ | 不限 | 部分生物制品、疫苗 |
| 冷藏 | 2℃ ~ 8℃ | 35% ~ 75% | 生物制品、疫苗、胰岛素 |
| 阴凉 | ≤ 20℃ | 35% ~ 75% | 部分中药材、易受热分解药品 |
| 常温 | 10℃ ~ 30℃ | 35% ~ 75% | 大多数普通药品 |

### 使用约定

1. **录入约束**：商品档案的"储存条件"字段是结构化枚举，不接受自由文本（M1-001 验收标准 5）
2. **温度判定**：温度数据由外部冷链系统采集后通过 M5-002 推送到 WMS；M-VR 规则可比对**温度超标事件**与商品所在库区/运输工具的允许温度区间用于业务关联（v7 边界：WMS 不直接采集温度，原 M5-001 已移除）
3. **库区匹配**：M1-004 库区"温区"属性使用同一枚举集，上架时温区不匹配拒绝（M2-005）
4. **冷链定义**：储存条件为"冷藏"或"冷冻"的商品在本系统统一称为"冷链商品"，涉及冷链业务规则
5. **可扩展**：未来如需新增枚举（如"阴凉冷藏"），由系统管理员在配置中心维护，本表同步更新
6. **ERP 推送的不规则文本规整化**：ERP / 上游系统的储存条件常为不规则自由文本（如"2-8℃避光保存""阴凉处保存""室温"），ERP 发布器在 INSERT 前通过 **M-PM 参数对照模块**（user-stories-mpm-parameter-mapping.md）规整到本表 4 个标准枚举；未命中规则的源文本进入 ERP 发布失败队列并触发 M-PM 待办，不得进入接口表

### 例外处理

- 商品包装写"室温保存" → M-PM 规则映射为"常温"
- 商品包装写"低温保存" → 需供应商澄清具体区间，规则不预置默认映射；留在 ERP 发布失败队列，完成"冷藏"或"冷冻"映射后重新发布
- 包装无明确储存条件 / M-PM 全部规则未命中 → 不写 ERP 接口表；若绕过前置校验，WMS 以不可重试失败拒绝且不创建商品
