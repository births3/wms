# 用户故事：M3 库存（查询与批次管理）

> 模块：M3 inventory
> 依赖：M1 基础档案、M2 入库、H1 权限、H2 审计
> 关联 ADR：0001、0006（TDD）、ADR-0008（借鉴 Odoo ADR-0008 §2 inventory_move 三段式）

---

## US-M3-001：实时库存查询

**作为** 仓库主管（或货主）
**我要** 按商品/批号/库位/货主/温区等维度查询当前库存
**以便** 随时掌握库存全貌，支撑出库决策和补货计划

### 验收标准

1. 查询维度：商品、批号、库位（排-列-层）、库区、温区、货主、库存状态
2. 显示字段：商品信息、批号、生产日期、有效期、数量、库位、容器/托盘、库存状态
3. 支持组合筛选 + 模糊搜索
4. 支持导出 Excel
5. 货主只能看到自己的库存（多租户隔离）
6. 实时性：库存变动后查询立即反映（无延迟缓存）
7. 支持 API 查询（供外部系统调用）
8. **库位维度专项视图**（按库位反查内容）：
   - 输入库位编码（或扫库位码）→ 显示该库位当前所有商品 + 批号 + 数量 + 状态
   - 显示库位元信息：温区、色标、最大容积、当前已用容积、剩余容积、最大 SKU 数、当前 SKU 数
   - 一键跳转到 US-M3-011 库位历史追踪
9. **批次维度专项视图**（按批号反查流向，与 US-M3-002 联动）：
   - 输入批号 → 显示该批次的所有库位分布 + 总数量 + 状态分布

## US-M3-002：批次与效期管理

**作为** 仓库主管
**我要** 对所有库存按批号+效期管理，监控近效期和过期风险
**以便** 在过期前预警、配合 ERP 决策，避免过期损失和 GSP 违规

### 验收标准

1. 每条库存记录必须关联：批号、生产日期、有效期
2. **出库批号由 ERP 指定**：WMS 不做 FIFO/FEFO 分配决策，只校验指定批号有库存
3. **近效期预警**：距过期 < 6 个月（默认，可配置）的批次自动标记"近效期"
4. **近效期预警报表**：按商品/批号/剩余天数排序，供仓库主管查看并反馈 ERP 优先出库
5. **过期锁定**：到达有效期的批次自动变为"不合格"状态，锁定不可出库；批量隔离写入 `approval_source = M3-002-EXPIRY`、`approval_id = 批次 ID`、原因“有效期到期自动隔离”
6. 近效期/过期预警推送企业微信通知（仓库主管）
7. **召回标记字段**（v25 新增）：每条库存批次记录含 `recall_flag` 字段（默认 false），用于标识该批次是否被纳入药品召回；字段属性：
   - 触发途径：仓库主管手动标记 / M-QL 召回类型联系单审批通过自动标记 / M-TC 反查触发标记
   - 标记后行为：批次状态自动联动变为"隔离"（M3-003 §审批源 = 质量联系单, approval_id = 召回联系单 ID）；不可分配出库；H4 通知仓库主管 + 已发货客户清单提示回收
   - 取消标记：仅仓库主管 + 质量负责人双人审批可取消（与 M1-010 麻精毒放分类双人审批同标准）
   - GSP 法规依据：不-4 召回流程；clarifications #21 决策"批次召回标记 = 需要"
8. 批次追溯：输入批号可查看该批次的完整流转记录（入库→库位→出库→客户）；含召回标记历史
9. 批次追溯 + 召回标记变更写入审计追踪（含 approval_source = 质量联系单 / approval_id = 召回联系单 ID / 操作人 / 时间 / 旧值 / 新值）

## US-M3-003：库存状态管理

**作为** 仓库主管
**我要** 管理库存的质量状态，通过加减锁改变状态
**以便** 不同状态的库存存放在对应色标区域，且只有合格可出库

### 库存质量状态机

=== "📊 流程图"

    ```mermaid
    stateDiagram-v2
        [*] --> 合格 : M2 验收合格上架
        合格 --> 隔离 : 质量联系单/对账差异/<br/>养护异常/温度超标事件
        隔离 --> 合格 : 验收结论
        隔离 --> 不合格 : 验收结论
        合格 --> 报损扣减 : 报损报溢单
        不合格 --> 报损扣减 : 报损报溢单/质量联系单
        不合格 --> 待销毁 : 质量联系单
        待销毁 --> [*]
        报损扣减 --> [*]
    ```

=== "📝 源码"

    ```
    stateDiagram-v2
        [*] --> 合格 : M2 验收合格上架
        合格 --> 隔离 : 质量联系单/对账差异/<br/>养护异常/温度超标事件
        隔离 --> 合格 : 验收结论
        隔离 --> 不合格 : 验收结论
        合格 --> 报损扣减 : 报损报溢单
        不合格 --> 报损扣减 : 报损报溢单/质量联系单
        不合格 --> 待销毁 : 质量联系单
        待销毁 --> [*]
        报损扣减 --> [*]
    ```

### 验收标准

1. 库存状态（可配置，维护表管理）：合格、隔离、不合格（默认值，可扩展）
2. 状态与色标对应：合格→绿区、隔离→黄区、不合格→红区
3. **只有"合格"状态的库存可被出库分配**
4. **库存锁定**：波次分配后锁定对应数量（库存状态不变，仍为"合格"，但锁定数量不可被其他订单分配）；发货后正式扣减
5. 状态变更通过**加减锁**操作，必须有"原因"和"审批源"两个字段：
   - **原因（reason）**：自由文本，记录变更说明
   - **审批源（approval_source）**：标识触发本次变更的审批来源，类型枚举：
     - `质量联系单`（M-QL）：人工发起的合格→隔离/不合格→待销毁
     - `验收结论`（M2-003）：隔离→合格 或 隔离→不合格
     - `对账差异`（M-RC）：主管在对账差异列表勾选触发的隔离，审批源 ID = 对账记录 ID
     - `养护异常`（M3-004）：养护发现质量问题触发的隔离
     - `系统盘点`（M3-005）：盘点差异审批通过后的状态调整
     - `温度超标事件`（M5-003）：外部冷链系统推送超标事件，主管在事件列表勾选触发的隔离，审批源 ID = 外部冷链系统事件 ID
     - `报损报溢单`（M-SA）：来自 ERP 推送或手工创建的报损单，审批源 ID = 报损/报溢单 ID
   - 流转约束：
     - 隔离 → 合格：审批源必须为"验收结论"
     - 隔离 → 不合格：审批源必须为"验收结论"
     - 合格 → 隔离：审批源为"质量联系单""对账差异""养护异常""温度超标事件"之一
     - 不合格 → 待销毁：审批源必须为"质量联系单"
     - 任意状态 → 报损扣减：审批源为"报损报溢单"或"质量联系单"
6. 隔离操作立即生效（锁定库存，不可出库/移库）
7. 所有状态变更写入审计追踪
8. **ERP 反馈**：库存状态变更后自动将调整信息（商品/批号/数量/旧状态/新状态/原因）通过 API 反馈 ERP（异步，失败可重试）

### 库存增减触发规则

| 触发事件 | 库存动作 | 来源模块 |
|---------|---------|---------|
| M2 上架完成 | +增加（合格/不合格，按验收结论） | M2 domain event |
| M4 波次分配 | 锁定数量（状态不变，锁定部分不可再分配） | M4 波次算法 |
| M4 发货确认 | -扣减（正式出库，释放锁定） | M4 发货 |
| M4 强制作废回退上架 | 释放锁定数量 | M4 作废 |
| 盘盈审批通过 | +增加 | M3 盘点 |
| 盘亏审批通过 | -扣减 | M3 盘点 |
| 销退入库 | +增加 | M4 退货 |
| 报损执行 | -扣减 | M-SA 报损 |
| 报溢执行 | +增加 | M-SA 报溢 |
| 对账差异手动加锁 | 状态变"隔离" | M-RC 对账 |
| 温度超标事件主管勾选 | 状态变"隔离"（携带审批源=温度超标事件）| M5 冷链 |

## 跨故事约束（适用于所有 M3 用户故事）

1. **审计追踪**：所有库存变动（增/减/移/隔离/类型变更）必须写入审计表
2. **多货主**：库存按货主隔离，查询/操作自动过滤
3. **库存变更必须经领域服务**：禁止直接 SQL 修改库存（红线）
4. **事务一致性**：移库的"减+增"必须在同一事务内
5. **幂等性**：所有写操作支持 Idempotency-Key
6. **出库批号由 ERP 指定**：WMS 不做 FIFO/FEFO 分配决策，只校验指定批号有库存并执行拣选
7. **PDA 离线**：移库/盘点支持离线暂存；离线期间发生数据冲突（如该库位被他人占用、库存被外部系统占用）时，**暂存为"待主管处理"事件**，由仓库主管在 PC 端手动决策，禁止静默覆盖
8. **开放 API**：库存查询支持外部系统调用
9. **系统触发的隔离免二次审批**（v3.1 新增，K14）：以下三种触发源在源模块内已有人工决策环节，进入 M3 状态隔离时不再要求仓库主管二次审批，但 `approval_source` 字段必须填具体来源 ID：
   - **对账差异**：`approval_source = M-RC` + 对账 ID（M-RC 主管已在差异列表勾选）
   - **质量联系单**：`approval_source = M-QL` + 联系单 ID（M-QL 已经过 H4 企微审批）
   - **温度超标处置**：`approval_source = M5-超标事件 ID + M-VR 处置规则 ID`
   保管员手动加锁则需走 M-QL 联系单审批（人工发起的状态变更必须有显式审批源）
10. 测试要求：写操作必须含 L4（错误路径）+ L5（数据一致）+ L8（权限）+ L11（幂等）；读操作必须含 L4 + L8

### 测试维度覆盖

#### US-M3-001 实时库存查询

| 维度 | 场景 |
|------|------|
| L4 错误路径 | 查询条件为空 → 提示"请至少选择一个筛选条件"; 商品不存在 → 空结果; 查询超时（大数据量）→ 提示分页或缩小范围 |
| L5 数据一致 | 查询结果 = 入库累计 - 出库累计 - 冻结数量; 实时库存与批次明细汇总一致 |
| L8 权限 | 仓库主管查本仓全部; 货主查本货主; 保管员查本库区; 跨货主 → 0 结果 |
| L11 幂等 | 查询天然幂等 |

#### US-M3-002 批次与效期管理

| 维度 | 场景 |
|------|------|
| L4 错误路径 | 批号格式不合法 → M3_BATCH_FORMAT_INVALID; 效期修改后 < 当前日期 → M3_BATCH_ALREADY_EXPIRED; 批次状态变更无 approval_source → M3_APPROVAL_SOURCE_REQUIRED |
| L5 数据一致 | 批次状态变更与库存可用数量联动（隔离 → 可用数减少）; 近效期预警与 expire_warning_days 配置一致 |
| L8 权限 | 仓库主管可变更批次状态; 保管员只读; 状态变更需 approval_source |
| L11 幂等 | 状态变更支持 Idempotency-Key; 重复变更到相同状态 → 跳过 |

#### US-M3-003 库存状态管理

| 维度 | 场景 |
|------|------|
| L4 错误路径 | 目标状态不在合法流转路径 → M3_INVALID_STATE_TRANSITION; 冻结已冻结的库存 → M3_ALREADY_FROZEN; 解冻无 approval_source → M3_APPROVAL_SOURCE_REQUIRED |
| L5 数据一致 | 状态变更与可用库存原子更新; 状态机流转严格按定义（合格→隔离→待销毁→销毁 等） |
| L8 权限 | 仓库主管可冻结/解冻; 质量负责人可隔离/放行; 销毁需双人审批 |
| L11 幂等 | 状态变更支持 Idempotency-Key; 已在目标状态 → 返回当前状态（不报错） |

### PDA 弹性

> M3 查询/批次模块主要为 PC 端操作，PDA 端仅涉及库存查询（扫码查库存）。

#### 离线策略

| 场景 | 行为 |
|------|------|
| PDA 离线时查库存 | 显示最后同步的库存快照（标记"离线数据，可能不准确"） |

#### 扫码交互

| 场景 | 行为 |
|------|------|
| 扫描商品条码查库存 | 解析商品 → 显示该商品各批次库存明细 |
| 扫描库位码查库存 | 解析库位 → 显示该库位所有商品库存 |

#### 异常恢复

| 场景 | 行为 |
|------|------|
| 库存数据缓存过期 | 网络恢复后自动刷新; 过期数据标记"可能已变更" |
