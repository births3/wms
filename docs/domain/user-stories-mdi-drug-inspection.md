# 用户故事：M-DI 药检单查询模块

> 模块：M-DI drug-inspection
> 性质：独立业务模块（入库验收时使用）
> 波次：Wave 3（依赖 M2 入库验收流程）
> 依赖：M1 商品档案、M2 入库、H1 权限、H2 审计

---

## US-DI-001：药检单平台对接配置

**作为** 系统管理员
**我要** 配置药检单查询平台的 API 对接参数
**以便** 系统能自动从平台获取药检报告

### 验收标准

1. 平台配置：API 地址、认证方式（API Key / 账号密码）、超时设置
2. 支持多个药检平台（不同供应商可能用不同平台）
3. 平台状态：已对接/测试中/停用
4. 配置变更写入审计追踪

---

## US-DI-002：扫码批量查询药检单

**作为** 收货员
**我要** 在 PDA 或 PC 上扫描随货同行单上的二维码，批量查询并获取药检报告
**以便** 验收时能快速获取该批次的药检结果，无需手动逐个查询

### 验收标准

1. 扫描随货同行单二维码 → 解析出查询参数（供应商/商品/批号等）
2. 系统调用药检单平台 API → 批量获取该单所有商品的药检报告
3. 获取结果：药检报告 PDF / 图片 + 检验结论（合格/不合格）+ 检验日期
4. 支持一次扫码获取多个批号的药检单（随货同行单可能含多批号）
5. 获取成功 → 自动关联到对应 ASN 的验收记录
6. 获取失败 → 提示"未查到药检单"，可手动上传
7. **PDA 支持**：PDA 扫码触发查询，结果显示在 PDA 上
8. **PC 支持**：PC 端扫码枪扫码或手动输入二维码内容
9. 查询记录写入审计追踪

---

## US-DI-003：药检单存储与查看

**作为** 仓库主管 / 收货员
**我要** 查看已获取的药检报告（PDF/图片），并与 ASN/批次关联
**以便** 验收时参考药检结论，归档满足 GSP 要求

### 验收标准

1. 药检单存储在对象存储（MinIO/S3），关联：商品+批号+供应商+ASN
2. 查看方式：在验收详情页点击"药检单"可预览 PDF/图片
3. 支持手动上传药检单（平台查不到时的兜底）
4. 一个批次可关联多份药检单（如初检+复检）
5. 药检单不可删除（GSP 要求保留）
6. 支持按商品/批号/供应商/时间查询已有药检单
7. 药检单上传/关联写入审计追踪

---

## US-DI-004：药检单有效性校验

**作为** 系统（自动）
**我要** 在验收时自动校验药检单是否齐全且结论合格
**以便** 缺少药检单或药检不合格时提醒收货员处理

### 验收标准

1. 验收提交时系统检查：该 ASN 的所有批号是否都有关联的药检单
2. 缺少药检单 → 警告（可配置为阻塞或仅提醒）
3. 药检结论为"不合格" → 自动标记该批次为不合格
4. 校验规则可配置：哪些商品类别必须有药检单（如生物制品必须，普通药品可选）
5. 校验结果记录在验收记录中

---

## 跨故事约束

1. **审计追踪**：所有查询/上传/关联操作写入审计表
2. **多货主**：药检单按货主隔离
3. **GSP 合规**：药检单不可删除，保留期 ≥ 5 年
4. **离线**：PDA 离线时可先完成验收，药检单查询待恢复网络后补充
5. **对象存储**：药检单文件存储在 MinIO/S3，数据库只存元数据和引用路径
