# 用户故事：M-DI 药检单查询模块

> 模块：M-DI drug-inspection
> 性质：独立业务模块（入库验收时使用）
> 波次：Wave 3（依赖 M2 入库验收流程）
> 依赖：M1 商品档案、M2 入库、M3 库存、M-QL 质量联系单、H1 权限、H2 审计

---

## US-DI-001：药检单平台对接配置

**作为** 系统管理员
**我要** 配置药检单查询平台的 API 对接参数
**以便** 系统能自动从平台获取药检报告

### 验收标准

1. 平台配置：API 地址、认证方式（API Key / 账号密码）、超时设置
2. 支持多个药检平台（不同供应商可能用不同平台）
3. 平台状态：已对接/测试中/停用
4. 配置变更写入审计追踪

---

## US-DI-002：扫码批量查询药检单

**作为** 收货员
**我要** 在 PDA 或 PC 上扫描随货同行单上的二维码，批量查询并获取药检报告
**以便** 验收时一次扫码即可批量获取该批次的药检结果，无需手动逐个查询

### 验收标准

1. **PDA 药检单查询扫码顺序**：

```
1. 扫随货同行单二维码 → 解析查询参数（供应商/商品/批号等）
2. 调用药检单平台 API → 批量获取该单所有商品的药检报告
3. 显示报告列表（PDF/图片 + 检验结论 + 检验日期）
4. 选择报告关联到当前 ASN 验收记录 → 提交
```

2. **PDA 药检单查询字段表**：

| 字段 | 必填 | 系统带出/录入 | 说明 |
|------|------|-------------|------|
| 二维码内容 | 必填 | 扫码 | 随货同行单二维码 |
| 解析参数 | 系统带出 | — | 供应商 + 商品列表 + 批号 |
| 关联 ASN | 系统带出 | — | 当前验收 ASN |
| 报告列表 | 系统带出 | — | 平台返回的报告 + 结论 |
| 关联结果 | 系统带出 | — | 成功 / 失败（手动上传兜底）|
| 操作人 user_id | 系统带出 | — | |
| 查询时间 | 系统带出 | — | |

3. 系统调用药检单平台 API → 批量获取该单所有商品的药检报告
4. 获取结果：药检报告 PDF / 图片 + 检验结论（合格/不合格）+ 检验日期
5. 支持一次扫码获取多个批号的药检单（随货同行单可能含多批号）
6. 获取成功 → 自动关联到对应 ASN 的验收记录
7. 获取失败 → 提示"未查到药检单"，可手动上传
8. **PDA 支持**：PDA 扫码触发查询，结果显示在 PDA 上
9. **PC 支持**：PC 端扫码枪扫码或手动输入二维码内容
10. **离线支持**：PDA 离线时可先完成验收（M2-003），药检单查询待恢复网络后补充（参 M-DI 跨故事约束 4），离线期间冲突按"暂存待主管处理"
11. 查询记录写入审计追踪

## US-DI-003：药检单存储与查看

**作为** 仓库主管 / 收货员
**我要** 查看已获取的药检报告（PDF/图片），并与 ASN/批次关联
**以便** 验收时参考药检结论，归档满足 GSP 要求

### 验收标准

1. 药检单存储在对象存储（MinIO/S3），关联：商品+批号+供应商+ASN
2. 查看方式：在验收详情页点击"药检单"可预览 PDF/图片
3. 支持手动上传药检单（平台查不到时的兜底）
4. 一个批次可关联多份药检单（如初检+复检）
5. 药检单不可删除（GSP 要求保留）
6. 支持按商品/批号/供应商/时间查询已有药检单
7. 药检单上传/关联写入审计追踪

---

## US-DI-004：药检单有效性校验

**作为** 系统（自动）
**我要** 在验收时自动校验药检单是否齐全且结论合格
**以便** 缺少药检单或药检不合格时提醒收货员处理

### 验收标准

1. 验收提交时系统检查：该 ASN 的所有批号是否都有关联的药检单
2. 缺少药检单 → 警告（可配置为阻塞或仅提醒）
3. 药检结论为"不合格" → 自动生成 M-QL 质量联系单（类型=药检异常）并阻塞该批次验收；不得绕过审批直接改库存状态
4. M-QL 审批通过后，由 M-QL 调用 M3 库存状态变更，携带 `approval_source = 药检异常`、`approval_id = 质量联系单 ID`，将对应批次转为隔离或不合格
5. 校验规则可配置：哪些商品类别必须有药检单（如生物制品必须，普通药品可选）
6. 校验结果记录在验收记录中

## 跨故事约束

1. **审计追踪**：所有查询/上传/关联操作写入审计表
2. **多货主**：药检单按货主隔离
3. **GSP 合规**：药检单不可删除，保留期 ≥ 5 年
4. **离线**：PDA 离线时可先完成验收，药检单查询待恢复网络后补充；如离线期间该 ASN 状态发生冲突，**暂存为"待主管处理"事件**，禁止静默覆盖
5. **对象存储**：药检单文件存储在 MinIO/S3，数据库只存元数据和引用路径
6. **药检异常审批链**：药检不合格只能通过 M-QL → M3 状态变更链路处置，禁止 M-DI 直接修改库存状态
7. **幂等性**：药检单查询/上传/关联/异常联系单创建支持 Idempotency-Key，重复操作不产生重复记录

### 测试维度覆盖

#### US-DI-001 药检单创建

| 维度 | 场景 |
|------|------|
| L4 错误路径 | 关联 ASN 不存在 → DI_ASN_NOT_FOUND; 药检机构不在白名单 → DI_INSTITUTION_INVALID; 必填字段缺失 → DI_FIELD_REQUIRED; 重复创建同一批次药检单 → DI_DUPLICATE |
| L5 数据一致 | 药检单与 ASN/批次关联; 药检状态与验收流程联动（未通过 → 隔离） |
| L8 权限 | 收货员/仓库主管可创建; 货主只读; 跨货主 → 403 |
| L11 幂等 | 创建支持 Idempotency-Key |

#### US-DI-002 药检单 PDA 关联

| 维度 | 场景 |
|------|------|
| L4 错误路径 | 扫码无匹配 ASN → DI_ASN_NOT_FOUND; 药检报告文件上传失败 → 暂存本地; 文件格式不支持 → DI_FILE_FORMAT_INVALID |
| L5 数据一致 | PDA 关联结果与 PC 端一致; 附件与药检单关联 |
| L8 权限 | 收货员可关联; 保管员 → 403 |
| L11 幂等 | 同一药检单 + 同一附件重复关联 → 返回已有记录 |

#### US-DI-003 药检结果录入

| 维度 | 场景 |
|------|------|
| L4 错误路径 | 检验项目不在标准内 → DI_INVALID_ITEM; 结果值超出合理范围 → DI_VALUE_OUT_OF_RANGE; 药检单已关闭 → DI_ALREADY_CLOSED |
| L5 数据一致 | 检验结果与药检单状态联动（全部合格 → 通过; 任一不合格 → 不通过）; 不通过 → 触发 M-QL 联系单 |
| L8 权限 | 仓库主管/质量负责人可录入; 收货员只读 |
| L11 幂等 | 结果录入支持 Idempotency-Key; 重复录入同一项目 → 更新为最新值 |

#### US-DI-004 药检单查询与统计

| 维度 | 场景 |
|------|------|
| L4 错误路径 | 查询时间范围过大 → 分页; 无匹配 → 空列表 |
| L5 数据一致 | 统计数字与明细可对账; 合格率计算正确 |
| L8 权限 | 仓库主管查本仓; 货主查本货主; GSP 审计员查全部 |
| L11 幂等 | 查询天然幂等 |
