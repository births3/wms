# 用户故事：H4 企业微信通知与审批模块

> 模块：H4 wechat-work-notify
> 性质：横向能力（所有业务模块共用）
> 波次：Wave 1（与 H1/H2/H3 同期）
> 依赖：H1 权限（需要知道通知接收人）

---

## US-H4-001：通知配置

**作为** 系统管理员
**我要** 配置"什么事件 → 发什么通知 → 给谁"的规则
**以便** 业务事件发生时自动通知相关人员，无需人工传话

### 验收标准

1. 通知事件枚举（可扩展）：
   - 资质到期预警
   - 近效期预警
   - 温度超标
   - ASN 到货
   - 验收不合格
   - 盘点差异
   - 库存预警（安全库存/超储）
   - 审批待办
   - 审批结果
   - **召回联系单创建**（v25 审计修复）：M-QL "召回"类型联系单创建后触发；通知仓库主管 + 质量负责人 + 已发货客户回收提示（按 M-QL-002 §5 affected_customers 清单）；模板变量含 recall_id / recall_level / 时限
   - **召回回收完成**（v25 审计修复）：M-QL 召回联系单 status 流转到"回收完成"时通知仓库主管
2. 每个事件可配置：
   - 是否启用
   - 通知模板（支持变量占位符）
   - 接收人规则（指定角色 / 指定用户 / 货主相关人）
   - 通知方式：企业微信消息（必选）、短信（可选）、邮件（可选）
3. 配置变更写入审计追踪

---

## US-H4-002：企业微信消息发送

**作为** 系统（自动）
**我要** 在业务事件触发时，按配置规则向企业微信发送通知消息
**以便** 相关人员第一时间收到提醒

### 验收标准

1. 对接企业微信 API（应用消息 / 群机器人），企业 ID、Agent ID、密钥别名、回调地址和重试参数可在管理端维护
2. 消息内容从模板 + 业务数据渲染
3. 发送失败自动重试（可配置重试次数和间隔）
4. 所有发送记录入库（发送时间、接收人、内容、状态：成功/失败/重试中），写入审计追踪
5. 发送记录可查询（按事件/时间/接收人/状态筛选）
6. 支持批量发送（同一事件通知多人）

---

## US-H4-003：企业微信审批流对接

**作为** 系统（自动）
**我要** 将需要审批的业务单据推送到企业微信审批流，审批结果自动回写 WMS
**以便** 审批人在企业微信上完成审批，WMS 自动流转状态

### 验收标准

1. 支持的审批场景（可扩展）：
   - ASN 作废审批
   - 出库订单作废审批
   - 库存隔离审批
   - 盘点差异审批
   - 质量联系单审批（验收不合格）
   - 系统配置变更审批（GSP 关键参数）
2. 推送审批单到企业微信：包含业务摘要、审批人、审批流程 ID、回调地址
3. 企业微信审批完成后回调 WMS（webhook / 轮询）
4. 审批结果回写：审批人、审批时间、审批结论（同意/拒绝）、审批意见
5. 审批记录存储在 WMS（不依赖企业微信历史查询）
6. 审批超时提醒（可配置超时时长）
7. 审批记录写入审计追踪

---

## US-H4-004：通知发送记录查询

**作为** 系统管理员
**我要** 查询所有通知和审批的发送记录
**以便** 排查"通知没收到"或"审批没回写"的问题

### 验收标准

1. 查询维度：事件类型、时间范围、接收人、发送状态
2. 显示字段：事件、时间、接收人、内容摘要、状态、重试次数、失败原因
3. 支持手动重发（失败的通知）
4. 支持导出

---

## 跨故事约束

1. **异步发送**：通知/审批推送不阻塞业务主流程（异步队列）
2. **幂等**：同一事件重复触发不重复发送（去重 key）
3. **多货主**：通知接收人按货主过滤（货主 A 的事件不通知货主 B 的人）
4. **降级**：企业微信 API 不可用时，通知进入重试队列，不影响业务操作
5. **审计**：所有发送/审批记录 append-only

### 测试维度覆盖

#### US-H4-001 通知配置

| 维度 | 场景 |
|------|------|
| L4 错误路径 | 事件枚举不存在 → H4_EVENT_NOT_FOUND; 模板变量缺失 → H4_TEMPLATE_INVALID; 接收人规则为空 → H4_NO_RECIPIENTS |
| L5 数据一致 | 配置变更与审计记录原子写入; 启用/禁用状态与实际发送行为一致 |
| L8 权限 | 仅系统管理员可配置; 非管理员 → 403 |
| L11 幂等 | 相同 Idempotency-Key 重复提交配置变更 → 返回首次结果 |

#### US-H4-002 企业微信消息发送

| 维度 | 场景 |
|------|------|
| L4 错误路径 | 企业微信 API 返回错误 → 重试（ADR-0018 L2 标准重试）; access_token 过期 → 自动刷新后重试; 接收人不存在 → 记录失败 + 跳过 |
| L5 数据一致 | 发送记录与实际发送状态一致; 重试次数与记录一致 |
| L8 权限 | 系统自动触发，不需用户权限; 但事件源必须来自合法业务模块（防伪造） |
| L11 幂等 | 同一事件 + 同一接收人 + 同一去重 key → 不重复发送 |

#### US-H4-003 企业微信审批流对接

| 维度 | 场景 |
|------|------|
| L4 错误路径 | 推送审批单失败 → 重试 + 告警; 回调超时 → 轮询兜底; 审批人不存在 → 升级到仓库主管; 回调签名验证失败 → 拒绝 + 告警 |
| L5 数据一致 | 审批结果回写与企业微信侧一致; WMS 审批记录与业务单据状态原子更新 |
| L8 权限 | 审批人必须有对应业务权限; 非授权人审批 → 拒绝回写 |
| L11 幂等 | 同一审批单重复回调 → 幂等处理（已回写则跳过） |

#### US-H4-004 通知发送记录查询

| 维度 | 场景 |
|------|------|
| L4 错误路径 | 查询时间范围过大 → 提示分页; 无匹配记录 → 空列表 |
| L5 数据一致 | 查询结果与实际发送记录一致 |
| L8 权限 | 仅系统管理员可查全部; 普通用户只能查自己收到的通知 |
| L11 幂等 | 查询天然幂等; 手动重发支持 Idempotency-Key（不重复发送） |

### PDA 弹性

> H4 为后端服务模块，PDA 端不直接操作通知配置。但 PDA 端接收通知推送：

#### 离线策略

| 场景 | 行为 |
|------|------|
| PDA 离线时有新通知 | 企业微信 APP 自身处理离线推送; WMS PDA 端不额外处理 |
| PDA 恢复网络 | 自动拉取未读通知列表（如有 WMS 内通知中心） |

#### 扫码交互

不适用（H4 不涉及扫码）。

#### 异常恢复

| 场景 | 行为 |
|------|------|
| 通知推送失败（企微侧） | WMS 记录失败状态; 管理员可手动重发 |
| 审批回调丢失 | 定时轮询企业微信审批状态（每 5 分钟）; 发现已审批但未回写 → 补回写 |
