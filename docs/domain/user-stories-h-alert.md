# 用户故事：H-AL 告警引擎（alert-engine）

> 模块：H-AL 横向能力 / Wave 1（与 H4 一起实施）
> 性质：所有业务模块的告警基础设施（GSP 5.71 触发响应时间合规）
> 依赖：H1（权限）/ H2-005（事件总线）/ H4（消息发送通道）
> 关联 ADR：ADR-0001（技术栈）/ ADR-0007（v0.3 路线）

---

## 背景

GSP 5.71 / 7.97 / 7.100 / 8.119 / 冷-7 等条款均有"触发响应时间"要求（养护超期、近效期、不合格隔离响应、断链响应）。当前告警散落在各业务模块（"通知仓库主管"语句出现 16 个文件 32 次），缺统一的：

- 告警类型注册表（告警源 / 触发条件 / 默认级别）
- 告警分级（info / warning / critical）
- 告警生命周期（触发 → 通知 → 确认 → 升级 → 关闭）
- 升级机制（30 分钟未确认升一级 / 2 小时升 manager / 24 小时升 escalation_manager）
- 多渠道路由（企微 / 邮件 / 短信 / PDA 弹窗）
- 静默期 / 抖动抑制（同类告警短时间内只发一次）

H-AL 在 H4 通知（消息发送通道）之上承载**告警业务逻辑**。

---

## 跨故事约束

1. **审计追踪**：告警定义变更 + 触发记录 + 确认/升级/关闭操作写入 H2 审计追踪
2. **事件驱动**：告警基于 H2-005 事件总线订阅业务事件触发（不直接调用 → 解耦）
3. **多通道委托**：H-AL 不直接发短信/企微，调用 H4 各通道接口
4. **多货主**：告警定义按货主隔离；接收人按货主 + 仓库角色查询
5. **幂等性**：告警触发支持 Idempotency-Key（同事件 ID + 同告警类型 = 同一告警实例）
6. **GSP 合规**：触发响应时间相关告警（5.71 / 7.97 / 7.100 / 8.119 / 冷-7）必须可独立配置且不能停用
7. **测试要求**：写操作必须含 L4（错误路径）+ L5（数据一致）+ L8（权限）+ L11（幂等）；读操作必须含 L4 + L8

## US-AL-001：告警定义注册

**作为** 仓库主管 / 系统管理员
**我要** 维护本系统的告警类型清单（触发条件 / 默认级别 / 接收人组 / 升级规则）
**以便** 告警可控可配置 + 业务模块只需发布事件不必关心通知细节

### 验收标准

1. **告警定义字段**：
   - 告警 ID（业务唯一，如 `ALERT_TEMP_EXCEEDED`）
   - 告警名称（中文）
   - 触发事件（关联 H2-005 事件类型，如 `business.cold_chain.temp_exceeded`）
   - 触发条件（可选 JSON 表达式，如 `severity >= 'critical'`）
   - 默认级别：info / warning / critical
   - 默认接收人组（角色：仓库主管 / 养护员 / 系统管理员 / 货主联系人）
   - 升级规则引用（关联 US-AL-003）
   - 静默期（同类告警 N 分钟内只发一次，默认 5 分钟可配置）
   - 是否可停用：GSP 强制告警标 `is_disable_allowed = false`
   - 多语言消息模板（中文为主）
2. **GSP 强制告警预置**（系统初始化）：
   - 资质有效期 < 30 天（GSP 6.79）
   - 近效期 < 6 个月（GSP 7.100）
   - 养护超期 > 计划 +3 天（GSP 7.97）
   - 不合格隔离 > 24 小时未处理（GSP 8.119 / 不-1）
   - 冷链断链事件接收（GSP 冷-7）
   - 销毁审批超时 > 48 小时（GSP 7.103）
   - 这些告警 `is_disable_allowed = false`
3. **业务告警可配置**：业务方可增删非 GSP 强制类告警（如"月台空置率 > 阈值"）
4. **变更控制**：告警定义修改触发 M-QL 联系单（类型=告警定义变更）
5. **审计**：定义增删改写入 H2 审计

### 异常路径

- 删除已有触发记录的告警定义 → 不允许，必须先停用
- GSP 强制告警尝试停用 → 拒绝并提示"is_disable_allowed=false"

## US-AL-002：告警触发与生命周期

**作为** 系统（自动）
**我要** 收到事件后按定义触发告警，并按生命周期管理（触发 → 通知 → 确认 → 关闭）
**以便** 业务异常有完整闭环 + 不漏不重

### 验收标准

1. **触发流程**：
   - 订阅 H2-005 事件总线
   - 收到事件 → 匹配告警定义（事件类型 + 触发条件）
   - 命中 → 创建告警实例（含触发时间 / 事件载荷快照 / 接收人组）
2. **告警状态机**：
   - 已触发 → 已通知 → 已确认 → 已处理 → 已关闭
   - 已触发 → 已超时（未确认）→ 已升级 → 已确认 → ...
   - 已关闭 / 已忽略（业务方主动忽略 + 必填忽略原因）
3. **静默期**：同 (告警类型 + 关联资源 ID) 在静默期内仅触发一次（避免事件抖动）
4. **去重 key**：`alert_dedup_key = alert_type + resource_type + resource_id + 时间窗`
5. **通知委托**：调用 H4 接口按接收人组路由通道（企微 / 邮件 / 短信 / PDA 弹窗）
6. **确认流程**：接收人在企微 / PC / PDA 上点确认 → 状态变为"已确认"+ 暂停升级计时
7. **处理记录**：可附加处理动作描述（如"已派 X 处理 / 已生成 M-QL 联系单"）
8. **关闭流程**：
   - 自动关闭：业务事件解除（如温度恢复）→ 系统自动关闭
   - 手动关闭：接收人确认处理完毕后手动关闭
9. **审计**：触发 / 通知 / 确认 / 升级 / 关闭 全部写入 H2 审计

### 异常路径

- 通知发送失败（H4 报错）→ 重试 3 次 → 标记"通知失败"+ 触发"告警通知失败"二级告警
- 接收人组为空（角色无人）→ 升级到上级管理员
- 业务事件解除但告警未关闭 → 系统超时（默认 7 天）后自动关闭并记录"超时未关闭"

## US-AL-003：告警升级机制

**作为** 仓库主管 / 系统管理员
**我要** 配置告警的升级规则（多少时间未确认 → 升到谁）
**以便** GSP 触发响应时间合规 + 关键告警不被遗忘

### 验收标准

1. **升级规则字段**：
   - 规则 ID + 关联告警类型
   - 升级层级（最多 3 级）：
     - L1 主接收人（角色：养护员 / 收货员 / ...）
     - L2 直接上级（角色：仓库主管）
     - L3 升级管理员（角色：系统管理员 + 货主联系人）
   - 各层级超时阈值（默认 30 分钟 / 2 小时 / 24 小时，可配置）
   - 升级时是否仍通知下级（默认是，下级仍负责处理）
2. **升级触发**：状态为"已触发"或"已通知"且时长 > 阈值 → 升级到下一级
3. **升级停止条件**：
   - 已确认 → 暂停升级
   - 已关闭 → 终止升级
   - 已到 L3 仍未确认 → 持续每 24 小时再次发送（避免无限升级）
4. **多通道并行**：升级时通知所有上级 + 仍通知下级 = 不依赖单一渠道
5. **升级路由**：可针对节假日 / 夜间配置不同接收人（off_hours_handler）
6. **审计**：升级事件写入 H2 审计（含升级层级 / 时长 / 原因）

### 异常路径

- 升级时上级离职 → 走 H1 角色查找现任 → 仍空则升级到系统管理员
- 多重告警同时升级 → 每个告警独立计时不互相影响

## US-AL-004：告警看板与统计

**作为** 仓库主管 / GSP 审计员
**我要** 看到当前活跃告警 + 历史统计
**以便** 现场处置 + 月度合规报告

### 验收标准

1. **活跃告警列表**：
   - 按级别（critical 置顶）+ 时间倒序
   - 显示：告警类型 / 关联资源 / 触发时间 / 当前状态 / 接收人 / 已等待时长
   - 一键确认 / 关闭（按权限）
   - 关联跳转（点击告警跳到对应业务单据 / 资源页）
2. **筛选维度**：货主 / 仓库 / 级别 / 状态 / 时间 / 告警类型
3. **历史统计**：
   - 按月份的触发量 / 确认率 / 平均响应时长 / 升级率
   - 按告警类型 Top 10
   - 按接收人 Top 10（响应快的人 / 经常未响应的人）
4. **GSP 合规报表**：GSP 强制告警类的完整生命周期记录（监管审计可查）
5. **导出**：Excel + PDF（含数据筛选条件）
6. **实时更新**：基于 H2-005 事件订阅，看板状态变化 ≤ 5 秒刷新
7. **审计**：报表查询写入 H2 审计

### 异常路径

- 数据量大查询慢 → 默认查近 30 天，超出范围分页 + 异步查询
- 导出超大数据 → 限制单次 ≤ 10 万条 / 异步生成 + 邮件下载链接

## US-AL-005：告警通道与静默配置

**作为** 仓库主管 / 系统管理员
**我要** 配置告警的通知通道、夜间/节假日规则、静默期
**以便** 减少打扰 + 关键告警仍能突破

### 验收标准

1. **通道配置**：
   - 默认企微（活跃通道）
   - 邮件（备份通道，重要告警）
   - 短信（critical 级别 + 升级 L3 时启用）
   - PDA 弹窗（PDA 在线时实时推送）
   - 振铃（critical + 夜间 + L3 升级时仅适用主管）
2. **节假日规则**：
   - 工作日 / 周末 / 节假日字典（M-PM 维护）
   - 节假日告警的接收人可单独配置（如周末由值班主管接收）
3. **夜间规则**（默认 22:00-06:00）：
   - info 级别延迟到次日早上发送
   - warning 级别正常发送
   - critical 级别立即发送（不延迟）
4. **静默期**：
   - 全局静默：仓库维护期可配置全告警静默（管理员审批 + 时长上限 24 小时）
   - 类型静默：单告警类型静默（如冷链调试时关闭超标告警）
   - **GSP 强制告警不可静默**
5. **重启告警**：服务重启后未关闭的告警自动重新评估（如温度已恢复 → 自动关闭）
6. **审计**：通道 / 节假日 / 静默配置变更写入 H2 审计

### 异常路径

- 静默期设置过长（> 24 小时）→ 拒绝并提示需要分多次设置
- 节假日字典与系统时间不一致 → 以系统时间为准 + 告警

## 与其他模块的关系

| 模块 | 关系 |
|---|---|
| **H4 企业微信通知** | H4 = 消息发送通道（具体调企微/邮件/短信 SDK）；H-AL = 告警业务逻辑（分级/升级/生命周期）。H-AL 调用 H4 |
| **H2-005 事件总线** | H-AL 订阅事件总线触发告警（解耦） |
| **M-QL 质量联系单** | 告警的"处理"可链接到 M-QL 联系单（如温度超标 → 创建养护异常联系单） |
| **M5 冷链 / M3 养护 / M2 资质** | 业务事件源 |

## 业务边界声明

> H-AL 告警引擎的边界：
>
> 1. **承载告警业务逻辑**：分级 / 升级 / 生命周期 / 路由 / 静默
> 2. **不承载消息发送**：通道层（企微 / 邮件 / 短信 / PDA 弹窗）由 H4 实现
> 3. **不主管业务规则**：业务规则（如"温度多少算超标"）由 M-VR / M5 决定，H-AL 只负责"事件来了 → 谁处理 → 是否升级"
> 4. **GSP 强制告警不可停用**：6 类 GSP 强制告警 `is_disable_allowed=false`，业务方不可关闭
> 5. **告警 ≠ 通知**：通知是单向消息发送（H4），告警是有完整生命周期 + 升级机制（H-AL）
