## US-M6-001：GSP 法定台账自动生成

**作为** 仓库主管
**我要** 系统自动生成 GSP 要求的法定台账
**以便** 药监检查时直接打印提交，无需手工整理

### 验收标准

1. 法定台账类型：
   - 验收记录（入库验收明细）
   - 养护记录（在库养护明细）
   - 出库复核记录（出库复核明细）
   - **库存流水账（所有库存变动，详见下方字段表与查询维度）**
   - 温湿度记录（接收外部冷链系统数据，参 M5-002）
   - 不合格品处置记录
   - **购销记录（按 GSP 要求：进货登记 + 销售登记，从 M2/M4 单据汇总）**
   - **特殊管理药品专用台账（v24 新增，详见 US-M6-004）**：麻精毒放等分类按 M1-010 字典 `requires_dedicated_ledger=true` 自动生成专用台账，"五专"格式（专人 / 专柜 / 专账 / 专册 / 专用处方）由分类字段决定
2. 自动从业务数据汇总生成（不需要手工录入）
3. 支持按时间范围/商品/供应商/货主筛选
4. 支持打印（使用打印模板引擎）和导出 PDF/Excel
5. 台账数据不可修改（来源于审计追踪，只读）

### 查询维度（PC 端列表/检索）

1. **基础筛选**：
   - 时间范围（默认本月，可选近 7/30/90 天/自定义）
   - 商品（编码/名称模糊匹配）
   - 批号（精确匹配）
   - 库位（库区/排/列/层）
   - 货主（多货主隔离自动过滤）
2. **业务筛选**：
   - 操作类型（多选，从 22 类选）
   - 关联单据类型 / 单据号
   - 操作人（按 user_id 或姓名）
   - 审批源类型（多选，反向追溯用）
3. **状态筛选**：
   - 变动前/后状态（合格/隔离/不合格/待销毁）
   - 同步 ERP 状态（未同步/已同步/同步失败）
4. **聚合视图**：
   - 按商品+批号汇总（一行显示该批次的全部流水）
   - 按时间分组（按天/周/月）
   - 按操作人分组（绩效相关）
5. **导出**：
   - Excel 全字段导出
   - PDF 法定格式导出（参 GSP 第 142 条要求）
6. **排序**：默认按操作时间倒序；可按变动数量/批号排序

### 反向追溯能力

1. 输入批号 → 显示该批次完整流水（入库 → 全部变动 → 出库或当前剩余）
2. 输入审批源 ID（如对账记录 ID/质量联系单 ID）→ 显示由此审批源触发的所有库存变动
3. 输入关联单据号（如 ASN 号）→ 显示该单据涉及的所有库存变动
4. 反向追溯结果可导出，作为 GSP 检查证据

## US-M6-002：审计追踪查询

**作为** 仓库主管 / 系统管理员
**我要** 查询任意操作的完整审计记录（谁/什么时间/做了什么/旧值/新值）
**以便** 追溯问题、满足 GSP 不可篡改要求

### 验收标准

1. 查询维度：操作人、时间范围、操作类型、关联单据、商品、批号
2. 显示：操作人、时间、操作类型、旧值、新值、IP 地址、关联单据号
3. 审计数据 append-only（不可修改/删除）
4. 数据保留 ≥ 5 年
5. 支持导出
6. **数据完整性双重保障**（v11）：
   - 业务事件级：本故事 append-only 审计追踪记录单条操作
   - 全库快照级：H10 数据库备份与恢复（infra/technical-specs.md）做整库定时备份 + WAL 增量
   - 两者共同满足 GSP 数据完整性要求；详见 docs/compliance/gsp-ch5-warehouse-management.md
7. **恢复操作的审计**：H10 数据库恢复时，恢复事件本身写入本审计表（actor=`system-restore`，附触发人 user_id + 批准人 user_id + 恢复时点）

## US-M6-003：业务报表

**作为** 仓库主管 / 货主
**我要** 查看业务统计报表（出入库量/库存周转/效率/各业务模块岗位绩效等）
**以便** 数据驱动决策，从业务模块角度而非任务引擎角度看绩效

### 验收标准

1. 报表类型：
   - 出入库日报/月报（按商品/货主/供应商）
   - 库存周转率
   - 任务效率报表（来自 M-TE-010 任务引擎绩效）
   - 近效期预警报表
   - 合规风险报表（强制通过统计）
   - 对账差异报表
   - **业务模块岗位绩效报表**（v8 新增，详见下方）

2. **业务模块岗位绩效报表**（v8 新增，从业务模块角度看人员绩效，区别于 M-TE-010 任务引擎角度）：

| 报表 | 业务模块 | 关键指标 | 数据来源 |
|------|---------|---------|---------|
| 收货员绩效 | M2 入库 | 收货量 / 验收量 / 双人签字延迟 / 拒收率 / 档案补录触发数 | M2-002/003/004 |
| 养护员绩效 | M3 库存 | 养护完成率 / 异常发现率 / 平均养护时长 / 漏养护数 | M3-004 |
| 拣选员绩效 | M4 出库 | 拣选量 / 短拣率 / 拣选差错率（被复核驳回）/ 平均拣选时长 / 错拣导致退货笔数 | M4-003 + M4-008 反查 |
| 复核员绩效 | M4 出库 + M-PK | 复核量 / 复核漏检率（出库后被客户投诉/退货）/ 平均复核时长 | M4-004 + M-PK-002 |
| 包装员绩效 | M-PK | 装箱量 / 称重差异率 / 箱型选择准确率（推荐 vs 实用偏差）/ 平均装箱时长 | M-PK-002/003 |
| 补货员绩效 | M-RP | 补货量 / 紧急补货响应时长 / 补货差异率 | US-RP-005 |
| 综合岗位画像 | 跨模块 | 单人多岗位综合得分 / 培训需求识别 | 各模块汇总 |

3. **报表交叉视角**（业务 vs 任务引擎）：
   - **M-TE-010**：从任务引擎角度看（每人完成多少任务、平均时长）
   - **M6-003**：从业务模块角度看（拣选员的"业务关键指标"，如错拣导致的客户退货笔数）
   - 两者交叉对照可识别"任务做得快但业务质量差"的员工

4. **业务质量追溯**：
   - 客户投诉 → 反查出库订单 → 拣选员 / 复核员 / 包装员 user_id → 计入对应岗位的"业务质量"指标
   - 验收不合格 → 反查供应商 + 收货员（识别供应商问题 vs 收货员漏检）
   - 养护异常未在计划日 +3 天内发现 → 反查养护员的覆盖率

5. 支持图表展示（柱状图/折线图/饼图/雷达图 — 雷达图用于综合岗位画像）

6. 支持导出 Excel/PDF；支持邮件/企业微信定时推送（可配置）

7. **多维度过滤**：时间范围 / 仓库 / 货主 / 岗位 / 员工 / 报表类型

8. 货主只能看自己的数据（多货主隔离）

9. 报表本身只读，不产生写操作；导出 / 定时推送操作写入审计追踪（操作人 / 时间 / 报表类型 / 过滤条件）

## US-M6-004：特殊管理药品专用台账

**作为** 仓库主管 / GSP 审计员 / 监管检查员
**我要** 系统按 M1-010 字典自动生成"麻精毒放"等特殊管理药品的专用台账，"五专"管理可单独导出
**以便** 满足《麻醉药品和精神药品管理条例》《医疗用毒性药品管理办法》《放射性药品管理办法》等法规对专用账册的要求

### 验收标准

1. **触发条件**：M1-010 字典中 `requires_dedicated_ledger=true` 的所有分类自动生成独立台账（默认 8 类中除"普通药品"外的 7 类，可扩展）
2. **台账内容字段**（与库存流水账字段表保持一致基础上扩展，v25 升级）：
   - 流水号 / 操作时间 / 商品编码（含 special_drug_category）/ 商品名称规格 / 批号 / 生产日期 / 有效期
   - 库位（专柜专库标识）/ 货主
   - **流程**（v25 新增，process）：入库 / 出库 / 报损 / 报溢 / 销毁 / 退货
   - **节点**（v25 新增，node）：与流程关联，见 M-VR US-VR-006 流程-节点定义表
   - 操作类型（与 M6-001 操作类型枚举一致）
   - 变动数量 / 变动前数量 / 变动后数量
   - 关联单据类型 / 单据号
   - **第一操作人 user_id + 姓名**（必填）
   - **第二操作人 user_id + 姓名**（条件必填，规则见下条 §2.1）
   - **审批人 user_id + 姓名**（按 M-VR 双人策略 = `dual_scan_with_approval` 时必填）
   - **双人策略命中规则 ID**（关联 M-VR US-VR-006 规则，便于反查策略来源）
   - 审批源类型 / 审批源 ID / 备注

2.1 **第二操作人填写规则**（v25 升级）：当且仅当 M-VR 双人策略接口对该流程+节点返回 `dual_scan` / `dual_scan_with_approval` 时，第二操作人字段必填且 user_id 与第一操作人不同；返回 `single` 时第二操作人为空。覆盖以下流程节点：
   - **入库**：node=验收（普通药品默认必填）/ 收货 / 上架（特殊药品必填）
   - **出库**：node=复核（普通药品默认必填）/ 拣货 / 装箱 / 发货交接（特殊药品必填）
   - **报损**：node=报损执行（特殊药品必填）
   - **报溢**：node=报溢执行（特殊药品必填）
   - **销毁**：node=销毁执行（强制必填，麻精毒放销毁强制 dual_scan_with_approval）
   - **退货**：node=退货验收 / 退货上架（特殊药品必填）
3. **专册格式**：每个分类的台账按法规要求格式输出：
   - 麻精药品：日清月结，月底结存核对（GSP 要求）
   - 毒性药品：进销存逐笔登记
   - 放射性药品：在毒性药品基础上增加放射防护检查记录关联
   - 疫苗 / 血液制品：批次追溯到客户级
4. **专人查阅**：本台账查询权限独立配置（默认仅仓库主管 + 质量负责人 + 监管检查员；普通收货员 / 保管员不可查），权限变更须双人审批
5. **数据来源**：从 M6-001 库存流水账过滤得到（按 special_drug_category 字段过滤），不重复存储
6. **导出格式**：
   - 单一分类的专册（PDF / Excel）
   - "入库 + 验收 + 库存 + 出库 + 销毁"五栏式样式（PDF 法定格式；GSP 法规原文称"进货销售"，本系统按术语规范化使用入库 / 出库表达）
   - 月度结存核对报告（自动生成，按月份汇总）
7. **结存自动核对**：每月最后一日 23:59 自动生成上月结存对账，差异时企业微信通知仓库主管 + 质量负责人 + 系统管理员
8. **保留期限**：与 M6-001 共用 ≥ 5 年保留策略；放射性药品台账保留 ≥ 30 年（按法规要求）
9. **印章 / 签章**：导出 PDF 时按打印模板（H9）支持电子签章占位（具体签章流程暂不在本期实现，留接口）
10. **GSP 检查现场支持**：检查员账号可在 PC 端按"检查所需"批量导出指定时间窗的全部分类专册（zip 包）
11. 台账查询本身只读，不产生写操作
12. 导出 / 月度核对生成 / 检查现场批量导出操作写入审计追踪
13. 导出操作支持 Idempotency-Key

## 跨故事约束

1. **审计追踪**：报表本身不产生审计（只读）
2. **多货主**：报表按货主隔离
3. **GSP 合规**：法定台账数据不可篡改
4. **打印模板**：台账打印使用 US-M2-009 模板引擎
5. **数据完整性双层保障**：M6-002 业务事件级审计 + H10 数据库备份与恢复（基础设施级），两者共同满足 GSP；详见 docs/infra/technical-specs.md "H10 数据库备份与恢复" 段
6. **幂等性**：台账/报表生成支持 Idempotency-Key，相同时间窗口重复生成返回相同结果（只读模块本身无写操作）
