# 用户故事：M-RC 库存对账模块

> 模块：M-RC reconciliation
> 性质：独立业务模块（WMS 与 ERP 库存一致性保障）
> 波次：Wave 3（依赖 M2 入库反馈 + M4 出库反馈都跑通后）
> 依赖：M1 基础档案、M3 库存、H1 权限、H2 审计、H4 企业微信通知

---

## 背景

WMS 入库后反馈 ERP → ERP 记账 → ERP 下出库订单指定批号。
理论上 ERP 库存 = WMS 库存，但可能因网络延迟、并发、人工干预等导致不一致。
对账模块定期比对两边数据，发现差异即推送通知。

## US-RC-001：定时对账任务

**状态**：已实现（2026-07-23，内部验收通过；客户正式 ERP 环境证据由 H8 发布门禁单独收口）

**作为** 系统（定时任务）
**我要** 按配置的频率自动比对 WMS 库存与 ERP 库存
**以便** 在配置的对账周期内发现数据不一致，防止出库时才暴露问题

### 验收标准

1. 对账频率可配置（默认每天一次，可设为每小时/每 N 小时）
2. 对账维度：按商品+批号+货主，比对 WMS 在库数量 vs ERP 账面数量
3. ERP 库存数据获取方式：调用 ERP API 查询（WMS 主动拉取）
4. 对账结果分类：一致 / WMS 多（WMS > ERP）/ ERP 多（ERP > WMS）
5. 对账结果存储：对账记录表（对账时间、商品、批号、WMS 数量、ERP 数量、差异、状态）
6. 对账任务执行记录写入审计追踪

## US-RC-002：差异处理

**状态**：已实现（2026-07-26；异步闭环、显式库存分配、稳定分页和真实浏览器证据通过）

**作为** 仓库主管
**我要** 查看对账差异明细，并对选择的差异项进行锁定和处理
**以便** 差异不扩大，主管按风险优先级决定哪些差异需要立即冻结

### 验收标准

1. 差异列表：按商品/批号/货主/差异类型筛选；使用 `created_at + id` 降序稳定键集分页，默认 50、最大 200，返回不透明 `next_cursor`，默认查询不得隐含时间截断
2. **差异不自动锁定**：发现差异后只在差异列表中标记 + 推送企业微信通知（避免误锁影响业务）
3. **主管选择性加锁**：仓库主管在差异列表上勾选要锁定的差异项 → 触发"对账隔离"动作 → 该批次库存状态由"合格"变为"隔离"（携带审批源 = 对账 ID，参见 M3-003）
4. **批量解锁**：只有差异进入 `resolved` 或 `known_difference` 后才可批量解锁（释放隔离）；等待 M-SA 或 ERP 回执以及异常状态都不得提前释放
5. 处理方式（人工选择）：
   - 以 WMS 实物为准 → 通知 ERP 修正账面，状态进入 `erp_feedback_pending`；只有 H8 业务成功回执后进入 `resolved`
   - 以 ERP 为准 → 显式提交一个或多个库存分配，WMS 为每个分配创建可追踪的 M-SA 报损/报溢审批单，状态进入 `adjustment_pending`；全部调整单完成后进入 `resolved`
   - 标记为已知差异（如在途、时间差） → 不锁定，列表标记后归档
6. 显式库存分配项包含 `inventory_batch_id + quantity`，数量为正、批次不得重复，库存批次必须与差异同货主/商品/批号，所有分配数量合计必须等于差异绝对值；服务端按库存批次 ID 稳定排序加锁，禁止隐藏 FEFO。ERP 多但 WMS 尚无对应批次时，先走受控批次创建流程，不得猜测生产日期、效期或供应商
7. M-SA 调整拒绝/取消，或 H8 回执拒绝/死信时，差异进入 `exception` 并保留隔离；修复后通过原关联继续推进，不得伪装为已处理
8. 所有锁定、解锁、处置发起、子单/回执推进和异常操作写入审计追踪

### 差异处理状态

| 状态 | 含义 | 是否可释放隔离 |
|---|---|---|
| `open` | 已发现、尚未选择处置 | 否 |
| `adjustment_pending` | 已创建一个或多个 M-SA 调整单，等待全部完成 | 否 |
| `erp_feedback_pending` | 已生成 H8 ERP 修正消息，等待业务成功回执 | 否 |
| `exception` | 子调整拒绝/取消，或 ERP 回执拒绝/死信 | 否 |
| `resolved` | 全部 M-SA 调整完成，或 ERP 业务成功回执 | 是 |
| `known_difference` | 主管确认的可解释差异，已归档 | 是 |

## 跨故事约束

1. **审计追踪**：所有对账操作写入审计表
2. **多货主**：对账按货主隔离
3. **差异锁定 = 主管选择**：差异不自动锁定，由主管在差异列表勾选；锁定动作复用 M3 库存隔离机制（携带审批源=对账 ID）
4. **幂等性**：同一时间窗口重复触发对账不产生重复记录
5. **企业微信通知**：差异发现时通知仓库主管
6. **ERP 接口**：对账依赖 ERP 提供库存查询 API（需确认接口格式）
7. **异步闭环**：处置请求只负责创建 M-SA/H8 子流程和关联，不得直接把差异改为 `resolved`；状态由子流程的持久事件推进

## 2026-07-23 实施与验收结论

`US-RC-001`、`US-RC-002` 已按外向内 TDD 完成内部验收：

- H-SCH 按货主 Worker 周期性执行 `sync_worker.py --once --reconcile-due`；只有持有
  service-only `rc.reconciliation.ingest` 的服务账号可认领当前令牌货主的到期窗口、续租和提交快照，
  仓库主管的 `rc.reconciliation.execute` 只能维护频率，不能伪造 ERP 快照。
- 调度认领使用不可猜测 token 和 30–900 秒有限租约；分页拉取期间逐页续租，同一货主+窗口同一时刻
  只有一个 active claim。租约过期或 Worker 主动上报 pull/submit 失败后可由其他 Worker 按递增
  attempt 接管；认领、续租、完成、失败与租约过期均追加 H2 审计，失败与租约过期还会创建 H4 运维通知。
- `POST /reconciliation/runs` 必须绑定 active claim；对账批次、明细、差异通知、审计、幂等记录与
  claim completed 在同一 PostgreSQL 事务提交，任何一步失败均保持 claim 未完成且不留下半批次。
- Worker 只复用 H8 owner-wide（`warehouse_ids=[]`）active `inventory_snapshot` 出站路由，调用自研 ERP
  `GET /inventory-snapshots?owner_id=...&cursor=...`，校验统一 `snapshot_at`、分页和 canonical 商品/批号/在库数量后，一次提交 WMS 对账事务。
- 对账按货主、商品、批号聚合真实库存，持久化一致/WMS 多/ERP 多结果；同一窗口使用请求哈希防止不同幂等键重复或静默覆盖。
- 差异只通知、不自动隔离；主管可勾选差异隔离/释放，库存状态变更保留对账审批源、对账 ID 和原状态。
  不同对账窗口对同一库存批次隔离时共享原始状态并分别持有引用；释放单条差异只释放自身引用，
  仅最后一个有效对账引用释放时恢复库存状态，且不得接管没有对账引用的外部隔离。
- 2026-07-23 的“创建 outbox/调整单后立即已处理”证据已被 2026-07-26 的异步闭环决策取代。以 WMS
  为准必须保持 `erp_feedback_pending` 至 H8 业务成功回执；以 ERP 为准必须支持多条显式库存分配，
  并保持 `adjustment_pending` 至全部 M-SA 单完成。拒绝、取消或死信进入 `exception` 且不释放隔离。
- 列表契约改为 `created_at + id` 稳定键集分页，默认 50、最大 200，默认不加时间窗口；旧偏移分页或
  隐含时间截断证据不再满足本故事。
- 管理端使用公共 QueryPanel + DataGrid，商品/差异类型/处理状态/批号字段均中文展示，差异类型与处理状态使用多选控件。
- 真实 PostgreSQL、权限、审计、幂等、跨模块 M-SA、H8 业务回执、Python HTTP 契约和真实浏览器 E2E
  已通过。浏览器证据覆盖真实差异、终态后释放、多库存批次显式分配、`adjustment_pending`、
  `exception` 中文状态以及 51 条同时间数据的两页键集加载；截图见
  `artifacts/screenshot-portal/real-web/mrc-reconciliation/`。

客户正式 ERP dev/staging/生产请求、回执和重试证据仍属于 H8 外部发布门禁，不能用本地 HTTP 测试冒充；该发布证据缺口不回退已经完成的 M-RC 内部业务实现状态。

### 测试维度覆盖

#### US-RC-001 定时对账任务

| 维度 | 场景 |
|------|------|
| L4 错误路径 | ERP 超时/非 JSON/快照时间漂移/非法数量/超过分页上限 → Worker 受控上报 failed；无效/过期 claim 拒绝提交；同窗口不同请求 → `RC_IDEMPOTENCY_CONFLICT` |
| L5 数据一致 | WMS 真实库存按货主+商品+批号聚合，与 ERP canonical 快照逐项全量比对；对账结果、通知、审计、幂等与 claim completed 同事务提交或回滚 |
| L6 并发 | 两个 Worker 并发认领同一 owner+window 时仅一个获得 token；active lease 阻止重复 ERP 拉取，过期后新 attempt 可接管 |
| L3 业务流程 | H-SCH → service-only claim/renew → H8 active route → 自研 ERP HTTP → WMS 对账+claim complete 事务 |
| L8 权限 | 当前货主 `rc.reconciliation.execute` 仅可维护规则；claim/renew/failed/快照提交要求 service-only `rc.reconciliation.ingest`，仓库主管调用 → 403；接口不枚举其他货主，仓级 `inventory_snapshot` 连接不进入 owner-wide 对账调度 |
| L10 可观测 | claim、renew、completed、failed、lease expired 追加 H2；Worker failed/lease expired 生成 H4 运维通知 |
| L11 幂等 | 频率、claim、renew、failed 和对账提交均要求 Idempotency-Key；相同请求重放不重复 claim、审计、通知或对账批次 |
| V3 浏览器证据 | 页面读取真实 PostgreSQL 差异、保存 6 小时频率并生成截图证据 |

#### US-RC-002 差异处理

| 维度 | 场景 |
|------|------|
| L3 业务流程 | M-RC → M3 对账隔离；M-RC → M-SA 多调整单完成；M-RC → H8 ERP 修正与业务回执；差异发现 → H4 通知 |
| L4 错误路径 | 空选择、终态差异、错误处置、分配为空/重复/跨货主商品批号/合计不等于差异、数量超可用量、子调整拒绝/取消、ERP 回执拒绝/死信 → 受控失败且不误释放隔离 |
| L5 数据一致 | 隔离/释放保留每个库存批次原状态；跨窗口同批次分别持有隔离引用，最后一个引用释放才恢复且不接管外部隔离；WMS 为准的 H8 outbox 与 `erp_feedback_pending` 同事务；ERP 为准按批次 ID 稳定加锁并原子创建全部 M-SA 单、关联和 `adjustment_pending`；只有全部子流程成功后才原子进入 `resolved` |
| L7 性能 | `created_at + id` 键集分页在并发新增相同时间记录时无重复、无漏读；默认 50、最大 200，查询计划不依赖全表 OFFSET |
| L8 权限 | `read`、`execute`、`resolve` 分权；页面无 `resolve` 时只读；后端无权限 → 403 |
| L9 兼容性 | OpenAPI、api-client、前端模型同步移除单 `target_inventory_batch_id` 和偏移分页旧契约 |
| L10 可观测性 | 处置发起、每个子调整/回执推进、异常和最终关闭可通过 correlation_id、审计和指标关联 |
| L11 幂等 | 隔离、释放、WMS 为准、ERP 为准和已知差异均要求 Idempotency-Key；重放不重复库存变更、M-SA 单、outbox 或审计 |
| V3 浏览器证据 | 真实页面覆盖稳定加载更多、多条显式库存分配、等待/异常中文状态、终态后释放，并归档截图 |
