# WMS Review Fix Commit

用于把一批 WMS 变更从“待审查”推进到“已修复、已验证、按主题提交”。除非用户明确说“只审查”“只出报告”“只问有没有问题”“不要提交”或当前存在阻断问题，本技能默认完成本地分组提交。

## 先读

- `AGENTS.md`
- `docs/agent-collaboration.md`
- `docs/governance.md`
- 变更涉及目录的 `AGENTS.override.md`
- 任务相关的用户故事、ADR、设计文档、runbook 或代码文件

## 工作流

1. 运行 `git status --short` 和 `git diff --stat`，区分本轮变更、历史未提交变更和生成物。
2. 按主题分组：文档、治理脚本、前端、后端、测试、运行配置。跨主题变更必须拆组处理。
3. 对每组先 review，优先找：
   - 业务语义缺口、故事/RTM/字段/状态不一致。
   - 分层违规、裸 `fetch`、`any`、`unwrap`、硬编码密钥。
   - 缺测试、缺门禁接线、缺文档索引。
   - 提交粒度过大或混 scope。
4. 修复 review 发现的问题，只修本组问题；新增字段、状态、角色、模块、业务默认值前先问用户。
5. 再 review 同一组，重复“review → 修复 → review”，直到：
   - 没有阻断或高风险问题。
   - 相关脚本和测试通过。
   - 同一阻塞连续 3 轮仍无法解决时，停止并说明需要用户决策。
6. 全局验证：
   - 至少运行 `git diff --check`。
   - WMS 文件变更后运行 `just gov-t1`。
   - 前端、后端或脚本改动按范围补跑最小相关测试。
7. 默认分组提交：
   - 用户明确调用本技能、说“review 技能”、或要求“review 修复再 review”时，视为授权本轮本地分组提交。
   - 用户明确说“只 review / 只出报告 / 只问有没有问题 / 不提交 / 先别提交”时，停止在验证通过后的工作区状态。
   - 每组用显式路径 `git add <file...>`，禁止 `git add .`。
   - 每次提交前运行 `git diff --cached --stat`，确认只包含该组。
   - 提交信息用中文 Conventional Commits：`<类型>(<范围>)：<描述>`。
   - 已有脏工作区变更不得混进无关提交。
8. 提交后运行 `git status --short`，确认剩余变更是否符合预期。

## 分组建议

| 变更 | 提交类型/范围示例 |
|---|---|
| 文档、RTM、ADR、runbook | `文档(治理)：...` |
| 治理脚本和门禁接线 | `测试(治理)：...` 或 `修复(治理)：...` |
| 前端页面、组件、样式 | `功能(管理端)：...` |
| 后端 API、service、repository、migration | `功能(后端)：...` |
| 纯测试补充 | `测试(<范围>)：...` |

## 输出要求

- 先列审查结论：有无剩余问题。
- 列提交哈希和每组主题。
- 列验证命令与退出码。
- 如未推送，明确说明只完成本地提交。
