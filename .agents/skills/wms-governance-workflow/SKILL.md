# WMS 治理流程

当需要修改 WMS 需求、治理文档、用户故事、ADR、运行手册、证据门禁，或需要审查 / 修复治理失败时使用本技能。

## 先读

- `AGENTS.md`
- `docs/agent-collaboration.md`
- `docs/governance.md`
- `docs/layered-design.md`
- 相关模块的 `AGENTS.override.md`

## 工作流

1. 运行 `git status --short`。
2. 判断任务属于 P0、P1 还是 P2：
   - P0：现有脚本可验证。
   - P1：可新增或扩展脚本验证。
   - P2：需要人工语义判断。
3. 有风险变更先用编号选项向用户确认。
4. 无风险治理修复可直接改，保持 diff 小。
5. 运行 `just gov-t1`。
6. 只报告退出码和相关失败 / 警告。

## 必须确认的触发条件

新增或修改以下内容前必须确认：

- 模块、故事、基础设施、字段、角色、状态、审批源。
- 数据模型、校验、可空性、加密、审计要求。
- 跨模块语义。
- 没有既有证据支撑的业务默认值。
- 生产数据操作。

## 脚本优先规则

同类问题出现在 3 个或更多文件时，优先新增或改进治理检查，再批量修改文档。

## 输出要求

最终回复保持简短：

- 修改的文件或主题。
- 验证结果。
- 剩余风险或下一步。
